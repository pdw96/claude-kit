기준 `$base` 와 지금 작업트리의 차이를 모아 `.claude/audit-brief.md` 에 씁니다.

`$base` 가 비어 있으면 먼저 물어보세요 — 기본 브랜치인지, PR 의 머지 베이스인지,
직전 배포 태그인지에 따라 감사 결과가 달라집니다. **짐작하지 마세요.**

**사람이 없는 자리에서는 이 커맨드가 여기서 멈춥니다.** 클라우드 레인이나 CI
에서 쓰려면 기준을 인자로 넘겨야 합니다 — `/audit-brief origin/main audit-secrets`.
멈추는 것이 결함이 아니라, 짐작한 기준으로 만든 브리핑이 틀린 근거가 되는 쪽이
결함입니다.

## 왜 이것이 필요한가

감사자는 `Read` · `Grep` · `Glob` 만 갖고 있습니다. 실행도 git 도 없습니다.
PR 번호나 커밋 ID 만 주면 **스스로 차이를 구하지 못합니다.**

그래서 이 브리핑 없이 부르면 과거 상태와의 비교가 필요한 항목이 전부
「확인불가」로 남습니다. 그것 자체는 옳은 처분이지만, **기계로 구할 수 있는 것을
사람에게 묻고 있는 것**입니다. 사람에게만 물을 수 있는 것 — 프로덕션 설정,
운영 데이터, 배포 이력 — 만 확인불가로 남는 것이 옳은 잔여입니다.

## 할 일

**하나. 기준이 실재하는지 확인합니다.**

```
git rev-parse --verify $base
```

없는 기준이면 멈추고 알려 주세요. 잘못된 기준으로 만든 브리핑은 **틀린 근거**가
되고, 틀린 근거로 내린 판정은 안 내린 것보다 나쁩니다.

**둘. 아래를 모읍니다.** 실패한 명령이 있으면 그 자리를 비워 두지 말고 **실패한
사실을 브리핑에 적으세요.**

| 무엇 | 명령 |
|---|---|
| 기준 커밋 | `git rev-parse --short $base` 와 `git log -1 --format='%h %ad %s' --date=short $base` |
| 지금 위치 | `git rev-parse --short HEAD`, `git branch --show-current`, `git status --short` |
| 변경 파일 | `git diff --stat $base...HEAD` |
| 커밋 목록 | `git log --oneline $base..HEAD` |
| 본문 diff | `git diff $base...HEAD` |

작업트리에 커밋 안 된 변경이 있으면(`git status --short` 가 비어 있지 않으면)
`$base...HEAD` 는 그것을 담지 않습니다. 그 사실을 브리핑 머리에 적고, 필요하면
`git diff $base` 도 함께 넣으세요.

**셋. `.claude/audit-brief.md` 에 아래 모양으로 씁니다.**

```markdown
# 감사 브리핑

- 만든 시각: <지금>
- 기준: `<base>` = `<짧은 SHA>` (<날짜> <제목>)
- 대상: `<HEAD 짧은 SHA>` (브랜치 `<이름>`)
- 커밋 안 된 변경: <없음 / 있음 — 아래 diff 에 포함 여부>

## 변경 파일

<git diff --stat 결과>

## 커밋

<git log --oneline 결과>

## diff

<git diff 결과>

## 이 브리핑이 담지 않은 것

- 실행 결과 · 테스트 통과 여부
- 저장소 설정(브랜치 보호 · 룰셋 · 시크릿 저장소)
- 배포 환경 · 운영 데이터 · 배포 이력
- <잘라낸 것이 있으면 여기에 무엇을 얼마나 잘랐는지>
```

**diff 가 길면 자르되, 자른 사실을 반드시 적으세요.** 2000줄을 넘으면 파일별
`--stat` 은 전부 남기고 본문만 자른 뒤 「무엇을 얼마나 잘랐는가」를 적습니다.
말없이 자르면 감사자는 전부 본 줄 알고, **안 본 자리가 통과한 자리처럼**
보입니다 — 이 도구가 가장 피하려는 것입니다.

**넷. 감사자를 부릅니다.**

`$auditor` 가 주어졌으면 그 감사자를, 아니면 어느 감사자를 부를지 물어보세요.
부를 때 **브리핑 경로를 본문에 적어** 주세요:

```
@$auditor `.claude/audit-brief.md` 를 먼저 읽고, 그 diff 범위를 감사해 주세요.
```

## 남기는 것

**감사가 끝나면 그 기록을 `.claude/audits/<감사자 이름>-<날짜>-<시각>.md`(예:
`audit-secrets-2026-09-23-1430.md`)로 저장해 주세요.** 시각까지 붙여야 고친 뒤
같은 날 다시 돌린 기록이 앞의 것을 덮지 않습니다 — 덮이면 다음 회차가 이을
번호와 해소 근거가 사라집니다. 감사자는 쓰는 도구가 없어 스스로 남기지 못합니다. 다음 회차의
감사자가 이 폴더에서 자기 이름이 붙은 가장 최근 기록을 찾아 NC 번호를 잇고,
지난 부적합이 해소됐는지 · 유지되는지 · 이번엔 안 본 것인지를 가릅니다.
저장하지 않으면 매 회차가 첫 회차가 되고, 같은 번호가 회차마다 다른 결함을
가리킵니다.

**그리고 브리핑을 `.claude/briefs/<감사자 이름>-<날짜>-<시각>.md` 로 옮기세요.**
브리핑은 그 회차의 근거라 버리지 않되, `.claude/audit-brief.md` 자리에는 남기지
않습니다. 남아 있으면 다음에 감사자를 직접 부를 때 그것을 읽는데, 감사자는
브리핑의 대상 SHA 를 HEAD 와 견줄 수만 있고 `git status` 는 못 돌립니다 — 그
사이 **커밋하지 않은 변경**이 있어도 SHA 는 같아서 지난 diff 를 이번 것으로 씁니다.
`.claude/audits/` 에 두지 않는 까닭은, 감사자가 그 폴더에서 자기 이름이 붙은
가장 최근 파일을 지난 기록으로 집기 때문입니다.
