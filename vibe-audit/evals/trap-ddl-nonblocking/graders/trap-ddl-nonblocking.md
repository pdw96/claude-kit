## 먼저 할 것 — 볼 자리를 자른다

`migrations/versions/0002_orders_customer_index.py` 의 **잠금(쓰기가 멈추는가)** 판정만 봅니다. 보는
곳은 셋입니다 — 체크 항목 표에서 **항목 3** 을 다룬 행(판정 칸과 근거 칸), `## 부적합 목록` 절(`### NC-`
항목들), `## 확인불가 항목` 절(`### U-` 항목들). 관찰(OB) · 「안 본 것」 · 앞뒤 요약은 판정에 넣지
마세요. **NC 번호가 붙은 것만이 부적합이고, U 번호가 붙은 것만이 확인불가 항목입니다.**

다른 리비전 · 다른 항목의 처분, 그리고 `app/checkout.py` 의 NC(이 케이스의 대조군)는 보지 않습니다.

## 배경

저장소가 엔진 · 판을 적었습니다 — PostgreSQL 16(`CLAUDE.md` · `docker-compose.yml` 의 `postgres:16.4` ·
`psycopg`). 0002 는 운영 중인(점검 시간 없음) `orders` 에 `postgresql_concurrently=True` 로 인덱스를
만들고, `autocommit_block` 으로 트랜잭션 밖에서 돕니다. PostgreSQL 의 CREATE INDEX CONCURRENTLY 는
SHARE UPDATE EXCLUSIVE 잠금만 잡아 **쓰기를 막지 않습니다.** 리비전 독스트링이 그것을 맞게 적었습니다.
고칠 것이 없고, 대상(기존 행이 있는 운영 중인 표의 DDL)은 있습니다.

## 판정

PASS — 항목 3 의 행 판정이 **적합** 하나이고, 그 행이 0002(인덱스 · CONCURRENTLY)를 다룬다. 항목 3 을
여러 행으로 쪼갰으면 0002 를 다룬 행이 적합이다. 도중 실패 때 INVALID 인덱스가 남는다는 것 등을 관찰(OB)로
따로 적은 것은 괜찮습니다 — 행의 판정이 적합이면 PASS 입니다.

FAIL — 다음 중 하나에 해당한다
- 0002 의 잠금이 **NC 번호를 달았다** — 동시 생성 옵션 없는 인덱스로 읽었거나, 트랜잭션 · 잠금 시간을 들어
  부적합으로 걸었다
- 0002 의 잠금이 **U 항목**으로 섰다 — 얼마나 오래 걸리는지(행 수 · 트래픽)를 들어 확인불가로 둔 것도 그렇다
- 항목 3 의 판정 칸이 **확인불가** · **해당 없음** · 부적합이다 — 「쓰기를 멈추지 않으니 해당 없음」도 FAIL 이다.
  대상(운영 중인 표의 DDL)이 있고, 판정은 그 DDL 을 확인한 결과다
- 판정 칸에 판정 낱말이 **둘**이다 — 「적합 — 다만 확인불가」처럼 섞였다
- 0002 의 잠금을 아예 다루지 않았다 — 항목 3 이 0001 만 보고 적합이 난 것도 그렇다

**칸에 적힌 판정 낱말로 가릅니다.** 근거 칸이 사실(SHARE UPDATE EXCLUSIVE · 트랜잭션 밖)을 덧붙이는 것은
판정을 쪼갠 것이 아닙니다.

NC · U 번호가 몇 번인지, 문장이 어떤 서식인지는 보지 않습니다.
