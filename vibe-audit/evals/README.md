# 감사자를 감사한다

`audit-quality` 가 남에게 요구하는 것 — 평가셋 · 회귀 판정 · 무는 게이트 — 을
이 플러그인이 자기 자신에게 적용한 자리다.

```bash
./scripts/run-evals.sh
```

`--scaffold` 없이는 픽스처가 만들어지지 않아 빈 작업공간에서 돈다. 이 수트의
`fixture.sh` 는 전부 이 저장소가 쓴 것이다.

## 이 수트가 재는 것 — 오검율

**회수율(심은 결함을 몇 개 잡는가)은 아직 재지 않는다.** 미리 지어낸 결함은
저장소 뿌리 README 가 특화 항목에 대해 금지한 것 — 재지 않고 단정한 것 — 의
픽스처 판이기 때문이다.

대신 **오검율**을 잰다. 여기 있는 다섯은 전부 ERP 되먹임에 기록된 **실제로
겪은 거짓 판정**이고, 케이스 하나가 되먹임 한 건에 1:1 로 붙는다. 고친 자리마다
회귀 검사가 하나 서는 셈이다.

| 케이스 | 되먹임 | 무엇이 새던 자리 |
|---|---|---|
| `trap-local-dev-password` | 1차 · 2026-09-16 | 로컬 전용 개발 비밀번호를 시크릿으로 걸었다 |
| `trap-liveness-probe` | 1차 · 2026-09-16 | 라이브니스 프로브의 정상 설계를 부적합으로 봤다 |
| `trap-rollback-unproven` | 1차 · 2026-09-16 | 저장소에 흔적이 없다고 롤백을 「안 해 봤다」로 단정했다 |
| `gate-out-of-scope` | 2차 · 2026-09-20 | 담당 밖 발견을 NC 로 적었다 (서른셋 중 열여덟) |
| `gate-own-not-pushed` | 3차 · 2026-09-21 | 담당인 것을 근거 주는 감사자에게 통째로 넘겼다 |

거짓 지적을 두어 번 내면 아무도 감사자를 안 부른다. 오검이 이 도구에서
가장 비싼 결함이고, 그래서 먼저 잰다.

## 트리거 정확도 — 재는 대상이 다르다

위 다섯이 감사자의 **판정**을 잰다면, `route-*` 셋은 프론트매터 `description`
의 **반응**을 잰다. 감사자를 이름으로 지목하지 않은 자연스러운 말에 맞는 것이
뜨는가.

| 케이스 | 말 | 떠야 할 것 | 새면 안 되는 곳 |
|---|---|---|---|
| `route-quality` | "테스트랑 CI 가 실제로 막아 주고 있는지" | `audit-quality` | `audit-internal` |
| `route-contract` | "응답 모양이 쓰던 사람들 깨뜨리는 데가 없는지" | `audit-contract` | `audit-data` |
| `route-internal` | "적어 둔 것하고 실제가 어긋난 데 있는지" | `audit-internal` | `audit-quality` |
| `route-quiet` | "이 함수 이름 뭐로 바꾸면 좋을까" | **아무도** | 여섯 전부 |
| `route-unasked-auth` | "README 어느 절에 넣을까" (인증을 막 붙인 뒤) | `audit-secrets` | `audit-internal` |
| `route-unasked-secret` | "이대로 PR 올려도 될까" (키가 박힌 채) | `audit-secrets` | `audit-quality` |
| `route-unasked-contract` | "테스트 파일 이름 관례가 뭐야" (공개 응답 필드를 막 바꾼 뒤) | `audit-contract` | `audit-quality` · `audit-secrets` |
| `route-unasked-data` | "PR 제목 뭐로 할까" (위험한 마이그레이션을 막 짠 뒤) | `audit-data` | `audit-contract` · `audit-secrets` |

전부 `tool_used` 그레이더뿐이라 **심판 비용이 0** 이다. 판정 케이스가 없는
셋에 그대로 갔다.

**음성 그레이더(`route-not-*`)가 여기서 대조군 자리에 선다.** 없으면 여섯을
전부 띄우는 세션도 「맞는 감사자가 떴다」로 통과한다.

**이 문구들은 구성한 것이다.** 함정 다섯과 달리 실제로 겪은 문구 기록이 없다.
재는 대상이 다르기 때문에 그래도 된다 — 함정은 감사자의 판정을, 트리거는
description 의 반응을 본다. 후자는 입력을 만들지 않으면 잴 방법 자체가 없다.

### 트리거 케이스가 무는 것을 확인한다

세 번 걸었고, 첫 번째는 **안 물었다.**

| 변이 | 결과 |
|---|---|
| `audit-internal` 에 `audit-quality` 의 description 을 줌 | 1.000 — **안 뭄** |
| `audit-quality` 의 description 을 무관한 내용(정적 자산 압축)으로 | **0.250** — `route-correct` 2/2 실패 |
| 위 둘을 함께 | **0.000** — `route-correct` 0회 호출, `route-not-internal` 1회 호출 |

첫 변이가 안 문 것은 케이스의 결함이 아니라 **대조 설계의 결함**이었다. 이름과
제대로 된 description 을 그대로 가진 `audit-quality` 가 여전히 이겼기 때문이다.
이길 수 없게 만들자 바로 물었다.

읽어 낼 것이 하나 있다 — **description 이 라우팅을 실제로 움직인다.** 이름만으로
정해졌다면 두 번째 변이에서도 통과했을 것이다.

### 요청하지 않은 말에는 — 아홉 회차 중 0

위 셋은 전부 **「봐 주세요」라고 요청한** 말이다. description 은 그것 말고도
「인증 · 권한 · 환경변수 · CORS 설정을 건드린 뒤에 쓰세요」라고 적고 있는데,
그 절이 실제로 무언가를 움직이는지는 아무도 안 쟀다. 옳은 동작을 정하기 전에
**현재 상태부터** 쟀다 — 감사를 요청하지 않은 말 둘과, 무관한 말 하나.

| 말 | 상황 | 결과 |
|---|---|---|
| 「README 에 로컬 실행 방법 어디에 넣을까?」 | 방금 인증 미들웨어를 붙였고 `SESSION_SECRET` 이 코드에 박혀 있다 | `audit-secrets` **0/3** |
| 「지금 이 상태로 PR 올려도 될까?」 | 결제 라이브 키가 코드에 박혀 있고 `CLAUDE.md` 가 금지하고 있다 | `audit-secrets` **0/3** |
| 「이 함수 이름 뭐로 바꾸면 좋을까?」 | 감사와 무관 | 아무도 안 뜸 **3/3** |

**감사자는 아홉 회차 중 한 번도 스스로 뜨지 않았다.** 오탐도 0 이다.

안 뜬 자리에서 무슨 일이 일어나는지가 더 중요하다. 세션이 **자기가 훑었다.**

> 아직 PR 올리면 안 될 것 같아요. (…) **하드코딩된 라이브 API 키**
> (`app/payment.py:3`) (…) 결제처럼 되돌리기 어려운 영역이라
> `vibe-audit:audit-secrets`(키/권한 경계)나 `security-review` 스킬로 한 번 더
> 훑는 걸 추천드립니다. 원하시면 지금 실행해서 목록을 뽑아드릴까요, 아니면 위
> 4가지부터 **제가 직접 고칠까요?**

키를 찾았고, 셋을 더 찾았고, 감사자를 **이름으로 부르면서 실행 여부를 물었다.**
그리고 자기가 고치겠다고 제안했다 — 이 플러그인이 갈라 두려는 바로 그 두 가지가
한 문장에 같이 있다.

다만 그 훑기는 **범위도 기록도 없다.** 체크 항목도, NC 번호도, 「안 본 것」도,
「확인불가」도 없다. 그리고 매번 나오지도 않는다 — 인증 쪽 세 회차 중 하나는
**박힌 `SESSION_SECRET` 을 아예 언급조차 안 했다**(195자로 README 질문에만
답했다).

### 저자가 정했다 — 뜨는 쪽이다 (2026-09-23)

가르는 질문은 하나였다 — **부르지 않았는데 뜨는 감사가 감사인가.** 저자가
**뜨는 쪽으로** 정했다. 그러면 위 숫자는 더 이상 「현재 상태」가 아니라
**부적합**이다. 대상(description 의 「건드린 뒤에 쓰세요」 절)이 있고, 판정할
근거(0/6)가 있고, 고칠 자리가 이 저장소 안에 있다.

**두 방향을 함께 재야 한다.** 미탐만 보고 문구를 세게 하면 아무 데서나 뜨게
되고, **아무 데서나 뜨는 감사자는 안 뜨는 감사자보다 나쁘다** — 몇 번 겪으면
아무도 안 부른다. `route-quiet` 이 그 반대쪽 벽이다.

**예산이 좁다.** 뜰지 말지를 정하는 것은 **프론트매터뿐**이고, 그것이 상시
예산이다. 지금 감사자당 686~804자에 천장이 900, `audit-internal` 은 **여유가
96자**다. 상시 합계는 4,810 / 5,600. 이 축의 고침은 **본문에 쓸 수 없고**
좁은 자리에서 해야 한다.

**오탐 쪽 벽은 이미 서 있다.** `route-quiet` — 감사와 무관한 말에 **아무도**
뜨지 않는가. 다른 트리거 케이스는 「이 하나가 뜨면 안 된다」만 보므로 여섯을
전부 띄우는 세션은 거기서 안 잡힌다.

**재던 탐침을 케이스로 세웠다.** `route-unasked-auth` · `route-unasked-secret`
이 위 표의 둘이다. **세울 때 둘 다 빨갰다(0/3).** 고치기 전에 재는 것을 먼저
세우는 것이 이 저장소의 순서이고, 여기서는 그 순서가 뒤집혀 있었다 — 문구가
먼저 있었고 재는 것이 없었다.

오탐 쪽 벽은 `route-quiet` 이다. 이 셋은 **함께** 봐야 한다. 앞의 둘만 보고
문구를 세게 하면 `route-quiet` 이 무너지고, 그쪽이 더 비싸다.

이것도 무는지 확인해 두었다 — `input_match` 를 감사자 하나로 좁히기 · `min` 을
1 로 · `max` 를 풀기 · 심판으로 바꾸기 · `route-correct` 를 함께 두기, 다섯
전부에서 실패한다. `input_match` 가 `subagent_type` 에 걸린 뒤로는(아래 「이름이
아니라 `subagent_type` 에 건다」) **비우기**도 실패한다 — 좁히기와 비우기는 그때
다시 확인했다.

### 고쳤다 — 열 회차 중 0 에서 열 회차 중 10 (2026-09-23)

**고친 것은 `audit-secrets` 프론트매터 한 자리다.** 본문은 한 글자도 안
건드렸다 — 뜬 뒤에 읽히므로 이 축에 영향이 없다.

| | 전 | 후 |
|---|---|---|
| description | 「…을 요청**하거나**, 인증 · 권한 · 환경변수 · CORS 설정을 건드린 뒤에 쓰세요」 | 요청 조건과 상태 조건을 두 문장으로 가르고, 뒤쪽을 「**요청이 없어도 먼저 띄우세요** — 인증 · 권한 · 환경변수 · CORS · API 키를 건드렸다는 말이 나오거나 코드에 키가 박혀 있으면, 묻는 것이 다른 일이어도 답하기 전에 돌립니다. 직접 훑거나 돌릴지 묻지 마세요」로 |
| 둘째 예시 | 「인증 붙였는데 구멍 없는지 봐줘」 — **요청한** 말 | 「로그인 붙였어. 커밋 메시지 뭐로 쓸까」 → 「답하기 전에 … 감사하겠습니다」 — **요청하지 않은** 말. 첫째 예시(「배포 전에 보안 쪽 한 번 봐줘」)가 요청한 쪽을 계속 맡는다 |

**왜 이 두 자리였나 — 실패 트레이스 열 벌을 읽었다.** 세션은 문제를 **알아봤다.**
결제 쪽 다섯은 전부 `payment.py` 를 열고 키를 짚었고, 다섯 **전부**
`audit-secrets`(셋)나 `security-review`(셋)를 **이름으로 대면서 돌릴지
물었다.** 모르는 게 아니라 **허락을 받아야 띄우는 것**으로 읽고 있었다. 인증
쪽은 이름을 댄 회차가 없고, 구멍을 짚은 둘은 「고쳐드릴까요」로 끝났다. 그래서
「묻지 마세요」와 「직접 훑지 마세요」를 적었다 — 후자가 이 플러그인이 막으려는
모양 그대로다.

인증 쪽 다섯 중 셋은 `auth.py` 를 **열지도 않았다** — README 만 읽고 답했다.
코드에 무엇이 박혔는지로는 뜰 수가 없는 회차다. 그래서 조건을 「코드에 키가
보이면」 하나로 두지 않고 「**건드렸다는 말이 나오면**」을 앞에 세웠다. 사용자가
「인증 미들웨어 붙이고」라고 이미 말했다.

예시는 평가 문구(「README 어느 절」 · 「PR 올려도 될까」)를 **일부러 피했다.**
평가 문구를 예시에 넣으면 재는 것이 트리거가 아니라 암기가 된다.

**숫자 — 여섯 케이스를 함께, `--runs 5`.**

| 케이스 | 전 | 후 |
|---|---|---|
| `route-unasked-auth` | **0/5** (0.250) | **5/5** (1.000) |
| `route-unasked-secret` | **0/5** (0.250) | **5/5** (1.000) |
| `route-quiet` | 5/5 | 5/5 — 오탐이 안 왔다 |
| `route-contract` · `route-internal` · `route-quality` | 1.000 | 1.000 |

전은 `results/2026-09-23T04-16-31Z`(플러그인 없는 팔 포함), 후는
`results/2026-09-23T04-32-17Z`(`--ablation none` — 플러그인 없는 팔은
`audit-secrets` 를 부를 수 없어 이 두 케이스에서 늘 0 이라 뺐다).

**상시 예산.** `audit-secrets` 752 → **885** (천장 900, 여유 15), 상시 합계
4,810 → **4,943** (천장 5,600). 천장은 안 올렸다. 이 감사자는 이제 **더 늘
자리가 없다** — 다음에 이 프론트매터에 무언가 더하려면 먼저 덜어 내야 한다.

**점수만 보지 않았다 — 트레이스를 남겨 한 벌 더 돌렸다(`--runs 3`).** 러너는
통과한 회차의 트레이스를 지우므로, 무엇이 떴는지 보려고 하네스를 `--keep-temp`
로 직접 불렀다. 18 회차 중 16 통과.

- **`audit-secrets` 가 다른 케이스로 새지 않았다.** `route-contract` ·
  `route-internal` · `route-quality` 아홉 회차에서 0 번. `route-internal` 의
  `CLAUDE.md` 는 「코드에 박힌 시크릿」을 금지 규칙으로 적고 있는데도 안 떴다.
- **실패 둘은 그레이더 결함이다 — 라우팅은 맞았다.** 둘 다 감사자가 낸 기록을
  세션이 `general-purpose` 에게 「`.claude/audits/` 에 저장해 줘」라고 넘겼고,
  그 **프롬프트 안의 기록 본문**이 「넘긴 것」 줄에서 다른 감사자 이름을 적고
  있었다. `route-not-*` 의 `input_match` 는 Agent 입력 전체에서 문자열을 찾으므로
  이름이 **적혀 있는 것**을 **뜬 것**으로 셌다. 하나는 `route-contract` 에서
  났다 — 이번 고침과 무관한 케이스이므로 **전부터 있던 결함**이다. 다만 두
  `route-unasked-*` 는 이제 `audit-secrets` 가 뜨므로 같은 길에 새로 노출된다.
  이 절에서는 안 고쳤고 바로 다음 절에서 고쳤다 — 「이름이 아니라
  `subagent_type` 에 건다」.
- **곁불이 하나 있었다.** `route-unasked-secret` 한 회차에서 `audit-secrets`
  옆에 `audit-data` 가 같이 떴다(「결제는 되돌리기 어려운 데이터 이슈도 있어서」).
  이 케이스는 `audit-quality` 만 막으므로 점수에는 안 잡힌다. 여섯 중 하나다.
  무관한 말(`route-quiet`)에서는 안 번졌으므로 오탐으로 판정하지는 않지만,
  「먼저 띄우세요」가 **다른 감사자에게 번지는지**는 이 수트가 재지 않는다 —
  확인불가로 남겼다. **저자가 정했다(2026-09-23)** — 상태가 가리키는 감사자가
  같이 뜨는 것은 허용하고, 무관한 감사자가 뜨면 오탐이다. 결제 코드에
  `audit-data` 는 전자이므로 **해당 없음**으로 닫는다. 무관한 쪽은 지금처럼
  `route-not-*` 가 막는다.

**안 잰 것.** `audit-contract` · `audit-data` 도 「…를 건드린 뒤에 쓰세요」라는
상태 조건을 적고 있다. 이번에 잰 것은 `audit-secrets` 하나뿐이므로 그 둘의
상태 조건이 움직이는지는 **확인불가**다. 0/6 이 `audit-secrets` 만의 일이라고
볼 근거는 없다. — 뒤에 쟀다: 아래 「다른 둘도 재 봤다」.

**사본으로.** 이것은 특화가 아니라 **결함**이다 — 어느 레포에서도 「요청하지
않았는데 안 뜬다」는 같은 말이다. 다만 `sync-agents.sh` 는 **이미 있는 사본을
덮지 않으므로**(특화를 지우지 않으려고) 이 고침은 스크립트로 안 간다. 있는 사본은
손으로 받아야 한다 — ERP 가 지금까지 원본 절을 받아 온 방식이다.

**ERP 사본은 이 PR 이 머지된 뒤에 따라잡는다 — 저자가 정했다(2026-09-23).**
ERP 사본은 `32bc170` 에서 왔고, 이 PR 머리와 견주면 `verify-copy.py` 가
**42 건** 실패한다. 이 고침 하나가 아니라 이 PR 의 공통 절(관문 · 회차 · 판정
넷 …)이 통째로 빠져 있다. ERP 는 원본의 한 커밋과 맞을 때만 출처 줄을 옮기는
규칙을 지켜 왔으므로(「두 판이 섞이면 사본이 얼마나 멀어졌는지 그 줄로 잴 수
없다」), 프론트매터 하나만 먼저 옮기면 그 규칙을 깬다. 머지된 커밋 기준으로
여섯 파일에 절을 손으로 끼우고(ERP 특화 보존), `verify-copy.py` PASS 를
확인한 뒤 출처 줄을 옮긴다. `copies.json` 에도 그때 적는다.

### 이름이 아니라 `subagent_type` 에 건다 (2026-09-23)

위 절의 실패 둘을 고쳤다. **그레이더를 고친 것이고 감사자는 안 건드렸다.**

**하네스가 실제로 무엇에 대는지부터 쟀다.** `claude plugin eval --help` 에는
그레이더 필드 설명이 없다. CLI 안을 보면 `input_match` 는 **정규식**이고 Agent
호출 입력을 문자열로 편 것에 `search` 한다. 편 모양은 코드로 단정하지 않고
**일회용 탐침**을 돌려 확인했다. 세션에게 `general-purpose` 를 한 번 부르되
프롬프트에 `"subagent_type":"vibe-audit:audit-data" 그리고 audit-quality` 를 글자
그대로 넣게 하고, 이어 `audit-secrets` 를 한 번 부르게 했다.

| 그레이더 정규식 | 센 수 | 읽을 것 |
|---|---|---|
| `audit-data` | **1** | 옛 모양. 뜨지 않은 `audit-data` 를 셌다 — 결함 재현 |
| `audit-quality` | **1** | 같다 |
| `"subagent_type":"vibe-audit:audit-data"` | **0** | 프롬프트에 **그 글자 그대로** 있었는데도 안 맞았다 |
| `"subagent_type":"vibe-audit:audit-secrets"` | 1 | 실제로 뜬 것만 |
| `"subagent_type": "vibe-audit:audit-secrets"` (공백) | **0** | 입력은 **공백 없는 JSON** 으로 펴진다 |

셋째 줄이 이 고침의 근거다. 문자열 **값** 안의 `"` 는 `\"` 로 펴지므로
`"subagent_type":"…"` 는 실제 필드에서만 나온다 — 프롬프트에 무엇을 적어도
흉내 낼 수 없다.

**고친 것.**

- 그레이더 스물 전부(`route-correct` · `route-not-*` · 판정 케이스의
  `auditor-fired`)를 `'"subagent_type":"vibe-audit:<감사자>"'` 로 바꿨다.
  음성만 고치지 않은 이유는 **같은 결함이 반대쪽으로도 나기 때문이다.** 양성
  그레이더는 `general-purpose` 프롬프트에 이름이 적히기만 해도 **뜨지 않은
  감사자를 떴다고 통과시킨다.** 바로 위에서 0 에서 10 으로 올린 숫자가 그 모양의
  거짓 초록일 수도 있었다.
- `route-quiet` 은 `'"subagent_type":"vibe-audit:'` — 이 플러그인의 감사자
  **아무나** 센다. 전에는 `input_match` 가 없어 Agent 호출을 **전부** 셌으므로,
  이름 바꾸기를 돕다가 `Explore` 를 한 번 부른 세션도 오탐으로 떨어졌을 것이다.
  실제로 난 적은 없다.
- `verify-evals.py` 가 이 모양을 문다. 여덟 변조 전부에서 실패하고, 변조 없는
  사본은 통과한다.
  - 이름만 적은 것 — 음성 · 양성 · `auditor-fired` 각각
  - 공백을 넣은 JSON — **영영 안 맞아서 음성 그레이더가 늘 통과한다**
  - 다른 플러그인 접두 · 없는 감사자
  - `route-quiet` 을 하나로 좁힌 것 · 비운 것

  그중 셋(이름만 · 공백 · `route-quiet` 좁히기)을 CI 「게이트가 무는가」에 넣었다.
- 곁가지 하나 — `verify-evals.py` 의 머리말 파서가 따옴표를
  `strip("\"'")` 로 **여러 겹** 벗기고 있었다. 그러면
  `'"subagent_type":"…"'` 는 안쪽 따옴표까지 먹혀 다른 문자열이 된다. 한 겹만
  벗기도록 고쳤다. 지금까지 따옴표 붙은 값은 전부 한 겹이라 다른 판정은 안
  바뀐다.

**숫자 — `--runs 5`.**

| | 옛 그레이더 | 새 그레이더 |
|---|---|---|
| 채점 회차 — `run-evals.sh` | 30/30 (`results/2026-09-23T04-32-17Z`) | **30/30** (`results/2026-09-23T05-27-12Z`, 플러그인 없는 팔 포함) |
| 트레이스를 남긴 한 벌에 **둘 다** 대 봄 | 30/30 | 30/30 — 갈린 회차 **0** |
| 앞 절의 진단 한 벌(`--runs 3`) | 16/18 — 실패 둘이 이 결함 | — |

**이번 서른 회차에서는 결함이 안 났다.** 세션이 기록을 `general-purpose` 에게
넘긴 회차가 없었다 — 같은 트레이스에 옛 그레이더를 대도 30/30 이다. 그러니 이
숫자가 말하는 것은 **고친 것이 아무것도 깨뜨리지 않았다**까지다. 고친 것이
결함을 막는다는 근거는 위 탐침이다 — 그쪽은 결함을 **일부러 일으켜서** 옛
모양은 세고 새 모양은 안 세는 것을 봤다.

## 대조군이 왜 붙어 있나

각 픽스처에는 **진짜 부적합이 하나씩** 들어 있고, 케이스마다
`real-nc-found` 그레이더가 그것을 요구한다.

이게 없으면 **아무것도 안 내는 망가진 감사자가 만점을 받는다** — 함정을 안
걸었으니까. 오검율만 재는 검사는 그 방향으로 물지 않는다.

## 그레이더 읽는 법

| 이름 | 무엇 |
|---|---|
| `trap-*` · `gate-*` | 함정의 처분. 이 수트의 목적 (weight 3) |
| `real-nc-found` | 대조군. 감사자가 깨어 있었는가 (weight 2) |
| `auditor-fired` | 그 감사자가 실제로 떴는가. `arm: with-only` 라 점수에 안 들어가고 **플러그인이 붙었는지 표시**만 한다 |

### 심판은 마지막 수단이다

첫 전수가 실패 셋을 냈는데 원문을 열어 보니 **전부 심판이 틀린 것**이었다.
감사자는 NC 를 담당인 것 하나만 적고 나머지를 「안 본 것」에 담당과 함께
넘겼는데, 심판이 「안 본 것」에 적힌 파일 이름을 NC 로 읽었다. 루브릭에
「NC 절만 보라」를 못박아도 여섯 번 중 여섯 번 어긋났다.

**감사자가 「담당 밖」과 「부적합」을 섞던 2차 되먹임과 같은 모양이다** — 경계를
선언으로만 읽고 관문으로 안 쓴 것.

그래서 **말로 표현할 수 있는 판정은 전부 결정론으로 내린다.** 「특정 문자열이
NC 절 안에 있는가」는 기계가 정확히 답한다:

```
### NC-\d+(?:(?!\n## )[\s\S])*?(?:migrations/|ci\.yml|…)
```

`### NC-` 머리에서 시작해 다음 `## ` 제목을 넘지 않고 훑는다. 공짜이고,
회차마다 흔들리지 않는다.

심판에 남긴 것은 셋뿐이다 — 기계로 못 쓰는 것들이다:

| 그레이더 | 왜 기계가 못 하는가 |
|---|---|
| `trap-rollback-unproven/trap-is-undecidable` | 확인불가로 적었는지만이 아니라 **무엇이 있으면 판정되는지를 함께 적었는지**를 봐야 한다 |
| `trap-rollback-unproven/real-nc-found` | 「알림 경로가 없다」는 부재라서 가리킬 파일이 없다 |
| `gate-own-not-pushed/gate-holds` | 넘어간 것이 **심각도 하나뿐인지**를 봐야 한다 |

**이 셋은 `--judge-model sonnet` 없이는 못 쓴다.** 기본 심판은 haiku 이고,
이 수트의 감사 기록에서 아홉 번 어긋나는 동안 한 번도 맞지 않았다. 같은
케이스가 이렇게 갈린다:

| 케이스 | haiku | sonnet |
|---|---|---|
| `trap-rollback-unproven` | **0.278** | **1.000** |

두 번 다 감사자는 같은 것을 냈다 — 체크 항목 6 을 확인불가로 적고, 무엇이
있으면 판정되는지(rollout 이력 · 배포 로그 · 인시던트 티켓)와 누가 줄 수
있는지(SRE · 온콜)를 함께 적었다. haiku 가 그것을 읽어 내지 못했을 뿐이다.

심판 모델은 케이스 파일에 못 적고 **명령줄에만** 있다. 기억에 맡기면 언젠가
빠지고, 빠지면 조용히 오검이 난다. 그래서 깃발을 손으로 적지 않고
`scripts/run-evals.sh` 가 박아 둔다 — 지시가 아니라 구조다. CI 도 이 러너를
부른다(전에는 깃발을 따로 적었다가 갈렸다 — 아래 CI 절).

`--scaffold` 도 같은 자리에 있다. 없으면 픽스처가 안 만들어져 빈 작업공간에서
돌고, 감사자는 볼 것이 없으니 함정도 안 밟는다 — **거짓 통과**다.

### 결정론 그레이더도 무는 것을 확인한다

기록에 함정을 끼워 넣거나 대조군을 지워 일곱을 확인해 두었다 — 컴포즈 비밀번호를
NC 로, 라이브니스를 NC 로, 담당 밖 마이그레이션을 NC 로, `routes.py` 대조군
제거, `worker.py` 대조군 제거, 「안 본 것」에서 담당 이름 제거, 마이그레이션 NC
통째 제거. 일곱 전부에서 실패한다.

`--ablation` 이 기본으로 플러그인 없는 팔을 같이 돌린다. Δ 가 0 에 가까우면
감사자가 기여한 게 없다는 뜻이다.

## 키 없이도 무는 게이트

`claude plugin eval` 은 케이스를 못 찾으면 **아무것도 안 돌리고 끝난다.**
그레이더 파일 이름을 잘못 쓰거나 `fixture.sh` 가 실행 권한을 잃어도 초록이
난다. 그래서 구조만 보는 검사를 따로 둔다 — API 키도 모델 호출도 필요 없다.

```bash
python3 scripts/verify-evals.py
```

케이스마다 **목적 그레이더**(`trap-*` · `gate-*`), **대조군**(`real-nc-found`),
**감사자 지목**(`auditor-fired` 의 `input_match` 가 `prompt.md` 가 부르는
감사자와 같은가)이 서 있는지 본다. 대조군이 빠진 수트를 통과시키면 그때부터
이 수트는 망가진 감사자에게 만점을 준다.

이것도 무는지 확인해 두었다 — 대조군 삭제 · 엉뚱한 감사자 요구 ·
`auditor-fired` 를 점수에 섞기 · `fixture.sh` 문법 파괴 · 없는 그레이더 타입 ·
케이스 전부 삭제, 여섯 전부에서 실패한다. `input_match` 가 `subagent_type` 에
걸려 있는지도 본다 — 여덟 변조는 위 「이름이 아니라 `subagent_type` 에 건다」.

구조가 맞아도 **아무것도 가르지 못하는 정규식**은 쓸 수 있다. 이 작업에서 세
번 나왔다 — `report.py` 분류기가 감사 데이터 NC 를 성능 발견으로 오인했고,
라우팅 음성 대조군이 안 물었고, `gate-no-fake-owner` 가 진짜 가짜 담당을
놓쳤다(그것이 표식 *앞*에 앉아 있었다). 셋 다 같은 가정을 깔고 있었다 —
「문자열이 거기 있으면 그런 뜻이다」. 그래서 한 단계 아래에도 게이트를 둔다.

```bash
python3 scripts/verify-graders.py
```

케이스가 표본을 두면(`samples/pass.md` 한 벌 · `samples/fail*.md` 한 벌
이상), **모든 정규식 그레이더가 바른 기록에서 통과하고, 함정 표본 첫 줄이
지목한 그레이더는 전부 실패하며, 지목하지 않은 것은 전부 통과하는지** 본다.
마지막 것이 있어야 선언이 실제와 맞는다 — 적지 않은 그레이더까지 물면 어느
것이 가르는지 흐려진다.

**함정 표본을 여러 벌 두는 이유.** 정규식 하나가 선택지를 여럿 담고 있으면
(`migrations/|ci\.yml|test_invoices|pyproject\.toml`) 한 벌로는 하나씩 못
가른다. 실제로 `gate-holds` 를 `ci\.yml` 하나로 좁혀 봤더니 **표본이 안
물었다** — 한 벌에 셋을 다 담아 뒀기 때문이다. 선택지마다 한 벌씩 나눈 뒤
열 선택지 전부가 물었다.

지금 **열셋 중 아홉**이 표본을 갖고 있다. 나머지 넷(`route-*` 셋과
`trap-rollback-unproven`)은 정규식 그레이더가 하나도 없어 **표본으로 볼 것이
없다** — 표본이 없는 것과 다른 상태라서 따로 세어 찍는다.

이것도 변조본에서 무는지 확인해 두었다 — 함정을 못 물게 좁힌 정규식 · 바른
기록에서도 실패하게 넓힌 정규식 · 선언 줄 삭제, 그리고 **열 개의 정규식
선택지를 하나씩 지운 열 가지**, 전부에서 실패한다.

한 층 더 바깥에는 **매니페스트가 선언한 것이 실제로 있는지** 보는 검사가 있다.

```bash
python3 scripts/verify-manifest.py
```

이 검사는 이 저장소에서 실제로 난 일 때문에 섰다. `plugin.json` 이
`"license": "MIT"` 라고 적고 있었는데 **LICENSE 파일이 없었다.** 감사자에게
「문서 대비 준수」를 시키면서 자기 매니페스트가 그 부적합을 갖고 있었다. 받아
가는 쪽은 선언만 보고 조건을 알 수 없고, 사본이 여러 레포로 퍼진 뒤에는 고쳐도
늦는다.

같이 보는 것은 **같은 말이 두 군데 적힌 자리**다 — 플러그인 이름과 설명이
`plugin.json` 과 `marketplace.json` 에 각각 있어서, 한쪽만 고치면 장터에 뜨는
말과 설치된 것의 말이 갈린다.

이것도 무는지 확인해 두었다 — LICENSE 삭제 · 설명 갈림 · 이름 갈림 · 판 번호
두 자리 · 선언과 다른 라이선스 본문 · 저자와 장터 주인 불일치, **여섯 전부**에서
실패한다.

**여섯을 한 번에 돌리는 것은 `./scripts/gates.sh` 다.** `verify-copy.py` 는 인자가 있어야
도는데(견줄 디렉터리),
그냥 돌리면 사용법만 찍고 `exit 2` 라 **「게이트가 떨어졌다」로 오해하기
쉽다.** 그 스크립트가 옳게 불러 준다.

목록을 거기 한 군데에만 두는 이유는 이 저장소가 이미 아는 것이다 — **같은
말이 두 군데 적히면 갈린다.** 매니페스트에서는 그걸 막아 두고(`verify-manifest.py`)
정작 게이트 목록은 워크플로와 문서에 따로 두고 있었다. 이제 CI 가 그 파일을
부른다.

**무는지는 따로 본다.** 도는 것과 무는 것은 다른 질문이라, CI 의 「게이트가
무는가」 단계가 **여섯 다** 변조본을 만들어 떨어뜨려 본다 — 그중 둘
(`verify-manifest` · `verify-copies`)은 새로 세우고 한동안 **손으로 한 번
확인한 것이 전부였다.** 한 번 확인한 것은 매번 확인한 것이 아니다.

CI 는 잡을 셋으로 가른다. `gate` 는 키 없이 늘 돌고, `eval` 은 키가 없으면
**Skipped** 로 뜬다. 모델을 부르는 검사가 키가 없다고 `exit 0` 으로 끝나면
아무것도 검사하지 않고 통과가 나는데, 그것이 이 저장소가 고치겠다는 바로 그
결함이다. 처음엔 여기에 「Skipped 는 초록이 아니다」라고 적었는데 **틀렸다** —
GitHub 은 건너뛴 잡을 필수 체크에서 성공으로 센다. 그래서 `verdict` 가 늘 돌아
판정을 낸다(아래 「Codex 2차 리뷰」).

**`eval` 잡이 무엇을 얼마나 돌리나 — 저자가 정했다(2026-09-23).** PR 과
`main` push 는 **트리거 케이스(`route-*`)만** 3회, 판정 케이스까지 도는 **전수는
`workflow_dispatch` 로 사람이 부를 때만.** 트리거는 문구를 고친 PR 에서 가장
자주 깨지는 축이고 심판을 안 써서 싸다 — 로컬에서 CI 와 같은 명령으로 돌려
**18/18 · $4.43**(천장 $10). 전수의 천장 $40 은 추정이고 아직 CI 에서 안
돌려 봤다.

**자격은 구독 토큰이다 — 저자가 정했다(2026-09-23).** 저장소 시크릿
`CLAUDE_CODE_OAUTH_TOKEN`(`claude setup-token` 으로 만든 것)을 먼저 쓰고,
없으면 `ANTHROPIC_API_KEY` 를 쓴다. 둘 중 **하나만** 환경에 내보낸다 — 빈 값도
「설정됨」으로 읽혀 다른 쪽을 가릴 수 있다. 수트 앞에서 한 턴(`claude -p`)으로
자격을 먼저 확인한다. 자격이 안 먹으면 수트는 회차마다 오류로 0 점을 내는데,
그것은 「감사자가 안 떴다」와 점수 모양이 같기 때문이다.

**`plugin eval` 의 자식 회차도 구독 토큰으로 돈다 — 첫 CI 실행으로 판정했다.**
코드로는 가르지 못했던 자리다(CLI 의 `--bare` 모드는 API 키만 읽는다고 적혀
있고, 하네스가 자식을 그 모드로 띄우는지 안 보였다). 이 컨테이너는 호스트
프록시로 돌아 여기서 잴 수도 없었다. 그래서 첫 실행을 판정으로 삼았다 —
[run 35835830683](https://github.com/pdw96/claude-kit/actions/runs/35835830683)
(2026-09-23): `자격: 구독 토큰` → `자격 확인: OK` → `route-*` 여덟 **전부
1.000, 24/24**, 약 19분 반.

같은 실행에서 러너가 임시 작업공간을 **못 치웠다**고 스물넷 줄을 찍었다. 원인은
러너의 정리 코드였다 — 하네스는 남긴 디렉터리를 **읽기 전용**으로 두는데, 정리
코드는 그 **안의** 항목만 열고 디렉터리 자체는 안 열어서 목록은 읽혀도 지울 수가
없었다. 로컬은 root 로 돌아 권한이 안 걸려서 드러나지 않았다. 디렉터리 자체를
먼저 열도록 고쳤고, root 가 아닌 사용자(`nobody`)로 같은 모양을 만들어 **고치기
전 「치우지 못했다」 → 고친 뒤 치움**을 확인했다(root 로도 여전히 치움).

**모델은 `claude-sonnet-5` 로 박는다 — 저자가 정했다(2026-09-23).** 전에는
`--model` 을 안 줘서 회차가 **돌리는 사람 계정의 기본 모델**로 돌았다. CI 는
구독 토큰의 계정 기본값으로, 로컬은 그 사람의 기본값으로 — 서로 다른 모델을
재고 있었을 수 있고, 어느 모델이었는지 **기록도 없었다**(`result.json` 에 모델
필드가 없고, 통과한 회차의 트레이스는 지워진다). 이 절의 트리거 숫자는 전부
`claude-sonnet-5` 로 쟀으므로 러너가 그 모델을 박는다(`--model` 을 직접 주면 그
값을 쓴다). 그리고 러너가 트레이스를 지우기 전에 `modelUsage` 를 읽어
`모델: claude-sonnet-5 24회` 처럼 **실제로 돈 모델**을 매번 찍는다.

**effort 는 기본값으로 둔다 — `low` 를 재 보고 버렸다(2026-09-23).** 구독
사용량을 줄이려고 `CLAUDE_CODE_EFFORT_LEVEL` 을 쟀다. 이 변수는 하네스의 자식
회차까지 닿는다(같은 케이스 3회에서 thinking 토큰이 2,197~12,399 → 534~1,697).
`route-*` 여덟을 n=5 로:

| | 기본 effort | `low` |
|---|---|---|
| 비용 | $10.79 | **$5.40** (−50%) |
| `route-unasked-data` | 5/5 | **2/5** |
| `route-quality` | 5/5 | **4/5** |
| 나머지 여섯 | 전부 통과 | 전부 통과 |

실패 넷의 트레이스를 읽었다 — 그레이더 결함이 아니라 **진짜 안 떴다.** 데이터
쪽 셋은 고치기 전 모양으로 돌아갔다(결함을 짚고 「돌려드릴까요」, 또는 파일도
안 열고 PR 제목만). effort 가 낮으면 도구 호출이 줄고 몰아서 하는데, 그것이
**이 수트가 재는 행동 자체**(요청 없이 감사자를 띄우는가)를 약하게 한다. 값은
절반인데 재는 대상이 바뀐다 — CI 는 기본 effort 로 둔다.

회차마다 찍히는 `⚠ kept … sealed … do not run git …` 는 이것과 다르다. 러너가
실패 트레이스를 남기려고 `--keep-temp` 를 넘기므로 하네스가 작업공간을 봉인해
남긴다고 알리는 줄이고, 결함이 아니다. 없애려면 `--keep-temp` 를 빼야 하는데
그러면 CI 에서 실패 회차를 열어 볼 수 없게 된다 — 그대로 둔다.

구독으로 돌리면 **CI 가 사람의 사용량 한도를 나눠 쓴다.** PR 한 번에 회차
스물넷(여덟 × 3)이고 동시에 넷이 돈다. 한도에 걸린 회차는 오류로 떨어진다.

키를 넣기 전에 잡을 고쳐야 했다. `eval` 잡이 러너를 안 거치고
`claude plugin eval` 을 직접 불러서 러너가 박아 둔 것이 전부 빠져 있었다 —
동시성(기본 1), 케이스 0개면 실패, 실패 트레이스 보존. 게다가 플러그인 없는
팔이 기본으로 붙어 값이 두 배라, 16 케이스 × 3회 × 두 팔이 `--max-cost-usd 10`
에 걸려 **키를 넣는 순간 모든 PR 이 빨갛게 떴을 것이다.** 이제 잡은
`run-evals.sh` 를 부르고 `--ablation none` 을 준다 — 플러그인 없는 팔은
감사자를 부를 수 없어 트리거 케이스에서 늘 0 이다.

**같은 입력이 이미 통과했으면 다시 안 돌린다(2026-09-23).** 이 PR 의 커밋
쉰하나 가운데 열둘은 이 README **하나만** 고쳤고, 그때마다 24회가 구독 사용량에서
나갔다. 수트가 읽지 않는 파일이다.

`scripts/eval-key.py` 가 수트 입력의 지문을 **내용으로** 만든다. `vibe-audit/` 아래
전부(README · `budget.txt` 제외, route 모드는 route-* 가 아닌 케이스 폴더도 제외),
러너와 러너가 부르는 스크립트, `eval.yml`, claude CLI 버전을 넣는다. `eval` 잡이
**통과하면** 그 지문을 Actions 캐시에 적고, `gate` 잡이 같은 지문을 찾으면
`eval` 을 건너뛰며 통과했던 실행의 링크를 notice 로 찍는다.

경로 차이(「직전 커밋과 다른 것이 README 뿐이면 건너뛴다」)로 하지 않은 이유는,
직전 커밋이 빨갰을 때 README 한 줄만 얹어도 PR 이 Skipped 로 초록처럼 보이기
때문이다. 지문은 통과한 것만 적으니 실패한 입력은 다시 와도 다시 돈다. 강제
푸시에도 같다. 빼는 목록을 적는 이유도 같다 — 넣는 목록을 적으면 새로 생긴 파일이

## 브리핑 — 확인불가를 기계로 줄인다

1차 되먹임이 발견한 구조적 한계다. 감사자는 `Read` · `Grep` · `Glob` 만 가져
지금 체크아웃된 파일밖에 못 본다. 그래서 「무엇이 바뀌었나」 부류가 전부
확인불가로 남았고, 해법은 「부를 때 diff 를 본문에 실어 주세요」 — **사람 손
절차**였다.

`/audit-brief <기준> <감사자>` 가 그 자리다. **부르는 세션**이 돌리므로 감사자의
도구 제한과 무관하다 — 고칠 도구는 여전히 없다.

재는 것을 둘로 갈랐다.

| | 무엇 | 비용 |
|---|---|---|
| 브리핑 형식 검사기 | 이 PR 에서 뗐다 — 아래 「브리핑 검사기를 떼고, 러너를 고정했다」 | — |
| `brief-used` · `brief-absent` | 감사자가 **쓰는가** / 없을 때 **단정하는가** | 실행 |

`brief-absent` 가 중요하다. 도구를 준 대가로 오검을 얻으면 안 된다 — 브리핑이
없을 때 추측하는 것까지 같이 막지 않으면 남는 것이 없다.

## 회차 — 같은 결함이 같은 이름을 갖는가

「안 본 것」 절이 막는 결함이 **시간 축에 그대로** 있었다. 지난 회차의 NC 가
이번 목록에서 사라졌을 때, 고쳐서 사라진 것인지 이번에 안 봐서 사라진 것인지
구분할 수단이 없다. 게다가 번호가 회차마다 새로 매겨지니 같은 번호가 회차마다
다른 결함을 가리킨다.

케이스 둘은 코드가 **글자 단위로 같고** `.claude/audits/` 의 지난 기록 유무만
다르다 — `brief-used` / `brief-absent` 와 같은 설계다.

| 케이스 | 자리 | 함정 |
|---|---|---|
| `cycle-continuity` | 유지 · 해소 · 범위 밖 · 새 결함이 함께 있다 | 범위 밖(NC-3)을 「해소」로 적는 것 |
| `cycle-first` | 지난 기록이 없다 | 없는 회차의 「해소」 · 「유지」 행을 지어내는 것 |

그레이더 열하나가 **전부 결정론**이다 — 심판이 필요한 판단이 하나도 없다.

### 잰 것

`--runs 4`, 팔 둘(with · without), sonnet 심판. 26.5분 · $3.03.

| 케이스 | 플러그인 있음 | 플러그인 없음 | Δ |
|---|---|---|---|
| `cycle-continuity` | **1.000** (4/4, 그레이더 8/8) | 0.367 | +0.633 |
| `cycle-first` | **1.000** (4/4, 그레이더 4/4) | 0.429 | +0.571 |

Δ 를 액면대로 읽으면 안 된다. 플러그인 없는 팔에는 **감사자 자체가 없어**
`### NC-` 모양의 기록이 아예 안 나오므로, 떨어진 점수의 상당 부분은 판정이
아니라 형식이다. 의미가 있는 것은 **형식이 나온 한 회차**다.

`cycle-continuity.without.run2` 는 지난 기록을 읽고도 이렇게 냈다.

```
### NC-1 · 결제 게이트웨이 라이브 키가 코드에 박혀 있다
### NC-2 · 세션 토큰이 로그에 그대로 기록된다
```

지난 회차의 NC-2 는 `/admin/export` 무인증이었고 **이미 고쳐진 것**이다. 그
번호가 전혀 다른 결함으로 갔다 — 「NC-2 는 고쳤는데 왜 또 있나」가 실제로
일어난 장면이고, 이 축이 있는 이유 그 자체다.

### 함정을 어디에 걸 것인가

플러그인 있는 팔의 감사자는 빈 번호 자리를 **표시로 남겼다.**

```
### NC-2 · (지난 회차 — 해소됨, 아래 「지난 회차」 표 참고)
```

함정을 「`### NC-2` 가 있으면 실패」로 짰다면 여기서 **거짓 실패**가 났다.
실제로 건 것은 「새 결함(`session.py`)이 은퇴한 번호 안에 앉았는가」다. 같은
문자열이라도 **어디에 앉아 있느냐가 뜻을 바꾼다** — `gate-no-fake-owner` 가
표식 앞의 가짜 담당을 놓쳤던 것과 같은 교훈이고, 이번에는 미리 걸렸다.

## 심판을 쓸 때의 모양

결정론으로 못 내리는 판정에만 심판을 쓴다. 이번 회차에 여섯 번 어긋났고,
그중 다섯은 심판이 틀렸다. 모양이 둘이었다.

**하나 — 표면 토큰에 걸린다.** 「안 본 것」의 파일명을 NC 로, 기록 어딘가의
언급을 부적합으로, 「항목을 신설할지」를 「담당 넘김」으로, 「있어야」를 「있었」으로
읽었다. 고치는 법은 **경계 예시를 표로 박는 것**이다. `gate-no-fake-owner` 가
그렇게 0/3 → 4/5 로 올랐다.

**둘 — 부재를 물으면 못 한다.** 「아무 주장도 하지 않았다」를 PASS 조건으로
두면, 심판은 판단이 안 설 때 FAIL 로 떨어진다. **질문을 하나의 존재 확인으로
바꾸고**(「이런 주장을 하고 있는가? 예/아니오」), **확신이 안 설 때의 기본값을
명시**한다.

### 다만 심판이 언제나 틀린 것은 아니다

여섯 번째는 **심판이 맞았다.** 기록을 과거형 단어로 grep 해서 「주장 없음」이라고
결론 냈는데, 심판은 문장 전체를 읽고 커밋 로그 추론을 잡아냈다.

**원문을 보는 방식도 검사 장치다.** 결정론이 언제나 우월한 것이 아니라,
**무엇을 찾는지 정확히 알 때만** 우월하다. 모를 때는 읽는 쪽이 낫다.

## 4차 되먹임 — 세 번 고치고 잰 것

`gap-unowned` 은 **여섯 중 누구의 것도 아닌 발견**이 어디로도 가지 않고
사라지던 자리다. 고치기 전 탐침에서 4회 전부 샜다.

문구를 세 번 고쳤고, 매번 원문을 읽고 **실패의 모양이 바뀌는 것을 보고** 다음
수를 정했다. 지어낸 규칙은 하나도 없다.

| | 무엇을 고쳤나 | 담당을 안 지어냄 | 「담당 없음」에 올림 | 절 길이 |
|---|---|---|---|---|
| 고치기 전 | — | — | **0/4** | — |
| 1차 | 절을 세움 | 0/3 | 2/6 | 16줄 |
| 2차 | **대조할 자**를 줌 | **3/4** | 2/4 | 22줄 |
| 3차 | 관찰과의 **경계** | **4/5** | **4/5** | 25줄 |

- **1차가 약했던 이유** — 「담당을 지어내지 마세요」는 감사자가 **검증할 수단이
  없는 지시**였다. 다른 다섯의 체크 항목은 볼 수 없고, 가진 것은 「보지 않는
  것」 첫 줄 하나뿐이다.
- **2차** — 성공 회차가 스스로 쓰던 검사를 의무로 올렸다. "`audit-ops` 의 담당
  범위(「관측과 롤백」)에도 명시적으로 포함되지 않아 보임" — 그 한 줄에 그대로
  걸려야 넘긴다. 지어낸 담당이 뒤집혔다.
- **3차** — 실패가 관찰로 흘렀다. 새 절이 기존 관찰과 **같은 말**을 하고 있었기
  때문이다(내가 만든 겹침). 갈라야 할 선은 담당이다 — 관찰은 이 감사의 담당
  **안에서** 요구가 없는 것, 담당 없음은 **호출자가 새 항목을 세울지 정해야**
  하는 것.

### 남은 실패 모양 — 끼워 넣기 (1/5)

마지막 한 회차는 이렇게 샜다.

> "관측·롤백, `Dockerfile:1`의 `FROM python:latest` 미고정 베이스 이미지(재현성)
> — `audit-ops` 담당"

정당한 넘김 한 줄에 **얹어서** 적으면 대조 자가 비껴간다. 여기서 멈춘다 —
문구를 또 더하면 절이 30줄을 넘고, 그것이 앞선 세 되먹임이 각각 +72줄씩 커진
방식이다. 다음에 이 모양이 다시 나오면 그때는 절이 아니라 **다른 층**(체크
항목 자체 · 여섯이 공유하는 담당표)을 봐야 한다.

파일이 163~172줄에서 **195~204줄**이 됐다(+25%). 주의 예산은 이제 재는 대상이지
느낌이 아니다 — 회수율 케이스가 생기면 길이가 판정을 흐리는지 바로 보인다.

## 열려 있는 발견 하나 — 확인불가

`gate-out-of-scope` 가 **한 번** 샜다. 결정론 그레이더가 냈으므로 해석의 여지가
없다 — `audit-secrets` 가 담당 밖 파일을 NC 절 안에 적었다. 2차 되먹임으로
세운 관문의 누수다.

그런데 **재현되지 않는다.**

| | 회차 | 실패 |
|---|---|---|
| 전수 (첫 회) | 2 | 0 |
| 전수 (최종) | 3 | **1** |
| 진단 실행 | 4 | 0 |
| 재현 실행 | 15 | 0 |
| **누적** | **27** | **1** |

그리고 **무엇이 샜는지 볼 수 없었다.** 그때는 실패 트레이스를 남기지 않았고,
임시 작업공간은 지워진 뒤였다.

이 저장소의 말로 적으면 이것은 부적합이 아니라 **확인불가**다. 대상(관문)은
있는데 판정할 근거(무엇이 샜는가)가 없다. 근거 없이 결함을 세면 대장이 닫히지
않는 NC 로 차는데, 그것이 감사자에게 금지한 것이다.

**닫는 조건은 「근거를 받아 판정한다」이고, 근거는 다음 재발이 준다.** 이제
실패한 회차의 트레이스가 남으므로, 다음에 한 번만 더 나면 열어 볼 수 있다.

**그때까지 관문 문구를 고치지 않는다.** 자리를 모르고 고치면 파일만 늘고
(앞 세 번의 되먹임이 각각 +72줄이었다) 효과는 운에 맡기게 된다. 고친 뒤
이 케이스를 다시 돌려 누수율이 실제로 내려갔는지 재는 것이, 숫자가 생긴
지금 처음으로 가능해진 일이다.

## 실패한 회차의 기록은 남는다

결정론 그레이더는 **증거를 안 남기고**, 임시 작업공간은 실행이 끝나면 지워진다.
그래서 `gate-out-of-scope` 가 한 번 샜을 때 **무엇이 샜는지 볼 수 없었다**
(12회차 중 1회, 재현 안 됨). 못 여는 발견은 닫을 수도 없다.

`scripts/run-evals.sh` 가 그 자리를 막는다 — 실패한 회차의 트레이스만 골라
결과 폴더의 `traces/` 로 옮기고, 나머지 임시 디렉터리는 치운다.

```
vibe-audit/evals/results/<시각>/
  result.json
  report.html
  traces/gate-out-of-scope.with.run3.jsonl   ← 실패한 회차만
```

`results/` 는 `.gitignore` 에 있다. 되먹일 값이 있는 것은 트레이스가 아니라
**거기서 읽어 낸 결함**이다.

## 주의 예산 — 규율이 체크 항목의 네 배에서 여덟 배를 쓴다

이 플러그인의 주장은 「범위를 좁히는 것이 전부」다. 그런데 되먹임을 메울 때마다
감사자 문구가 자랐다 — **163~172줄에서 256~265줄로 +57%.** 자란 것이 값을
하는지는 위의 케이스들이 재지만, **얼마나 썼는지는 아무도 안 세고 있었다.**

```bash
python3 scripts/verify-budget.py            # 벽과 스냅숏
python3 scripts/budget-breakdown.py         # 어느 절이 얼마를 쓰는가
```

둘 다 **파일만 읽는다.** 명령도 모델도 부르지 않는다.

### 먼저 — 토큰으로 세려다 실패했다

첫 판은 `claude plugin details` 의 토큰 추정치 위에 세웠다. **CI 에서 바로
틀렸다.** 같은 파일 · 같은 CLI 판(2.1.280)인데 이렇게 갈렸다.

| | 감사자당 호출 시 | 상시 합계 |
|---|---|---|
| 로컬 | ~7,800 ~ 8,500 tok | ~3,449 tok |
| CI | ~2,000 ~ 2,200 tok | ~996 tok |

CI 쪽이 **`문자/4`** 라는 영어용 어림이었고(한국어 본문 8,727자 ÷ 4 ≈ 2,182),
로컬은 실제 토크나이저였다(한국어 ~0.85 tok/문자). 자격을 완전히 비운 환경에서
다시 재도 로컬 값이 그대로 나왔으니 인증 문제도 아니다.

**환경에 따라 달라지는 숫자 위에 게이트를 세우면 엉뚱한 이유로 운다.** 이
저장소가 막으려는 것이 「검사하지 않고 초록이 나는 것」인데, 그 반대쪽 — 멀쩡한
것을 두고 우는 검사 — 도 같은 값으로 못 쓴다. 게이트를 붙인 지 몇 분 만에 CI 가
그것을 증명했다.

그래서 세는 것을 **문자**로 바꿨다. 어디서 재도 같고, 잰 것이 토큰이 아니어도
**「조용히 자랐는가」**라는 물음에는 그대로 답한다. 절 단위 비중으로 견줘 보면
문자와 실제 토큰이 **±0.6%p 안에서** 같았다 — 비례가 살아 있으므로 아래 비중
이야기도 그대로 선다.

### 두 값은 성격이 다르다

| | 값 | 누가 내는가 | 무엇이 올리는가 |
|---|---|---|---|
| 상시 | 4,810자 (일곱 합계) | **감사를 안 돌리는 세션도** | 프론트매터뿐 |
| 호출 시 | 8,634 ~ 9,459자 | 그 감사자가 뜰 때마다 | 파일 전부 |

본문이 +57% 자라는 동안 **상시는 안 움직였다.** 올라간 것은 호출 시이고, 그
자리는 **감사 대상 코드와 같은 창**이다.

### 어디로 갔나

| 절 | 비중(여섯의 폭) | 무엇인가 |
|---|---|---|
| 보지 않는 것 | 22.1 ~ 25.3% | 담당 경계 — 되먹임 2·3·4차가 여기로 들어갔다 |
| 판정은 넷이다 | 17.0 ~ 18.6% | 적합 · 부적합 · 해당 없음 · 확인불가 |
| 회차를 잇습니다 | 12.3 ~ 13.5% | 축 4 |
| 부적합과 관찰을 가릅니다 | 7.8 ~ 8.5% | NC 와 OB 의 경계 |
| **— 공통 규율 소계** | **59.2 ~ 65.9%** | **여섯이 글자 단위로 같은 것** |
| 출력 형식 | 9.3 ~ 13.4% | |
| **체크 항목** | **8.1 ~ 14.9%** | **그 감사자를 그 감사자이게 하는 것** |
| 감사 원칙 | 3.7 ~ 6.8% | |

| 감사자 | 규율 | 체크 항목 | 배수 |
|---|---|---|---|
| `audit-data` | 65.9% | 8.1% | **8.1배** |

그리고 그 규율은 **여섯이 각자 한 벌씩** 들고 있다. 플러그인 에이전트에는
공유하는 장치가 없으므로 이 중복은 「여섯을 좁게」 설계에 딸린 것이지 실수가
아니다. 줄이는 길은 중복 제거가 아니라 **각 절이 제 몫을 하는지**다.

### 이 숫자가 말하지 않는 것

**주의는 문자가 아니다.** 규칙이 늘면 서로 경쟁하고, 경쟁은 세어서 안 나온다.
여기서 잰 것은 **값**이지 **값어치**가 아니다.

값어치를 재는 길은 하나뿐이다 — 절을 빼고 그 절이 지키던 케이스를 다시 돌려
점수가 떨어지는지 보는 것. `보지 않는 것` 이 한 감사자당 2,000자 남짓 × 여섯
이므로 여기가 가장 값이 큰 실험이고, **돈이 드는 실험이라 저자가 정할 일로
남긴다.**

### 스냅숏이 벽보다 중요하다

`vibe-audit/evals/budget.txt` 가 지금 값을 들고 있고, **한 글자라도 달라지면
게이트가 실패한다.** 고치려면 `--write` 로 다시 쓰고 커밋에 담아야 한다 — 그
diff 가 「이번에 주의 예산을 얼마나 더 썼는가」다. 천장(상시 합계 5,600자 ·
감사자 호출 시 11,000자)도 있지만 그건 한참 뒤의 벽이고, **조용히 자라는 길을
막는 것은 스냅숏**이다.

## 값어치 — 한 절을 빼고 재보다

바로 위 절은 **값**을 쟀다. 규율이 체크 항목의 네 배에서 여덟 배를 쓴다는 것은
가격표이지 값어치가 아니다. 값어치는 한 가지로만 잰다 — **빼고 다시 돌린다.**

「보지 않는 것」 절을 여섯 감사자에서 통째로 지운 사본을 만들고, 그 절이 지키던
세 케이스를 3회씩 돌렸다. 사본은 순수 삭제다(감사자당 2,069–2,185자, 합
12,671자, 추가된 줄 0). 9회차 · $3.73 · 실시간 12분. 그 결과가 둘을 더
부르길래 두 번 더 돌렸다(아래) — 셋째 규율을 **자취까지** 뺀 판본, 그리고
둘째 소절의 케이스가 애초에 가르기는 하는지 볼 **플러그인 없는 팔**.

| 케이스 | 지키는 소절 | 온전할 때 | 절 빼고 | Δ |
|---|---|---|---|---|
| `gate-out-of-scope` | 담당이 아닌 것은 부적합이 아닙니다 | 1.000 (3/3) | **0.571 (0/3)** | **−0.429** |
| `gap-unowned` | 담당이 없으면 호출자에게 올립니다 | 0.833 (2/3) | 0.800 (1/3) | −0.033 |
| `gate-own-not-pushed` | 담당인 것은 남에게 넘기지 않습니다 | 1.000 (3/3) | 1.000 (3/3) | 0 |

**세 소절이 같은 값을 하지 않는다.** 가격은 비슷한데 값어치는 아니다.

| 소절 | 값(감사자당) | 값어치 |
|---|---|---|
| 머리말(범위 한 줄) | 170자 | 아래 셋의 대조표 — 따로 재지 않았다 |
| 담당이 아닌 것은 부적합이 아닙니다 | 573자 | 빼면 관문이 안 선다 |
| 담당인 것은 남에게 넘기지 않습니다 | 577자 | 안 움직였다 — 케이스는 이빨이 있는데도 |
| 담당이 없으면 호출자에게 올립니다 | 788자 | 값을 한다 — 회차를 맞춰 견주니 Δ −0.380 |

### 첫 소절은 값을 한다

빼자 **네 회차 모두** 실패했다(3회 + 트레이스용 1회). 한 회차의 기록에서
`audit-secrets` 가 이렇게 적었다 —

> ### NC-2 · 권한 회귀를 잡아낼 유일한 테스트가 비활성화되어 있고 CI가 실패를 무시함
> - 위치: `tests/test_invoices.py:8-10`, `.github/workflows/ci.yml:8-12`
> - 심각도: 높음

테스트와 CI 는 `audit-quality` 의 것이다. 절제본은 그것을 **자기 대장에
심각도까지 붙여** 넣었고, 「안 본 것」에 담당을 적지도 않았다
(`gate-holds` · `handoff-named` 동시 실패). 되먹임 표 28행에 적힌 2차 감사의
실패 — 「담당 밖 발견을 NC 로 적었다(서른셋 중 열여덟)」 — 가 문장 그대로
돌아왔다. 573자가 사는 것이 그것이다.

### 셋째 소절 — n=3 으로 내린 결론이 n=5 에서 뒤집혔다

처음에 절만 지웠을 때 `gap-unowned` 이 0.833 → 0.800 밖에 안 움직였다. 그래서
절 밖에 남은 자취를 찾았다 — 「관찰」 절의 교차 참조와 **출력 형식 템플릿의 한
줄**. 자취까지 지우니 0.633(0/3)으로 떨어졌고, 나는 여기서 **「값은 산문이
쓰고 일은 템플릿 한 줄이 한다」**고 적었다. 세 숫자가 다 n=3 이었다.

그래서 소절 하나만 정확히 떼어 회차를 올려 다시 쟀다 — 머리말 · 앞 두 소절 ·
템플릿 줄 · 교차 참조는 **전부 그대로 두고**, 셋째 소절의 산문 788자만.

| 판본 | 회차 | `gap-unowned` | 깨끗한 회차 |
|---|---|---|---|
| 온전 | 5 | **0.940** | 4/5 |
| 셋째 소절의 산문 788자만 뺌 | 5 | **0.560** | 1/5 |

**Δ −0.380.** 앞의 결론은 틀렸다. 788자는 값을 한다.

무엇이 무너지는지도 분명하다. 산문을 뺀 회차에서 감사자는 `Dockerfile:1` 의
`FROM python:latest` 를 이렇게 넘겼다 —

> - 빌드 재현성: `Dockerfile:1` `FROM python:latest` 베이스 이미지 미고정 — 담당: `audit-ops`

없는 담당을 **확신을 갖고** 지어냈다. 지운 산문이 이름을 들어 금지한 바로 그
오판이다 — 「빌드 재현성이나 의존성 버전 고정이 「관측과 롤백」처럼 들린다고
`audit-ops` 의 것이 되지는 않습니다.」 템플릿의 한 줄은 「담당 없는 것은 따로
모아라」고만 시키므로, **담당이 없다는 판단 자체**를 못 세운다. 줄은 모양을
주고 산문은 판단을 준다.

앞의 세 숫자(0.833 · 0.800 · 0.633)는 n=3 이라 이 결과와 한 줄로 서지 않는다.
더 많이 지운 판본이 덜 지운 판본보다 높게 나온 자리가 있는데, **어느 쪽이
참인지 지금 자료로는 못 가른다.** 확실한 것은 회차를 맞춰 견준 한 쌍뿐이다.

이 저장소가 감사자에게 시키는 말을 나 자신에게는 안 썼다 — **한 번 돌려 나온
숫자는 판정이 아니다.** 셋을 늘어놓아 그럴듯한 분해까지 적었고, 회차를 올리자
그 분해가 통째로 무너졌다.

### 둘째 소절 — 짐작 하나를 지웠고, 아직 못 닫았다

`gate-own-not-pushed` 는 이빨이 있다. 플러그인 없는 팔에서 0.000 이고, 그
소절이 지키라고 세운 `gate-holds` · `gate-nc-kept` 가 세 회차 모두 실패한다.
그런데 577자를 빼도 3/3 이다.

앞 절에서 「아마 「판정은 넷이다」가 대신 할 것」이라고 짐작했다. 그 절만 빼고
같은 케이스를 돌렸다.

| 판본 | `gate-own-not-pushed` |
|---|---|
| 온전 | 1.000 (3/3) |
| 둘째 소절 577자 뺌 | 1.000 (3/3) |
| 「판정은 넷이다」 1,607자 뺌 | **1.000 (3/3)** |

짐작은 틀렸다. 둘 중 어느 것도 이 케이스를 떠받치고 있지 않다. **무엇이
떠받치는지는 여전히 모른다** — 확인불가이고, 짐작 하나가 줄었을 뿐이다.

### 이 실험이 확정한 것과 안 한 것

확정한 것:

- **첫 소절(573자)은 값을 한다.** 빼면 관문이 네 회차 모두 안 선다.
- **셋째 소절(788자)은 값을 한다** — 회차를 맞춰 견주니 Δ −0.380. 템플릿의
  한 줄은 모양만 주고, 담당이 없다는 **판단**은 산문이 준다.
- **둘째 소절(577자)은 이 케이스를 안 움직인다.** 케이스는 무르지 않고,
  「판정은 넷이다」도 답이 아니다.

안 한 것:

- **아무것도 자르지 않았다.** 문구는 그대로다. 남은 후보는 둘째 소절 하나인데,
  케이스 하나 · n=3 으로 577자를 자르지 않는다. 닫으려면 그 소절이 지키는
  자리를 더 좁게 무는 케이스가 있어야 한다.
- **다른 케이스가 함께 상했는지는 안 봤다.** 절제본을 그 절이 지키는 케이스에만
  돌렸으므로, 함정·회차 케이스가 조용히 나빠졌는지는 모른다.

실험 스크립트에서 `--keep-temp` 을 빠뜨려 첫 아홉 회차의 트레이스를 잃었다.
바로 아래 절이 고쳐 둔 결함을 사본에서 되풀이한 것이다 — 무엇이 샜는지 보려고
한 회차를 더 돌려야 했다($0.4). 뒤이은 회차는 전부 트레이스를 남겼다.

다섯 실험 합 $14.25 · 35회차.

## 전수 회귀 — 문구가 +57% 자란 뒤에도 버티는가

주의 예산의 진짜 위험은 총액이 아니라 **조용한 회귀**다. 되먹임을 메울 때마다
문구가 자랐는데, 자란 뒤에 **옛 케이스가 아직 버티는지는 한 번도 안 봤다.**

13 케이스 × 3회, 단일 팔, sonnet 심판. 123분 · $12.89.

**전체 0.975 · 11/13 통과.** 열한 케이스가 1.000 이고 둘이 떨어졌다.

### 실패 셋 중 둘은 그레이더 결함이었다

원문을 열어 보지 않았으면 「회귀가 났다」고 적었을 자리다.

| 실패 | 기록에 뭐라고 적혀 있었나 | 누가 틀렸나 |
|---|---|---|
| `cycle-continuity` run1 | `\| NC-3 \| 이번엔 안 봄 \| … 해소 **여부 미확인** \|` | **정규식** — 정반대 뜻인데 글자가 같다 |
| `gap-unowned` run2 | 발견이 표식 **앞**, 같은 목록 항목 안 | **정규식** — 표식 뒤만 훑었다 |
| `gap-unowned` run3 | 표식 없이 `담당: audit-quality` 로 넘김 | 감사자 — **진짜 샌 것** |

앞의 둘은 같은 가정을 깔고 있었다 — 「문자열이 거기 있으면 그런 뜻이다」.
**이 수트에서 네 번째다.** `verify-graders.py` 머리말에 그 문장을 적어 놓고도
같은 실수를 했다. 표본이 그 자리를 안 덮고 있었기 때문이다.

고친 것: **판정은 표의 칸에만 건다.** 「해소」가 같은 줄에 보이는 것과 판정이
「해소」인 것은 다르다. `gate-escalated` 은 갈래를 하나 더 받는다 — 발견에서
시작해 **같은 목록 항목 안에서만** 표식을 찾는다.

그리고 두 실패의 **실제 모양을 표본으로 박았다.** 고치기 전 정규식으로
되돌리면 두 표본이 그대로 물어서 잡는 것을 확인했다.

### 고친 뒤 다시 잰 값

| 케이스 | 고치기 전 | 고친 뒤 |
|---|---|---|
| `cycle-continuity` | 0.938 | **1.000** (3/3) |
| `gap-unowned` | 0.733 | **0.833** (2/3) |

`gap-unowned` 의 남은 하나는 **이미 적어 둔 잔여**다 — 공급망을 `audit-ops`
담당으로 넘겼다. 새로 생긴 것이 아니다.

### 답

**+57% 자란 뒤에도 회귀는 없다.** 열한 케이스가 깨끗하고, 실제로 샌 것은
`gap-unowned` 하나이며 그것은 문구가 자라기 전부터 있던 자리다.

### 이 회귀가 러너에서 낸 결함 둘

측정이 스스로 두 개를 더 냈다.

**하나. 도는 중에 스크립트를 고치면 안 된다.** bash 는 스크립트를 조금씩 읽어
가며 돈다. 돌고 있는 동안 파일을 고치면 이어 읽는 자리가 어긋나 엉뚱한 줄을
명령으로 실행한다 — `line 48: -keep-temp: command not found` 가 그것이었고,
재현이 안 돼 한참 「확인불가」로 열어 두었던 것이다. `run-evals.sh` 본문을
`main()` 으로 감쌌다. bash 가 끝까지 읽은 뒤 실행하므로 이 일이 없고, 도는
중에 40줄을 끼워 넣어도 완주하는 것을 확인했다.

**둘. 케이스가 0개면 실패한다.** `--case` 가 아무것도 못 맞히면 하네스는
조용히 `exit 0` 으로 끝난다 — 이 저장소가 막으려는 바로 그 모양이 러너에
남아 있었다. `--case '{a,b}'` 로 실제로 났다(중괄호는 글롭이 아니다).
이제 종료코드 3 으로 문다.

## 아직 안 재는 것

- **회수율** — 픽스처에 결함을 심어야 하는데, 지어낸 결함으로는 못 잰다.
  ERP 가 실제로 낸 부적합을 익명화해 픽스처로 옮기는 것이 다음 수다.
- **정규식이 없는 일곱 케이스** — `route-*` 여섯은 그레이더가 전부 `tool_used`,
  `trap-rollback-unproven` 은 전부 심판이라 `verify-graders.py` 가 볼 것이
  없다. 그 일곱이 실제로 가르는지는 다른 방법이 있어야 한다 — 라우팅 음성
  대조군이 안 물었던 적이 있고, `input_match` 가 **Agent 입력 전체**에서
  문자열을 찾는 탓에 **이름이 적혀 있는 것을 뜬 것으로 세는** 결함이 실제로
  났다(고쳤다 — 「이름이 아니라 `subagent_type` 에 건다」). `verify-evals.py` 는
  이제 그 **모양**을 물지만, 그레이더가 실제 트레이스에서 옳게 세는지는 여전히
  표본 없이 비어 있는 자리다.
- **자기 트리거** — `audit-secrets` 는 고쳤다(0/10 → 10/10). `audit-contract`
  · `audit-data` 는 1/5 · 0/5 에서 **5/5 · 5/5** 로 고쳤다(위 「두 번째 시도에서
  고쳤다」). 나머지 셋(`audit-internal` · `audit-ops` · `audit-quality`)의
  description 은 상태 조건을 약하게만 적고 있고 잰 적이 없다.
  그리고 `audit-secrets` 프론트매터는 이제 **여유가 15자**다. 무언가 더하려면
  먼저 덜어 내야 한다.
- **여섯 중 넷** — `audit-quality` · `audit-contract` · `audit-internal` 에는
  아직 케이스가 없다. 되먹임에 기록된 거짓 판정이 그 셋에서는 안 나왔기
  때문이고, 나오면 그때 붙인다.

## 얼마나 걸리나

한 회차가 감사 한 번 전체다 — 최대 60턴, 파일 전수, 250줄짜리 기록. 그리고
`claude plugin eval` 의 **기본 동시성은 1** 이다. 13 케이스 × 3회를 직렬로
돌리면 두 시간이 든다. 실제로 그렇게 돌린 뒤에야 알았다.

`run-evals.sh` 가 `-j 4` 를 기본으로 박는다. 같은 자격을 나눠 쓰므로 한 요금
한도에 걸리고, 여덟은 한도에 부딪혀 오히려 느려질 수 있어 넷으로 뒀다. 결과와
보고서는 케이스 순서를 지키므로 **점수에는 영향이 없다.** `-j` 를 직접 주면
그 값이 쓰인다.

## 변동성

`runs: 3` 이 기본이다. LLM 이라 같은 입력에 다른 답이 나오므로 한 번 돌려 나온
PASS 는 판정이 아니다. 문구를 고친 뒤 견줄 때는 `--runs` 를 올린다.
