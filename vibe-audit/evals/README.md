# 감사자를 감사한다

`audit-quality` 가 남에게 요구하는 것 — 평가셋 · 회귀 판정 · 무는 게이트 — 을
이 플러그인이 자기 자신에게 적용한 자리다. 이 파일은 살아 있는 문서다 — 수트의
지금 모양만 든다. 날짜를 박은 작업 기록은 `docs/eval-log/` 에 달마다 쌓는다(「기록」).

**2026-10-06 까지의 절은 `docs/eval-log/2026-09-16_2026-10-06.md` 에 글자 그대로 있다.**
스크립트 · 그레이더 · 조각 폴더 · ADR 이 `evals/README.md 「…」` 로 부르는 절은 그 파일에서 찾는다.

```bash
./scripts/run-evals.sh
```

## 재는 것

### 오검율

**회수율(심은 결함을 몇 개 잡는가)은 재지 않는다.** 미리 지어낸 결함은 재지 않고
단정한 것의 픽스처 판이기 때문이다.

대신 **오검율**을 잰다. 판정 케이스(`trap-*` · `gate-*` · `gap-*` · `brief-*` · `cycle-*`)는
되먹임이 기록한 **실제로 겪은 거짓 판정**이나 그 판정을 낳은 구조의 자리이고(「케이스」 표의 「어디서」),
되먹임 한 건에 케이스 하나가 붙는다. 고친 자리마다 회귀 검사가 하나 서는 셈이다.

거짓 지적을 두어 번 내면 아무도 감사자를 안 부른다. 오검이 이 도구에서 가장 비싼 결함이고,
그래서 먼저 잰다.

### 트리거 정확도

판정 케이스가 감사자의 **판정**을 잰다면, `route-*` 는 프론트매터 `description` 의
**반응**을 잰다. 감사자를 이름으로 지목하지 않은 자연스러운 말에 맞는 것이 뜨는가.

- **청한 말** — `route-quality` · `route-contract` · `route-internal` · `route-ops`. 맞는 감사자가 뜨고,
  헷갈리기 쉬운 이웃은 안 뜬다.
- **청하지 않은 말**(자기 트리거) — `route-unasked-*`. 사용자는 다른 것을 묻는데 코드의 상태가
  감사를 부를 만하다. `audit-secrets` · `audit-contract` · `audit-data` 는 이때 떠야 하고, `audit-ops` 는
  배포 · 장애 · 관측 · 롤백을 말하지 않으면 안 떠야 한다(`route-unasked-ops`). `audit-internal` ·
  `audit-quality` 의 자기 트리거는 재지 않는다(「재지 않는 것」).
- **무관한 말** — `route-quiet`. 아무도 안 뜬다.

전부 `tool_used` 그레이더뿐이라 **심판 비용이 0** 이다. **음성 그레이더(`route-not-*`)가
대조군 자리에 선다** — 없으면 여섯을 전부 띄우는 세션도 「맞는 감사자가 떴다」로 통과한다.
이 문구들은 구성한 것이다 — 트리거는 입력을 만들지 않으면 잴 방법이 없다.

## 재는 법

### 그레이더와 대조군

| 이름 | 무엇 |
|---|---|
| `trap-*` · `gate-*` 등 목적 그레이더 | 함정의 처분. 이 수트의 목적 |
| `real-nc-found` | 대조군. 감사자가 깨어 있었는가 |
| `auditor-fired` | 그 감사자가 실제로 떴는가. `arm: with-only` 라 점수에 안 들어가고 **플러그인이 붙었는지 표시**만 한다 |

판정 케이스의 픽스처에는 **진짜 부적합이 하나씩** 들어 있고 `real-nc-found` 가 그것을 요구한다.
없으면 **아무것도 안 내는 망가진 감사자가 만점을 받는다** — 함정을 안 걸었으니까.

**말로 표현할 수 있는 판정은 결정론으로 내린다.** 「특정 문자열이 NC 절 안에 있는가」는
정규식이 정확히 답하고, 공짜이고, 회차마다 흔들리지 않는다. `input_match` 는 이름이 아니라
`subagent_type` 에 건다 — Agent 입력 어딘가에 이름이 적힌 것을 뜬 것으로 세지 않게.

### 심판

기계로 못 쓰는 판정에만 심판을 쓴다 — 부재(가리킬 파일이 없는 「알림 경로가 없다」), 「무엇이
있으면 판정되는지를 함께 적었는가」, 넘긴 것이 심각도 하나뿐인가 같은 것. 심판 모델은 케이스
파일에 못 적고 명령줄에만 있어서 `scripts/run-evals.sh` 가 박는다 — 기본 심판으로는 조용히
오검이 난다.

심판이 틀리는 모양은 둘이다. **표면 토큰에 걸린다** — 고치는 법은 경계 예시를 표로 박는 것이다.
**부재를 물으면 못 한다** — 질문을 하나의 존재 확인(「이런 주장을 하고 있는가?」)으로 바꾸고,
확신이 안 설 때의 기본값을 적는다. 결정론이 언제나 낫지는 않다 — **무엇을 찾는지 정확히 알 때만**
낫다.

### 키 없이도 무는 게이트

`claude plugin eval` 은 케이스를 못 찾으면 아무것도 안 돌리고 끝난다. 그래서 구조만 보는 검사를
따로 둔다 — API 키도 모델 호출도 필요 없다. 목록은 `./scripts/gates.sh` 한 군데에 있다.

- `verify-evals.py` — 케이스마다 목적 그레이더 · 대조군 · 감사자 지목(`auditor-fired` 가
  `prompt.md` 가 부르는 감사자를 `subagent_type` 으로 거는가)이 서 있는가.
- `verify-graders.py` — 케이스가 표본(`samples/pass.md` 한 벌 · `samples/fail*.md` 한 벌 이상)을 두면,
  모든 정규식 그레이더가 바른 기록에서 통과하고, 함정 표본 첫 줄이 지목한 그레이더는 전부 실패하며,
  지목하지 않은 것은 전부 통과하는가. 정규식 하나가 선택지를 여럿 담으면 선택지마다 표본을 한 벌씩 둔다.
  정규식 그레이더가 없는 케이스(`route-*` · `trap-rollback-unproven`)는 표본으로 볼 것이 없다 — 따로
  세어 찍는다.
- `verify-budget.py` — 감사자 · 커맨드의 글자 수가 `budget.txt` 스냅숏과 천장 안에 있는가.

도는 것과 무는 것은 다른 질문이라, CI 「게이트가 무는가」 단계가 게이트마다 변조본을 만들어
떨어뜨려 본다.

### 러너

`scripts/run-evals.sh` 가 깃발을 박는다 — 심판 모델 · `--scaffold`(없으면 빈 작업공간에서 돌아
**거짓 통과**) · 수트 모델 · 동시성. 값은 그 파일이 든다. 실패한 회차의 트레이스만 결과 폴더에 옮기고,
트레이스의 `modelUsage` 에서 실제로 돈 모델을 찍는다.

CI(`.github/workflows/eval.yml`)는 PR 과 `main` push 에서 **`route-*` 만** 돌리고, 판정 케이스까지
도는 **전수는 `workflow_dispatch`** 로 사람이 부를 때만 돌린다. 회차 · 문턱 · 비용 천장은 그 파일이 든다. 수트 입력의 지문
(`scripts/eval-key.py` — `vibe-audit/` 아래에서 `README.md` 가 아닌 파일 · 러너와 러너가 부르는 스크립트 ·
`eval.yml` · CLI 판)이 이미 통과했으면 다시 돌지 않는다. 그래서 이 파일과 `docs/eval-log/` 를 고쳐도
수트가 돌지 않는다. 같은 입력을 다시 표본으로 뽑고 싶으면 Actions → Caches 에서 `eval-route-` 항목을
지우고 재실행한다.

`runs: 3` 이 기본이다. 같은 입력에 다른 답이 나오므로 한 번 돌려 나온 PASS 는 판정이 아니다. 문구를
고친 뒤 견줄 때는 `--runs` 를 올린다.

### 재지 않는 것

- **회수율** — 지어낸 결함으로는 못 잰다. 실제 부적합을 익명화해 픽스처로 옮겨야 한다.
- **정규식이 없는 케이스가 실제 트레이스에서 옳게 세는가** — `route-*` 는 그레이더가 전부 `tool_used`,
  `trap-rollback-unproven` 은 전부 심판이다. `verify-evals.py` 는 모양을 물지만 표본이 없다.
- **`audit-internal` · `audit-quality` 의 자기 트리거** — 위 「트리거 정확도」.
- **`audit-contract` 의 판정** — 판정 케이스가 없다. 되먹임에 기록된 거짓 판정이 그 감사자에서는
  안 나왔다. 나오면 그때 붙인다.

## 고정한 것

러너와 정규식 그레이더는 **고정**했다 — 새 방어를 더하지 않고, 아래 「고치는 것」만 고친다. 하네스의 결과 ·
모델의 출력을 모양으로 짐작하는 장치라 모양을 통과하고 뜻이 틀린 입력은 늘 더 만들 수 있고, 리뷰 회차마다
그 가설적 모양이 지적으로 이어졌기 때문이다. 브리핑 검사기는 같은 까닭으로 떼었다가 모양을 짐작하지 않는
방식으로 다시 세웠다. 리뷰 봇은 `AGENTS.md` 「Review guidelines」를 따라 이 절에서 셋의 범위를 읽는다.

### 러너 — `scripts/run-evals.sh` 와 `eval.yml` 의 러너 부분

처음 고정한 날과 까닭: `docs/eval-log/2026-09-16_2026-10-06.md` 「브리핑 검사기를 떼고, 러너를 고정했다」(2026-09-25).

**고치는 것** — 실제 CI 실행에서 난 결함, 그리고 회귀를 통과(exit 0)로 내는 결함. 하네스가 이상한
`result.json` · 트레이스를 쓰는 가설적 모양은 알려진 한계다.

| 한계 | 왜 두는가 |
|---|---|
| 러너는 하네스의 `result.json` 과 트레이스를 믿는다 — 채점 결과 자체를 다시 계산하지 않는다 | 다시 계산하면 하네스를 다시 짜는 것이다 |
| 사용량 한도는 결과 문구로 알아본다(`LIMIT`) | 문구가 바뀌면 한도가 회귀로 보인다 — 수트 전체로는 거짓 초록이 아니라 거짓 빨강 쪽이다 |
| 모델 확인은 트레이스 `modelUsage` 에 요청한 이름이 **보이는지만** 본다 | 곁에 다른 모델(배경 작업)이 보이는 것은 막지 않는다 |
| 캐시 지문은 수트 · 러너 · 워크플로 · CLI 판만 본다 | 모델 쪽이 같은 이름으로 바뀐 것은 지문이 모른다 — `workflow_dispatch` 전수가 그 몫이다 |
| 한 회차의 흔들림은 문턱(route 1.0 · 전수 0.8)과 「매번 떨어짐」으로만 본다 | 더 세밀한 통계는 회차 수를 늘리는 일이다 |

### 정규식 그레이더 — `vibe-audit/evals/*/graders/*.md` 의 `type: regex`

처음 고정한 날과 까닭: `docs/eval-log/2026-09-16_2026-10-06.md` 「정규식 그레이더를 고정했다 · route-ops 는 공백으로 둔다」(2026-09-25).
그 절의 `route-ops` 공백은 케이스 `route-ops` 가 생겨 메워졌다 — 같은 파일 「새 route 케이스 둘」.

**고치는 것** — 실제 수트 실행의 트레이스에서 틀린 판정이 나온 경우. 그때 그 모양을 표본으로 박고 고친다.
모양을 지키고 뜻을 뒤집는 가설적 문장은 알려진 한계다.

| 한계 | 예 |
|---|---|
| 목록 경계는 `-` · `*` 만 안다 | 번호 목록(`1.` · `2.`)의 형제 항목이 한 항목으로 읽힌다 — `handoff-named` · `gate-escalated(-perf)` |
| 부정 · 불확실 · 모순은 **알려진 말만** 막는다 | 「아니 · 아님」 · 「여부 · 인지」 · 「존재 · 있음」 밖의 말로 뒤집으면 못 잡는다 |
| 관계를 **같은 줄 · 항목 · 절에 함께 있음**으로 짐작한다 | 문장 구조를 모른다 — 같은 항목 안의 반대 서술을 가르지 못한다 |
| 담당 주장은 `audit-*` 이름이 붙은 담당 · 몫 · 소관만 본다 | 이름 없이 「품질 쪽 몫」처럼 적은 담당은 안 걸린다 |

### 브리핑 검사기 — `vibe-audit/scripts/verify-brief.py`

모양을 보던 검사기를 뗀 날과 까닭: `docs/eval-log/2026-09-16_2026-10-06.md` 「브리핑 검사기를 떼고, 러너를 고정했다」(2026-09-25).
다시 세운 날과 방식: `docs/eval-log/2026-09-16_2026-10-06.md` 「브리핑 검사기를 git 과 대조하는 방식으로 다시 세웠다」(2026-09-28).

모양을 짐작하지 않고 git 과 견준다 — 브리핑에서는 **무엇을 담았다고 하는지**(대상 · 기준 · 머지 베이스 ·
자름 · 파일마다의 +/- 줄 수 · 「담지 않은 것」)만 읽고, 담았어야 할 것은 저장소에 다시 묻는다.
`/audit-brief` 가 감사자를 부르기 전에 돌리고, PASS 전에는 감사자를 부르지 않는다. 무는지는
`scripts/test-verify-brief.py` 가 본다. 다른 둘과 달리 평소대로 리뷰한다 — 아래는 알려진 한계다.

- **보지 않는 것** — 줄의 내용(가림과 부딪힌다), 커밋 몫과 작업트리 몫을 제 소절에 나눴는지(파일마다
  합쳐 센다), 「변경 파일」 · 「커밋」 절의 내용.
- **플러그인으로 깐 쪽** — 커맨드 본문에서 `${CLAUDE_PLUGIN_ROOT}` 가 풀리지 않아(anthropics/claude-code#9354)
  커맨드가 검사기 자리를 적어 줄 수 없다. 플러그인 폴더의 `scripts/verify-brief.py` 로 찾게 하고, 못 찾으면
  머리의 `검사:` 에 「못 돌림」과 까닭을 적는다 — 말없이 건너뛰지 않는다.

## 기록

날짜를 박은 작업 기록 — 되먹임 회차 · 측정 · 리뷰 회차 — 은 이 파일이 아니라 `docs/eval-log/` 에 둔다.
그 폴더는 `vibe-audit/` 밖이라 수트 지문에도 배포에도 들지 않는다(ADR 0011).

- `2026-09-16_2026-10-06.md` — 이 파일이 살아 있는 문서가 되기 전의 전부. 글자 그대로 옮겼다.
- 그 뒤는 **`<YYYY-MM>.md`** — 그달의 기록을 그 파일 끝에 덧붙인다. 지난 항목은 고치지 않는다
  (`docs/procedure.md` 「살아 있는 문서와 기록」).

이 파일이 든 것 — 케이스 표 · 재는 법 · 고정한 것과 그 한계 — 이 바뀌면 그 자리를 고친다.
