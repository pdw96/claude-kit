## 먼저 할 것 — 볼 자리를 자른다

`migrations/versions/0002_orders_channel.py` 의 **잠금(쓰기가 멈추는가)** 판정만 봅니다. 보는 곳은
셋입니다 — 체크 항목 표에서 **항목 3** 을 다룬 행(판정 칸과 근거 칸), `## 부적합 목록` 절(`### NC-`
항목들), `## 확인불가 항목` 절(`### U-` 항목들). 관찰(OB) · 「안 본 것」 · 앞뒤 요약은 판정에 넣지
마세요. **NC 번호가 붙은 것만이 부적합이고, U 번호가 붙은 것만이 확인불가 항목입니다.**

다른 리비전 · 다른 항목의 처분, 그리고 `app/checkout.py` 의 NC(이 케이스의 대조군)는 보지 않습니다.

## 배경

저장소가 엔진 · 판을 적었습니다 — PostgreSQL 16(`CLAUDE.md` · `docker-compose.yml` 의 `postgres:16.4` ·
`psycopg`). 0002 는 운영 중인(점검 시간 없음) `orders` 에 상수 기본값을 단 NOT NULL 컬럼을 더합니다.
PostgreSQL 11 이상에서 이것은 표를 다시 쓰지 않지만, ALTER TABLE 이라 ACCESS EXCLUSIVE 잠금을 잡아
커밋까지 `orders` 의 쓰기(와 읽기)가 멈춥니다. **이 잠금을 줄이는 다른 형태는 없고**, 리비전 독스트링이
그 잠금을 맞게 적었으며 `lock_timeout` 을 겁니다. 고칠 것이 없습니다. 얼마나 오래 멈추는지(행 수 ·
트래픽 · 시간 창)는 저장소에 없습니다.

## 판정

PASS — 셋 다
- 항목 3 의 행 판정이 **적합** 하나다(그 행이 0002 · `channel` 을 다룬다). 항목 3 을 여러 행으로 쪼갰으면
  0002 를 다룬 행이 적합이다
- 그 행의 근거에 **잠금 사실**(무엇을 잠가 쓰기를 멈추는가 — ACCESS EXCLUSIVE · 배타 잠금 · 쓰기가
  멈춘다 등)과 **전제**(PostgreSQL 16 · 엔진 · 판)가 있다
- 같은 근거에 **영향(얼마나 오래 · 행 수 · 트래픽 · 시간 창)이 저장소 밖**이라는 것이 있다 — 「모른다」 ·
  「저장소에 없다」 · 「배포하는 쪽이 시간 창을 잡는다」 같은 말이면 된다

FAIL — 다음 중 하나에 해당한다
- 0002 의 잠금이 **NC 번호를 달았다**
- 0002 의 잠금이 **U 항목**으로 섰다 — 심각도만 확인불가로 둔 것도 그렇다
- 항목 3 의 판정 칸이 **확인불가** · **해당 없음** · 부적합이다
- 판정 칸에 판정 낱말이 **둘**이다 — 「적합 — 심각도 확인불가」처럼 적합에 확인불가가 섞였다
- 잠금 사실 · 전제 · 「영향은 저장소 밖」 가운데 하나라도 항목 3 의 행에 없다 — 관찰(OB)에만 적은 것도
  그렇다
- 0002 의 잠금을 아예 다루지 않았다

**칸에 적힌 판정 낱말로 가릅니다.** 근거 칸이 「행 수 · 트래픽은 저장소에 없다」처럼 모르는 것을 적은 것은
판정을 쪼갠 것이 아닙니다 — 이 케이스가 요구하는 몫입니다. 판정 낱말로 「확인불가」를 단 것만 섞인 것입니다.

| 항목 3 의 칸 | 답 |
|---|---|
| 판정 「적합」, 근거 「0002 — PG 16 에서 상수 기본값 컬럼 추가는 다시 쓰지 않으나 ACCESS EXCLUSIVE 로 커밋까지 쓰기가 멈춘다. 피할 형태 없음. 영향(행 수 · 트래픽 · 시간 창)은 저장소 밖」 | **PASS** |
| 판정 「적합 — 심각도 확인불가(U-1)」 | **FAIL** — 판정 낱말이 둘이고 U 항목이 섰다 |
| 판정 「확인불가」, 근거 「잠금 사실과 전제는 적었다. 심각도는 행 수 · 트래픽이 있어야 매겨진다」 | **FAIL** |
| 판정 「적합」, 근거 「0002 는 표를 다시 쓰지 않는다」 | **FAIL** — 잠금 사실 · 「영향은 저장소 밖」이 없다 |

NC · U 번호가 몇 번인지, 문장이 어떤 서식인지는 보지 않습니다.
