# 조각 3 — 문서 대조 검사 (2026-10-06 착공)

요구사항이다 — **무엇을 · 왜.** 어떻게 · 경계는 같은 폴더의 `design.md`, 대안이 있던 결정은 ADR 0010.

## 문제

절차 지도(`docs/procedure.md`)는 문서의 모양 — 의도 · 마스터플랜 · 요구사항 · 설계의 절 제목, 마스터플랜이 가리키는
경로, 조각의 상태와 폴더 — 을 앵커볼트로 정했다. 그런데 **어겨도 떨어지는 검사가 없다.** 지키는 것은
`CHECKLIST.md` 「조각을 시작했다면」의 두 줄뿐이고, 그 두 줄이 스스로 「조각 나눔 「문서 대조 검사」가 맡을
자리다」라고 적고 있다.

- **모양이 하루에 두 번 옮겨졌다.** 조각 2 착공 PR(#14) 안에서 c2c448a 가 `docs/baseline.md` → `docs/master-plan.md`,
  `PRD.md` · `docs/design/slice-2.md` → 조각 폴더로 옮겼고, 609d30e 가 `plan.md` → `requirements.md` 로 바꾸고
  `INTENT.md` 를 뗐다. 가리키는 줄(README 의 `PRD.md` 링크 등)은 사람이 손으로 따라 고쳤다. 다음 이름 바꾸기에서
  한 줄을 놓쳐도 알려 주는 것이 없다.
- **사람이 기억하는 검사는 건너뛴다** — 강호쟁패 ADR-0005 의 결론이고, 이 저장소의 규칙(「물지 않는 검사는 게이트가
  아니다」)과 같은 말이다.
- **다음 조각이 이 모양에 기댄다.** 조각 나눔 「리뷰 루프」는 지적을 설계 ② · ③ 에 비춰 가른다 — 그 칸이 있다는
  것이 먼저 지켜져야 한다(조각 2 요구사항 「로드맵의 근거」).

## 핵심 사용자와 시나리오

- 사용자: 저자 한 명.
- 시나리오: 조각을 꺼내 마스터플랜의 상태를 `진행` 으로 바꾸고 조각 폴더에 요구사항 · 설계를 쓴다 →
  `./scripts/gates.sh` 를 돌린다 → 설계에서 `## ③ 받는 입력` 제목을 빠뜨렸거나, 의존한 조각이 아직 `닫힘` 이 아니거나,
  마스터플랜이 가리키는 파일이 옮겨져 없으면 **어느 파일의 무엇인지 찍고 0 이 아닌 종료코드로** 떨어진다 → 고치고
  다시 돌려 통과 → PR 을 연다. CI gate 잡이 같은 검사를 돈다. 조각을 닫을 때 요구사항 끝에 `## 닫으며 (<날짜>)` 를
  빠뜨려도 같은 자리에서 떨어진다.

## 성공 기준

- 문서 대조 검사가 `scripts/gates.sh` 에 있고, 이 저장소의 지금 문서에서 통과한다.
- 설계 ⑤ 의 변조본이 **하나도 빠짐없이** 떨어지고, 대조(통과해야 하는 모양)는 통과한다 — 키 없이, 로컬과 CI 에서 같다.
- 검사를 한 군데 망가뜨리면 키 없이 도는 게이트 어딘가가 떨어진다 — 로컬과 CI 에서.
- 필수 제목을 바꾸는 곳이 한 군데다 — 거기서 제목 한 줄을 더하면 틀이 떨어진다.
- `CHECKLIST.md` 에서 검사가 맡게 된 것이 사람 목록에서 빠지고, 검사가 안 보는 것만 남는다.
- 모델을 부르지 않는다 — 검사 자체의 비용 $0.

## 하지 않을 일

1. **시간에 기댄 문장을 검사하지 않는다** — 「아직 판정 안 한」처럼 상태를 말하는 정상 문장과 뜻으로만 갈린다. 사람이
   본다(ADR 0010).
2. **기록의 「지난 항목을 고치지 않는다」를 git 으로 물지 않는다** — ADR 머리줄의 「…가 대체한다」처럼 고치는 정상
   자리가 있고, 로컬 `gates.sh` 에는 견줄 기준 커밋이 없다(ADR 0010).
3. **의도를 다른 문서가 들 때 그 문서의 세 절을 검사하지 않는다** — 모양으로는 필수이고(「의도 문서의 칸」) 사람이
   본다. 검사는 경로가 있는지만 본다(ADR 0010).
4. **칸의 내용을 보지 않는다** — 성공 기준이 숫자인가, 하지 않을 일이 셋 이상인가, ④ 에 ADR 번호가 있는가,
   `없음 — <이유>` 가 이유를 댔는가. 모양(제목 · 경로 · 조각 나눔 · 닫는 기록)만 본다.
5. **다른 레포의 문서를 보지 않는다** — 틀과 검사가 레포로 가는 길은 조각 나눔 「틀 배포」.
6. **리뷰 지적을 가르거나 구현 PR 을 막지 않는다** — 조각 나눔 「리뷰 루프」 · 「설계 → 구현 관문」.
7. **문서의 모양을 바꾸지 않는다** — 검사는 `docs/procedure.md` 의 표를 읽기만 한다. 모양을 바꾸는 것은 앵커볼트라
   저자에게 먼저 묻는다(`CLAUDE.md`).

## 제약

- 스택: python3 표준 라이브러리 · bash. git 을 부르지 않는다 — `.git` 이 없는 폴더에서도 같은 판정이어야 한다.
- 모델 비용 **$0**. 다만 구현 PR 이 `.github/workflows/eval.yml` 을 고치면 수트 지문(`eval-key.py`)이 바뀌어 route
  수트가 한 번 돈다 — 구독 토큰의 주간 한도 안.
- 기간 **하루**.
- `./scripts/gates.sh` 는 지금 열 개 검사가 그대로 통과해야 한다.
- 리뷰: PR 본문에 설계 ② 를 적고, 그 밖의 지적은 고치지 않고 답글로 넘긴다. **3라운드**를 넘기면 소유자가 판정한다.

### 제약에서 어긋난 것

- **route 수트가 한 번이 아니라 네 번 돌았다.** #18 의 머리 넷(e704e1e · 2b7984b · 505c5c0 · 04c3658)이 다
  `eval.yml` 을 고쳤다. 리뷰 지적을 고치면 검사의 줄이 바뀌고, 「게이트가 무는가」는 그 줄을 글자로 들고 있어
  같이 고쳐야 한다. 그런데 `eval.yml` 전체가 수트 지문(`eval-key.py`)에 들어 수트가 다시 돈다. 수트는 네 번 다
  통과했고 구독 토큰의 주간 한도 안이었다. 아래 「넘긴 것」.
- **리뷰가 3라운드를 넘었다 — 소유자가 판정했다.** #17 은 Codex 세 회차와 감사 두 회차(`audit-internal` ·
  `audit-quality`) 뒤에 소유자가 Codex 4회차를 불렀다. 그 고침(3b6ae31)은 5회차 없이 머지했다. #18 은 Codex 세
  회차의 지적을 다 고쳤고, 소유자가 부른 4회차는 지적이 없었다.

### 리뷰가 찾은 갈래

#18 의 Codex 지적 다섯 가운데 셋은 R1(「예외로 끝나지 않는다」)이었다 — 긴 의존 사슬, Python 3.12 의 링크 고리,
긴 의존 칸. 자체 시험은 보장마다 「떨어져야 할 모양」을 댔지만, 검사가 **떨어지는 방식** — 예외 없이 줄을 찍는가 —
은 커다란 입력이나 이상한 파일로 대 보지 않았다. 세 번째 지적을 고치며 그 갈래의 남은 자리(UTF-8 이 아니거나 읽지
못하는 문서)를 같이 막았다(04c3658).
