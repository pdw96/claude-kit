# 조각 45 — 모델이 모르는 판 (2026-10-29 착공)

요구사항이다 — **무엇을 · 왜.** 어떻게 · 경계는 같은 폴더의 `design.md`, 대안이 있던 결정은 ADR 0058.

이 조각을 「다음 조각」으로 적은 닫힌 조각은 조각 44 「감사자 README 의 모호한 수」다 — 그 `## 닫으며 (2026-10-29)` 끝 줄이 이 줄을 다음 조각으로 적었다(닫는 세션이
남은 순서 없는 줄 넷을 대 보이고, 셋은 새 근거를 기다리는 줄이고 이 줄만 꺼내는 조건이 없다며 추천해 저자가 골랐다). 착공은 그 닫는 PR 이 머지된 `main`(`5e380e9`)
위에서 연다. 의존한 「확인불가로 미루는 감사자」는 `닫힘` 이다(#152 머지 `7ce445b`). 착공 세션이 조각 나눔의 줄이 든 갈래 셋에 「판에 기대는 것 자체를 부적합으로」를
더해 넷을 보이고 물어, 저자가 세션이 추천한 「재는 것으로 두고 닫는다」를 골랐다(ADR 0058 의 1). 이어 다시 재는 때를 둘 자리를 물어, 저자가 세션이 추천한
`CHECKLIST.md` 의 새 절을 골랐다(ADR 0058 의 2). 이 착공 세션의 claude-kit 클론은 얕지 않았다(`git rev-parse --is-shallow-repository` → `false`).

## 문제

**`audit-data` 가 고정된 판을 확인하고도 그 판의 동작을 몰라 확인불가로 미룬다 — 그리고 그것을 언제 다시 볼지 정한 곳이 없다.**

- **문구는 한 번 고쳤다.** 조각 40 이 「항목 4 · 5 — 프레임워크가 정하는 때도 판으로」를 넣었다. `recall-commit-after-response`(FastAPI `yield` 의존성 뒤의 커밋 —
  응답이 나간 뒤에 돈다)는 기준선 1/3 에서 첫 문구(`0259266`) 3/6, 실려 나간 문구(`0542807`) **4/6** 이 됐다 — 성공 문턱 5/6 에 못 미쳤다
  (`docs/eval-log/2026-10.md` 「`audit-data` 판으로 — 조각 40 PR B」).
- **놓친 꼴이 바뀌었다.** 기준선은 「프레임워크 동작은 저장소 밖」으로 미뤘고, 고친 뒤에 놓친 회차는 다 `requirements.txt` 의 `FastAPI==0.141.1` 을 위치에 적고도
  「그 판의 종료 시점 동작은 내가 아는 범위를 넘는다」로 미뤘다. 문구가 다룰 수 있는 근거(「저장소 밖」)는 사라졌고, 남은 것은 수트 모델이 그 판을 모른다는
  것이다 — 조각 40 설계 ② 「보장하지 않는 것」의 첫 줄.
- **「아는 판으로 미뤄 판정」은 위험하다.** FastAPI 에서 `yield` 의존성 뒤의 코드가 도는 때는 판마다 두 번 뒤집혔다 — 0.106.0 전에는 응답을 보낸 뒤, 0.106.0 ~ 0.117 은
  응답을 보내기 전, 0.118.0 부터 다시 보낸 뒤이고, 0.121.0 이 `Depends(scope="function")` 로 앞쪽을 고를 수 있게 했다(FastAPI 릴리스 노트 0.106.0 · 0.118.0 과 문서
  「Advanced Dependencies」 — 착공 세션이 2026-10-29 웹 검색으로 확인했다). 감사자가 「아는 마지막 판을 전제로」 판정하면 모델이 아는 판에 따라 정반대의 결론이 난다.
- **다시 볼 때가 없다.** 이 수는 수트 모델(`scripts/run-evals.sh` 의 `DEFAULT_MODEL=`)에 달렸는데, 수트 모델을 바꾸는 PR 이 회수율을 다시 재라는 말은 어디에도 없다.
  `vibe-audit/evals/README.md` 「회수율」은 「감사자 문구를 고친 PR 은 이 숫자와 견준다」만 적는다. 조각 나눔의 순서 없는 줄 둘(「가르지 못한 결함 다섯」 · 「가르지 못한
  빈 갈래 둘」)도 「다른 수트 모델」을 꺼내는 조건으로 적지만, 수트 모델이 바뀌는 때 그 줄들을 대 보게 하는 자리가 없다.

## 핵심 사용자와 시나리오

- 사용자: 수트 모델을 바꾸는 PR 을 내는 세션과 그 PR 을 머지하는 저자.
- 시나리오: 세션이 `run-evals.sh` 의 `DEFAULT_MODEL=` 을 새 모델로 바꾼다 → 머지 전 `CHECKLIST.md` 의 「수트 모델을 바꿨다면」 절을 본다 → `vibe-audit/evals/README.md`
  「회수율」이 든 법대로 회수율을 새 모델로 다시 재 기준선과 같은 줄로 견주고 → 조각 나눔에서 「다른 수트 모델」을 꺼내는 조건으로 둔 줄을 대 본다 → 새 수가
  `recall-commit-after-response` 의 놓침이 줄었는지를 보이고, 꺼낼 줄이 있으면 저자가 정한다.

## 성공 기준

1. **다시 재는 때가 선다** — `CHECKLIST.md` 에 `## 수트 모델을 바꿨다면` 절이 있고, 그 절의 체크가 둘이다 — (가) 회수율을 새 수트 모델로 다시 재 기준선과 견줬다
   (재는 법은 `vibe-audit/evals/README.md` 「회수율」을 가리킨다) (나) 조각 나눔에서 「다른 수트 모델」을 꺼내는 조건으로 둔 줄을 대 봤다.
2. **회수율 절이 남은 놓침을 설명한다** — `vibe-audit/evals/README.md` 「회수율」이 `recall-commit-after-response` 의 남은 놓침을 「수트 모델이 고정 판의 동작을 모른다 —
   감사자 문구로 풀지 않는다(ADR 0058)」로 들고, 수트 모델을 바꾸는 PR 이 다시 재는 법(`recall-commit-after-response` 는 회차를 더해)을 든다. 기준선과 조각 40 뒤의 수는
   글자 그대로다.
3. **감사자 · 판 · 지문이 그대로다** — 구현 PR 의 diff 에 `vibe-audit/agents/` · `vibe-audit/.claude-plugin/plugin.json` · `vibe-audit/evals/budget.txt` · `scripts/` 가
   없다. `python3 scripts/eval-key.py route` · `full` 과 `python3 scripts/gate-key.py` 의 끝 줄이 `main`(`5e380e9`)과 같다 — route 수트도 변조 시험도 돌지 않는다.
4. **게이트** — 착공 PR 과 구현 PR 의 CI gate 잡 · verdict 가 초록이고, 구현 PR 작업트리의 인자 없는 `./scripts/gates.sh` 가 끝 줄 「스물여덟 다 통과」로 끝난다.
5. **감사 회차** — 닫기 전에 `audit-internal` 을 돌려 `docs/audit/` 의 부적합 대장에 등록하고(그 등록이 `verify-ledger.py` 를 지난다), `## 닫으며` 가 회차를 든다.

## 하지 않을 일

1. **감사자 문구를 고치지 않는다** — `audit-data` 를 포함해 여섯 다 글자 그대로다. 「판에 기대는 것 자체를 부적합으로」 · 「아는 마지막 판을 전제로」는 고르지 않았다
   (ADR 0058 의 1).
2. **회수율 · 수트를 재지 않는다** — 수트 모델을 바꾸지 않는다. 지금 문구는 조각 40 B 가 잰 문구(`0542807`) 그대로라 새로 잴 것이 없다. 이 조각의 모델 비용은 0 이다.
3. **키 없는 검사를 세우지 않는다** — 「수트 모델이 바뀌었는데 회수율을 다시 재지 않았다」를 무는 검사는 두지 않는다(ADR 0058 의 2). `gates.sh` · `test-gates.py` 의
   목록과 「스물여덟」은 그대로다.
4. **`/audit-brief` 와 브리핑을 고치지 않는다** — 의존성 판의 문서를 브리핑에 싣는 갈래는 고르지 않았다(ADR 0058 의 1). `vibe-audit/commands/audit-brief.md` ·
   `vibe-audit/scripts/verify-brief.py` 는 그대로다.
5. **조각 나눔의 다른 줄을 고치지 않는다** — 「가르지 못한 결함 다섯」 · 「항목 10 과 머리의 어긋남」 · 「가르지 못한 빈 갈래 둘」은 글자 그대로다. 새 절이 그 줄들을 대
   보게 할 뿐이고, 꺼낼지는 그때 저자가 정한다.
6. **사본에 심지 않는다** — `CHECKLIST.md` · `vibe-audit/evals/README.md` 는 사본에 가지 않는다(`copies.json` 그대로).

## 제약

- 스택: 마크다운 — `CHECKLIST.md` 의 새 절 · `vibe-audit/evals/README.md` 「회수율」의 한 줄 · ADR 하나.
- 원본: `main` `5e380e9`.
- 비용: 모델 비용 **0** — route 수트 · 전수 · 회수율 측정을 돌리지 않는다. 고칠 두 파일은 수트 지문(`eval-key.py`)과 변조 시험 지문(`gate-key.py`) 밖이라 구현 PR 의 CI 는
  변조 시험 없이 끝난다.
- 기간: 닫기까지 **2026-11-05**.
- 리뷰: PR 본문에 설계 ② 를 적고, 착공 PR 도 구현 PR 도 스킬 `slice-review` 로 가른다. PR 마다 **3라운드**를 넘기면 소유자가 판정한다.
- 감사 회차: 닫기 전 — `audit-internal`(대장의 NC-16 이 고침으로 「다음 `audit-internal` 회차」의 재감사를 기다린다 — `docs/audit/nc-ledger.md`. 바뀌는 것(`CHECKLIST.md` ·
  `vibe-audit/evals/README.md` · ADR)은 `vibe-audit` README 「대략의 주기」 표의 어느 줄에도 닿지 않는다 — 감사자 문구도 공개 API 도 앵커볼트 층도 아니다).
