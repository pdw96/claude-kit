# 조각 59 — 같은 목록의 경계 (2026-11-09 착공)

요구사항이다 — **무엇을 · 왜.** 어떻게 · 경계는 같은 폴더의 `design.md`, 대안이 있던 결정은 ADR 0078.

이 조각을 「다음 조각」으로 적은 닫힌 조각은 조각 58(감사 회차의 바뀌는 것)이다 — 그 `## 닫으며 (2026-11-09)` 를 읽었다. 넘겨받은 것은 이 줄에 더한 사례(감사 회차 39 「문서에 없어서」
C — 기록이 꼴 목록을 다시 든다, 2 회째)와 NC-42(고침 — 다음 `audit-internal` 회차의 재감사를 기다린다)다. 의존은 `—` 다. 저자가 이 착공 세션에서 갈래 셋을 정했다 — 셋 다 세션이
추천한 쪽이다(ADR 0078 의 1 ~ 3). 착공은 `main`(`30822f5`) 위에서 연다. 이 착공 세션의 클론은 얕지 않았다(`git rev-parse --is-shallow-repository` → `false`).

## 문제

**규칙 「같은 목록은 한 자리에 둔다」(`CLAUDE.md` 「작업 방식」, ADR 0073 의 5)의 「목록」이 어디까지인지 정한 데가 없다.** ADR 0073 의 5 는 「어디에」(저장소 전체 — 문서 · 코드 · 틀 ·
스킬)만 정했고 「무엇이」는 정하지 않았다.

- **안내 · 설명 속 이름 열거** — `scripts/sync-agents.sh:633` 이 감사자 여섯의 이름을 안내 줄에 글자로 찍는다. `README.md:11` 의 감사자 설명, 각 감사자의 「보지 않는 것」 절
  (`vibe-audit/agents/audit-*.md`)도 이름을 열거한다. 첫 자리는 `vibe-audit/agents/` 의 파일들이다. 감사 회차 34 가 이것을 「같은 목록」으로 볼지 몰라 부적합으로 세지 않았다
  (`docs/audit/records/audit-internal-2026-11-05-115617.md` 「문서에 없어서 판정할 수 없었던 것」 (가)).
- **기록 속 목록** — 조각 57 설계 ③ 의 표가 처음 세운 목록이고 `CLAUDE.md` 「새 장치는 새어 나간 결함에만」 줄이 둘째 자리였는데, 둘이 갈려 NC-41(보통)이 났다(회차 38 「문서에 없어서」 C).
  조각 58 설계 ② C 가 같은 줄의 꼴 목록을 괄호에 다시 들었다(회차 39 「문서에 없어서」 C — 2 회째). 기록은 고치지 않는 문서라(`docs/procedure.md` 「살아 있는 문서와 기록」) 규칙 5 가
  걸리는지가 감사마다 판정 밖으로 남는다.
- **「다음 감사 회차가 본다」로 넘긴 일** — 조각 54 · 55 의 설계 ② 「보장하지 않는 것」이 「다음 `audit-internal` 회차가 본다」로 넘겼다(`docs/slices/54-repeated-asks/design.md:35` ·
  `docs/slices/55-duplicate-lists/design.md:38`). 대장에도 조각 나눔에도 줄이 없어, 회차가 지나면 그 넘김은 아무 데도 남지 않는다. 지도의 단계 6 은 넘긴 것을 조각 나눔의 줄로 두게 하지만
  (`docs/procedure.md` 「두 층」), 설계 ② 가 감사 회차로 넘기는 꼴은 다루지 않는다. 회차 34 가 바로 그 「다음 회차」였는데 무엇을 얼마나 볼지가 어디에도 없었다(같은 기록 (나)).

## 핵심 사용자와 시나리오

- 사용자: 이 저장소에서 조각을 착공하며 설계를 쓰는 세션.
- 시나리오: 세션이 설계 ② 에 「이 일치를 무는 검사는 없다」를 적는다 → 절차 지도 「감사 회차」를 읽고, 이 조각의 닫기 전 `audit-internal` 이 그 일치를 보게 감사 회차 줄의 「왜」에 범위를 적는다
  → 다음 조각까지 미루는 몫은 조각 나눔에 줄을 둔다. 세션이 설계 ③ 에 닫힌 목록을 들고 같은 목록을 `CLAUDE.md` 의 새 줄에 넣는다 → `CLAUDE.md` 「같은 목록은 한 자리에 둔다」를 읽고, 기록은
  규칙 밖이고 갈리면 살아 있는 줄이 원천이라는 것을 안다. 감사 회차가 안내 줄의 이름 열거를 보면 규칙 5 의 목록이 아니라는 것을 같은 줄에서 읽는다.

## 성공 기준

1. **결정이 기록된다** — 착공 PR 이 ADR 0078 을 더하고, 그 ADR 이 1 ~ 3 을 이 착공 세션의 저자가 정한 것으로 든다.
2. **목록의 경계가 매 세션 읽힌다** — PR A 뒤 `CLAUDE.md` 「같은 목록은 한 자리에 둔다」 줄이 (가) 목록은 규칙 · 설정이 읽거나 무엇이 드는지 정하는 열거이고, (나) 안내 · 설명 속 이름 열거와
   기록(설계 · ADR)은 밖이며, (다) 기록이 살아 있는 줄과 갈리면 살아 있는 줄이 원천이라고 말하고 ADR 0078 을 가리킨다. `CLAUDE.md` 의 절 제목 다섯은 그대로다.
3. **넘긴 일이 남는다** — PR A 뒤 `docs/procedure.md` 「감사 회차」가 설계 ② 의 「보장하지 않는 것」을 감사 회차로 넘길 때 그 조각의 닫기 전 회차면 감사 회차 줄의 「왜」에 범위를 적고,
   다음 조각의 회차면 조각 나눔에 줄을 둔다고 말한다. 감사자를 고르는 원천은 셋 그대로다(`python3 scripts/verify-counts.py` PASS — 닻 「원천 {N}에서 고르고」).
4. **장치가 늘지 않는다** — `git diff --stat 30822f5 <각 머지> -- scripts .github vibe-audit vibe-slice compare` 가 빈 출력이다. 수트 지문(`scripts/eval-key.py route` · `full`)이 `30822f5` 과
   같다.
5. **게이트** — `./scripts/gates.sh` 가 이 조각의 PR 마다 작업트리와 CI gate 잡에서 통과한다.
6. **감사 회차** — 닫기 전 감사 회차를 돌려 `docs/audit/` 의 대장에 등록했다.

## 하지 않을 일

1. **안내 · 설명 속 이름 열거를 고치지 않는다** — `scripts/sync-agents.sh:633` · `README.md:11` · 감사자의 「보지 않는 것」 절은 그대로다(ADR 0078 의 1).
2. **지난 기록을 고치지 않는다** — 조각 54 · 55 · 57 · 58 의 설계 · 요구사항은 그대로다. 규칙은 소급하지 않는다 — 조각 54 · 55 가 넘긴 일에 조각 나눔 줄을 새로 두지 않는다.
3. **검사를 세우지 않는다** — 같은 목록을 찾는 검사 · 넘긴 일을 무는 검사가 없다. 새 실패 조건이 없다(`CLAUDE.md` 「새 장치는 새어 나간 결함에만」).
4. **`vibe-audit` · `vibe-slice` 를 고치지 않는다** — 판 · 수트 지문 · 사본 · 두 스킬의 지도 링크가 그대로다.
5. **저장소 전수로 두 벌을 찾지 않는다** — 정한 경계로 지난 회차가 든 자리(설계 ③)만 가른다.
6. **조각 나눔의 다른 줄을 다루지 않는다** — 「`/audit-brief` 커맨드의 제외 목록」 · 「상시 회차의 문턱」 · 「닫는 PR 의 글을 보는 회차」 · 「리뷰 기준의 원천 경계」 등.

## 제약

- 스택: 마크다운. 스크립트를 고치지 않는다.
- 원본: `main` `30822f5`.
- 비용: **$0** — 측정이 없다. 수트 지문은 `vibe-audit/` 만 읽는다(`scripts/eval-key.py` 머리) — 이 조각은 그 밖이다.
- 기간: 닫기까지 **사흘**(2026-11-12 까지).
- 리뷰: 착공 PR 도 구현 PR 도 스킬 `slice-review` 로 가른다. PR 마다 **3라운드**를 넘기면 소유자가 판정한다.
- 감사 회차: 닫기 전 — `audit-internal`(대장이 이 조각에 기대는 것 — NC-42 가 고침으로 다음 `audit-internal` 회차를 기다린다. 바뀌는 것 — 작업 규칙 · 절차 지도의 규칙 글. `CLAUDE.md` 의 경계와
  지도의 넘긴 일 줄이 ADR 0078 · 설계 ③ 과 같은 말을 하는가). `audit-quality` 는 고르지 않는다 — 검사 · 변조본 · 평가셋이 바뀌지 않고, 새 장치의 꼴을 더하거나 고치지 않아 상시 회차도
  걸리지 않는다.
