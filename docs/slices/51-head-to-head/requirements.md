# 조각 51 — 다른 플러그인과 맞대기 (2026-11-02 착공)

요구사항이다 — **무엇을 · 왜.** 어떻게 · 경계는 같은 폴더의 `design.md`, 대안이 있던 결정은 ADR 0066.

이 조각을 「다음 조각」으로 적은 닫힌 조각은 없다. 조각 50 의 `## 닫으며 (2026-11-02)` 는 다음 조각으로 「감사자가 거듭 청한 절차 물음」을 적었는데, 같은 날 다른 세션이
이 플러그인을 인기 플러그인과 견준 검토를 저자에게 냈고, 저자가 그 검토의 「다음 걸음」을 하자고 해 순서를 바꿨다. 그 줄은 `예정` 그대로 남는다. 저자가 이 착공 세션에서
셋을 정했다 — 대상은 공개 확산, 측정은 11 월 한도를 넘는 것을 알고 바로, 새 장치는 새어 나간 결함에만(마스터플랜의 다른 두 줄). 의존은 `—` 다. 착공은 `main`(`93d4617`)
위에서 연다. 이 착공 세션의 claude-kit 클론은 얕지 않았다(`git rev-parse --is-shallow-repository` → `false`).

## 문제

**이 플러그인이 다른 플러그인보다 무엇을 더 잡는지 잰 적이 없다.** 수트는 감사자 문구끼리 견준다 — 오검 · 트리거 · 회수율이 다 「고친 문구가 옛 문구보다 나쁘지
않은가」다. 감사자가 맨 Claude 나 널리 쓰는 리뷰 플러그인보다 나은지는 어느 숫자도 답하지 않는다.

- **겹치는 공식 플러그인이 있다** — `anthropics/claude-plugins-official`(`a7ba5b9`, 2026-10-30)에 `claude-security`(위협 모델 · 구성요소별 탐색 · 발견을 따로
  검증)와 `pr-review-toolkit`(에이전트 여섯, 그 가운데 `code-reviewer` 가 `CLAUDE.md` 준수를 본다)이 있다. `audit-secrets` · `audit-internal` 과 같은 자리를 노린다.
  `security-guidance`(편집 훅) · `code-review`(GitHub PR 이 있어야 돈다)도 겹치지만 픽스처 하나를 읽는 자리에서는 돌지 않는다(설계 ③ C).
- **회수율은 놓친 결함으로 쟀는데 견줄 쪽이 없다** — 회수율 여섯은 담당 감사자가 놓치고 Codex 리뷰가 찾은 ERP 의 결함이다(조각 39). 기준선 16/18 · 재측정 17/18 이
  나왔지만(`docs/eval-log/2026-11.md`), 플러그인 없이도 17/18 이면 감사자의 몫은 0 이다.
- **투자가 장치 쪽에 몰렸다** — 감사자 · 스킬 문구 약 150KB 를 `scripts/` 의 스크립트 34 개 약 1.28 만 줄이 지킨다(2026-11-02 세었다). 이 투자가 값을 하는지는
  감사자가 남보다 나을 때만 답이 있다.
- **잃는 것** — 앞서지 않는 축에 감사자 문구 · eval · 사본 동기화를 계속 들이고, 「공개 확산」의 README 가 잰 적 없는 주장을 하게 된다.

## 핵심 사용자와 시나리오

- 사용자: 저자 한 명, 그리고 「차별점으로 좁히기」 · 「공개 확산」을 착공하는 세션.
- 시나리오: 세션이 `./scripts/run-compare.sh` 를 팔마다 한 번 돌린다 → 같은 재료 열 · 같은 수트 모델 · 같은 심판으로 세 팔의 회차가 돈다 → 러너가 케이스 × 팔마다
  맞힌 회차와 비용을 찍는다 → 세션이 `docs/eval-log/2026-11.md` 에 표를 적고 ADR 0066 의 판정 규칙으로 축마다 앞선다 · 같다 · 뒤진다를 가른다 → 저자가 그 표로
  「차별점으로 좁히기」에서 무엇을 좁히고 무엇을 주장할지 정한다.

## 성공 기준

1. **재료 열이 선다** — `compare/` 에 케이스 열이 설계 ③ A 의 닫힌 목록 그대로 있고, 하나마다 출처 케이스(`vibe-audit/recall/` · `vibe-audit/evals/`)의 픽스처를
   글자 그대로 쓰며, 프롬프트는 축마다 하나이고 도구 이름을 부르지 않는다(ADR 0066 의 2).
2. **채점이 팔을 가리지 않는다** — 케이스마다 심판 그레이더 하나가 기대 결과만 보고 판정하고, 감사자의 기록 꼴(`### NC-`)을 요구하지 않는다(ADR 0066 의 3). 설계 ⑤ 의
   손 대조에서 심판과 사람의 판정이 갈린 회차를 표에 적는다.
3. **러너가 잰다** — `./scripts/run-compare.sh <팔>` 이 설계 ② 의 깃발(수트 모델 · 심판 · 픽스처 · 비용 천장)을 박아 돌고, 끝에 케이스마다 맞힌 회차 · 팔이 떴는지 ·
   비용을 찍는다. 경쟁 팔은 `a7ba5b9` 가 아닌 클론을 받지 않는다.
4. **세 팔을 다 돌린다** — 설계 ③ B 의 팔 × 케이스마다 `--runs 3`. 회차가 모자란 칸은 표에 그 수와 까닭을 적는다.
5. **판정이 남는다** — `docs/eval-log/2026-11.md` 에 케이스 × 팔 표 · 축마다 앞선다 · 같다 · 뒤진다(ADR 0066 의 4 의 규칙 그대로) · 팔마다 회차당 비용 · 수트 모델 ·
   CLI 판 · 경쟁 플러그인의 커밋이 선다.
6. **수트와 갈린다** — `scripts/run-evals.sh` · `vibe-audit/` 를 고치지 않는다. 이 조각의 PR 에서 `eval-key.py` 의 두 모드 지문이 `main` 과 같다.
7. **게이트** — `./scripts/gates.sh` 가 이 조각의 PR 마다 CI gate 잡에서 통과한다. 검사 · 시험 스크립트는 글자 그대로다.
8. **감사 회차** — 닫기 전 `audit-quality` 를 돌려 `docs/audit/` 의 대장에 등록했다.

## 하지 않을 일

1. **감사자 문구를 고치지 않는다** — 뒤진 축이 나와도 이 조각은 재기만 한다. 좁히거나 넘기는 일은 「차별점으로 좁히기」다.
2. **새 검사 · 변조본 · 게이트를 세우지 않는다** — `compare/` 는 `verify-evals.py` · `verify-graders.py` · `gates.sh` 가 보지 않는 한 번의 측정 재료다. 러너는 검사가
   아니다(마스터플랜 「새 장치는 새어 나간 결함에만」).
3. **경쟁 플러그인을 저장소에 싣지 않는다** — 고정한 커밋의 클론을 러너에 경로로 넘기고, 러너가 임시 폴더에 엮는다. 그 문구를 옮겨 적지 않는다.
4. **편집 · PR 에 붙어 도는 것과 견주지 않는다** — `security-guidance`(편집 훅) · `code-review`(GitHub PR) · 내장 `/security-review`(브랜치의 바뀐 것)는 픽스처를
   통째로 읽는 자리와 맞지 않는다(설계 ③ C).
5. **수트 모델을 팔마다 바꾸지 않는다** — 세 팔 다 세션 모델은 `run-evals.sh` 의 수트 모델이다. `claude-security` 가 권하는 Opus 로 다시 재는 일은 이 조각 밖이다.
   플러그인이 에이전트에 박은 모델(`pr-review-toolkit` 의 `code-reviewer` · `code-simplifier` 가 `model: opus`, `claude-security` 의 보조 넷이 `model: sonnet`)은 고치지 않고, 트레이스에서 실제로 돈 모델을 읽어 표에 적는다(설계 ②).
6. **정밀도를 따로 재지 않는다** — 오검은 함정 케이스 하나(`trap-local-dev-password`)가 드는 만큼만 본다.
7. **README · 의도를 고치지 않는다** — 결과로 주장을 세우는 일은 「차별점으로 좁히기」 · 「공개 확산」이다.

## 제약

- 스택: bash · python3 표준 라이브러리 · `claude plugin eval`(새 러너 하나로만 부른다 — `CLAUDE.md` 「금지」의 줄을 B 가 함께 고친다, ADR 0066 의 5).
- 원본: `main` `93d4617`. 경쟁 쪽: `anthropics/claude-plugins-official` `a7ba5b93db0c7c8d17f3f1d25853adca79598a1a`(읽기 전용 클론).
- 측정: 세 팔 × 설계 ③ B 의 칸 × `--runs 3`. 자격은 세션의 `EVAL_OAUTH_TOKEN` — 저장소에 쓰지 않는다.
- 비용: 조각 전체 **$45** 천장 — 러너가 팔마다 `--max-cost-usd` 를 건다. 회수율 회차당 약 $0.22(조각 48 의 U-34 측정)에서 어림하면 `vibe-audit` · 없음 두 팔 60 회 약
  $13, `pr-review-toolkit` 24 회 약 $6 ~ 10, `claude-security` 6 회는 여럿이 도는 스캔이라 회차당 $1 ~ 3 으로 본다 — 합 $30 안팎. 넘을 것 같으면 멈추고 저자에게
  올린다. 11 월 한도는 이미 넘었고 저자가 알고 정했다(2026-11-02). 수트 지문을 바꾸지 않아 route 수트가 돌지 않는다.
- 기간: 닫기까지 **사흘**(2026-11-05 까지).
- 리뷰: PR 본문에 설계 ② 를 적고, 착공 PR 도 구현 PR 도 스킬 `slice-review` 로 가른다. PR 마다 **3라운드**를 넘기면 소유자가 판정한다.
- 감사 회차: 닫기 전 — `audit-quality`(바뀌는 것이 평가 재료 · 러너다 — 평가셋이 판정 기준 역할을 하는지 보는 감사자다. 대장에 이 조각에 기댄 줄은 없다).
