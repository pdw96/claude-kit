# 조각 49 — `gap-unowned` 표식 아래의 번호 목록 · 표 (2026-11-02 착공)

요구사항이다 — **무엇을 · 왜.** 어떻게 · 경계는 같은 폴더의 `design.md`, 대안이 있던 결정은 ADR 0064.

이 조각을 「다음 조각」으로 적은 것은 조각 48 의 `## 닫으며 (2026-11-01)` 이다 — 그 기록의 「넘긴 것」(성공 기준 5 — ADR 0063 이 B 에서 세운 줄)과 「다음 조각」을 읽고
착공한다(ADR 0012). 그 조각은 이 줄을 「이 조각의 전수를 떨어뜨린 거짓 실패라 고치기 전까지 다음 전수도 같은 까닭으로 떨어질 수 있다」로 골랐다. 의존은 `—` 다. 착공 세션이
갈래 셋(표 꼴의 원문 · 번호 항목의 경계 · 전수)을 물어 저자가 셋 다 세션이 추천한 쪽을 골랐다(ADR 0064 의 1 ~ 3). 착공은 `main`(`fcd3e1c`) 위에서 연다. 이 착공 세션의
claude-kit 클론은 얕지 않았다(`git rev-parse --is-shallow-repository` → `false`).

## 문제

**`gap-unowned` 의 두 정규식 그레이더가 바른 기록을 꼴만 보고 떨어뜨린다. 그 거짓 실패가 조각 48 의 전수를 문턱 아래로 보냈다.**

- **번호 목록** — 전수 [run 41265204732](https://github.com/pdw96/claude-kit/actions/runs/41265204732) 1 회차가 성능(`app/report.py`)과 공급망(`Dockerfile` ·
  `requirements.txt`)을 `### 담당 없음 — 호출자 판단 필요` 바로 아래 `1.` · `2.` 로 올렸다. `gate-escalated` · `gate-escalated-perf` 가 둘 다 떨어졌고, `gap-unowned` 은 **0.795**
  로 문턱 0.8 아래였다. 그 run 의 verdict 가 실패다. 착공 세션이 그 회차의 원문(아티팩트 13067302713 의 `gap-unowned.with.run1.jsonl`)을 지금 두 그레이더에 대 다시 확인했다 — 둘 다
  떨어진다.
- **덧붙임 붙은 표식 줄 아래의 표** — 그 뒤 로컬 6 회차(0.936)의 4 회차가 같은 둘을 「담당 없음 — 호출자 판단 필요 (NC 번호 없음)」 줄 · 빈 줄 · 표로 올렸고, 같은 둘이 떨어졌다.
  원문은 남지 않았다(ADR 0064 「맥락」).
- **같은 케이스가 같은 까닭으로 세 번 고쳐졌다** — 조각 20(표식 줄 바로 아래 첫 항목) · 조각 21(표의 행 · 공급망의 첫 항목)이 원문에 나온 꼴만 넓혔다(`vibe-audit/evals/README.md`
  「고치는 것」). 그 원칙은 그대로이고, 이번에 나온 꼴이 둘 더다.
- **받는 순간 넓어지는 구멍** — 두 그레이더의 첫 갈래는 번호 항목을 항목의 머리로 받으면서 경계로는 보지 않는다. 그래서 한 번호 항목에 붙은 표식이 이웃 번호 항목의 발견까지 덮는다 —
  성능이 표식 밖에 있는 `1. report.py …` · `2. Dockerfile … 담당 없음 — 호출자 판단 필요` 가 지금 `gate-escalated-perf` 를 지난다. 한계 표가 이미 이것을 든다.

## 핵심 사용자와 시나리오

- 사용자: 전수의 verdict 를 보고 머지를 정하는 저자.
- 시나리오: 감사자 문구를 고친 조각이 전수를 돌린다 → `audit-secrets` 가 성능 · 공급망을 「담당 없음 — 호출자 판단 필요」 아래 번호 목록이나 덧붙임 붙은 표식 줄 아래 표로 올린다 →
  두 그레이더가 그 기록을 지나게 한다 → `gap-unowned` 이 그 꼴 때문에 문턱 아래로 가지 않는다 → 저자가 verdict 만 보고 머지를 정한다. 반대로 표식이 이웃 번호 항목에만 붙고 발견은
  표식 밖이면 그레이더가 떨어뜨린다.

## 성공 기준

1. **원문이 지난다** — 전수 run 41265204732 1 회차의 최종 응답이 착공 머리(`fcd3e1c`)의 두 그레이더에서 떨어지고, B 의 두 그레이더에서 지난다. 그 원문에서 감사자가 돌려준 기록이
   바른 기록 한 벌(`samples/pass-*.md`)로 박히고, `verify-graders.py` 가 그 벌에서 정규식 그레이더 전부를 지나게 본다.
2. **표 꼴이 지난다** — eval-log 의 설명(덧붙임 「(NC 번호 없음)」 · 빈 줄 · 성능과 공급망의 표의 행)대로 지은 바른 기록 한 벌이 B 의 두 그레이더를 지나고, 착공 머리의 두 그레이더에서
   떨어진다.
3. **이웃 번호 항목이 막힌다** — 표식이 이웃 번호 항목에만 붙은 함정 표본이 그레이더마다 한 벌(성능 · 공급망) 서고, B 의 그 그레이더가 떨어뜨린다. 착공 머리의 그레이더는 지나간다.
4. **넓히고 좁힌 자리마다 문다** — 설계 ③ 의 자리 셋(번호 항목 · 덧붙임 · 번호 경계)을 하나씩 되돌리면 `verify-graders.py` 가 그 자리의 표본에서 떨어진다 — 두 그레이더에서 다 본다.
   덧붙임의 담당 주장을 막는 자리도 같다(설계 ② G).
5. **지난 판정이 그대로다** — 지난 표본 열일곱이 지난 그대로다 — `pass*.md` 넷은 지나고, `fail*.md` 열셋은 첫 줄이 지목한 그레이더가 문다. `verify-graders.py` 의 다른 케이스 판정이
   그대로다.
6. **바뀐 자리가 좁다** — B 의 `git diff --stat` 의 `vibe-audit/` 가 두 그레이더 · `gap-unowned/samples/` · `vibe-audit/evals/README.md` 뿐이다. 감사자 · 케이스 입력 · 다른 그레이더 ·
   검사 스크립트 · 러너는 글자 그대로다.
7. **한계 표가 맞다** — `vibe-audit/evals/README.md` 「고정한 것」 정규식 그레이더 한계 표의 「목록 경계는 `-` · `*` 만 안다」 줄이 `gate-escalated(-perf)` 를 들지 않는다.
8. **게이트가 그대로다** — `./scripts/gates.sh` 가 각 PR 에서 로컬과 CI gate 잡에서 통과하고, 「PASS test-gates.py — … 고정 목록 30 그대로」다. 모델을 부르는 측정이 없다 — 비용 0.
9. **감사 회차** — 닫기 전 `audit-quality` 를 돌려 대장에 등록했다.

## 하지 않을 일

1. **감사자 문구 · 케이스 입력을 바꾸지 않는다** — `vibe-audit/agents/` · `fixture.sh` · `prompt.md` · `case.yaml` 은 그대로다. 판도 그대로다.
2. **다른 그레이더 · 케이스의 떨어짐을 다루지 않는다** — 같은 run 2 회차의 `gate-no-fake-owner`(심판) · `handoff-named` 의 같은 번호 목록 한계 · `brief-absent` · `gate-own-not-pushed` ·
   `trap-liveness-probe` 는 그대로다.
3. **설계 ③ 의 닫힌 목록 밖으로 넓히지 않는다** — 표식이 목록 항목인 꼴(넷째 갈래) 아래의 번호 자식 · 굵은 글씨 안의 덧붙임 · 괄호가 아닌 덧붙임 같은, 실제 기록에 나오지 않은 꼴은
   받지 않는다.
4. **전수 · 로컬 측정을 돌리지 않는다**(ADR 0064 의 3). 다음 전수가 이 케이스를 다시 떨어뜨리면 그 조각이 트레이스로 본다.
5. **검사를 새로 세우지 않는다** — `verify-graders.py` · `gates.sh` · `bite-gates.sh` · `test-gates.py` 는 그대로다. 표본은 기존 검사가 본다.
6. **트레이스 · 아티팩트를 저장소에 싣지 않는다** — 표본에는 감사자가 돌려준 기록만 옮긴다.
7. **조각 나눔의 다른 줄을 다루지 않는다** — 「가르지 못한 결함 다섯」 · 「배포 경로 다시 재기」 · 「감사자가 거듭 청한 절차 물음」 · 「걷은 사본의 대장 줄」 · 「프로필의 언어 칸」 등.

- 원본: `main` `fcd3e1c`. `gap-unowned` 은 `3633675`(조각 21) 뒤 움직이지 않았다.
- 원문: 전수 1 회차의 트레이스는 아티팩트 13067302713(2027-01-30 까지)에 있다. 착공 세션이 받아 봤다 — B 의 세션도 같은 길로 받는다. 받지 못하면 B 를 멈추고 저자에게 올린다.
- 앵커볼트: 건드리지 않는다 — 이름 · `tools` · 공통 절 · 대장의 모양 · 문서 모양 · 고정 영역 그대로다.
- 비용: 0 — 모델을 부르지 않는다. 그레이더 파일은 route 지문 밖이라 PR 에서 route 수트가 새로 돌지 않는다(ADR 0064 의 3).
- 기간: 닫기까지 **2026-11-06**.
- 리뷰: PR 본문에 설계 ② 를 적고, 착공 PR 도 구현 PR 도 스킬 `slice-review` 로 가른다. PR 마다 **3라운드**를 넘기면 소유자가 판정한다.
- 감사 회차: 닫기 전 — `audit-quality`(평가셋의 그레이더 · 표본이 바뀐다 — 검사 장치가 무엇을 막는지가 바뀌는 자리. 대장에 이 조각에 기대는 줄은 없다).
