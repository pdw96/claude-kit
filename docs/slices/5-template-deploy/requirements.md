# 조각 5 — 틀 배포 (2026-10-07 착공)

요구사항이다 — **무엇을 · 왜.** 어떻게 · 경계는 같은 폴더의 `design.md`, 대안이 있던 결정은 ADR 0013.

## 문제

틀 넷(의도 · 마스터플랜 · 요구사항 · 설계)은 claude-kit 의 `docs/templates/` 에만 있다 — 조각 2 가 「틀은 claude-kit 에만
둔다」로 남겼다(조각 2 요구사항 「제약」 · 하지 않을 일 1). 다른 레포가 틀을 받을 길이 없다.

- **강호쟁패에는 조각 나눔도 설계 문서도 없다.** ① 마켓플레이스와 계정 스킬 `project-kickoff` 로 섰다 — 저장소에
  `.claude/` 가 없고, 감사자는 「사용자 전역 플러그인 vibe-audit의 에이전트. 저장소에는 없다」(강호쟁패 `CLAUDE.md`).
  의도와 범위는 `PRD.md`(54줄) 하나가 든다. 조각 나눔 「리뷰 루프」는 그 레포 설계 ② · ③ 에 비춰 지적을 가르는데, 비춰
  볼 설계가 없다 — 그래서 틀 배포가 리뷰 루프보다 먼저다(조각 2 요구사항 「로드맵의 근거」).
- **ERP 는 클라우드 세션으로 일한다.** 클라우드 레인은 마켓플레이스 설치를 받지 못하고 레포 안의 사본만 뜬다
  (README 「설치」의 이슈 셋). ERP 에는 감사자 사본이 이미 있어(`copies.json`), `sync-agents.sh` 에 무엇을 더하면 「사본이
  일부만 있다」로 멈춘다.
- **`audit-internal` 은 기준 문서로 `PRD.md` 를 찾는다**(체크 항목 뼈대 1 · 6 · 7). 틀대로 선 레포에서 범위와 성공 기준은
  의도 문서의 Not 과 조각 폴더 요구사항의 「하지 않을 일」 · 「성공 기준」에 있는데, 감사자는 그 자리를 이름으로 모른다.
  ADR 0008 이 이 일을 조각 나눔 「틀 배포」에 넘겼다.

## 핵심 사용자와 시나리오

- 사용자: 저자 한 명, 그리고 다른 레포에서 조각을 여는 Claude Code 세션.
- 시나리오: 저자가 claude-kit 에서 틀을 고쳐 머지한다 → 강호쟁패의 대화형 세션은 `vibe-slice` 플러그인을 처음 한 번
  install 한 뒤로는 갱신(`claude plugin update vibe-slice@pdw96-kit`, 또는 그 마켓플레이스의 자동 갱신)과
  리로드로 새 틀을 받는다 — 틀을 고친 PR 이 플러그인의 판을 올렸을 때 → 세션이 `slice-docs` 스킬로 조각의 요구사항과 설계를 틀대로
  쓰고, 단계의 들어가고 나가는 조건은 claude-kit 의 절차 지도에서 읽는다 → ERP 는 저자가 `sync-slice.sh` 를 한 번
  돌려 스킬 사본을 레포에 심고, 클라우드 세션이 같은 스킬로 같은 일을 한다 → 조각을 머지한 뒤 `audit-internal` 은
  의도 문서 · 마스터플랜 · 조각 요구사항을 기준 문서로 읽고 「하지 않을 일」을 어긴 코드를 짚는다.

## 성공 기준

1. 마켓플레이스 `pdw96-kit` 에 플러그인이 둘이고, `claude plugin validate ./vibe-slice` 와 `verify-manifest.py` 가
   `vibe-slice` 를 본다 — 두 매니페스트의 `vibe-slice` 설명을 한쪽만 바꾸거나, 마켓플레이스에서 한 줄을 빼거나 겹치면
   `verify-manifest.py` 가 떨어진다.
2. 틀의 원천이 한 군데다 — `docs/templates/` 가 없고, `vibe-slice/skills/slice-docs/templates/` 의 넷을 문서 대조 검사가
   T1 · T2 로 문다(그 자리의 틀 하나를 지우거나 제목 한 글자를 바꾸면 `test-verify-docs.py` 의 변조본이 떨어진다).
3. `sync-slice.sh` 를 임시 git 레포에 돌리면 `.claude/skills/slice-docs/` 에 `SKILL.md` 와 틀 넷이 서고 `SKILL.md`
   프론트매터 뒤에 출처 커밋이 박힌다. 다시 돌리면 덮지 않고 멈추고, `--force` 면 덮는다. 원본에 커밋 안 된 변경이나
   HEAD 에 없는 파일(무시된 파일도)이 있으면 아무것도 심지 않는다.
4. 강호쟁패(대화형 · 플러그인)와 ERP(클라우드 · 사본)의 세션에서 `slice-docs` 스킬이 뜨고, 부르면 스킬 폴더의 틀을
   그대로 읽는다 — 부르는 레포의 작업 디렉터리가 아니라. 그리고 강호쟁패가 `vibe-audit` 를 갱신하면 새 뼈대의
   `audit-internal` 을 쓴다(`vibe-audit` 의 판이 오른다). 저자가 단계 5(배포)에서 본다.
5. `audit-internal` 의 뼈대 1 · 6 · 7 이 의도 문서 · 마스터플랜 · 조각 요구사항을 이름으로 들고, 조각 요구사항의
   「하지 않을 일」은 **감사 대상 변경이 속한 조각**의 것만 기준으로 쓴다. 새 판정 케이스 하나가 수트에서 통과한다 —
   진행 조각의 「하지 않을 일」을 어긴 코드는 부적합으로 내고(진짜 부적합), 닫힌 조각이 하지 않기로 한 것을 뒤 조각이
   한 코드는 부적합으로 내지 않는다(덫).
6. `audit-internal` 의 호출 시 문자가 천장 11,000 을 넘지 않는다 — 천장은 올리지 않는다(ADR 0004).
7. route 수트는 `audit-internal` 을 고친 구현 PR 에서만 돈다 — 플러그인 · 사본 길의 구현 PR 머리에서 CI eval 잡이
   「같은 지문」으로 건너뛴다.
8. `./scripts/gates.sh` 가 구현 PR 마다 통과한다.

## 하지 않을 일

1. **절차 지도를 다른 레포에 보내지 않는다** — 스킬과 틀은 claude-kit 의 `docs/procedure.md` 를 가리키기만 한다. 지도를
   일반형과 claude-kit 몫으로 나누지도 않는다(ADR 0013 의 2).
2. **대장에 적지 않는다** — `copies.json` · `feedback.json` 의 모양은 그대로다. 스킬 사본은 비교 · 되먹임의 대상이 아니다
   (ADR 0013 의 5).
3. **다른 레포에서 문서 대조 검사를 돌리지 않는다** — 그 검사는 claude-kit 의 `docs/procedure.md` 를 원천으로 읽는다.
   조각 나눔 「다른 레포의 문서 대조 검사」로 넘긴다.
4. **`vibe-audit` 에 싣지 않는다** — 수트 지문 · 상시 예산 · 감사자 사본과 떼어 둔다(ADR 0013 의 3).
5. **`audit-internal` 의 프론트매터 설명과 공통 절을 고치지 않는다** — 설명은 라우팅에 닿고, 공통 절은 앵커볼트다.
6. **계정 스킬 `project-kickoff` 를 고치지 않는다** — `PRD.md` 를 쓰는 자리는 그대로 두고 「계정 스킬의 일」에 적는다.
7. **강호쟁패 · ERP 저장소를 이 조각의 PR 에서 고치지 않는다** — 플러그인 install 과 사본 심기는 저자가 단계 5 에서
   한다. 강호쟁패의 `PRD.md` 를 `INTENT.md` 로 옮기지도 않는다.
8. **「…의 칸」 네 절과 틀의 `##` 제목을 바꾸지 않는다** — 틀은 자리만 옮긴다.

## 제약

- 스택: bash · python3 표준 라이브러리, 마크다운. Claude Code 플러그인 · 스킬의 모양은 `claude plugin validate` 가 받는 것.
- 모델 비용: route 수트가 `audit-internal` 을 고친 PR 에서 돌고, 새 판정 케이스를 재려고 전수를 한 번 돌린다 — 월 한도
  $20 안(`CHECKLIST.md`). 그 밖의 PR 은 수트 지문에 드는 파일(`eval-key.py route --list` · `full --list`)을 건드리지
  않는다 — `eval.yml` 도.
- 글자 예산: `audit-internal` 의 호출 시는 10,962 자로 천장 11,000 까지 38 자다. 문구를 넓히려면 같은 PR 에서 압축이
  먼저다(ADR 0004). 천장은 올리지 않는다.
- 기간 **이틀**.
- `./scripts/gates.sh` 는 지금 열둘이 그대로 통과해야 하고, 더하는 게이트도 통과해야 한다.
- 리뷰: PR 본문에 설계 ② 를 적고, 그 밖의 지적은 고치지 않고 답글로 넘긴다. **3라운드**를 넘기면 소유자가 판정한다.
