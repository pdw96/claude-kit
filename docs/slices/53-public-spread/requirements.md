# 조각 53 — 공개 확산 (2026-11-03 착공)

요구사항이다 — **무엇을 · 왜.** 어떻게 · 경계는 같은 폴더의 `design.md`, 대안이 있던 결정은 ADR.

이 조각을 「다음 조각」으로 적은 닫힌 조각은 조각 52(차별점으로 좁히기)다 — 그 `## 닫으며 (2026-11-03)` 를 읽었다. 넘겨받은 것은 루트 `README.md` 「무엇이 다른가 — 다른 플러그인과
맞대기」 절과 「착공에서 의도의 「범위 변경」이 먼저다」다. 저자가 이 착공 세션에서 넷을 정했다 — 밖 사용자는 받아 쓰게만 한다, 영어는 README 만, 자리는 `README.en.md` 새로,
`vibe-audit` 를 앞세운다(ADR 0072 의 1 ~ 4). 착공은 `main`(`737448c`) 위에서 연다. 이 착공 세션의 클론은 얕지 않았다(`git rev-parse --is-shallow-repository` → `false`).

## 문제

**길은 열려 있는데 입구가 없다.** `pdw96/claude-kit` 는 public · MIT 이고, 빈 HOME 에서 `README.md` ① 의 명령 셋이 그대로 돌아 `vibe-audit` 0.4.8 · `vibe-slice` 0.9.3 이 깔렸다
(2026-11-03, CLI 2.1.317). 그런데 밖 사람이 그 길에 닿기 전에 읽는 글이 다 한국어이고 저자 레포에 맞춰져 있다.

- **입구가 한국어 하나다** — 루트 `README.md` · 매니페스트 설명 · 감사자 설명이 한국어다. 저장소의 About 설명과 topics 는 비어 있다(별 1).
- **설치 설명이 저자 레포의 사정부터 든다** — 「설치 — 경로가 셋인 이유」는 고쳐지지 않은 버그 셋과 사본 레포(③)의 심기 스크립트를 마켓플레이스 명령과 같은 무게로 든다. 밖
  사람에게 필요한 것은 ① 의 명령 셋이다.
- **잰 것이 영어로 없다** — 조각 51 · 52 가 잰 차별점(함정 두 케이스에서 `vibe-audit` 3/3 · 2/3, 플러그인 없음 0/3 · 0/3)과 그 한계는 한국어 README 에만 있다.
- **옮길 때 원문보다 강하게 읽힐 자리가 둘 있다** — 감사 회차 27 OB-1 · 29 OB-29: 「로컬 개발에만 쓰는 값을 고칠 결함으로 올리지 않는다」는 그 케이스에서 `vibe-audit` 가 값을
  **확인불가로 냈다**는 뜻이다. 회차 29 OB-28: 그 케이스의 `pr-review-toolkit` 1/3 칸은 리뷰 에이전트를 띄우지 않은 회차($0.145)인데 README 의 원값 줄은 조각 51 의 $0.48 만 든다.
- **도구는 한국어로 말한다** — 감사자 · 스킬 · 감사 출력이 한국어이고, 영어 요청에서 감사자가 뜨는지는 잰 적이 없다(route 수트 · 맞대기의 요청 본문이 다 한국어).
- **잃는 것** — 밖 사람이 무엇을 받는지 모른 채 지나가거나, 받은 뒤 한국어 출력 · 잰 적 없는 트리거를 보고 README 가 약속한 것과 다르다고 읽는다.

## 핵심 사용자와 시나리오

- 사용자: Claude Code 를 쓰는 밖 개발자 한 명 — 영어로 읽고, 이 저장소의 저자 레포와 무관하다.
- 시나리오: 저장소 첫 화면 맨 위의 English 줄을 누른다 → `README.en.md` 에서 감사자 여섯이 무엇이고 고칠 도구가 없다는 것을 읽는다 → 「무엇이 다른가」에서 함정 두 케이스의 숫자와
  한계 — 표본 크기 · 재료 · 수트 모델 · 경쟁 커밋, 도구가 한국어로 말한다는 것 — 를 읽는다 → 설치 블록 셋을 붙여 넣어 두 플러그인을 깐다 → 자기 레포에서 감사자 하나를 이름으로
  불러 한국어 감사 기록을 받는다.

## 성공 기준

1. **범위 변경이 먼저 선다** — 착공 PR 이 `INTENT.md` 의 Why 에 밖 사용자의 문단을, What 에 「밖 사용자의 입구 — 영어 README 하나」를, Not 에 5 「밖 사용자의 보고를 되먹임으로 들이지
   않는다」를 더하고, 마스터플랜 「범위 변경」에 2026-11-03 줄이 있다.
2. **영어 입구가 선다** — `README.en.md` 가 있고, `README.md` 첫 문단 위의 한 줄이 그리로 간다. `README.en.md` 는 설계 ③ A 의 절을 다 든다.
3. **설치가 선다** — 빈 HOME 에서 `README.en.md` 의 설치 블록을 글자 그대로 돌려 두 플러그인이 그때 `plugin.json` 의 판으로 `enabled` 인 것을 PR B 본문에 보인다.
4. **주장이 원문과 같다** — `README.en.md` 「무엇이 다른가」의 숫자마다 `README.md` 의 같은 숫자와 `docs/eval-log/2026-11.md` 의 칸을 대는 표가 PR B 본문에 있다. 그 절은 `claude-security`
   를 상대로 앞선다고 말하지 않는다. 두 README 의 「한계」가 사실 둘 — `trap-local-dev-password` 에서 `vibe-audit` 는 그 값을 확인불가로 냈다, 그 케이스의 `pr-review-toolkit` 세 회차는
   리뷰 에이전트를 띄우지 않았고 회차당 원값 $0.145 다 — 을 든다(ADR 0072 의 6).
5. **언어의 한계가 앞에 있다** — `README.en.md` 가 설치 블록보다 앞에서 「감사자 · 스킬 · 출력은 한국어다, 영어 요청에서 감사자가 뜨는지는 재지 않았다」를 든다.
6. **수가 물린다** — `README.en.md` 가 원천이 있는 수(감사자 수 따위)를 아라비아 숫자로 쓰고, 그 수마다 `scripts/verify-counts.py` 의 닻이 있다. 그 수를 바꾼 사본에서 검사가 D1 로
   떨어지는 것을 PR B 본문에 보인다.
7. **두 벌이 살아 있는 문서다** — `docs/procedure.md` 「살아 있는 문서와 기록」이 `README.en.md` 를 들고, `CHECKLIST.md` 가 「`README.md` 를 고치면 `README.en.md` 를 함께」를 든다.
8. **도구 · 수트는 그대로다** — `git diff --stat 737448c <각 머지> -- vibe-audit vibe-slice .claude-plugin scripts/run-evals.sh` 가 비고, 이 조각의 PR 마다 `eval-key.py route` · `full`
   이 `main` 과 같다.
9. **게이트** — `./scripts/gates.sh` 가 이 조각의 PR 마다 작업트리와 CI gate 잡에서 통과한다.
10. **감사 회차** — 닫기 전 감사 회차를 돌려 `docs/audit/` 의 대장에 등록했다.

## 하지 않을 일

1. **도구를 영어로 옮기지 않는다** — 감사자 여섯의 설명(트리거) · 본문 · 공통 절, `vibe-slice` 의 스킬 · 틀 · 절차 지도, 검사의 출력이 한국어 그대로다(ADR 0072 의 2).
2. **매니페스트를 고치지 않는다** — `marketplace.json` · `plugin.json` 의 설명 · 판이 그대로다. 수트 지문 · 글자 예산 · 사본이 그대로다.
3. **밖 보고를 받는 장치를 세우지 않는다** — 이슈 틀 · 후보 대장의 출처 칸 따위(`INTENT.md` Not 5).
4. **새로 재지 않는다** — 영어 요청의 트리거 · 영어 저장소에서의 판정 · 맞대기 재측정. 이 조각의 측정 비용은 0 이다.
5. **README 의 주장을 바꾸지 않는다** — 「저장소 규칙의 효력 범위를 가린다」와 그 표는 ADR 0069 의 2 그대로다. 「한계」에 사실 둘을 더할 뿐이다.
6. **저장소 밖에 손대지 않는다** — 저장소 설정(About 설명 · topics), 공식 마켓플레이스 · 디렉터리 제출, 홍보 글은 이 조각의 PR 이 하지 않는다.
7. **새 검사 · 변조본 · 게이트를 세우지 않는다** — 있는 검사(`verify-counts.py`)의 닻 목록에 줄을 더할 뿐이다(마스터플랜 「새 장치는 새어 나간 결함에만」).
