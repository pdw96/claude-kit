# 조각 12 — main 푸시가 통과한 수트 지문을 읽게 (2026-10-12 착공)

요구사항이다 — **무엇을 · 왜.** 어떻게 · 경계는 같은 폴더의 `design.md`, 대안이 있던 결정은 ADR 0021.

## 문제

**수트 지문을 바꾸는 PR 은 route 수트가 두 번 돈다 — PR 에서 한 번, 머지 뒤 `main` 푸시에서 한 번.** 통과한 지문은 Actions 캐시에
적히는데(`eval.yml` 「통과한 입력을 적는다」), PR 실행이 적은 캐시는 그 PR 의 merge ref(`refs/pull/<N>/merge`) 범위라 그 PR 의 실행만
읽는다. `main` 푸시는 `main` 범위만 읽어, PR 에서 같은 지문이 통과했어도 찾지 못하고 다시 돈다.

- 조각 11 성공 기준 6 이 이것으로 못 미쳤다 — #49 의 첫 머리 c7a0758 이 수트를 돌려 통과했고(run 38218665101), 머지 8734f58 의 `main` 푸시가
  **같은 키로** 한 번 더 돌렸다(run 38221927726). 조각 11 「닫으며」.
- `eval.yml` 의 `main` 푸시 51 가운데 eval 잡이 돈 것이 19 다(성공 15 · 실패 3 · 취소 1, 2026-09-26 ~ 10-12, `main` a341e25). 지금의
  `eval-key.py route` 규칙으로 머지마다 첫 부모와 머지의 파일 쪽 지문을 견주면 바뀐 머지가 13 이고, 13 다 `main` 에서 돌았다. 나머지 여섯은
  파일 쪽이 같은데 돌았다 — CLI 판이 그 사이 올랐거나 그때의 지문 규칙이 지금과 달랐다(가르지 않았다).
- route 수트 한 번은 30회다 — route 케이스 열 × 3회(`vibe-audit/evals/route-*`). 구독 토큰의 사용량에서 나간다.
- 조각 11 은 착공의 셈(제약 「route 수트 한 번」)이 이것을 몰랐다. 키를 바꾸는 조각은 다 같은 셈을 틀린다.

## 핵심 사용자와 시나리오

- 사용자: 저자 한 명, 그리고 claude-kit 에서 수트 입력(감사자 · 케이스 · 러너 · `eval.yml`)을 고치는 세션.
- 시나리오: 세션이 감사자 문구를 고친 PR 을 낸다 → PR 의 첫 머리에서 지문이 새것이라 route 수트가 돌아 통과하고, 그 키가 PR 범위
  캐시에 적힌다 → 저자가 머지한다 → `main` 푸시의 gate 잡이 `main` 범위 캐시에서 못 찾자, 이 푸시 커밋을 머지 커밋으로 가진 PR 하나를
  API 로 찾고 그 PR 의 merge ref 에 같은 키가 있는지 캐시 목록 API 로 본다 → 있어서 eval 잡을 건너뛰고, 「건너뛰는 근거」가 그 PR 번호와
  캐시가 적힌 때를 찍으며, 같은 키를 `main` 범위에도 적는다 → verdict 가 「같은 입력이 이미 통과했다」로 초록이다 → 다음 PR 들은 `main`
  범위에서 그 키를 읽어 건너뛴다.

## 성공 기준

1. 머지된 PR 이 통과한 지문을 `main` 푸시가 알아본다 — 이 조각의 구현 PR 이 `eval.yml` 을 고쳐 그 PR 에서 수트가 한 번 돌고, 그 머지의
   `main` 푸시는 eval 잡을 건너뛴다. 「건너뛰는 근거」에 그 PR 번호가 찍히고, 그 푸시가 `main` 범위에 같은 키를 적는다(Actions → Caches
   에서 `refs/heads/main` 의 그 키).
2. 판정이 문다 — `gates.sh` 가 부르는 자체 시험이 가짜 API 로 꼴마다 판정을 본다. 건너뛰는 꼴은 「머지된 그 PR 하나의 merge ref 에 키가
   글자 그대로 있다」뿐이고, 그 밖의 꼴(다른 PR 의 ref · 키가 앞부분만 같음 · 머지 안 된 PR · 머지 커밋이 다름 · PR 이 없음 · 둘 · API
   오류 · 뜻밖의 응답)은 다 「돈다」다. 어긋내 보기 — 판정의 조건을 한 자리씩 빼면 자체 시험이 떨어진다.
3. 근거를 못 읽으면 돈다 — API 가 실패하거나 응답이 뜻밖이면 eval 잡이 돌고, gate 잡은 떨어지지 않는다(경고 한 줄).
4. 새 파일이 수트 지문 밖이다 — `eval-key.py route --list` · `full --list` 에 판정 스크립트 · 자체 시험 · 변조본이 없다.
5. `main` 푸시의 eval 잡이 이 조각에서 돌지 않는다 — 구현 PR 의 머지 푸시가 성공 기준 1 로 건너뛰고, 착공 PR · 닫는 PR 은 지문을 바꾸지
   않는다. route 수트는 구현 PR 의 첫 머리에서 한 번 돈다.
6. `gates.sh` 가 로컬과 CI gate 잡에서 다 통과한다 — 스물둘에서 새 검사 둘을 더해 스물넷.

## 하지 않을 일

1. **캐시를 버리지 않는다** — 통과한 지문의 저장소는 그대로 Actions 캐시다. 아티팩트 · 커밋 상태 · 별도 워크플로(`workflow_run`)로
   옮기지 않는다(ADR 0021 의 1).
2. **다른 PR 의 캐시를 믿지 않는다** — 근거는 그 푸시를 머지 커밋으로 가진 PR 하나의 merge ref 뿐이다. 어느 ref 에서든 같은 키를 찾지
   않는다(ADR 0021 의 2).
3. **수트 지문의 규칙을 바꾸지 않는다** — `eval-key.py` 의 넣고 빼는 것 · CLI 판을 키에 넣는 것은 그대로다. CLI 판이 PR 과 머지 사이에
   오르면 지금처럼 `main` 에서 돈다.
4. **PR 쪽 동작을 바꾸지 않는다** — PR 실행은 지금처럼 제 범위와 `main` 범위만 읽는다. `workflow_dispatch` 는 지금처럼 찾아보지 않고 늘 돈다.
5. **플러그인 파일을 고치지 않는다** — `vibe-audit/evals/README.md` 의 「Actions → Caches 에서 `eval-route-` 항목을 지우고 재실행」은
   그대로 둔다. `main` 에서 다시 돌리는 길은 `eval.yml` 머리 주석과 `docs/architecture.md` 가 든다. 판을 올리지 않는다.
6. **캐시 항목을 지우지 않는다** — 닫힌 PR 범위의 캐시 정리는 이 조각의 일이 아니다. 판정은 읽기만 한다.

## 제약

- 스택: bash · python3 표준 라이브러리(`urllib` · `json`), GitHub REST API — CI 의 `GITHUB_TOKEN` 하나. 새 액션 · 외부 CLI 를 들이지 않는다.
- 모델 비용: route 수트 **한 번**(30회) — 구현 PR 이 `eval.yml` 을 첫 머리에서만 고친다. 리뷰 고침은 지문 밖 파일(판정 스크립트 · 시험 ·
  문서)에 낸다. 리뷰가 `eval.yml` 로만 고칠 수 있는 지적을 내면 한 번을 더 쓰고 「닫으며」에 적는다(ADR 0020 의 5 와 같은 셈).
- 판정은 `main` 푸시에서만 쓰여, 구현 PR 이 머지되기 전에는 실물에 대어 볼 수 없다 — 머지 전에는 PR 실행에서 같은 API 두 곳을 읽어
  보기만 하고(판정에 쓰지 않는다), 머지 뒤 첫 `main` 푸시가 성공 기준 1 의 실물이다.
- 글자 예산: 건드리지 않는다.
- 기간 **하루**.
- `./scripts/gates.sh` 는 착공 PR 까지 스물둘, 구현 PR 부터 스물넷이다.
- 리뷰: PR 본문에 설계 ② 를 적고, 착공 PR 도 구현 PR 도 스킬 `slice-review` 로 가른다. **3라운드**를 넘기면 소유자가 판정한다.
