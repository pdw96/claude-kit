# 조각 19 — `audit-data` 판정 표의 빈 갈래 둘 (2026-10-14 착공)

요구사항이다 — **무엇을 · 왜.** 어떻게 · 경계는 같은 폴더의 `design.md`, 대안이 있던 결정은 ADR 0029.

이 조각을 「다음 조각」으로 적은 것은 조각 18 의 `## 닫으며 (2026-10-14)` 이다 — 그 기록의 「넘긴 것」 · 「지켜본 것」을 읽고
착공한다(ADR 0012). 「지켜본 것」의 후속 작업 카드가 이 조각이다.

## 문제

**원본 `audit-data` 항목 3 의 판정 표에 빈 갈래가 둘 있다.** 엔진 · 판을 확인한 뒤 쓰는 표가 세 줄이다 — 피할 형태를 안 썼다(부적합) ·
피할 형태가 없다(「잠금 사실과 전제를 적고 심각도 확인불가」) · 잠금 설명이 어긋난다(부적합).

- **FB-30 — 「피할 형태가 없다」 줄에 판정이 없다.** 그 줄은 판정 넷(적합 · 부적합 · 해당 없음 · 확인불가) 가운데 하나를 주지 않고
  심각도만 적는다. 출력 형식의 체크 항목 표는 행마다 넷 중 하나를 적게 하므로 감사자가 그 자리에서 판정을 지어낸다 — 근거 없는 NC 로
  가거나, 심각도의 「확인불가」를 행의 판정으로 옮겨 통과 여부에서 부적합처럼 묶는다. 고칠 것이 없는 자리가 열린 줄로 남는다.
- **FB-31 — 「네 눈 어느 것에도 해당하지 않는다」 갈래가 없다.** 표의 머리는 「표를 다시 쓰는가 · 기존 행 전체를 검증하는가 · 잠금을 잡고
  인덱스를 만드는가 · 잠금이 언제 풀리는가」 네 눈인데, 넷 다 아니면 무엇인지 표가 말하지 않는다. 쓰기를 멈추지 않는 DDL 이 판정 없이
  남거나 「잠금 위험」으로 걸린다.
- **둘 다 ERP 가 찾았다** — 사본을 `018842c` 로 다시 심는 PR(pdw96/ERP#111)의 리뷰 2 · 3 라운드가 같은 절을 짚었고, 그 PR 이 「보장하지 않는
  것」에 「원본으로 넘긴 것 — 원본 `audit-data` 판정 표의 빈 갈래 둘」을 적었다. 대장 `feedback.json` 은 둘을 `defect` · 혼합으로 갈랐다
  (seen 커밋 `1046566`, 기준 `018842c`).
- **ERP 사본은 이미 메웠다** — 그러나 특화가 섞였다. 「리비전 · PR 이 잠금을 맞게 적었으면 적합 · 설명이 없으면 부적합(W-1)」은 ERP 에
  배포처가 없어서 나온 말이고(FB-4 에서 빼기로 한 것), NC-21 의 예는 ERP 의 일이다. 원본에는 일반 몫만 들어가야 한다.
- **예산이 없다.** `audit-data` 는 호출 시 11,000 / 11,000 이다(`vibe-audit/evals/budget.txt`). 갈래를 더하려면 같은 감사자 안에서 줄여야
  한다(ADR 0004).
- **문구 없이도 맞힐 수 있다.** 조각 18 에서 수트 모델은 옛 문구로도 노골적인 자리를 대개 바르게 판정했다. 문구를 넣었다는 것만으로는
  `fed_back` 의 「그것이 지켜진다」를 보이지 못한다.

## 핵심 사용자와 시나리오

- 사용자: claude-kit 의 저자, 그리고 `audit-data` 를 부르는 세션(마켓플레이스로 설치한 레포와, 다음 심기 이후의 두 사본 레포).
- 시나리오: 세션이 FB 하나의 오검 쪽 픽스처를 만든다 — 엔진 · 판은 저장소에 있고, 표에 갈래가 없어서 판정이 갈리는 자리다 → 옛 문구(지금
  원본에 예산을 비운 줄임만 더한 바탕)와 새 문구(바탕에 그 FB 의 갈래를 더한 판)로 같은 픽스처 · 그레이더를 세 번씩 잰다 → 가르면 그 FB 의 갈래가 원본에 들어가고 저자가 그 FB 를
  `fed_back` 으로 정한다. 두 판까지 만들어도 못 가르면 갈래를 넣지 않고 `defect` 그대로 조각 나눔의 후보로 넘긴다(ADR 0029 의 2) → 둘을 다
  지난 뒤 조각을 닫는다.

## 성공 기준

1. **FB 마다 판정이 났다** — FB-30 · 31 각각이 설계 ② 「가른다」에 비춰 **가름**이나 **못 가름**이다. 그 근거(픽스처 판 · 옛 · 새 문구의
   회차별 결과 · 비용)가 `docs/eval-log/2026-10.md` 의 날짜 항목에 있다. 판은 FB 마다 둘을 넘지 않는다.
2. **가른 FB 의 갈래가 원본에 있다** — FB-30 을 가르면 「피할 형태가 없다」 줄의 판정이 **적합**이고 잠금 사실 · 전제와 「영향(행 수 ·
   트래픽 · 시간 창)은 저장소 밖」을 근거에 적게 한다 — 심각도 확인불가 · U 항목은 없다(ADR 0029 의 1). FB-31 을 가르면 표에 「위 네 눈 어느 것에도 해당하지 않는다 → 적합」 줄이 있다. 두 줄 다 ERP 의 「적었으면 적합」 ·
   「설명이 없으면 부적합」 · W-1 · NC-21 · Alembic 열이 없다. 못 가른 FB 의 줄은 글자가 그대로다.
3. **예산 · 앵커가 그대로다** — `audit-data` 호출 시 예산이 천장 11,000 안이고 천장은 그대로다. 공통 절 넷과 프론트매터는 글자가 그대로다
   (`verify-copy.py vibe-audit/agents` 통과). 원본이 바뀌면 판이 0.4.0 → 0.4.1 이다.
4. **가른 FB 는 `fed_back`** — 저자가 정한 뒤 `status` 가 `fed_back` 이고 `feedback` 이 설계 ② L1 의 모양이다. 못 가른 FB 는 `defect`
   그대로이고 줄이 바뀌지 않았다. `verify-feedback.py` 가 통과한다.
5. **들인 케이스는 `main` 에서 통과한다** — 이 조각이 더한 케이스마다 `--runs 3` 점수가 문턱(0.8) 이상이고 `verify-evals.py` ·
   `verify-graders.py` 가 통과한다. 못 가른 픽스처는 들이지 않는다.
6. **감사자 문구가 바뀌면 전수가 초록이다** — 감사자를 고친 PR 의 머리에서 `workflow_dispatch` 전수 verdict 가 초록이다.
7. `./scripts/gates.sh` 가 이 조각의 PR 마다 로컬과 CI gate 잡에서 통과하고, 검사 수는 스물넷 그대로다.

## 하지 않을 일

1. **ERP 의 특화를 원본에 올리지 않는다** — 「리비전 · PR 이 잠금을 맞게 적었으면 적합」 · 「잠금 설명이 없으면 부적합 — 고치는 것은
   적는 것이다(W-1)」 · NC-21 의 예 · Alembic 두 열 표 · PG 실측은 사본에만 산다(FB-4 에서 빼기로 한 것). 「설명이 어긋나면 부적합」 줄은
   이미 원본에 있어 그대로 둔다.
2. **판정 표 밖의 항목 3 을 고치지 않는다** — 네 눈의 목록 · 「먼저 엔진 · 판을 확인합니다」 · 원시 SQL 과 API 를 둘 다 찾으라는 문단은
   FB-4 의 문구이고 `gate-ddl-lock` 이 그것을 잰다. 예산을 줄일 때도 그 자리는 건드리지 않는다.
3. **조각 18 이 넘긴 줄을 다루지 않는다** — 「가르지 못한 결함 다섯」(FB-6 · 7 · 8 · 17 · 34) · 「항목 10 과 머리의 어긋남」은 이 조각과
   겹치지 않게 둔다. `audit-internal` · `audit-secrets` 는 고치지 않는다.
4. **`gap-unowned` 의 성능 넘김 흔들림 · 회수율 측정을 다루지 않는다** — 조각 나눔의 순서 없는 후보다. 전수에서 `gap-unowned` 가
   떨어지면 그 줄의 증거로 적을 뿐이다.
5. **사본을 다시 심지 않는다** — 갈래가 원본에 들어가도 ERP · 강호쟁패는 다음 심기에서 받는다. ERP 「감사한 커밋」 두 자리 · 강호쟁패
   `.gitignore` 는 그 레포의 일이다.
6. **대장 · 수트의 모양을 바꾸지 않는다** — `feedback.json` 의 칸 · 상태 넷(`docs/schema.md`), 러너 · 지난 그레이더(`vibe-audit/evals/README.md`
   「고정한 것」), `eval.yml` 은 그대로다. 지난 FB 의 줄은 고치지 않는다.
7. **천장을 올리지 않는다** — 줄여서 못 넣으면 그 PR 을 멈추고 저자에게 올린다(ADR 0004).

## 제약

- 스택: bash · python3 표준 라이브러리 · `run-evals.sh`(수트 모델 · 심판은 그 파일이 박는다) · `verify-*.py` · `gates.sh`.
- 원본: `main` `9c64df8`. `vibe-audit/` 는 `018842c` 뒤 움직이지 않았다(조각 18 「닫으며」 배포).
- 측정: `run-evals.sh --case <케이스> --ablation none --runs 3`. 옛 문구는 지금 원본에 예산을 비운 줄임만 더한 바탕이고, 새 문구는 바탕에 그 FB 의 갈래만 더한 판이다(설계 ② J1). 픽스처는
  케이스 폴더 안에서만 돌린다 — 조각 18 에서 저장소 맨 위에서 돌려 `CLAUDE.md` 를 덮은 적이 있다. 자격은 세션의 `EVAL_OAUTH_TOKEN` —
  저장소에 쓰지 않는다.
- 비용: 로컬 측정은 조각 전체 **$20** 안(조각 18 은 판 둘 + 진단에 $2.61). 넘을 것 같으면 멈추고 저자에게 올린다. 전수는 `CHECKLIST.md`
  의 월 한도 $20 안에서 감사자를 고친 PR 에 한 번.
- 판정: `fed_back` 은 저자가 정한다(`CHECKLIST.md` 「대장을 건드렸다면」).
- 기간: **사흘**.
- 리뷰: PR 본문에 설계 ② 를 적고, 착공 PR 도 구현 PR 도 스킬 `slice-review` 로 가른다. **3라운드**를 넘기면 소유자가 판정한다.
