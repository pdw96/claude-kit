부품 · 경계 · 흐름과 틀의 수가 바뀌지 않는다. `INTENT.md` 는 그대로다 — What 의 「프로필(`Profile.md`) … 의 틀」 안이고 Not 에 걸리지 않는다.

## ② 보장하는 것 / 보장하지 않는 것

**보장하는 것**

- **Q 인터뷰 물음** — 틀 머리 주석의 물음에 「어느 말로 답하고 남기나 — 대화 · 커밋 메시지 · PR 본문 · 답글. 자리마다 다르면 자리마다」가 선다. 「설명하는 법」의 물음(용어 ·
  동작) 다음, 「혼자 쓰나 여럿이 쓰나」 앞이다 — 그 물음의 번호만 하나 밀린다. 다른 물음의 글은 그대로다.
- **L 언어 줄** — 틀 「설명하는 법」에 `- **언어** — <…>` 줄이 「동작」 다음 · 「고치는 때」 앞에 선다. 자리표가 네 자리(대화 · 커밋 메시지 · PR 본문 · 답글)를 들고, 자리마다 어느
  말인지를 적게 한다. 자리표 밖의 고정 글은 없다 — 「도구를 여러 번 쓴 턴 뒤에도」는 틀에 두지 않는다(ADR 0065 의 4).
- **M 지도** — 「Profile.md 의 칸」의 `## 설명하는 법` 칸이 「용어 · 분야마다 달리 설명하는 것 · 동작을 보이는 모양 · 답하는 말, 그리고 고치는 때」 꼴로 답하는 말을 든다.
  문서 대조 검사가 원천으로 읽는 제목 칸은 그대로라 O1 · O2 · T1 · T2 가 고치기 전과 같게 지난다.
- **S 스킬** — `slice-docs` 의 「이미 있으면 덮지 않는다」가 고치는 것에 「「설명하는 법」에 없는 언어 줄」을 더한다. 다른 고침과 같이 먼저 보이고 받으면 한다(그 줄 머리 「아래 고침은
  다 먼저 보이고 받으면 한다」). 인터뷰는 틀의 물음 그대로라 새로 세울 때는 Q 가 묻는다(ADR 0065 의 2).
- **C 이 저장소** — `CLAUDE.md` 「작업 방식」에 「대화 · 커밋 메시지 · PR 본문 · 답글은 한국어로 — 도구를 여러 번 쓴 턴 뒤에도」 뜻의 한 줄이 선다(ADR 0065 의 3 · 4) — 「도구를 여러 번 쓴
  턴 뒤에도」는 틀이 아니라 여기에만 있다.
- **판과 고정** — `vibe-slice` 판이 0.9.3 이고 `verify-manifest.py` 가 두 파일을 같게 본다. 두 스킬의 지도 링크가 B 의 첫 커밋이고 `verify-map-pin.py` 가 지난다. `budget.txt`
  가 `--write` 의 결과라 `verify-budget.py` 가 지난다.

**보장하지 않는 것(알려진 한계)**

- **효과** — 세션이 도구를 여러 번 쓴 턴 뒤에도 정한 말로 답하는지는 이 조각이 보장하지 않는다(ADR 0065 의 1). ImproveEnglish 는 손으로 적은 줄이 있어도 갈렸다. 다시 갈리면
  매 턴 넣는 훅이 그 레포 설정의 몫으로 남는다(요구사항 하지 않을 일 2).
- **프로필의 글** — 언어 줄이 있는지 · 네 자리를 다 드는지는 검사가 묻지 않는다(ADR 0042 의 6). 사람이 본다.
- **이미 있는 프로필** — 스킬을 다시 부르기 전까지 ERP · ImproveEnglish 의 프로필은 그대로다. ERP 의 스킬 사본은 다시 심기 전까지 옛 틀이다(요구사항 하지 않을 일 5).
  플러그인으로 받은 세션은 `claude plugin update vibe-slice@pdw96-kit` 뒤 · 계정 동기화로 받은 세션은 동기화 뒤에 새 틀을 읽는다.
- **코드 주석 · 문서의 말** — 네 자리 밖이다(요구사항 하지 않을 일 6).

검사 장치가 아니다 — 새로 읽는 입력이 없다. 고치는 자리는 지금 파일의 글이다(`main` `6c0d8b3`).

**정한 것**

## ⑤ 검증 계획

새 검사를 세우지 않는다 — 맞음은 기존 검사와 diff 로 보인다. 다 B 에서 돈다.

- V1 **성공 기준 1 · 2 · ② Q · L** — B 의 `git diff 6c0d8b3 -- vibe-slice/skills/slice-docs/templates/profile.md` — 물음 하나 · 줄 하나 · 번호 하나가 바뀌고 `##` 줄이 diff 에 없다.
  틀에 「턴 뒤에도」가 없는 것을 `grep` 으로 B 본문에.
- V2 **성공 기준 3 · ② M** — 지도의 diff 가 그 셀 하나이고, `verify-docs.py`(이 저장소 모드)와 `verify-docs.py --repo .` 가 지난다.
- V3 **성공 기준 4 · ② S** — `slice-docs/SKILL.md` 의 diff 가 그 하위 항목과 지도 링크뿐이다.
- V4 **성공 기준 5 · ② C** — `CLAUDE.md` 의 diff 가 「작업 방식」의 한 줄 더하기뿐이다.
- V5 **성공 기준 6** — `verify-manifest.py` · `verify-map-pin.py` · `verify-budget.py` PASS 줄, B 의 두 커밋 순서.
- V6 **성공 기준 7** — 각 PR 의 커밋 전 작업트리에서 인자 없는 `./scripts/gates.sh` 의 끝 줄과 CI gate 잡. `git diff --stat 6c0d8b3 <B 머리> -- scripts/` 가 비어 있다.
- V7 **성공 기준 8** — B 가 머지된 뒤 `main` 에서 기준 `6c0d8b3` 로 `audit-internal` 을 돌리고 닫는 PR 의 대장에 등록한다.

단계 5(배포 · 롤백) — 플러그인 판이 오른다. 배포는 마켓플레이스 · 계정 동기화가 머지된 `main` 을 받는 것이고, 받은 판은 `claude plugin list` 나 세션의
`~/.claude/plugins/synced/` 에 보인다. 되돌리는 길은 B 를 되돌리는 것이다.
