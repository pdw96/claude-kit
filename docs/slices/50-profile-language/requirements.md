# 조각 50 — 프로필의 언어 칸 (2026-11-02 착공)

요구사항이다 — **무엇을 · 왜.** 어떻게 · 경계는 같은 폴더의 `design.md`, 대안이 있던 결정은 ADR 0065.

이 조각을 「다음 조각」으로 적은 것은 조각 49 의 `## 닫으며 (2026-11-02)` 이다 — 그 기록의 「넘긴 것」(없음)과 「다음 조각」을 읽고 착공한다(ADR 0012). 그 닫는 세션은 남은 예정 줄
일곱 가운데 꺼내는 조건이 없는 셋을 대 보이고 이 줄을 추천했고, 저자가 골랐다. 의존은 `—` 다. 착공 세션이 갈래 셋(효과를 재나 · 이미 있는 프로필 · 이 저장소)을 물어 저자가 셋 다
세션이 추천한 쪽을 골랐다(ADR 0065 의 1 ~ 3). 착공은 `main`(`6c0d8b3`) 위에서 연다. 이 착공 세션의 claude-kit 클론은 얕지 않았다(`git rev-parse --is-shallow-repository` →
`false`).

## 문제

**세션이 답하는 말을 정하는 자리가 프로필 틀에 없다. 그래서 레포마다 손으로 적고, 적은 레포도 도구를 여러 번 쓴 턴 뒤로 영어로 답했다.**

- **틀에 칸이 없다** — 프로필 틀(`vibe-slice/skills/slice-docs/templates/profile.md`)의 인터뷰 물음 여섯과 「설명하는 법」의 네 줄(용어 · 분야마다 · 동작 · 고치는 때)
  어디에도 「어느 말로 답하고 남기나」가 없다. 절차 지도 「Profile.md 의 칸」의 `## 설명하는 법` 칸도 그것을 들지 않는다.
- **손으로 적은 레포가 있다** — ImproveEnglish 가 「설명하는 법」에 「언어」 줄을 손으로 더했다(2026-10-29). 그 레포의 클라우드 세션이 도구 불러오기 · GitHub 호출 · 에이전트 ·
  알림 읽기를 거친 턴 뒤로 영어로 답했다(2026-10-31 저자가 보인 화면). 줄이 있어도 갈렸다.
- **이 저장소도 같다** — 프로필이 없는 이 저장소의 클라우드 세션이 2026-11-02 도구를 여러 번 쓴 턴 뒤로 영어로 답해 저자가 「한글로」라고 다시 말했다(조각 49 의 닫는 세션).
- **다른 레포에서도 같은 말이다** — 답하는 말은 사람마다 정할 것이고, 대화 · 커밋 메시지 · PR 본문 · 답글이 같은 말일 까닭도 없다. 레포의 특화가 아니다(`INTENT.md` Why).
- **이미 있는 프로필은 받지 못한다** — 스킬 `slice-docs` 는 이미 있는 프로필에서 「빠진 절」만 채운다. 언어 줄은 절 안의 한 줄이라 틀을 고쳐도 ERP · ImproveEnglish 의 프로필에는
  제안되지 않는다.

## 핵심 사용자와 시나리오

- 사용자: 한국어로 일하는 저자 — 세션과 대화하고, 커밋 · PR · 답글을 읽는다.
- 시나리오: 새 레포에서 `slice-docs` 로 프로필을 세운다 → 인터뷰가 「어느 말로 답하고 남기나」를 자리마다(대화 · 커밋 메시지 · PR 본문 · 답글) 묻는다 → 프로필의 「설명하는 법」에
  언어 줄이 서고 `CLAUDE.md` 가 가져온다. 이미 프로필이 있는 레포에서 `slice-docs` 를 부르면, 언어 줄이 없다고 먼저 보이고 받으면 더한다. 프로필이 없는 이 저장소는 `CLAUDE.md`
  한 줄이 같은 일을 한다.

## 성공 기준

1. **틀에 물음이 있다** — B 의 `templates/profile.md` 머리 주석의 인터뷰 물음에 「어느 말로 답하고 남기나 — 대화 · 커밋 메시지 · PR 본문 · 답글」이 한 물음으로 선다. 물음의 수가
   하나 늘고, 다른 물음의 글은 그대로다.
2. **틀에 칸이 있다** — B 의 틀 「설명하는 법」에 `**언어**` 줄이 서고, 네 자리(대화 · 커밋 메시지 · PR 본문 · 답글)를 든다. 「도구를 여러 번 쓴 턴 뒤에도」 그 말로 답한다는
   글이 자리표(`<…>`) 밖에 있어 베껴도 남는다(ADR 0065 의 4). 틀의 `##` 제목 셋은 글자 그대로다.
3. **지도가 맞다** — B 의 `docs/procedure.md` 「Profile.md 의 칸」 `## 설명하는 법` 칸이 답하는 말을 든다. 그 절의 제목과 표 서식은 그대로다.
4. **스킬이 이미 있는 프로필에 제안한다** — B 의 `slice-docs/SKILL.md` 「어디서 시작하나」의 프로필 줄이 「설명하는 법」에 언어 줄이 없으면 먼저 보이고 받으면 더하라고 든다(ADR
   0065 의 2).
5. **이 저장소의 입구** — B 의 `CLAUDE.md` 「작업 방식」에 답하는 말 한 줄이 선다 — 네 자리와 「도구를 여러 번 쓴 턴 뒤에도」(ADR 0065 의 3). 그 밖의 줄과 절 제목은 그대로다.
6. **판과 고정** — `vibe-slice` 0.9.2 → 0.9.3(`plugin.json` · `marketplace.json`), 두 스킬의 지도 링크가 B 의 지도를 고친 커밋을 가리키고 `verify-map-pin.py` 가 지난다.
   `vibe-audit/evals/budget.txt` 는 `verify-budget.py --write` 의 결과다.
7. **게이트가 그대로다** — 인자 없는 `./scripts/gates.sh` 가 각 PR 의 커밋 전 작업트리와 CI gate 잡에서 통과하고, 「PASS test-gates.py — … 고정 목록 30 그대로」다. 검사 · 시험
   스크립트는 글자 그대로다. 모델을 부르는 측정이 없다 — 비용 0.
8. **감사 회차** — 닫기 전 `audit-internal` 을 돌려 대장에 등록했다.

## 하지 않을 일

1. **효과를 재지 않는다**(ADR 0065 의 1) — 도구를 여러 번 쓴 턴 뒤에도 정한 말로 답하는지는 이 조각의 성공 기준이 아니다. 다시 갈리면 그 관찰이 다음 줄(훅)의 근거가 된다.
2. **훅을 세우지 않는다** — 매 턴 지시를 넣는 `UserPromptSubmit` 훅 같은 것은 그 레포 설정의 몫이다. 이 저장소의 `.claude/settings.json` 도 그대로다.
3. **새 검사를 세우지 않는다** — 문서 대조 검사는 `Profile.md` 의 절 제목도 문장도 묻지 않는다(ADR 0042 의 6). 언어 줄이 있는지도 묻지 않는다. `verify-docs.py` · 시험 ·
   변조본 · `gates.sh` 는 그대로다.
4. **절을 더하지 않는다** — 틀의 `##` 제목 셋과 「Profile.md 의 칸」의 제목 · 표 서식(앵커볼트)은 그대로다. 언어는 「설명하는 법」의 한 줄이다.
5. **사본 레포를 고치지 않는다** — ERP 의 스킬 사본을 다시 심지 않고, ERP · ImproveEnglish 의 프로필도 고치지 않는다. 그 레포에서 스킬을 부르면 성공 기준 4 의 제안이 간다
   (`INTENT.md` Not 4).
6. **코드 주석 · 문서의 말을 다루지 않는다** — 언어 줄이 가르는 자리는 대화 · 커밋 메시지 · PR 본문 · 답글 넷이다. 레포의 문서와 코드가 어느 말인지는 그 레포의 작업 규칙이 든다.
7. **이 저장소에 `Profile.md` 를 두지 않는다**(ADR 0065 의 3) — 이 저장소는 `CLAUDE.md` 한 줄로 받는다. 프로필을 세울지는 조각 31 의 하지 않을 일 6 대로 그 인터뷰의
   몫이다.
8. **조각 나눔의 다른 줄을 다루지 않는다** — 「배포 경로 다시 재기」 · 「감사자가 거듭 청한 절차 물음」 · 「걷은 사본의 대장 줄」 등.

## 제약

- 스택: 마크다운(틀 · 지도 · 스킬 · 입구) · JSON(판) · 기존 python3 검사. ADR 하나.
- 원본: `main` `6c0d8b3`. 프로필 틀은 조각 31(`0d61fb3`) 뒤 움직이지 않았다. 두 스킬의 지도 링크는 `2e60e97` 을 가리킨다.
- 증거의 원문: ImproveEnglish 의 프로필과 그 화면은 이 세션에 붙지 않아 보지 못했다 — 마스터플랜 줄의 글(저자가 보인 것)에 기댄다.
- 앵커볼트: 건드리지 않는다 — 이름 · `tools` · 공통 절 · 대장의 모양 · 문서의 절 제목과 「…의 칸」 표 서식 · 고정 영역 그대로다. 지도의 칸은 셀의 글만 바뀐다.
- 비용: 0 — 모델을 부르지 않는다. 틀 · 지도 · 스킬은 수트 지문 밖이다.
- 기간: 닫기까지 **2026-11-06**.
- 리뷰: PR 본문에 설계 ② 를 적고, 착공 PR 도 구현 PR 도 스킬 `slice-review` 로 가른다. PR 마다 **3라운드**를 넘기면 소유자가 판정한다.
- 감사 회차: 닫기 전 — `audit-internal`(틀 · 지도 · 스킬 · `CLAUDE.md` — 이 프로젝트가 스스로 정한 규칙이 바뀐다. `vibe-audit` README 「대략의 주기」의 「조각 서너 개 머지한 뒤」에도
  닿는다 — 지난 `audit-internal` 은 회차 23(조각 48). 대장에 이 조각에 기대는 줄은 없다).
