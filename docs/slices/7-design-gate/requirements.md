# 조각 7 — 설계 → 구현 관문 (2026-10-08 착공)

요구사항이다 — **무엇을 · 왜.** 어떻게 · 경계는 같은 폴더의 `design.md`, 대안이 있던 결정은 ADR 0016.

## 문제

절차 지도는 단계 3(구현)의 들어가는 조건을 「착공 PR 이 머지됐다」로 적었지만 무는 것이 없다. ADR 0006 이 「강제는
없다」로 남겼고, 지도 머리도 「여기 적힌 것을 어겨도 떨어지는 검사는 … 「설계 → 구현 관문」이 `닫힘` 이 되기 전까지
없다」고 적는다. 조각 6 의 `slice-review` 도 단계 3 의 조건은 보장하지 않는다(조각 6 설계 ② 보장하지 않는 것).

그 자리를 어긴 PR 은 둘이다(2026-10-08 에 셌다).

| PR | 한 PR 에 붙은 것 | 무엇이 났나 |
|---|---|---|
| 강호쟁패 #1 | 착공 문서(`PRD.md` · 스키마 · 구조 · ADR 0001 ~ 0004) · 가설공사 · 검사 스크립트 | 파일 90, 리뷰 12회차, 지적 38 가운데 20 스레드가 검사 스크립트 하나 — 수렴하지 않아 그것을 PR 에서 뗐다(`docs/procedure.md` 「사례」) |
| claude-kit #7 | 기획 · 설계 문서(`PRD.md` · ADR 0001 ~ 0004 · `docs/schema.md`) · 비교기 · 후보 대장 검사기 · CI | 파일 16. 절차 지도가 서기 전이다 |

**claude-kit 은 절차 지도가 선 뒤로 어긴 적이 없다 — 지킨 것은 검사가 아니다.** 착공 다섯과 그 첫 구현 PR 의 시각이다(UTC, 분 단위로 반올림).

| 착공 머지 | 첫 구현 PR 을 연 때 | 사이 |
|---|---|---|
| #14 08:31 | #15 08:39 | 8 분 |
| #17 12:18 | #18 12:33 | 15 분 |
| #20 01:21 | #21 01:27 | 5 분 |
| #24 06:30 | #25 06:37 | 7 분 |
| #28 21:59 | #29 22:05 | 5 분 |

한 세션이 한 가지에서 PR 을 하나씩 열어 순서가 저절로 지켜졌다. 세션이 둘이거나 가지를 나누면 아무것도 막지 않는다.

- **증거가 난 레포에는 claude-kit 의 CI 가 닿지 않는다.** 강호쟁패는 플러그인 `vibe-slice` 만 쓰고 저장소에 `.claude/` 가
  없다. ERP 는 사본을 쓴다. 두 레포에 닿는 것은 스킬뿐이다. `slice-docs` 는 「구현 코드도 쓰지 않는다 — 구현은 착공 PR 이
  머지된 뒤 설계 ⑥ 의 나눔대로 간다」 한 줄을 들고, 착공 PR 에 무엇을 싣는지는 적지 않는다.
- **`eval.yml` 은 수트 지문에 든다.** 고치면 route 수트(케이스 열 × 세 회)가 돈다 — 조각 나눔 「게이트 변조본을 수트 지문
  밖으로」.

## 핵심 사용자와 시나리오

- 사용자: 저자 한 명, 그리고 조각을 여는 Claude Code 세션(이 레포와 `vibe-slice` 를 받은 다른 레포).
- 시나리오: 세션이 조각을 꺼내 `slice-docs` 로 요구사항 · 설계를 쓴다 → 스킬이 착공 PR 에 싣는 것(결정 문서)을 적어 두어
  구현을 같이 싣지 않는다 → claude-kit 에서 실수로 구현 파일을 실으면 `gates.sh` 가 로컬과 CI 에서 G1 로 떨어진다 → 착공이
  머지되어 기준 가지(`main`)의 마스터플랜에 조각이 `진행` 이고 설계가 있다 → 구현 PR 이 G2 를 지나간다. 착공이 머지되기
  전에 구현 PR 을 열면 G2 로 떨어진다 → 다른 레포에서는 구현 PR 에 리뷰가 오면 `slice-review` 가 가르기 전에 착공이 기준
  가지에 머지됐는지 보고, 아니면 가르지 않고 단계 3 의 조건이라고 말한다. 착공 PR 이 구현을 실었으면 안으로 가른다.

## 성공 기준

1. `scripts/verify-slice-gate.py` · 자체 시험 `scripts/test-verify-slice-gate.py` · 변조본 `scripts/bite-slice-gate.py` 가
   `gates.sh` 에 들어 열일곱이 통과한다. 변조본은 검사를 G1 · G2 · B1 · B3 자리마다 망가뜨린 사본에 자체 시험을 대어 다
   떨어지는지 보고, 하나라도 지나가면 떨어진다 — 자체 시험을 비우면 `gates.sh` 가 떨어진다.
   자체 시험은 임시 git 레포에서 G1(착공 PR 에 구현 파일) · G2(기준에 `진행` 조각이 없음 · `진행` 조각의 설계가 기준에
   없음) 변조본마다 떨어지고, 착공 · 구현 · 닫는 PR 꼴에서 지나간다.
2. 역사 재연 — claude-kit 의 머지된 PR #15 ~ #31 열일곱을 머지 커밋의 두 부모(기준 · 머리)에 대면 다 지나가고, #14 ·
   #7 은 「기준에 마스터플랜이 없다 — 보지 않는다」를 찍는다. 착공과 구현을 한 PR 로 붙인 꼴 — #28 의 기준 `69f0008` 에
   #29 의 머리 `5eff890` — 은 G1 로 떨어진다. 그 표가 검사를 들이는 구현 PR 본문에 있다.
3. 이 조각의 다음 구현 PR 이 CI gate 잡에서 그 검사를 지나가고, 잡 로그에 기준 · 머리 sha 와 그것을 어디서 읽었는지가 찍힌다.
4. 스킬 — `slice-docs` 가 착공 PR 에 싣는 것(결정 문서)을 적고, `slice-review` 가 구현 PR 의 기준을 모으기 전에 착공이 기준
   가지에 머지됐는지 보며, 착공 PR 이 구현을 실으면 안이라고 적는다(grep). `vibe-slice` 판이 오르고, `claude plugin validate
   ./vibe-slice` · `verify-manifest.py` 가 통과하고, `verify-budget.py` 가 천장 안이다 — 호출 시 ≤ 4,500, `vibe-slice` 상시
   합계 ≤ 5,600.
5. 강호쟁패(플러그인)와 ERP(사본)의 세션에서 새 판의 `slice-docs` · `slice-review` 가 뜬다 — 저자가 단계 5 에서 본다.
6. `./scripts/gates.sh` 가 구현 PR 마다 통과하고, 구현 PR 이 바꾼 파일 가운데 수트 지문(`eval-key.py route --list` ·
   `full --list`)에 드는 것이 0 이다.

## 하지 않을 일

1. **나가는 조건 「⑥ 밖의 것을 싣지 않았다」를 검사로 물지 않는다** — 설계 ① 표와 구현 PR 이 바꾼 파일을 견주지 않는다.
   `slice-review` 의 안 갈래(「⑥ 의 그 줄이 담지 않은 일」, ADR 0015 의 1)가 리뷰에서 본다(ADR 0016 의 2).
2. **단계 3 의 다른 조건을 물지 않는다** — 설계 ④ 의 열어 둔 것을 정했나, 구조 문서를 고쳤나.
3. **PR 이 어느 조각의 것인지 가리지 않는다** — 기준 가지에 설계가 머지된 `진행` 조각이 하나라도 있으면 지나간다(ADR 0016
   의 3). 커밋 꼬리말 · PR 본문 · 라벨을 읽지 않는다.
4. **조각 밖 PR 의 예외 표지를 두지 않는다** — 조각 사이의 고침은 조각 나눔에 줄을 먼저 더한다(절차 「두 층」).
5. **수트 지문에 드는 파일을 고치지 않는다** — `eval.yml` 도. 검사와 그 변조본은 `gates.sh` 가 부른다(ADR 0016 의 6).
6. **다른 레포에 검사를 심지 않는다** — 다른 레포는 스킬이 맡고, 키 없이 무는 것은 조각 나눔 「다른 레포의 문서 대조 검사」.
7. **브랜치 보호 · ruleset 을 바꾸지 않는다** — 어느 체크를 필수로 거는지는 저장소 설정이고 저자가 한다.
8. **강호쟁패 · ERP 저장소를 이 조각의 PR 에서 고치지 않는다** — 플러그인 갱신과 사본 다시 심기는 저자가 단계 5 에서 한다.

## 제약

- 스택: bash · python3 표준 라이브러리, git(역사 전체 — 기준 가지의 파일을 읽는다). 스킬의 모양은 `claude plugin validate` 가
  받는 것.
- 모델 비용: 이 조각의 파일로는 route 수트가 돌지 않는다 — **수트 지문에 드는 파일**(`eval-key.py route --list` · `full
  --list`)을 건드리지 않는다. 예산 스냅숏 `vibe-audit/evals/budget.txt` 는 지문 밖이고, 스킬을 고치는 PR 이 고친다(조각 6
  「닫으며」 — 제약을 「`vibe-audit/` 를 건드리지 않는다」로 적어 글자를 어겼다). CI 의 CLI 판이 오르면 판마다 한 번 돌 수
  있다(`CLAUDE.md` 「스택」).
- 글자 예산: `slice-review` 호출 시 3,919 / 4,500(여유 581), `vibe-slice` 상시 합계 348 / 5,600. 천장은 올리지 않는다(ADR 0004).
- 기간 **이틀**.
- `./scripts/gates.sh` 는 지금 열넷이 그대로 통과해야 하고, 검사가 들어온 뒤로는 열일곱이다.
- 리뷰: PR 본문에 설계 ② 를 적고, 착공 PR 도 구현 PR 도 스킬 `slice-review` 로 가른다. **3라운드**를 넘기면 소유자가 판정한다.
