# 조각 1 — 사본 비교 · 되먹임 (2026-10-05 착공)

## 문제

되먹임 셋은 전부 **써 보다가 우연히** 나왔다(README 「되먹인 자리마다 회귀 검사를 세운다」).
사본이 원본과 어디서 갈렸는지 보는 수단이 없다 — `verify-copy.py` 는 공통 절이 같은지만 보고,
사본에만 있는 차이는 사람이 diff 를 손으로 읽어야 한다. 판정한 결과가 남는 자리도 없어서,
특화로 기각한 차이가 다음에 견줄 때 다시 올라온다.

손으로 견줘 본 첫 회차(2026-10-05)에서 이 비용이 그대로 드러났다. 로컬 ERP 클론이 원격보다
뒤처져 있었는데 비교를 다 하고 나서야 알았다 — 감사자 여섯을 다 고친 원격의 커밋(ADR 0010 ·
0011)을 빼고 견준 셈이다.

## 핵심 사용자와 시나리오

- 사용자: 저자 한 명.
- 시나리오: ERP 에서 감사 회차가 끝난다 → claude-kit 에서 비교 스크립트를 부른다 → 스크립트가
  대장의 사본마다 그 레포를 받아(fetch) 원격보다 뒤이거나 사본 자리가 더러우면 **멈춘다** →
  원본(심을 때의 커밋)과 사본(그 레포의 HEAD)을 감사자 파일마다 견줘 차이 덩어리를 뽑는다 →
  `feedback.json` 에 이미 판정된 덩어리는 빼고 **미판정 후보만** 찍는다 → 저자가 후보마다
  특화 · 결함 · 보류를 적는다 → 결함은 일반형으로 옮기고 eval 케이스를 세워 게이트와 수트를
  통과시킨 PR 로 낸다 → 그 PR 에서 후보를 「되먹임 완료」로 옮기고 원본 커밋과 케이스를 적는다.

## 성공 기준

> 게이트에서 끌어내 제안했고, 저자가 그대로 확정했다(2026-10-05).

- 2026-10-05 의 ERP 원격 사본을 원본 `3d6964a` 와 견주면, 아래 「첫 회차 손 비교」의 자리가
  **빠짐없이** 후보로 나온다. 출처 주석 줄과 공백만 다른 덩어리는 나오지 않는다.
- 한 번 판정한 후보는 다음 실행에서 미판정으로 다시 안 나온다 — 줄이 옮겨져도.
- 사본이 원격보다 뒤이거나 작업트리가 더러우면 0 이 아닌 종료코드로 멈춘다.
- 위 셋을 임시 저장소로 재현하는 검사가 `gates.sh` 에 있고, CI 「게이트가 무는가」에서 변조본으로
  떨어지는 것을 보인다.
- 비교 자체는 모델을 부르지 않는다 — 비용 $0.

## 하지 않을 일

1. **대장(`copies.json`) 밖의 레포는 보지 않는다.** 심을 때의 커밋이 없으면 사본이 바꾼 것과
   원본이 그 뒤 움직인 것을 가를 수 없다. 보려면 `sync-agents.sh` 로 먼저 심어 대장에 올린다.
2. **원본을 자동으로 고치지 않는다.** 체계는 후보까지만 낸다. 판정과 원본 수정 PR 은 저자가 한다.
3. **원본 → 사본 방향은 다루지 않는다.** 그것은 `sync-agents.sh` 의 일이다.
4. **특화를 원본에 레포별 분기로 넣지 않는다.** 원본은 일반형으로 남는다.
5. **첫 조각은 감사자 여섯만 견준다.** 커맨드(`audit-brief.md`) · 검사기(`verify-brief.py`)
   사본은 다음 조각이다.

## 제약

- 스택: bash · python3 표준 라이브러리 · git. 모델 호출 없음.
- 호스팅: 비교는 저자의 로컬 기계에서 돈다(ADR 0001). CI 는 키 없이 도는 검사만 더한다 —
  후보 대장이 성한지, 비교 스크립트가 무는지.
- 월 비용 한도: **$20 · 되먹임 두 회차.** 회차당 약 $5–10 — 판정 케이스 하나 × 3회 $0.89,
  `route-*` 18회 $4.43(evals/README 의 실측).
- 외부 API와 쿼터: Anthropic(구독 토큰) — eval 만 쓴다. 주간 한도를 CI 와 나눠 쓴다.
- 주기: 사본 쪽 감사 회차가 하나 끝난 뒤 한 번.
- 글자 예산: 2026-10-05 기준 여유가 상시 557자 · 감사자 호출 시 695자. **압축이 먼저, 천장을
  올리는 것은 저자 승인**(ADR 0004).

## 첫 회차 손 비교 (2026-10-05)

로컬 ERP 클론(원격보다 뒤처진 것)을 원본 `3d6964a` 와 견준 결과다. **판정이 아니라 자리 목록**이다 —
스크립트가 이것을 빠짐없이 내는지가 첫 성공 기준이고, 판정은 원격을 받은 뒤 저자가 한다.

### 스크립트로 다시 견준 결과 (2026-10-05)

- **로컬 클론 그대로:** `STOP erp: 사본 레포 HEAD 가 origin/main 보다 241 커밋 뒤다` — 성공 기준 3.
- **ERP 원격 `main`(`6d9cd89`)을 따로 받아:** 후보 17, 위 표의 자리가 다 나왔다 — 성공 기준 1.
  대장 경로 줄은 감사자 여섯에 걸친 후보 **하나**이고, 출처 주석 줄과 빈 줄만 다른 자리는 안 나왔다.
  `audit-quality` 끝의 두 문단(「자동 게이트를 세우라」 · 확인불가)은 순서만 바뀌었는데, 하나를 지운 덩어리와
  더한 덩어리, 후보 둘로 나온다. 어느 쪽을 옮긴 것으로 잡을지는 diff 가 고른다 — 이번엔 확인불가 문단이다.
- 이 결과를 저자가 판정했다(2026-10-05) — 특화 9 · 결함 8. 판단자 셋(블라인드 둘 · 반박자 하나)이
  초안을 따로 봤고, 원문으로 확인된 정정을 받았다. 판정과 근거는 `feedback.json` 에 있다.
- 비교기가 정규화한 줄로 견주게 된 뒤(Codex 리뷰) FB-13 · 14 는 한 덩어리 FB-18 로 나온다. 둘은
  지우지 않는다 — 한 번 매긴 번호는 사라지지 않는다(`verify-feedback.py`).
