설계다 — **어떻게 · 경계.** 무엇을 · 왜는 같은 폴더의 `requirements.md`.

## ② 보장하는 것 / 보장하지 않는 것

**보장하는 것**

- D1 **지도의 단계가 이 저장소 밖의 스킬을 도구로 들지 않는다.** 「일곱 단계」의 「맡는 도구」 칸을 이렇게 고친다.
  - 0 착수 전 — 마스터플랜. 프로젝트 층이 없으면 스킬 `slice-docs`(플러그인 `vibe-slice`)로 의도 · 마스터플랜과 작업 규칙(`CLAUDE.md`)을 세운다.
    프로필(`Profile.md`)은 같은 스킬이 세울지 묻는다. 넘어갈 준비는 이 줄의 「나가는 조건」이 든다 — 따로 맡는 도구를 두지 않는다.
  - 4 검증 — 그 저장소의 CI 게이트 · `vibe-audit` 감사자 · 리뷰 봇 · 스킬 `slice-review`. 감사 계획과 부적합 대장은 빈자리(D3). 산출물 · 나가는
    조건의 「감사 계획이 이 PR 을 들 때」는 그대로 둔다 — 계획이 없으면 드는 PR 이 없어 조건이 비고, 「감사 계획」 조각이 그 칸을 채운다.
  - 5 배포 · 롤백 — `audit-ops`(관측 · 롤백 · 배포 직전). 안정화는 빈자리.
- D2 **「계정 스킬의 일」 절을 지운다.** 든 것은 하나 — 「`project-kickoff` 가 `PRD.md` 를 쓴다」였다. 다른 문서가 의도를 들 때의 규칙(`INTENT.md`
  를 새로 쓰지 않고 마스터플랜 「가리키는 문서」의 의도 줄이 그것을 가리킨다)은 「의도 문서의 칸」과 「대상과 관계」가 이미 든다. 그 절을 가리키던
  0 단계 칸의 「아래 「계정 스킬의 일」」도 D1 이 지운다.
- D3 **「빈자리」 표에 두 줄.** 지도의 규칙대로 증거가 있어 조각 나눔에 줄이 있다.

  | 빈자리 | 단계 | 비어 있는 것 | 증거 | 조각 나눔 |
  |---|---|---|---|---|
  | 감사 계획 | 4 · 6 | 조각 · PR 마다 어느 감사자를 어느 단계에서 돌리나 | 사본 레포마다 손으로 적는다 — 강호쟁패 `CLAUDE.md` 「조각을 끝낼 때마다 `audit-internal`」. 이 저장소의 README 「첫 조각이 끝나면 `@audit-data` 부터」 · `vibe-audit/README.md` 「대략의 주기」 | 「감사 계획」 |
  | 부적합 대장 | 4 → 6 | 감사가 낸 부적합을 판정하고 재감사로 닫힐 때까지 따라가는 자리 | ERP `docs/audit/` — 손으로 세워 감사 ㊸ 까지 따라왔다. 강호쟁패는 감사 기록 하나뿐이고 대장이 없다 | 「부적합 대장」 |

  표의 다른 줄처럼 증거는 레포의 자리를 든다 — 지운 스킬의 이름은 들지 않는다(요구사항 성공 기준 1).
- D4 **입구 둘이 지도와 같은 말을 한다.**
  - `README.md` 「새 프로젝트를 열 때」 — 1 감사자를 심는다(그대로) · 2 스킬 `slice-docs` 로 의도 · 마스터플랜 · 작업 규칙(`CLAUDE.md`)을 세워 조각을
    나눈다 · 3 첫 조각이 끝나면 `@audit-data` 부터(옛 4). 「계정에 붙어 있는 스킬 넷」 줄을 지운다. 감사 계획 · 부적합 대장의 줄은 「감사자 여섯은 개별
    감사만 한다. 무엇을 언제 감사할지와 부적합을 닫힐 때까지 따라가는 자리는 절차 지도 「빈자리」에 있다」로.
  - `vibe-audit/README.md` 「감사 계획과 부적합 대장」 첫 문단 — 「무엇을 언제 돌릴지, 부적합을 어떻게 추적할지는 이 플러그인이 맡지 않습니다 —
    claude-kit 절차 지도의 「빈자리」입니다. 이 플러그인은 개별 감사만 합니다.」 지도는 GitHub 링크로 가리킨다(이 파일은 플러그인 폴더라 상대
    경로가 저장소 밖에서 깨진다).
  - 둘 다 살아 있는 문서라 「아직」 · 「다음 조각에서」를 쓰지 않는다(지도 「살아 있는 문서와 기록」).
- D5 **`INTENT.md` Not 3** — 「**절차를 계정 스킬에 기대지 않는다** — 계정 스킬은 이 저장소 밖에서 바뀌고 지워진다. 절차 지도가 단계를 맡기는
  도구는 이 저장소의 플러그인과 그 레포의 CI · 리뷰다. 맡을 도구가 없는 자리는 지도의 「빈자리」에 적는다.」 A 가 싣는다.

**보장하지 않는 것(알려진 한계)**

- **이미 설치한 플러그인의 README** — `vibe-audit/README.md` 를 고쳐도 판을 올리지 않으므로(ADR 0043 의 3) 이미 받은 세션의 플러그인 폴더에는 옛
  문단이 남는다. 그 파일은 세션이 읽어 들이지 않고 사람이 GitHub 에서 읽는다.
- **사본 레포의 문서** — ERP · 강호쟁패가 스스로 적은 줄(ERP ADR 0001 의 `project-kickoff`)은 그 레포의 일이다.
- **`ai-native-build` 이 맡던 일** — 본문이 없어 무엇이 비었는지 가르지 못한다. 「빈자리」 표에 줄을 두지 않는다 — 증거가 생기면 그때 더한다.
- **감사 계획 · 부적합 대장의 내용** — 하지 않을 일 2.

## ④ 결정

**정한 것**

- 지운 넷의 자리를 이 저장소의 도구와 「빈자리」로 옮긴다 — 다시 만들거나 들이지 않는다. ADR 0043 의 1.
- `INTENT.md` Not 3 을 지우지 않고 「절차를 계정 스킬에 기대지 않는다」로 바꾼다. ADR 0043 의 2.
- 플러그인 판을 올리지 않는다. ADR 0043 의 3.
- 남는 둘을 조각 둘로, 「부적합 대장」 → 「감사 계획」 순서로 · 대장은 `vibe-audit` 에. ADR 0043 의 4.

**열어 둔 것**

없음 — B 의 문구는 ② D1 ~ D4 가 든다.

## ⑤ 검증 계획

- V1 **성공 기준 1** — B 의 작업트리에서 `git grep -n -E "project-kickoff|build-gate|separate-audit|ai-native-build" -- ':!docs/slices' ':!docs/adr' ':!docs/eval-log'`
  가 0 줄이고, 같은 조건의 `git grep -n "계정 스킬"` 이 `INTENT.md` Not 3 과 마스터플랜의 이 조각 줄 둘뿐이다. 결과를 B 의 PR 본문에 싣는다.
- V2 **성공 기준 2** — B 의 diff 를 ② D1 ~ D4 와 줄마다 대어 PR 본문에 싣는다. 새 검사를 세우지 않는다 — 이름을 무는 검사는 지운 스킬이 다시 생길
  일을 막지 못하고, 막을 것은 Not 3 이 든다.
- V3 **성공 기준 3** — `./scripts/gates.sh` 스물넷을 A · B 의 로컬과 CI gate 잡에서. A 는 결정 문서만이라 설계 → 구현 관문을 지난다. B 는 `진행`
  조각 32 의 설계가 머지된 위라 지난다.
- 단계 5 — 배포처가 없다. B 의 머지로 `main` 의 문서가 바뀌는 것이 전부다. 되돌리는 길은 B 를 되돌리는 것이다 — 닫는 기록이 머지된 뒤라면 그것을
  먼저 되돌린다.
