# 조각 11 — 게이트 변조본을 수트 지문 밖으로 (2026-10-12 착공)

요구사항이다 — **무엇을 · 왜.** 어떻게 · 경계는 같은 폴더의 `design.md`, 대안이 있던 결정은 ADR 0020.

## 문제

**검사를 고치면 route 수트가 다시 돈다.** 키 없는 검사가 무는지는 CI 「게이트가 무는가」 스텝이 변조본으로 본다 — `eval.yml` 70 ~ 778 줄,
멈춤 자리(`::error::`) 63(2026-10-12, `main` 0202faa). 검사의 줄을 바꾸면 그 줄을 글자로 든 변조본도 같이 고쳐야 하는데, `eval.yml` 은
수트에 깃발을 넘기는 파일이라 통째로 수트 지문(`eval-key.py`)에 든다. 변조본만 고쳐도 지문이 바뀌어 route 수트(route-* × 3회 = 24회)가
다시 돈다.

- 조각 3 #18 은 머리 넷이 다 이 스텝을 고쳐 수트가 한 번이 아니라 네 번 돌았다(조각 3 「닫으며」).
- 그 스텝이 선 뒤 `eval.yml` 을 고친 커밋 59 가운데 40 은 이 스텝 **안만** 고쳤다 — 수트가 읽는 깃발은 그대로인데 지문이 바뀌었다
  (2026-10-12, `git log -- .github/workflows/eval.yml` 의 커밋마다 diff 의 덩어리가 그 커밋의 스텝 안인지 셌다).
- 그래서 조각 7 · 9 · 10 은 제 검사의 변조본을 `eval.yml` 대신 `gates.sh` 가 부르는 `bite-*.py` 셋에 두었다(ADR 0016 의 6 · ADR 0018 의
  6 · ADR 0019 의 5). 변조본이 두 자리로 갈렸고 — 새 검사를 세우는 사람은 어느 쪽에 둘지 고른다(`CLAUDE.md` 「작업 방식」) — 옛 검사를
  고칠 때는 여전히 `eval.yml` 을 고친다.
- 조각 4 #22 Codex 3회차가 짚은 둘도 이 스텝 안이라 넘겨 왔다(조각 4 「닫으며」). 그 가운데 하나 — 가짜 트레이스가 수트 모델 id
  `claude-sonnet-5-5` 를 글자로 들어, 수트 모델을 바꾸면 `run-evals.sh` 와 함께 이 스텝을 손으로 고친다(`CLAUDE.md` 「스택」).

## 핵심 사용자와 시나리오

- 사용자: 저자 한 명, 그리고 claude-kit 에서 검사를 고치는 세션.
- 시나리오: 리뷰가 `verify-evals.py` 의 지적을 낸다 → 세션이 검사를 고치고 그 줄을 글자로 든 변조본을 `scripts/bite-gates.sh` 에서
  따라 고친다 → 로컬 `./scripts/gates.sh` 가 변조본까지 돌려 통과하고, 커밋 안 한 수정은 그대로 남는다 → 푸시하면 CI gate 잡이 같은
  `gates.sh` 를 돌린다 → 바꾼 파일이 수트 지문 밖이라 `eval-key.py route` 가 앞서 통과한 지문과 같고, eval 잡은 건너뛰며 verdict 가
  「같은 입력이 이미 통과했다」로 초록이다. 나중에 저자가 `run-evals.sh` 의 수트 모델을 바꾸면 변조본은 손대지 않아도 새 모델로 가짜
  트레이스를 만든다.

## 성공 기준

1. `eval.yml` 에 「게이트가 무는가」 스텝이 없고, 그 변조본이 다 `scripts/bite-gates.sh` 에서 돌며, `gates.sh` 가 그것을 부른다 —
   `./scripts/gates.sh` 가 로컬과 CI gate 잡에서 스물둘 다 통과한다.
2. 옮김이 변조본을 바꾸지 않았다 — `eval.yml` 기준의 스텝 본문과 `bite-gates.sh` 의 diff 가 설계 ② 가 허락한 자리(B2)뿐이고, 멈춤 자리
   63 이 그대로 있다. 어긋내 보기 — 검사 하나를 늘 통과하게 망가뜨리면 `bite-gates.sh` 가 떨어진다.
3. `bite-gates.sh` 가 수트 지문 밖이다 — `eval-key.py route --list` · `full --list` 에 없고, 그 파일만 고친 작업트리의 `eval-key.py route`
   가 기준과 같다. 변조본 파일이 지문에 들면 `bite-gates.sh` 가 떨어진다(K1).
4. 로컬에서 돌려도 작업트리가 그대로다 — `copies.json` 과 지문 시험이 흔드는 파일에 커밋 안 한 수정을 두고 `gates.sh` 를 돌리면, 끝난 뒤
   `git diff` 가 돌리기 전과 바이트로 같다. 변조본이 떨어져 끝나도 · INT · TERM 으로 끊어도 같다.
5. 수트 모델 id 를 `run-evals.sh` 한 군데만 든다 — 임시 작업트리에서 `DEFAULT_MODEL` 을 다른 id 로 바꾸면 `bite-gates.sh` 를 고치지 않고도
   통과하고, `CLAUDE.md` 「스택」에서 변조본을 따라 고치라는 문장이 빠진다.
6. route 수트가 이 조각에서 많아야 한 번 돈다 — 지문에 드는 파일을 바꾸는 것은 `eval.yml` 의 스텝 지움 하나이고, 그 PR 의 첫 머리에서
   한 번 돈 뒤 그 PR 의 다음 머리와 다른 구현 PR 은 같은 지문으로 건너뛴다.

## 하지 않을 일

1. **변조본을 Python 으로 다시 쓰지 않는다** — bash 한 파일로 글자 그대로 옮긴다(ADR 0020 의 2). 검사마다 `bite-*.py` 로 나누는 것도 아니다.
2. **변조 자리를 더하거나 빼지 않는다** — 옮김이다. 더하는 것은 변조본이 지문 밖에 있는지 보는 K1 하나다.
3. **`claude plugin validate` 를 떨어뜨리는 변조본을 두지 않는다** — CLI 판을 고정하지 않아, 하네스가 바뀌면 변조본이 깨질 수 있다
   (ADR 0020 의 4). `docs/architecture.md` 의 「그것을 떨어뜨리는 변조본은 없다」가 그대로다.
4. **수트 지문의 규칙을 바꾸지 않는다** — `eval-key.py` 의 넣고 빼는 것은 그대로고, `eval.yml` 은 수트의 깃발을 들어 지문에 남는다.
   `eval.yml` 의 다른 잡과 스텝도 그대로다.
5. **기존 변조본 셋(`bite-slice-gate.py` · `bite-verify-docs.py` · `bite-map-pin.py`)을 합치지 않는다** — 이미 지문 밖이고 `gates.sh` 가 부른다.
   머리 주석의 「다른 검사의 변조본은 CI 「게이트가 무는가」에 있다」만 고친다.
6. **`gates.sh` 를 빠르게 하지 않는다** — 로컬에서 2분 31초가 6분 남짓으로 는다(2026-10-12 실측, 「게이트가 무는가」 3분 41초). 병렬화 ·
   골라 돌리기는 두지 않는다(ADR 0020 의 1).
7. **수트 모델 · 심판 모델을 바꾸지 않는다** — 바꿔도 변조본이 따라오게만 한다.

## 제약

- 스택: bash · python3 표준 라이브러리, git — 변조본 몇은 역사 전체가 있어야 한다(CI 는 `fetch-depth: 0`).
- 모델 비용: route 수트 **한 번** — `eval.yml` 이 지문에 들어 스텝을 지우는 PR 이 한 번 돌린다. 그 PR 은 `eval.yml` 을 첫 머리에서 지움으로만
  고치고, 리뷰 고침은 지문 밖 파일에만 낸다. 리뷰가 `eval.yml` 로만 고칠 수 있는 지적을 내면 한 번을 더 쓰고 「닫으며」에 적는다(ADR 0020
  의 5). 다른 구현 PR 은 지문에 드는 파일을 건드리지 않는다.
- 글자 예산: 건드리지 않는다 — 플러그인 파일을 고치지 않는다.
- 기간 **하루**.
- `./scripts/gates.sh` 는 스물하나가 그대로 통과하고, 옮기는 PR 부터 스물둘이다.
- 리뷰: PR 본문에 설계 ② 를 적고, 착공 PR 도 구현 PR 도 스킬 `slice-review` 로 가른다. **3라운드**를 넘기면 소유자가 판정한다.

### 제약에서 어긋난 것

- **모델 비용** — route 수트가 한 번이 아니라 두 번 돌았다. 위 성공 기준 6. 리뷰가 `eval.yml` 을 짚은 일은 없어 ADR 0020 의 5 가 감수하기로 한
  「한 번 더」는 쓰지 않았다 — 더 돈 한 번은 `main` 푸시다.
- **플러그인 파일** — 제약은 「플러그인 파일을 고치지 않는다」인데, #49 가 `vibe-audit/evals/README.md` 의 한 문장(CI 「게이트가 무는가」
  → `bite-gates.sh`)을 `vibe-audit` 판 0.3.0 그대로 고쳤다. 같은 착공의 설계 ① 이 그렇게 정했다 — 수트 문서이고 감사자 · 커맨드가 아니라
  판을 올리지 않는다(조각 4 PR B 의 선례). 제약과 설계 ① 이 갈린 채 착공이 머지됐고, `CHECKLIST.md` 「플러그인의 파일을 고쳤다면」의 판
  줄과도 어긋난다. 그래서 이미 설치한 레포는 `claude plugin update` 뒤에도 옛 문장을 든다. 감사자 · 커맨드 · `verify-brief.py` 는 그
  파일을 읽지 않아 감사의 동작은 같고, 글자 예산(감사자 · 커맨드)도 그대로다. 조각 나눔에 줄을 더하지 않는다 — 다음에 `vibe-audit` 판이
  오를 때 함께 간다.
