# 조각 56 — `slice-review` 를 새 단계 3 에 맞추기 (2026-11-05 착공)

요구사항이다 — **무엇을 · 왜.** 어떻게 · 경계는 같은 폴더의 `design.md`, 대안이 있던 결정은 ADR.

이 조각을 「다음 조각」으로 적은 닫힌 조각은 조각 55(같은 목록의 두 벌 셋)다 — 그 `## 닫으며 (2026-11-05)` 를 읽었다. 넘겨받은 것은 프로필 쌍을 이 줄에 합친 것(ADR 0074 의 1)과, 이 줄의
꺼내는 조건을 「이 줄 밖에서 지도 링크를 다시 박는 조각보다 먼저」로 고친 것(감사 회차 34 OB-43)이다. 의존한 조각 54(감사자가 거듭 청한 절차 물음)는 `닫힘` 이다. 저자가 이 착공 세션에서
갈래 셋을 정했다 — 셋 다 세션이 추천한 쪽이다(ADR 0075 의 1 ~ 3). 착공은 `main`(`e6ee6b5`) 위에서 연다. 이 착공 세션의 클론은 얕지 않았다(`git rev-parse --is-shallow-repository` → `false`).

## 문제

**리뷰 지적을 가르는 스킬이 절차 지도와 다르게 말한다.** 조각 54 가 지도에 두 길을 냈다(ADR 0073 의 2) — 구현 PR 은 소유자가 정한 새 ADR 로 설계 ⑥ 과 하지 않을 일을 넓힐 수 있고, 닫는 PR 은
소유자가 판정한 대장 줄의 고침을 싣는다. 지도는 갈래 · 기준의 규칙을 스킬 `slice-review` 하나가 든다고 하는데, 스킬은 그 전 글 그대로다.

| 스킬 자리 | 지금 말 | 지도와 부딪히는 것 |
|---|---|---|
| `slice-review/SKILL.md:18` | 닫는 PR 의 기준 — 성공 기준 · 단계 6 의 나가는 조건 | 판정 고침이 기준에 없다 |
| `:20` | 그 PR 이 새로 들이는 ADR 은 기준이 아니다 | 넓힘 ADR 을 같은 PR 에 실으면 기준에 들지 않는다 |
| `:28` | 하지 않을 일을 하거나 ⑥ 의 그 줄 밖을 하면 **안** — 고친다 | 넓힘도 판정 고침도 「안」이 된다 |
| `:39` | ⑥ 밖의 보장은 조각 나눔의 줄로 넘긴다 | ADR 0073 의 2 가 버린 대안과 같은 길이다 |

- **이 저장소는 풀린다, 다른 레포는 아니다** — 여기서는 ADR 0073 이 「닿는 ADR」이다. 두 스킬의 지도 링크를 다시 박으면 다른 레포의 세션은 새 단계 3 과 옛 스킬을 함께 읽고, 같은 PR 을 지도로는
  소유자 판정으로 · 스킬로는 「안」으로 가른다(감사 회차 32 「문서에 없어서」).
- **글자 예산이 빠듯하다** — `slice-review` 는 호출 시 4494 자, 천장 4500 자다(`scripts/verify-budget.py`).
- **프로필 쌍** — 틀 머리 주석(`slice-docs/templates/profile.md:14`)과 스킬 `slice-docs` 의 줄(`SKILL.md:42-43`)이 「이미 있는 프로필에서 고치는 것」을 따로 들고 다르다(회차 25 OB-27 ·
  ADR 0074 의 1). 고치면 `vibe-slice/` 가 바뀌어 지도 링크를 다시 박게 되므로 이 조각에 모았다.
- **지도 링크가 낡았다** — 두 스킬이 `86d27cc` 의 지도를 박았고, 지도는 조각 54(`47f46fd`)가 고쳤다. `vibe-slice/` 를 고치는 PR 은 `verify-map-pin.py` M5 로 링크를 다시 박아야 한다.

## 핵심 사용자와 시나리오

- 사용자: 다른 레포에서 `vibe-slice` 0.9.4 를 받아 조각을 진행하는 세션.
- 시나리오: 구현 PR 이 ⑥ 의 그 줄 밖의 고침 하나를 싣고, 같은 PR 의 새 ADR 이 넓힌 ⑥ 줄과 하지 않을 일 2 를 들며 소유자가 정했다 → 리뷰 봇이 「⑥ 밖이다」라고 짚는다 → 세션이 `slice-review` 를
  부르면 그 ADR 과 넓힌 몫을 기준에 넣어 「안」으로 가르지 않는다. 닫는 PR 이 대장의 「고침」 판정 줄을 고친 코드를 싣고 리뷰가 「하지 않을 일 3 위반」이라 짚어도, 스킬이 그 고침을 기준으로 받아
  가른다. 스킬이 가리키는 지도 링크를 열면 같은 말이 있다.

## 성공 기준

1. **결정이 기록된다** — 착공 PR 이 ADR 0075 를 더하고, 그 ADR 이 1 ~ 3 을 저자가 정한 것으로 든다.
2. **스킬이 지도와 같은 말을 한다** — PR A 뒤 `slice-review/SKILL.md` 의 설계 ③ A 네 자리가 넓힘 ADR(소유자가 정한 것)과 닫는 PR 의 판정 고침을 기준으로 받고, 그 규칙을 옮겨 적지 않고 지도의
   단계 3 · 「닫는 PR」 단락을 가리킨다. ⑥ 밖의 보장을 「조각 나눔의 줄로만」 넘기는 글이 남지 않는다.
3. **천장 안이다** — PR A 뒤 `python3 scripts/verify-budget.py` 가 PASS 이고 `SKILL_ON_INVOKE_MAX` 가 4500 그대로다. `slice-review` 의 호출 시 문자가 4500 이하다.
4. **프로필 쌍이 한 자리다** — PR A 뒤 `profile.md` 머리 주석이 「이미 있는 프로필에서 고치는 것」의 목록을 들지 않고 스킬 `slice-docs` 를 가리킨다. 스킬 `slice-docs` 의 그 줄은 그대로다.
5. **지도 링크가 지금 지도다** — PR A 뒤 `python3 scripts/verify-map-pin.py` 가 PASS 이고, 박은 커밋의 `docs/procedure.md` 가 그 PR 머리의 것과 같다.
6. **판이 오른다** — PR A 뒤 `vibe-slice/.claude-plugin/plugin.json` 이 0.9.4 이고 `python3 scripts/verify-manifest.py` 가 PASS 다.
7. **지도 · `vibe-audit` · 수트는 그대로다** — `git diff --stat e6ee6b5 <각 머지> -- docs/procedure.md vibe-audit .github ':(exclude)vibe-audit/evals/budget.txt'` 가 비고, 이 조각의 PR 마다 `eval-key.py route` · `full` 이 `main` 과 같다.
8. **게이트** — `./scripts/gates.sh` 가 이 조각의 PR 마다 작업트리와 CI gate 잡에서 통과한다.
9. **감사 회차** — 닫기 전 감사 회차를 돌려 `docs/audit/` 의 대장에 등록했다.

## 하지 않을 일

1. **절차 지도를 고치지 않는다** — 단계 3 · 6 · 「닫는 PR」 단락이 앞선다(ADR 0075 의 1). `docs/procedure.md` 는 그대로다.
2. **글자 천장을 올리지 않는다** — `SKILL_ON_INVOKE_MAX` 는 4500 그대로다(ADR 0075 의 2 · ADR 0004).
3. **틀 머리 주석의 다른 목록을 다루지 않는다** — 인터뷰 물음 · 혼자 · 여럿의 줄은 그대로다. 「목록」이 어디까지인지는 조각 나눔 「같은 목록의 경계」가 든다.
4. **스킬의 다른 규칙을 바꾸지 않는다** — 갈래 · 멈춤 · 답글 · 회차 표의 뜻이 그대로다. 예산을 맞추려 줄이는 문장도 뜻을 바꾸지 않는다.
5. **`vibe-audit/` 를 고치지 않는다** — 감사자 · 커맨드 · 판 · 수트 지문이 그대로다. 예산 스냅숏 `vibe-audit/evals/budget.txt` 만 바뀐다 — 두 플러그인이 같이 쓰는 스냅숏이고 수트 지문 밖이다.
6. **사본 레포에 다시 심지 않는다** — `sync-slice.sh` 로 다른 레포의 `.claude/skills/` 를 덮는 일은 그 레포의 몫이다.
7. **조각 나눔의 다른 줄을 다루지 않는다** — 「`/audit-brief` 커맨드의 제외 목록」 · 「같은 목록의 경계」 · 「새 장치는 새어 나간 결함에만」 · 「걷은 사본의 대장 줄」 등.

## 제약

- 스택: 마크다운 · JSON. 스크립트를 고치지 않는다.
- 원본: `main` `e6ee6b5`.
- 비용: **$0** — 측정이 없다. `vibe-slice/` 는 수트 지문 밖이다(`scripts/eval-key.py` 머리).
- 기간: 닫기까지 **사흘**(2026-11-08 까지).
- 리뷰: 착공 PR 도 구현 PR 도 스킬 `slice-review` 로 가른다. PR 마다 **3라운드**를 넘기면 소유자가 판정한다.
- 감사 회차: 닫기 전 — `audit-internal`(바뀌는 것 — 스킬 `slice-review` · 틀 머리 주석이 절차 지도 · 규칙 5 와 같은 말을 하는가) · `audit-quality`(대장이 이 조각에 기대는 것 — NC-38 이
  고침으로 다음 `audit-quality` 회차를 기다린다).
