# 조각 57 설계 — 새 장치는 새어 나간 결함에만

설계다 — **어떻게 · 경계.** 무엇을 · 왜는 같은 폴더의 `requirements.md`.

## ① 바뀌는 것

| 파일 | PR | 무엇 |
|---|---|---|
| `docs/master-plan.md` | 착공 · 닫기 | 조각 나눔 — 「새 장치는 새어 나간 결함에만」을 순서 57 · `진행` 으로 · 조각 폴더. 닫기에서 `닫힘` · 다음 조각 |
| `docs/slices/57-leaked-defects-only/` · `docs/adr/0076-leaked-defects-only.md` | 착공 | 이 요구사항 · 설계 · ADR |
| `CLAUDE.md` | A | 「작업 방식」에 줄 하나 — 「새 검사를 세우면 …」 줄 바로 앞. ③ A · ③ B · 막지 않는 것 · ADR 0076 |
| `CHECKLIST.md` | A | 「항상」의 「새 검사를 세웠다면」 줄을 고친다 — 새 장치를 세웠다면 그 ADR 이 새어 나간 결함을 가리키고 그 꼴에서 떨어지는지를 묻고, 장치 · 증거의 목록은 `CLAUDE.md` 를 가리킨다. 항목을 더하지 않는다 |
| `docs/audit/` | 닫기 | 닫기 전 감사 회차의 기록 · 브리핑 · 대장 등록. NC-39 의 판정 |

앵커볼트는 건드리지 않는다 — `CLAUDE.md` 의 절 제목 셋(「…의 칸」 원천)이 그대로이고 줄 하나를 더할 뿐이다. 「가변」의 「검사가 읽는 글」도 아니다 — `scripts/verify-counts.py` 가 `CLAUDE.md` ·
`CHECKLIST.md` 에서 읽는 닻(`읽기 전용 {N}.` · `「…의 칸」 {N} 절` · `틀 {N}도` · `검사 {N}(`)을 고치지 않는다. 스크립트 · 플러그인 · CI 는 그대로다. 시스템 구조(`docs/architecture.md`)는
그대로다 — 부품 · 경계 · 흐름이 같다.

## ② 보장하는 것 / 보장하지 않는 것

**보장하는 것**

- **A 한 자리** — 「언제 새 장치를 세우나」는 `CLAUDE.md` 「작업 방식」의 한 줄이 든다. 무엇이 새 장치이고(③ A) 무엇이 증거이며(③ B) 무엇을 막지 않는지는 그 줄이 들고, `CHECKLIST.md` 는
  그 줄을 가리킨다(ADR 0073 의 5). ADR 0076 은 그날의 결정이다.
- **B 증거와 장치가 맞물린다** — 새 장치의 ADR 이 증거 하나 이상을 번호나 링크로 들고, 그 장치는 그 결함의 꼴에서 떨어진다. 「무는 것 · 재는 것이 없다」는 것만으로는 증거가 아니다.
- **C 고침을 막지 않는다** — 있는 규칙이 같은 것을 계속 물게 하는 고침(읽는 글의 변경 · 오검 · 놓침)과, 있는 규칙이 이미 요구하는 대상 줄(③ A 의 「막지 않음」)은 증거 없이 된다.
- **D NC-39 가 갈린다** — 닫는 세션이 이 규칙을 근거로 NC-39 의 판정을 저자에게 올린다(세션의 추천은 반박 — ADR 0076 의 4).
- **E 장치가 늘지 않는다** — 요구사항 성공 기준 5.

**보장하지 않는 것(알려진 한계)**

- **규칙을 어긴 PR 을 키 없이 막지 않는다** — 사람(`CHECKLIST.md`)과 닫기 전 감사 회차가 본다. 이 규칙을 무는 검사는 그 자신이 새어 나간 결함 없는 장치다(ADR 0076 의 3).
- **이미 선 장치가 증거를 가졌는지 가르지 않는다** — 소급하지 않는다(하지 않을 일 1).
- **「같은 꼴에서 떨어진다」를 재지 않는다** — 증거의 결함을 되돌린 변조본에서 떨어지는지는 그 장치를 세우는 조각의 설계 ⑤ 가 든다.
- **다른 레포의 규칙** — 그 레포의 `CLAUDE.md` 가 정한다(하지 않을 일 4).
- **리뷰가 이 밖을 짚으면 범위 밖이다** — 요구사항 하지 않을 일.

## ③ 받는 입력

검사 장치가 아니다 — 규칙이 가르는 대상을 이 저장소의 실제 장치에서 뽑은 닫힌 목록으로 든다. 이 밖의 꼴이 나오면 그것을 세우는 조각이 이 표에 비춰 저자에게 묻는다.

**A 무엇이 새 장치인가** — 단위는 새 실패 조건이다(ADR 0076 의 2).

| 꼴 | 예(착공 `f8cf848`) | 가름 |
|---|---|---|
| 새 검사 · 시험 스크립트 | `scripts/verify-*.py` · `test-*.py` · `bite-*.py` | 새 장치 |
| 게이트의 새 줄 · CI 의 새 잡 · 떨어지는 새 스텝 | `scripts/gates.sh` 가 부르는 것 28 · `.github/workflows/eval.yml` 의 잡 | 새 장치 |
| 있는 검사의 새 규칙 — 새 규칙 ID · 새 실패 머리 줄 | `verify-docs.py` 의 `C1` · `F1` 따위 · `verify-map-pin.py` 의 `M1` ~ `M6` | 새 장치 |
| 새 변조본 · 대조군 | `bite-gates.sh` · `bite-*.py` · `test-*.py` 의 변조본 | 새 장치. 새로 세운 장치의 변조본은 그 장치와 한 몫이다(`CLAUDE.md` 「새 검사를 세우면」) |
| 새 평가 케이스 | `vibe-audit/evals/<케이스>/` · `vibe-audit/recall/<케이스>/` | 새 장치. 되먹임 한 건의 케이스는 그 되먹임이 증거다(`CLAUDE.md` 「되먹임 한 건에 eval 케이스 하나」) |
| 있는 규칙이 이미 요구하는 대상 줄 | `verify-counts.py` `ANCHORS` 의 닻 · `test-gates.py` 고정 목록의 이름 · 원천 표의 행 | **막지 않음** — 규칙은 그대로이고 대상이 늘 뿐이다 |
| 있는 규칙을 같은 것을 물게 고치기 | 읽는 글이 바뀐 검사의 고침(`CLAUDE.md` 「가변」) · 오검 · 놓침의 고침 | **막지 않음** — 놓침의 고침은 놓친 결함이 그 자체로 증거다 |
| 떨어뜨리지 않는 측정 | `scripts/run-compare.sh` · `compare/` · 러너의 보고 칸 | **규칙 밖** — PR 을 떨어뜨리지 않는다(ADR 0076 의 5) |
| 사람이 보는 줄 | `CHECKLIST.md` 의 항목 | **규칙 밖** — 키 없이 무는 것이 아니다 |

**B 무엇이 새어 나간 결함의 증거인가** — 그때의 게이트(`gates.sh` · CI)가 초록인 머리에서 드러난 틀린 결과다(ADR 0076 의 5).

| 증거 | 드는 법 |
|---|---|
| 대장의 부적합 — 감사 회차가 낸 NC 가운데 반박되지 않은 것 | NC 번호 |
| 리뷰 지적 — 스킬 `slice-review` 로 「안」으로 갈라 고친 결함 | PR 링크와 회차 표의 그 줄 |
| 사본 되먹임 — `feedback.json` 의 후보 | 후보 번호(FB-n) |
| 머지 뒤 드러난 결함 — 이슈 · 고친 커밋 | 이슈 링크나 커밋 |

증거가 **아닌** 것 — 장치의 부재만 드는 지적(「재는 평가가 없다」 · 「무는 변조본이 없다」), 관찰(OB) · 확인불가(U), 리뷰가 「밖」 · 「말하지 않음」 · 「반박됨」으로 가른 지적.
같은 결함은 한 번만 센다 — 감사와 리뷰가 같은 것을 짚었으면 증거는 하나다.

## ④ 결정

**정한 것**

- 강도 — 완전 동결 · 비율 제한이 아니라 새어 나간 결함에만 — ADR 0076 의 1(저자, 2026-11-02)
- 새 장치의 단위는 새 실패 조건 — ADR 0076 의 2(저자)
- 사람이 본다 — `CHECKLIST.md` 의 있는 줄에 덧붙인다 — ADR 0076 의 3(저자)
- NC-39 의 평가를 세우지 않는다 · 닫는 세션에 반박을 추천한다 — ADR 0076 의 4(저자)
- 증거의 정의(③ B) · 떨어뜨리지 않는 측정은 밖 — ADR 0076 의 5
- 이 저장소의 규칙이고 `vibe-slice` 틀에 넣지 않는다 — ADR 0076 의 6
- 소급하지 않는다 — ADR 0076 의 7
- 감사 회차 `audit-quality` · `audit-internal` — ADR 0076 의 8

**열어 둔 것**

없음 — 두 줄의 글은 PR A 가 쓰고 리뷰가 본다. 줄이 들 것은 ② A · ③ 이 닫는다.

## ⑤ 검증 계획

시험을 세우지 않는다 — 규칙의 문구다. 있는 검사와 `git` 에 대어 본다.

| 보장 | 무엇으로 보이나 |
|---|---|
| A 한 자리 | PR A 본문에 `CLAUDE.md` 새 줄 · `CHECKLIST.md` 고친 줄의 글. `CHECKLIST.md` 새 글에 ③ A 의 꼴 이름(「규칙 ID」 · 「평가 케이스」 따위)과 ③ B 의 증거 이름(「NC」 · 「되먹임」 따위)이 옮겨 적히지 않았는지 `grep` 결과를 든다. `git diff --stat` 의 `CLAUDE.md` 덩이가 줄 더하기뿐이고 `grep -n '^## ' CLAUDE.md` 가 착공과 같다 |
| B 맞물린다 | `CLAUDE.md` 새 줄에 「ADR 이 증거를 가리킨다」와 「그 꼴에서 떨어진다」가 있다 — PR A 본문 |
| C 고침을 막지 않는다 | `CLAUDE.md` 새 줄에 ③ A 의 「막지 않음」 두 꼴이 있다 — PR A 본문 |
| D NC-39 | 닫는 PR 의 `## 닫으며` 와 대장의 NC-39 판정 칸 |
| E 늘지 않는다 | 요구사항 성공 기준 5 의 명령 |

- **게이트** — `./scripts/gates.sh` 를 PR 마다 돌리고 끝 줄을 PR 본문에 든다. `python3 scripts/verify-counts.py` · `python3 scripts/verify-docs.py` 가 PASS 다(`CLAUDE.md` 의 닻 · 절 제목).
