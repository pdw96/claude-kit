# 조각 65 — 상시 회차의 문턱 (2026-11-10 착공)

요구사항이다 — **무엇을 · 왜.** 어떻게 · 경계는 같은 폴더의 `design.md`, 대안이 있던 결정은 ADR 0084.

이 조각을 「다음 조각」으로 적은 닫힌 조각은 조각 64(넘긴 일이 받지 않는 꼴)다 — 그 `## 닫으며 (2026-11-10)` 를 읽었다. 넘겨받은 것은 없다 — 회차 45 의 NC-51 · NC-52 는 고침으로 다음
`audit-internal` 회차를 기다리고, 「문서에 없어서」 A · B 는 조각 나눔 「넘김의 「다음」과 넘긴 감사자」로 갔다. 이 줄의 근거는 조각 58 의 닫는 세션이 회차 39 「문서에 없어서」 A 로 두었다.
의존은 `—` 다. 저자가 이 착공 세션에서 문턱의 갈래를 정했다 — 세션이 추천한 쪽(ADR 0084 의 1). 착공은 `main`(`383a82e`) 위에서 연다. 이 착공 세션의 클론은 얕지 않았다(`git
rev-parse --is-shallow-repository` → `false`).

## 문제

**상시 회차의 문턱이 예시에 걸려 있어, 예시 밖 꼴의 새 장치를 더하는 조각에 그 회차가 서는지 정해져 있지 않다.**

- `CLAUDE.md` 「작업 방식」의 「새 장치는 새어 나간 결함에만」 줄은 정의를 「새 장치는 새 실패 조건이다」로 두고, 「두 「—」 뒤는 예시이고 정의는 그 앞의 말이다 — 예시에 없는 꼴이면
  세우는 조각이 저자에게 묻는다」고 한다. 그런데 같은 줄 끝의 상시 회차는 「첫 「—」 뒤의 꼴을 더하거나 고치는 조각」에 선다(ADR 0077 의 3) — 예시다.
- 예시 밖 꼴이 이미 둘 있다 — 있는 케이스의 새 그레이더 · 정규식(과 그것이 요구하는 표본), 문턱 · 천장 조이기(감사 회차 37 OB-4, `docs/audit/records/audit-quality-2026-11-06-073737.md`).
  그런 꼴을 더하는 조각은 담당 표로 `audit-quality` 만 걸리고, 「새 장치에 증거가 있는가」를 보는 `audit-internal` 이 서는지는 아무 데도 없다(감사 회차 39 「문서에 없어서」 A,
  `docs/audit/records/audit-internal-2026-11-09-052447.md`).
- 지금 그 꼴은 「저자에게 묻는다」로만 간다. 묻는 일은 세션이 그 꼴이 예시 밖인 줄을 알아챌 때만 일어난다 — ADR 0077 의 3 이 문턱을 가름에 두지 않은 까닭(「가름이 틀린 조각이 바로 회차를
  받지 못한다」)이 예시 밖에 남는다.
- 새어 나간 결함은 없다 — ADR 0077 뒤 실패 조건을 고친 조각이 없다(설계 ③ B). 규칙 글끼리의 빈자리다.

## 핵심 사용자와 시나리오

- 사용자: 있는 eval 케이스에 그레이더를 더하거나 검사의 천장을 조이는 조각을 착공하는 세션과, 그 조각의 닫기 전 `audit-internal` 회차.
- 시나리오: 세션이 착공 문서를 쓰며 `CLAUDE.md` 「새 장치는 새어 나간 결함에만」 줄을 읽는다 → 그레이더는 첫 「—」 뒤에 이름이 없지만 무엇이 떨어지는지를 바꾸므로 실패 조건을 더하는
  조각으로 읽는다 → 새 장치인지(증거가 필요한지)는 저자에게 묻고, 답과 상관없이 감사 회차 줄에 닫기 전 `audit-internal` 을 상시 회차로 든다 → 그 회차가 새 그레이더의 ADR 이 새어 나간
  결함을 드는지 본다.

## 성공 기준

1. **결정이 기록된다** — 착공 PR 이 ADR 0084 를 더하고, 그 ADR 이 1 을 이 착공 세션의 저자가 정한 것으로 들며 머리에 「ADR 0077 의 3 을 대체한다」를 든다. 같은 PR 이 ADR 0077 끝에
   `## 대체 (2026-11-10)` 절과 「- 3 은 ADR 0084 가 대체했다 — …」를 덧붙인다.
2. **문턱이 정의에 선다** — PR A 뒤 `CLAUDE.md` 「새 장치는 새어 나간 결함에만」 줄의 끝 문장이 (가) 상시 회차의 문턱을 실패 조건을 더하거나 고치는 조각으로 두고, (나) 첫 「—」 뒤를 그
   예시로 두며, (다) 규칙이 그대로인 대상 줄은 밖이고 규칙의 고침은 안인 것을 들거나 같은 줄의 「막지 않는다」 문장을 가리키고, (라) ADR 0084 를 든다.
3. **한 자리다** — PR A 뒤 `grep -rn '상시 회차다' CLAUDE.md docs/procedure.md CHECKLIST.md AGENTS.md README.md` 가 `CLAUDE.md` 한 줄이다. 꼴의 이름을 다시 적지 않는다.
4. **설계 ③ 의 꼴이 선다** — 설계 ③ A 의 행마다 PR A 의 문장이 「안」 · 「밖」 하나를 내고, PR A 본문이 행마다 한 줄씩 든다.
5. **장치가 늘지 않는다** — `git diff --stat 383a82e <각 머지> -- scripts .github vibe-audit vibe-slice compare` 가 빈 출력이다. 수트 지문(`scripts/eval-key.py route` · `full`)이 `383a82e`
   과 같다.
6. **게이트** — `./scripts/gates.sh` 가 이 조각의 PR 마다 작업트리와 CI gate 잡에서 통과한다. `python3 scripts/verify-docs.py` · `python3 scripts/verify-counts.py` ·
   `python3 scripts/verify-map-pin.py` 가 PASS 다(절 제목 · 새 수 없음 · 지도를 고치지 않음).
7. **감사 회차** — 닫기 전 감사 회차를 돌려 `docs/audit/` 의 대장에 등록했다.

## 하지 않을 일

1. **검사를 세우지 않는다** — 문턱을 무는 검사가 없다. 새 실패 조건이 없다(ADR 0084 의 5).
2. **「새 장치」의 정의 · 증거 · 막지 않는 것을 고치지 않는다** — 같은 줄의 끝 문장 하나만 고친다. 첫 「—」 뒤의 예시에 그레이더 · 문턱 조이기를 더하지 않는다 — 예시를 늘리는 일이
   아니라 문턱을 정의에 두는 일이다. 「저자에게 묻는다」도 그대로다.
3. **지난 기록을 고치지 않는다 — 소급하지 않는다** — ADR 0077 의 본문 · 조각 58 ~ 64 의 요구사항 · 설계 · 감사 기록은 글자 그대로다. ADR 0077 은 끝에 대체 절만 덧붙인다(ADR 0084 의 4).
4. **다른 자리를 고치지 않는다** — `docs/procedure.md`(원천 셋째의 예시 포함) · `CHECKLIST.md` · `AGENTS.md` · `README.md` · `INTENT.md` 는 그대로다(ADR 0084 의 3).
5. **`vibe-audit` · `vibe-slice` 를 고치지 않는다** — 감사자 문구 · 커맨드 · 스킬 · 틀 · 판 · 수트 지문 · 사본 · 두 스킬의 지도 링크가 그대로다. 상시 회차를 다른 레포에 보내지 않는다(ADR
   0077 의 2 그대로).
6. **조각 나눔의 다른 줄을 다루지 않는다** — 「닫는 PR 의 글을 보는 회차」 · 「ADR 대체 표기의 자리」 · 「넘김의 「다음」과 넘긴 감사자」 · 「규칙 5 표의 행 사이와 답의 꼴」 등.

## 제약

- 스택: 마크다운. 스크립트를 고치지 않는다.
- 원본: `main` `383a82e`.
- 비용: **$0** — 측정이 없다. 수트 지문은 `vibe-audit/` 만 읽는다(`scripts/eval-key.py` 머리) — 이 조각은 그 밖이다.
- 기간: 닫기까지 **사흘**(2026-11-13 까지).
- 리뷰: 착공 PR 도 구현 PR 도 스킬 `slice-review` 로 가른다. PR 마다 **3라운드**를 넘기면 소유자가 판정한다.
- 감사 회차: 닫기 전 — `audit-internal`(바뀌는 것 — `CLAUDE.md` 의 규칙 글: 끝 문장 · ADR 0084 · 설계 ② 가 같은 말을 하는가, 설계 ③ A 의 행마다 「안」 · 「밖」 하나가 나는가, 같은 줄의
  정의 · 「저자에게 묻는다」 · 「막지 않는다」와 갈리지 않는가, ADR 0077 의 대체 절이 양쪽에 있는가. 대장이 이 조각에 기대는 것 — NC-51 · NC-52 가 고침으로 다음 `audit-internal` 회차를
  기다린다(`docs/audit/nc-ledger.md`). 이 조각이 넘긴 일 — 문턱을 무는 검사가 없어 이 회차가 본다(설계 ②)). `audit-quality` 는 고르지 않는다 — 검사 · 변조본 · 평가셋이 바뀌지 않고, 실패
  조건을 더하거나 고치지 않아 새 문턱으로도 상시 회차가 걸리지 않는다(ADR 0084 의 6).
