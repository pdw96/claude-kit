## ② 보장하는 것 / 보장하지 않는 것

**보장하는 것** — 번호는 조각 3 설계 ② 와 조각 9 설계 ② 에 잇는다. ⑤ 와 B 의 PR 본문이 같이 쓴다.

- C1 **루트에 `CLAUDE.md` 가 저장소 안의 파일로 있다.** 없거나 · 폴더거나 · 저장소 밖을 가리키는 링크면 떨어진다. 두 모드에서 같다. 마스터플랜이
  없으면(O3) 묻지 않는다 — 가리킬 것이 없다. 다른 레포 모드에서 첫 조각 전이어도 묻는다 — 스킬이 처음 쓰는 호출에서 쓴다(ADR 0041 의 10).
- C2 **`CLAUDE.md` 가 의도를 가리킨다.** 마스터플랜 「가리키는 문서」 의도 줄의 첫 경로 토막(I2 가 읽는 것)이 ③ 의 꼴로 `CLAUDE.md` 에 없으면
  떨어진다. 의도 줄이 I1 · I2 로 떨어졌거나 C1 로 떨어졌으면 묻지 않는다 — 한 까닭에 실패 줄 하나.
- C3 **`CLAUDE.md` 가 마스터플랜을 가리킨다.** `docs/master-plan.md` 가 ③ 의 꼴로 없으면 떨어진다. C1 로 떨어졌으면 묻지 않는다.
- **「`CLAUDE.md` 의 칸」이 다섯째 원천이다** — 이 저장소 모드는 지도의 그 절(O1 · O2)과 틀(T1 · T2)을, 다른 레포 모드는 검사 옆 틀(A1 · A2)을 다른
  넷과 같은 규칙으로 본다. 새 번호가 아니라 지금 규칙의 넓힘이다. 그 절이 원천이 되는 것은 틀의 모양뿐이다 — `CLAUDE.md` 자체의 절 제목은 묻지
  않는다(하지 않을 일 1).
- R1 · R2 가 그대로 선다 — `CLAUDE.md` 를 읽지 못하면 다른 문서와 같이 R1 로 찍고, 새 검사도 모델 · 네트워크 · git 을 부르지 않는다.
- 자체 시험에 C1 · C2 · C3 의 꼴이 있고(⑤ V1 · V2), 변조본이 그 자리마다 하나씩 자체 시험에서 떨어진다(⑤ V3) — 조각 3 · 9 의 시험 틀 그대로다.
- **스킬** — `slice-docs` 는 처음 쓰는 호출에서 의도 · 마스터플랜과 함께 `CLAUDE.md` 를 다룬다. 없으면 `/init` 을 먼저 부르라고 말하고, 그 뒤 틀의 세
  절을 인터뷰로 받아 쓴다. 있으면 덮지 않고, 빠진 절과 가리키는 줄을 사용자에게 먼저 보인 뒤 받으면 더한다(ADR 0041 의 3 · 4). 스킬의 이 행동은 키
  없는 검사가 없다 — 사람이 본다.
- **사본** — C 뒤 ERP 의 두 사본 머리줄 출처가 B 의 머지 커밋이고, ERP 에서 `verify-docs.py --repo .` 가 0 이다.

**보장하지 않는 것(알려진 한계)**

- **`CLAUDE.md` 의 절 제목과 문장의 뜻** — 하지 않을 일 1 · 5.
- **루트 밖의 `CLAUDE.md`** — 하위 폴더 · `.claude/CLAUDE.md` · `CLAUDE.local.md` 는 보지 않는다. Claude Code 는 그것들도 읽지만, 세 레포가 다 루트에
  둔다(③).
- **대소문자를 가리지 않는 파일 시스템** — macOS · Windows 에서는 `claude.md` 도 C1 을 지난다. 겪지 않은 꼴이다.
- **다른 사본 레포 · 이미 설치한 플러그인** — C 가 심는 것은 ERP 하나다. 플러그인으로 받은 세션은 `claude plugin update vibe-slice@pdw96-kit` 뒤에
  새 틀과 검사를 읽는다(ADR 0013).
- **아직 겪지 않은 가설적 경계 사례** — 조각 3 설계 ② 의 같은 줄 그대로다.

## ③ 받는 입력

**`CLAUDE.md`** — 저장소 맨 위의 그 이름 하나. 줄은 다른 문서와 같은 `lines()` 로 읽는다 — 코드 펜스 안과 줄 머리에서 연 주석 안은 뺀다.

**가리키는 줄의 꼴** — 세 레포의 `CLAUDE.md`(2026-10-20 기본 가지 — claude-kit `a6fdee5` · ERP `68ac6c4` · 강호쟁패 `8dc3c06`)에서 뽑은 닫힌 목록이다.
의도와 마스터플랜을 가리키는 자리는 다 한 꼴이다.

| 꼴 | 보기 | 세 레포의 자리 | 판정 |
|---|---|---|---|
| 백틱 토막 하나가 경로와 글자 그대로 같다 | `` `INTENT.md` `` · `` `PRD.md` `` · `` `docs/master-plan.md` `` | claude-kit 33 · 38, ERP 5 · 46, 강호쟁패 5 · 114 | 가리킨다 |

그 밖은 다 가리키지 않는 것으로 읽는다 — 마크다운 링크(`[의도](PRD.md)`), 맨 글자(`PRD.md`), 다른 글자가 섞인 백틱 토막(`` `PRD.md 를 본다` `` ·
`` `./PRD.md` ``), 펜스 · 주석 안의 토막. 세 레포에 없는 꼴이고, 마스터플랜의 「가리키는 문서」가 경로를 백틱 토막으로 받는 것(M2 · I2)과 같은 규칙이다.

**의도의 경로** — 마스터플랜 「가리키는 문서」 의도 줄의 첫 백틱 토막. I2 가 읽는 것과 같다. 세 레포에서 `INTENT.md` · `PRD.md` · `PRD.md` 다.

세 레포의 지금 `CLAUDE.md` 는 다 C1 · C2 · C3 를 지난다 — 이 착공 세션이 `a6fdee5` 의 검사 함수(`lines()` · `section()` · `table()`)로 세 레포의
의도 경로와 백틱 토막을 뽑아 보았다.

## ④ 결정

**정한 것**

- `CLAUDE.md` 를 다섯째 문서로 쓴다 — 틀은 절 제목만, 내용은 인터뷰로. ADR 0041 의 1 · 2.
- 이미 있으면 덮지 않고 보여 준 뒤 더한다 — ADR 0041 의 3.
- 사실은 `/init` 몫 — ADR 0041 의 4.
- 틀의 절 셋과 그 제목 — ADR 0041 의 5.
- 검사는 가리키는 줄만, 없으면 떨어진다 — ADR 0041 의 6 · 10.
- 지도에 「`CLAUDE.md` 의 칸」 — ADR 0041 의 7.
- `AGENTS.md` 는 쓰지 않는다 — ADR 0041 의 8.
- 범위 변경으로 다룬다 — ADR 0041 의 9.
- ERP 다시 심기를 이 조각의 C 로 — ADR 0041 의 11.

**열어 둔 것**

없음 — 착공 인터뷰에서 다 정했다. 「`CLAUDE.md` 의 칸」 표의 「담는 것」 문구와 스킬의 새 줄은 B 가 쓰고, 리뷰가 ② 에 비춰 가른다.

## ⑤ 검증 계획

**시험 규칙** — 키 없이 도는 시험을 넓히는 조각이다. 꼴 하나하나와 보장의 조건 → 꼴 → 변조본의 대응은 B 의 시험 코드와 PR 본문이 든다(ADR 0039).

- V1 **조건마다 거절 꼴 하나 이상, 두 모드에서** — C1 은 없음 · 폴더 · 저장소 밖 링크, C2 · C3 는 ③ 의 거절 꼴마다 하나(링크 · 맨 글자 · 섞인 토막 ·
  펜스 안 · 주석 안). 이 저장소 모드는 베낀 트리의 `CLAUDE.md` 를, 다른 레포 모드는 임시 레포(의도 줄 `PRD.md`)의 `CLAUDE.md` 를 바꾼다.
  묻지 않아야 할 자리 하나씩 — 의도 줄이 I2 로 떨어진 트리에 C2 가 서지 않고, `CLAUDE.md` 가 없는 트리에 C2 · C3 가 서지 않는다.
- V2 **거절 시험은 exit 1 · 기대한 파일 · 선 번호 · 서지 않아야 할 번호가 없음을, 성공 시험은 exit 0 을 본다** — 지금 자체 시험의 규칙 그대로다.
  성공 꼴은 ③ 의 받는 꼴 하나이고, 이 저장소 트리 그대로 · 다른 레포 모드의 첫 조각 전 임시 레포가 다 지난다. 「`CLAUDE.md` 의 칸」 절 · 틀이 빠진
  트리가 O1 · T1 · A2 로 떨어지는 꼴도 하나씩.
- V3 **변조본** — C1 · C2 · C3 의 자리마다 하나가 자체 시험에서 떨어진다 — 이 저장소 모드는 `bite-gates.sh`, 다른 레포 모드는 `bite-verify-docs.py`.
  `KINDS` 의 다섯째를 지운 사본도 하나.
- V4 **세 레포에 댄다** — B 머리의 검사를 ERP · 강호쟁패의 기본 가지에 `--repo` 로 대어 exit 0 인 것을 B 의 PR 본문에 싣는다(요구사항 성공 기준 3).
  고친 검사를 걷어 낸 `a6fdee5` 의 검사에 V1 의 꼴을 대어 지나가는 것도 싣는다 — 검사가 없던 자리임을 보인다.

**그 밖**

- `verify-budget.py` — 스킬 `slice-docs` 의 호출 시 길이(B).
- `verify-map-pin.py` · `verify-manifest.py` — 지도 링크 판과 두 설명(B).
- `./scripts/gates.sh` — B 의 로컬과 CI gate 잡. A 는 결정 문서만이라 관문을 지난다.
- C — ERP 에서 `verify-docs.py --repo .` 를 돌린 결과를 그 PR 본문에 싣는다. 사본 파일 밖의 차이(머리줄 · 지도 링크 말고)가 없는지 원본과 견준다
  (#114 와 같은 확인).
- 단계 5 — B 의 머지가 `vibe-slice` 0.5.0 의 배포이고, C 의 머지가 ERP 사본의 배포다. 되돌리는 길은 C → B 순으로 되돌리고 판을 올리는 것이다.
