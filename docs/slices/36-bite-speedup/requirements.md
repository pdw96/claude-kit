# 조각 36 — 변조 시험 빠르게 (2026-10-23 착공)

요구사항이다 — **무엇을 · 왜.** 어떻게 · 경계는 같은 폴더의 `design.md`, 대안이 있던 결정은 ADR 0047.

이 조각을 「다음 조각」으로 적은 닫힌 조각은 조각 35 다 — 그 `## 닫으며 (2026-10-23)` 가 다음 조각을 「변조 시험 빠르게」(순서 36)로 적고, 이
조각이 넘긴 줄이고 부적합 대장 NC-2 의 기한이 이 조각이라 저자가 골랐다고 했다. 넘긴 것은 NC-2 하나다. 의존 「게이트 변조 시험의 지문 건너뛰기」는
`닫힘` 이다. 조각 나눔의 줄은 「변조본을 함께 돌리거나 첫 실패에서 멈추게」를 이 조각에 넘겼다 — 저자가 이 착공 세션에서 둘 다로 정했다(ADR 0047 의 1).
그 줄이 이 조각에 실은 둘 — NC-2 의 고침과 첫 구현 PR 의 `.gitignore` 한 줄 — 도 든다. 이 착공 세션의 claude-kit 클론은 얕지 않았다
(`git rev-parse --is-shallow-repository` → `false`).

## 문제

**검사 코드를 고친 PR 은 CI gate 잡이 여전히 15 ~ 22분이고, 그 대부분이 문서 대조 검사의 자체 시험 하나를 변조본마다 처음부터 끝까지 다시 돌리는 데
든다.** 조각 35 가 지문이 같은 PR 을 건너뛰게 했지만, 지문이 바뀐 PR — 조각 35 에서만 B · C · D 셋, 그 머지 뒤 `main` 푸시 — 과 로컬은 그대로다.

- **숫자(CI)** — 조각 35 C 첫 머리(run 39883977211) 약 21분 46초, D 첫 머리(run 39903090279) 14분 40초. `main` 푸시 `f2e458d` 의 스텝 17분 9초 가운데
  변조 시험 다섯이 16분 38초 — `bite-gates.sh` 10분 10초 · `bite-verify-docs.py` 5분 13초 · 나머지 셋 1분 15초(run 39761325720).
- **어디서 오나** — `test-verify-docs.py`(CI 한 번 약 12초)를 변조본 일흔하나에 다시 돌린다 — `bite-verify-docs.py` 스물여섯과 `bite-gates.sh` 의 문서 대조 절
  마흔다섯(이 세션이 다시 셌다. 조각 나눔의 줄은 「마흔여섯 · 일흔둘」이라 적었다). 약 14분이다.
- **변조본은 「떨어지는가」만 본다** — `bite-gates.sh` 의 마흔다섯은 자체 시험이 0 이 아닌 종료로 끝났는지만 보고, `bite-verify-docs.py` 는 다른 레포
  모드의 판정 줄 하나 이상만 본다. 그런데 자체 시험은 첫 꼴에서 떨어져도 225 꼴을 끝까지 돈다. 이 세션의 클라우드 컨테이너(4 코어)에서 마흔다섯을
  첫 실패에서 멈추게 흉내 내 돌리니 349초였다 — 끝까지 돌면 한 번 약 31초 × 45 ≈ 23분.
- **하나씩 돈다** — 변조본은 제 사본에서 따로 돌아 서로 기대지 않는데 차례로 돈다. 같은 컨테이너에서 자체 시험 넷을 함께 돌리니 39초였다 — 하나는 31초.
- **로컬** — 같은 컨테이너에서 인자 없는 `gates.sh` 가 약 31분이다(ADR 0046 의 1 · 조각 35 B 30분 40초). 세션이 게이트를 끝까지 보지 않고 CI 에 맡긴다
  (조각 34 · 35 「닫으며」).
- **NC-2** — `test-gates.py` 가 CI 의 인자 없는 꼴(`GITHUB_ACTIONS=true`)과 변조 시험 실패의 전파를 무지 않는다(`docs/audit/nc-ledger.md`). 이 조각이 `bites`
  를 다시 짜므로 저자가 여기서 고치기로 했다.
- **`main` 이 다시 빨개질 자리** — 조각 35 C 의 gate 잡은 `main` 푸시에서 캐시 폴더 `.gate-pass/` 를 작업트리에 둔 채 `gates.sh` 를 부르는데, 관문 검사
  (`verify-slice-gate.py`)의 작업트리 모드가 무시되지 않은 새 파일을 바꾼 파일로 세어 `진행` 조각이 없는 동안 G2 로 떨어진다(run 39925223731).

## 핵심 사용자와 시나리오

- 사용자: 저자 한 명, 그리고 claude-kit 에서 검사를 고치는 세션.
- 시나리오: 세션이 검사 하나를 고친 구현 PR 을 낸다 → 지문이 새것이라 CI gate 잡이 변조 시험까지 다 돈다 → 문서 대조 검사의 변조본마다 자체 시험이
  첫 실패에서 멈추고, 변조본 여럿이 CPU 수만큼 함께 돈다 → 스텝이 6분 안에 끝난다 → 물지 않는 변조본이 있었다면 그 이름이 다 찍히고 빨갛다 → 세션은
  PR 을 내기 전에 로컬에서도 인자 없는 `gates.sh` 를 15분 안에 끝까지 본다 → 저자가 머지한다 → `main` 푸시가 머지된 PR 의 통과를 읽어 건너뛰고(조각 35),
  `.gate-pass/` 가 작업트리에 있어도 관문 검사가 떨어지지 않는다.

## 성공 기준

1. **CI 가 빨라진다** — 이 조각의 B(설계 ⑥ 의 PR 나눔) 첫 머리 — 지문이 새것이라 다 돈다 — 의 「키 없이 도는 게이트」 스텝이 **6분 안**이다(지금 14분 40초 ~
   21분 46초). 로그에서 `bite-verify-docs.py` · `bite-gates.sh` 의 시간을 줄 시각으로 센다.
2. **로컬이 빨라진다** — B 의 작업트리에서 인자 없는 `./scripts/gates.sh` 가 이 클라우드 컨테이너에서 **15분 안**에 「스물다섯 다 통과」를 찍는다(지금 약 31분).
3. **무는 힘은 그대로다** — 변조본 일흔하나가 B 뒤에도 다 떨어지고, 바꾸지 않은 검사를 변조본 자리에 넣은 대조군은 두 변조 시험 다 「물지 않았다」로
   떨어진다. 첫 실패에서 멈추는 자체 시험은 바른 검사에 끝까지 돌아 지금과 같은 수의 꼴을 통과로 센다.
4. **NC-2 를 고친다** — `test-gates.py` 가 `GITHUB_ACTIONS=true` 에 인자 없는 꼴(T1′)과 변조 시험 하나가 떨어진 꼴(T5)을 부르고, 감사가 든 어긋냄 넷
   (분기에 `|| [ GITHUB_ACTIONS = true ]` · `[ GITHUB_ACTIONS = true ] || bites` · `bites || true` · `./scripts/bite-gates.sh || true`)의 `gates.sh` 사본이
   `bite-gates.sh` 끝 절에서 다 떨어진다.
5. **`main` 의 관문 검사** — `.gitignore` 에 `.gate-pass/` 가 있고, 작업트리에 `.gate-pass/run.txt` 를 둔 채 `verify-slice-gate.py` 가 G2 로 떨어지지 않는다.
6. **비용** — route 수트는 이 조각에서 **한 번도** 돌지 않는다 — `eval.yml` 과 `vibe-audit/` 을 고치지 않는다. `gates.sh` 의 검사 수는 스물다섯 그대로다.
7. **게이트** — `./scripts/gates.sh` 가 이 조각의 PR 마다 CI gate 잡에서 통과한다.
8. **감사 회차** — 닫기 전에 `audit-quality` 를 돌려 `docs/audit/` 의 부적합 대장에 등록하고, `## 닫으며` 가 회차와 판정(NC-2 · NC-1 을 닫는지)을 든다.

## 하지 않을 일

1. **자체 시험의 꼴을 줄이지 않는다** — `test-verify-docs.py` 의 꼴 225 와 그 판정은 그대로다. 바른 검사에는 늘 끝까지 돈다. 첫 실패에서 멈추는 것은
   변조 시험이 부를 때뿐이다(ADR 0047 의 2).
2. **변조 시험 다섯을 서로 함께 돌리지 않는다** — `bite-gates.sh` 는 파일을 제자리에서 흔들어 다른 변조 시험과 함께 돌면 서로를 흔든다. 함께 도는 것은 한
   변조 시험 안의 문서 대조 변조본뿐이다(ADR 0047 의 3).
3. **나머지 변조 시험은 그대로다** — `bite-slice-gate.py` · `bite-map-pin.py` · `bite-eval-merged-pass.py` 와 `bite-gates.sh` 의 문서 대조 밖 절(합쳐 CI 약
   2분 남짓)은 손대지 않는다. 고친 뒤에도 느리면 조각 나눔에 새 줄로 넘긴다.
4. **`eval.yml` 을 고치지 않는다** — 그 주석의 「열아홉」 두 줄도 그대로다(조각 35 설계 끝 — 다음에 `eval.yml` 을 고치는 PR 몫). 감사 OB-1(적기가 분기를 믿는다)도
   그대로 둔다.
5. **지문 건너뛰기를 바꾸지 않는다** — `gate-key.py` 의 넣고 빼는 것과 `gates.sh` 의 `--skip-bite` 는 그대로다.
6. **플러그인 폴더를 고치지 않는다** — `vibe-slice/` 의 `verify-docs.py` 는 그대로라 다른 레포가 받는 것이 그대로다.

## 제약

- 스택: bash · python3 표준 라이브러리. 새 도구를 들이지 않는다 — 함께 돌리기는 `concurrent.futures`(파이썬)와 bash 의 내장 · `xargs` 로.
- 원본: `main` `a959096`. 근거: run 39761325720 · 39883977211 · 39903090279 의 gate 잡 로그, 이 세션의 클라우드 컨테이너(4 코어) 측정.
- 모델 비용: 없음 — route 수트가 돌지 않는다(성공 기준 6).
- 기간: 닫기까지 **이틀**(2026-10-25 까지).
- 리뷰: PR 본문에 설계 ② 를 적고, 착공 PR 도 구현 PR 도 스킬 `slice-review` 로 가른다. PR 마다 **3라운드**를 넘기면 소유자가 판정한다.
- 감사 회차: 닫기 전 — `audit-quality`(대장이 이 조각에 기댄다 — NC-2 의 기한이 이 조각의 `audit-quality` 회차이고, 그 회차가 NC-1 의 「부분 닫힘」도 다시
  본다. 저자가 조각 35 닫기 전 감사 회차에서 정했다(2026-10-23)). 바뀌는 것(검사 스크립트)은 `vibe-audit/README.md` 「대략의 주기」 표의 어느 행에도 닿지
  않고, `CLAUDE.md` 에 상시 회차가 없다. C 가 머지된 뒤 `/audit-brief` 로 기준 `a959096` 을 주고, 기록 · 브리핑은 `docs/audit/records/` · `briefs/` 에 둔다.
