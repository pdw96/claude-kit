# 조각 8 — 사본 머리줄 (2026-10-08 착공)

요구사항이다 — **무엇을 · 왜.** 어떻게 · 경계는 같은 폴더의 `design.md`, 대안이 있던 결정은 ADR 0017.

## 문제

사본 머리줄이 두 가지로 틀렸다.

**링크가 사본과 다른 판의 지도를 읽는다.** 두 스킬은 절차 지도를 `https://github.com/pdw96/claude-kit/blob/main/docs/procedure.md`
로 가리킨다(`slice-docs/SKILL.md` 8 줄 · `slice-review/SKILL.md` 9 줄). 사본은 출처 커밋의 스킬인데 링크는 그 뒤로 움직인
`main` 의 지도를 읽는다. 34aad2a(조각 6 PR B 의 머지) 뒤로 `docs/procedure.md` 를 고친 커밋이 다섯이고, 55a8a79(조각 7 PR C
의 머지) 뒤로 둘이다(2026-10-08 에 셌다). ERP 는 그 링크를 손으로 출처 커밋에 박았는데, 다시 심을 때마다 `--force` 가
폴더째 덮어 그것을 지웠다.

| 언제 | 무엇이 났나 | 어디 적혔나 |
|---|---|---|
| 조각 6 단계 5 — pdw96/ERP#102 | ERP 사본이 링크를 고정했다(34aad2a) | 조각 6 설계 끝 날짜 항목 「단계 5 에서 찾은 것」 |
| 조각 7 단계 5 — pdw96/ERP#106 | 다시 심기가 앞의 고정을 지워 ERP 세션이 `blob/55a8a79/` 로 다시 박았다 | 조각 7 「닫으며」 |

**머리줄이 되먹임의 방향과 거꾸로 읽힌다.** 두 심기 스크립트(`sync-slice.sh` · `sync-agents.sh`)가 같은 줄을 박는다 —
「이 레포에 맞게 고쳐도 된다 — 원본으로 되먹이지 않는다.」 그런데 의도는 「사본에서 드러난 결함만 원본으로 되먹인다」
(`INTENT.md` Why)이고, 실제로 ERP 사본의 고침 넷을 원본으로 옮겼고(#30 · ADR 0015), 저자가 ERP 에 「ERP 가 겪지 않는 조각
상황을 짚은 사본 지적은 원본으로 넘긴다」를 정했다(pdw96/ERP#103). 사본을 읽는 세션은 머리줄만 보고 거꾸로 할 수 있다.

## 핵심 사용자와 시나리오

- 사용자: 저자 한 명, 그리고 사본을 받은 레포(ERP)의 클라우드 세션.
- 시나리오: 저자가 claude-kit `main` 을 받아 `./scripts/sync-slice.sh ~/src/ERP --force` 를 부른다 → 원본 HEAD 가 원격 가지에
  있으니 심는다 → 사본 `SKILL.md` 의 절차 지도 링크가 `blob/<출처 전체 sha>/` 로, 머리줄이 새 문장으로 선다 → ERP 의 사본 PR diff 에
  링크와 머리줄만 바뀌고, ERP 세션이 링크를 손으로 고치는 커밋이 없다 → ERP 세션이 `/slice-review` 를 부르면 출처 커밋의
  지도를 읽는다 → 사본 지적을 받으면 머리줄대로 「다른 레포에서도 같은 말인가」로 가른다. 원본 HEAD 가 푸시되지 않았으면
  스크립트가 아무것도 쓰지 않고 멈춘다.

## 성공 기준

1. `test-sync-slice.py` 가 새 꼴마다 문다 — 심은 파일마다 `blob/main/` 이 `blob/<출처 전체 sha>/` 로 바뀌고 그 밖의 바이트는 그대로,
   손으로 `blob/<옛 커밋>/` 을 박은 사본을 `--force` 로 덮으면 새 출처로, ③ 밖의 claude-kit 링크 꼴이 원본에 있으면 멈춤,
   원본 HEAD 가 원격 가지에 없으면 멈춤, 두 스크립트의 머리줄이 글자 그대로 같음. 어긋내 보기 넷(바꿈을 지움 · 꼴 거절을
   지움 · 원격 확인을 지움 · `sync-agents.sh` 머리줄 한 글자를 바꿈)에서 다 떨어진다.
2. 실물 — 구현 PR 의 머리에서 빈 임시 레포에 `sync-slice.sh` 로 심은 사본을 원본과 견주면 다른 줄이 `SKILL.md` 마다 셋(머리줄 ·
   빈 줄 · 링크 한 줄)뿐이다. `sync-agents.sh` 로 심은 감사자 · 커맨드의 머리줄이 같은 문장이다. 그 출력이 구현 PR 본문에 있다.
3. 강호쟁패는 그대로다 — `vibe-slice` 판이 오르지 않고, 플러그인 스킬의 링크는 `blob/main/` 이다.
4. ERP 의 다음 다시 심기(`--force`)에서 사본 diff 의 링크가 `blob/55a8a79/` → `blob/<새 출처 전체 sha>/` 로 바뀌고, ERP 세션이 링크를
   손으로 고치지 않는다 — 저자가 단계 5 에서 본다.
5. `./scripts/gates.sh` 열일곱이 구현 PR 마다 통과하고, 구현 PR 이 바꾼 파일 가운데 수트 지문(`eval-key.py route --list` ·
   `full --list`)에 드는 것이 0 이다.

## 하지 않을 일

1. **원본 스킬의 링크를 고치지 않는다** — `vibe-slice/skills/` 는 `blob/main/` 그대로다. 플러그인은 자기 커밋을 모르므로
   대화형 세션(강호쟁패)은 `main` 의 지도를 읽는다 — 조각 나눔 「플러그인의 절차 지도 판」(ADR 0017 의 1 · 7).
2. **URL 이 아닌 「claude-kit `docs/procedure.md`」 글자를 바꾸지 않는다** — 틀 머리의 주석은 베낄 때 지운다.
3. **감사자 사본에 원격 확인을 걸지 않는다** — `sync-agents.sh` 는 머리줄 문장만 바꾼다. 감사자 · 커맨드에는 claude-kit
   링크가 없다(ADR 0017 의 4).
4. **이미 심긴 사본을 고치지 않는다** — ERP 의 사본은 그 레포가 다시 심을 때 바뀐다(`INTENT.md` Not 4).
5. **사본 대장(`copies.json`)과 `compare-copies.py` 의 출처 줄 알아보기를 고치지 않는다** — 그것은 「… 에서 옴.」 접두만 보므로
   옛 줄 · 새 줄을 다 알아본다.
6. **링크가 열리는지 네트워크로 보지 않는다** — 원격 추적 가지에 출처 커밋이 드는지만 본다.
7. **ERP 의 감사자 사본을 다시 심지 않는다** — `--force` 가 특화 감사자를 덮는다. 새 머리줄은 ERP 가 다음에 감사자를 심을 때
   선다(ADR 0017 의 8).

## 제약

- 스택: bash · python3 표준 라이브러리, git.
- 모델 비용: 수트 지문에 드는 파일(`eval-key.py route --list` · `full --list`)을 건드리지 않는다 — `eval.yml` 도. `sync-agents.sh`
  의 「게이트가 무는가」 변조본은 `eval.yml` 에 있으니 그대로 두고, 머리줄 문장은 `test-sync-slice.py` 가 견준다.
- 글자 예산: 스킬 문구를 고치지 않으니 닿지 않는다. 천장은 올리지 않는다(ADR 0004).
- 기간 **하루**.
- `./scripts/gates.sh` 는 열일곱이 그대로 통과해야 한다 — 게이트 수는 늘지 않는다.
- 리뷰: PR 본문에 설계 ② 를 적고, 착공 PR 도 구현 PR 도 스킬 `slice-review` 로 가른다. **3라운드**를 넘기면 소유자가 판정한다.
