# 조각 10 — 플러그인의 절차 지도 판 (2026-10-10 착공)

요구사항이다 — **무엇을 · 왜.** 어떻게 · 경계는 같은 폴더의 `design.md`, 대안이 있던 결정은 ADR 0019.

## 문제

**플러그인으로 받은 세션은 설치한 판이 아니라 `main` 의 절차 지도를 읽는다.** 두 스킬은 지도를
`https://github.com/pdw96/claude-kit/blob/main/docs/procedure.md` 로 가리킨다(`slice-docs/SKILL.md` 8 줄 · `slice-review/SKILL.md` 9 줄).
사본은 `sync-slice.sh` 가 그 링크를 출처 커밋으로 박지만(조각 8), 플러그인은 심는 단계가 없어 원본 그대로다 — 조각 8 이 이것을
하지 않을 일 1 로 두고 이 줄로 넘겼다(ADR 0017 의 7).

판마다 그 판의 지도와 지금 `main` 의 지도가 갈린 정도다(2026-10-10, `main` 2e25c48 에서 셌다).

| 판 | 판을 올린 커밋 | 그 뒤 지도를 고친 커밋 | `main` 과의 차이 |
|---|---|---|---|
| 0.1.0 | 980eff6 | 9 | 15 줄 더함 · 13 줄 뺌 |
| 0.3.0 | d21c1a1 | 5 | 10 · 7 |
| 0.4.1 | 824cbf2 | 1 | 1 · 1 — 빈자리 「설계 → 구현 관문」의 줄(e8314cc) |

지도를 고친 커밋 아홉 가운데 다섯은 플러그인을 고치지 않아 판이 오르지 않았다 — 조각을 닫는 PR 의 커밋 넷(조각 6 · 7 · 9)과 조각 7 PR B.
같은 판을 깐 세션이 언제 읽느냐에 따라 다른 지도를 읽는다. 지도는 단계마다의 들어가고 나가는 조건과 문서의 칸을 든다 — 스킬이 「여기에
옮겨 적지 않는다」고 그쪽을 읽게 한다.

**이 길이 지금 쓰인다.** 강호쟁패가 플러그인 길(0.4.1)로 조각 1 을 착공부터 닫기까지 돌았다 — #4 ~ #9(조각 9 「닫으며」). 강호쟁패는
대화형 세션 · Windows 이고 사본이 없다.

## 핵심 사용자와 시나리오

- 사용자: 저자 한 명, 그리고 `vibe-slice` 플러그인을 깐 레포(강호쟁패)의 대화형 세션.
- 시나리오: 저자가 claude-kit 에서 스킬을 고치는 PR 을 낸다 → `gates.sh` 의 새 검사가 원본 스킬의 지도 링크가 `blob/<전체 sha>/` 이고,
  그 커밋이 HEAD 의 조상이며, 그 커밋의 지도가 `vibe-slice/` 를 마지막으로 고친 커밋의 지도와 같은지 본다 — 지도가 그 사이 바뀌었으면
  어느 커밋을 박을지 찍고 떨어진다 → 저자가 링크를 다시 박고 판을 올려 머지한다 → 강호쟁패에서 `claude plugin marketplace update` ·
  `claude plugin update vibe-slice@pdw96-kit` 뒤 `/vibe-slice:slice-docs` 를 부르면 세션이 박힌 커밋의 지도를 읽는다 → 그 뒤 claude-kit 에서
  조각을 닫는 PR 이 지도만 고치면 링크는 그대로고 검사도 지나간다 — 강호쟁패의 세션은 깐 판의 지도를 계속 읽는다. ERP 는
  `sync-slice.sh --force` 로 다시 심으면 링크가 전과 같이 출처 커밋이다.

## 성공 기준

1. 검사가 꼴마다 문다 — `test-verify-map-pin.py` 가 임시 레포에서 대조(박은 링크 · 지도만 고친 뒤 · 지도를 고친 커밋을 박은 플러그인
   커밋)는 통과, 변조본(`blob/main/` · 짧은 sha · 조상이 아닌 커밋 · 없는 커밋 · 지도가 다른 커밋 · 그 밖의 claude-kit 링크 꼴 · 박은
   경로가 그 커밋에 없음 · 한 스킬의 지도 링크가 빠지거나 다른 경로를 박음)은 ② 의 기대 번호로 떨어진다. `bite-map-pin.py` 가 검사를 자리마다 망가뜨린 사본에서 자체 시험이 다 떨어진다.
2. 원본 — 두 `SKILL.md` 의 지도 링크가 `blob/<전체 sha>/` 이고, `verify-map-pin.py` 가 구현 PR 의 머리에서 통과한다. `vibe-slice` 판이 오르고
   `claude plugin validate ./vibe-slice` · `verify-manifest.py` 가 통과하며, `verify-budget.py` 가 천장 안이다(`slice-review` 호출 시 ≤ 4,500).
3. 사본 길 — `test-sync-slice.py` 가 원본이 `blob/<전체 sha>/` 를 박은 꼴에서도 사본의 링크가 출처 전체 sha 로 바뀌는지 보고, 짧은 sha 를
   박은 원본은 전처럼 멈추는지 본다. 실물 — 구현 PR 머리에서 빈 임시 레포에 심은 사본을 원본과 견주면 `SKILL.md` 마다 머리줄 · 빈 줄 ·
   링크 한 줄만 다르다.
4. 강호쟁패에서 — 저자가 단계 5 에서 새 판으로 갱신하고, 세션이 읽은 `SKILL.md`(`${CLAUDE_SKILL_DIR}` 의 판)의 링크가 박은 커밋이며 그
   커밋의 `docs/procedure.md` 가 구현 PR 머지에서 `vibe-slice/` 를 마지막으로 고친 커밋(`git log -1 <머지> -- vibe-slice/`)의 것과 같은지 본다 —
   머지 트리의 지도가 아니다. C 가 열린 사이 `main` 이 지도만 고쳤으면 머지 트리의 지도는 그보다 새롭고, 판의 지도는 그 전의 것이다(ADR 0019 의 2).
5. `./scripts/gates.sh` 가 구현 PR 마다 통과하고(검사가 들어온 뒤로 스물하나), 구현 PR 이 바꾼 파일 가운데 수트 지문
   (`eval-key.py route --list` · `full --list`)에 드는 것이 0 이다.

## 하지 않을 일

1. **지도를 플러그인에 싣지 않는다** — 지도는 한 벌이고 가리킨다(ADR 0013 의 2 그대로, ADR 0019 의 1).
2. **판 태그를 만들지 않는다** — 링크는 커밋이다. 태그를 만드는 워크플로도 두지 않는다(ADR 0019 의 1).
3. **지도만 고친 PR 에 링크를 다시 박거나 판을 올리라고 하지 않는다** — 링크는 플러그인을 고칠 때 다시 박는다(ADR 0019 의 2).
4. **판이 올랐는지 검사가 보지 않는다** — `CHECKLIST.md` 「플러그인의 파일을 고쳤다면」이 사람에게 든다.
5. **링크가 열리는지 네트워크로 보지 않는다** — 박은 커밋이 HEAD 의 조상인지만 본다. 원격에 푸시됐는지는 머지가 든다.
6. **이미 설치한 판과 이미 심긴 사본을 고치지 않는다** — 0.4.1 이하의 플러그인은 `blob/main/` 그대로라 갱신해야 바뀐다. ERP 의 사본은
   단계 5 에서도 다시 심지 않고, 그 레포가 다음에 심을 때 바뀐다(`INTENT.md` Not 4 · ADR 0019 의 8).
7. **검사는 파일을 고치지 않는다** — `--fix` 를 두지 않는다. 다시 박을 커밋은 M5 의 메시지가 찍는다(ADR 0019 의 7).
8. **URL 이 아닌 「claude-kit `docs/procedure.md`」 글자를 바꾸지 않는다** — 틀 머리의 주석은 베낄 때 지운다(조각 8 하지 않을 일 2).

## 제약

- 스택: bash · python3 표준 라이브러리, git — 검사는 역사 전체가 있어야 한다(CI 는 `fetch-depth: 0`).
- 모델 비용: 수트 지문에 드는 파일(`eval-key.py route --list` · `full --list`)을 건드리지 않는다 — `eval.yml` 도. 새 검사의 변조본은 `gates.sh` 가 부른다.
- 글자 예산: 링크 두 줄이 36 자씩 는다 — `slice-review` 호출 시 4,407 → 4,443(천장 4,500). 천장은 올리지 않는다(ADR 0004).
- 기간 **하루**.
- `./scripts/gates.sh` 는 열여덟이 그대로 통과하고, 검사가 들어오는 PR 부터 스물하나다.
- 리뷰: PR 본문에 설계 ② 를 적고, 착공 PR 도 구현 PR 도 스킬 `slice-review` 로 가른다. **3라운드**를 넘기면 소유자가 판정한다.

  스킬마다로 정하고 목록(빠짐 · 다른 경로 · 틀로 옮김 · 새 스킬)을 ② · ⑤ 에 넣었다(722743a).
- **#44 2회차 — 같은 PR 이 들인 문서끼리 갈렸다.** ③ 의 「폴더마다」를 ⑤ 가 대어 보지 않았고, 성공 기준 4 · ⑤ 단계 5 의 「머지 트리의 지도」가
  ADR 0019 의 2(`vibe-slice/` 를 마지막으로 고친 커밋)와 달랐다(0eb4fbc). 교훈 — 착공 PR 안에서 결정을 고치면 그 결정을 옮겨 적은
  칸(성공 기준 · ③ · ⑤)을 다 다시 대어 본다.
- **#45 — 시험 쪽이 C 의 꼴을 몰랐다.** 박은 꼴의 준비가 `blob/main/` 만 찾아, 작업트리를 C 의 꼴로 박으면 시험이 떨어졌다. PR 을 내기 전에
  찾아 두 꼴을 다 다시 박게 고쳤다 — 리뷰가 짚은 것이 아니다.

### 지켜본 것 — 줄을 더하지 않는다

증거가 해를 보이지 않아 조각 나눔에 줄을 더하지 않는다. 해가 드러나면 줄을 더한다.

- **얕은 클론에서 `gates.sh`** — 이 기록을 쓴 클라우드 세션의 클론이 얕고 로컬 `main` 이 낡아, 처음 돈 `gates.sh` 가 `verify-map-pin.py` 의
  R2 와 `verify-slice-gate.py` 의 거짓 G1 로 떨어졌다. 설계가 그린 시끄러운 실패 그대로이고, `git fetch --unshallow` 와 `main` 을 받아 온 뒤
  스물하나가 통과했다. 역사 전체가 있어야 한다는 것은 `CLAUDE.md` 「스택」이 든다.

- ERP 의 사본은 다시 심지 않았다(하지 않을 일 6 · ADR 0019 의 8) — ERP 가 다음에 `sync-slice.sh` 로 심을 때 출처 커밋이 박힌다. 조각 나눔에

- 변조본이 `eval.yml` 과 `gates.sh` 로 더 갈렸다 — `bite-map-pin.py` 가 하나 늘었다(ADR 0019 결과 5). 조각 나눔 「게이트 변조본을 수트 지문
  밖으로」가 그대로 든다.

다음 조각은 조각 나눔 「게이트 변조본을 수트 지문 밖으로」(순서 11) — 의존이 없다. 조각 9 와 이 조각이 연달아 변조본을 `gates.sh` 쪽에 더해
`eval.yml` 「게이트가 무는가」와 두 곳으로 갈렸다(저자, 2026-10-12).
