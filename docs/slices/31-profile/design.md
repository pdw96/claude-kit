## ② 보장하는 것 / 보장하지 않는 것

**보장하는 것** — 번호는 조각 3 · 9 · 30 설계 ② 에 잇는다. ⑤ 와 B 의 PR 본문이 같이 쓴다.

- P1 **루트에 `Profile.md` 가 있으면 저장소 안의 파일이고, `CLAUDE.md` 나 `CLAUDE.local.md` 가 ③ 의 꼴로 가져온다.** 이름이
  있는데 폴더거나 · 저장소 밖을 가리키는 링크거나 · 두 파일 어디에도 그 꼴이 없으면 떨어진다. 두 파일은 저장소 안의 파일일 때만
  읽는다 — 없거나 폴더거나 밖 링크면 가져오지 않는 것으로 친다. 두 모드에서 같다. `Profile.md` 라는 이름이 없으면 묻지 않는다 —
  고르는 문서다(ADR 0042 의 6). 마스터플랜이 없으면(O3) 묻지 않는다 — C1 ~ C3 와 같은 자리에서 부른다. `CLAUDE.md` 가 C1 로
  떨어졌어도 묻는다 — `CLAUDE.local.md` 가 가져올 수 있다.
- **「`Profile.md` 의 칸」이 여섯째 원천이다** — 이 저장소 모드는 지도의 그 절(O1 · O2)과 틀(T1 · T2)을, 다른 레포 모드는 검사 옆
  틀(A1 · A2)을 다른 다섯과 같은 규칙으로 본다. 새 번호가 아니라 지금 규칙의 넓힘이다. 그 절이 원천이 되는 것은 틀의 모양뿐이다 —
  `Profile.md` 자체의 절 제목은 묻지 않는다(하지 않을 일 1).
- R1 · R2 가 그대로 선다 — `Profile.md` · `CLAUDE.local.md` 를 읽지 못하면 다른 문서와 같이 R1 로 찍고, 새 검사도 모델 · 네트워크 ·
  git 을 부르지 않는다.
- 자체 시험에 P1 의 꼴이 있고(⑤ V1 · V2), 변조본이 그 자리마다 하나씩 자체 시험에서 떨어진다(⑤ V3) — 조각 3 · 9 · 30 의 시험 틀
  그대로다.
- **스킬** — `slice-docs` 는 처음 쓰는 호출에서 `CLAUDE.md` 다음에 프로필을 세울지 묻고, 저자가 프로필을 세우거나 고치자고 할 때도
  다룬다. 틀의 물음으로 인터뷰하고, 레포를 혼자 쓰면 `Profile.md` 를 올리고 `CLAUDE.md` 에, 여럿이 쓰면 `Profile.md` 와
  `CLAUDE.local.md` 를 `.gitignore` 에 더하고 `CLAUDE.local.md` 에 가져오는 줄을 넣는다. 이미 있으면 덮지 않고 빠진 절과 가져오는
  줄을 먼저 보인 뒤 받으면 더한다(ADR 0042 의 3). 스킬의 이 행동은 키 없는 검사가 없다 — 사람이 본다.
- **사본** — C 뒤 ERP 의 두 사본 머리줄 출처가 B 의 머지 커밋이고, ERP 에서 `verify-docs.py --repo .` 가 0 이다.

**보장하지 않는 것(알려진 한계)**

- **`Profile.md` 의 절 제목과 문장의 뜻** — 하지 않을 일 1. 세션이 프로필대로 설명하는지는 검사가 없다 — 사람이 본다.
- **루트 밖의 프로필과 가져오는 자리** — 하위 폴더 · `.claude/CLAUDE.md` · 홈 폴더(`~/.claude/`)는 보지 않는다(하지 않을 일 7).
  가져온 파일이 다시 가져오는 고리(Claude Code 는 네 단까지)도 보지 않는다.
- **`.gitignore` 의 줄** — 여럿이 쓰는 레포에서 두 파일이 올라가지 않는지는 보지 않는다. 검사는 작업 트리를 읽을 뿐 git 을 부르지
  않는다(R2).
- **여럿이 쓰는 레포의 클라우드 세션** — 올리지 않은 프로필은 새 클론에 없다(ADR 0042 의 3 의 대가).
- **대소문자를 가리지 않는 파일 시스템** — macOS · Windows 에서는 `profile.md` 도 이름이 있는 것으로 읽힌다. 겪지 않은 꼴이다.
- **다른 사본 레포 · 이미 설치한 플러그인** — C 가 심는 것은 ERP 하나다. 플러그인으로 받은 세션은 `claude plugin update
  vibe-slice@pdw96-kit` 뒤에 새 틀과 검사를 읽는다(ADR 0013).
- **아직 겪지 않은 가설적 경계 사례** — 조각 3 설계 ② 의 같은 줄 그대로다.

## ③ 받는 입력

**`Profile.md`** — 저장소 맨 위의 그 이름 하나. 내용은 읽지 않는다 — 이름이 있는지와 저장소 안의 파일인지만 본다.

**`CLAUDE.md` · `CLAUDE.local.md`** — 저장소 맨 위의 그 이름 둘. 줄은 다른 문서와 같은 `lines()` 로 읽는다 — 코드 펜스 안과 줄
머리에서 연 주석 안은 뺀다.

**가져오는 줄의 꼴** — 실물은 pdw96/ERP#125(`fb160d9`) `CLAUDE.md` 「작업 방식」의 한 줄뿐이고(`- **설명하고 결정을 묻는 법은 소유자
프로필을 따른다** — @Profile.md`), 닫힌 목록은 그 한 꼴이다(ADR 0042 의 7).

| 꼴 | 보기 | 판정 |
|---|---|---|
| 백틱 토막 밖에서 `@Profile.md` 가 글자 그대로 있고, 앞이 줄 머리나 공백 · 뒤가 줄 끝이나 공백 | `… — @Profile.md` · `@Profile.md` 한 줄 | 가져온다 |

그 밖은 다 가져오지 않는 것으로 읽는다 — 백틱 토막 안(`` `@Profile.md` `` — Claude Code 도 가져오지 않는다), 따옴표 안
(`"@Profile.md"` — 같다), 펜스 · 주석 안, `@` 없는 이름 · 마크다운 링크(`[프로필](Profile.md)`), 경로 변형(`@./Profile.md`), 붙은
문장 부호(`@Profile.md.` · `(@Profile.md)`), 대소문자가 다른 이름(`@profile.md`). 마지막 셋은 Claude Code 가 가져올 수도 있지만 실물에
없는 꼴이다 — 떨어지고, 실패 줄이 `@Profile.md` 로 쓰라고 말한다.

지금의 트리 — claude-kit `7bd2aa1` · ERP `main` `b4647ef` 에는 `Profile.md` 가 없다. ERP#125 의 머리 `fb160d9` 에는 있고 위 꼴로
가져온다. 이 착공 세션이 본 것이다. 강호쟁패는 이 세션에 붙지 않아 보지 못했다 — B 가 ⑤ V4 에서 댄다.

## ④ 결정

**정한 것**

- 프로필을 `slice-docs` 의 여섯째 문서로 — ADR 0042 의 1.
- 분야를 나눈 자기 신고 — ADR 0042 의 2.
- 혼자면 `CLAUDE.md`, 여럿이면 `CLAUDE.local.md` 가 가져온다 — ADR 0042 의 3.
- 틀의 절 셋과 그 제목 — ADR 0042 의 4.
- 지도에 「`Profile.md` 의 칸」 — ADR 0042 의 5.
- 검사는 가져오는지만, 없으면 묻지 않는다 — ADR 0042 의 6.
- 가져오는 꼴은 한 꼴 — ADR 0042 의 7.
- 범위 변경으로 다룬다 — ADR 0042 의 8.
- ERP#125 를 이 조각의 C 로 — ADR 0042 의 9.

**열어 둔 것**

없음 — 대화와 착공 인터뷰에서 다 정했다. 「`Profile.md` 의 칸」 표의 「담는 것」 문구, 틀 머리 주석의 물음, 스킬의 새 줄은 B 가 쓰고
리뷰가 ② 에 비춰 가른다.

## ⑤ 검증 계획

**시험 규칙** — 키 없이 도는 시험을 넓히는 조각이다. 꼴 하나하나와 보장의 조건 → 꼴 → 변조본의 대응은 B 의 시험 코드와 PR 본문이
든다(ADR 0039).

- V1 **P1 의 거절 꼴, 두 모드에서** — 이름의 꼴 둘(폴더 · 저장소 밖 링크)과 가져오는 자리가 없는 꼴 하나(두 파일 어디에도 꼴이 없다),
  ③ 의 거절 꼴마다 하나(백틱 · 따옴표 · 펜스 · 주석 · 링크 · 경로 변형 · 붙은 문장 부호 · 대소문자). 이 저장소 모드는 베낀 트리, 다른
  레포 모드는 임시 레포(의도 줄 `PRD.md`)에 `Profile.md` 를 두고 `CLAUDE.md` · `CLAUDE.local.md` 를 바꾼다. 묻지 않아야 할 자리
  하나씩 — `Profile.md` 가 없는 트리, 마스터플랜이 없는 트리에 P1 이 서지 않는다.
- V2 **거절 시험은 exit 1 · 기대한 파일 · P1 · 서지 않아야 할 번호가 없음을, 성공 시험은 exit 0 을 본다** — 지금 자체 시험의 규칙
  그대로다. 성공 꼴은 셋 — `CLAUDE.md` 가 가져온다 · `CLAUDE.local.md` 가 가져온다 · `CLAUDE.md` 가 C1 로 떨어진 트리에서
  `CLAUDE.local.md` 가 가져와 P1 은 서지 않는다. 「`Profile.md` 의 칸」 절 · 틀이 빠진 트리가 O1 · T1 · A2 로 떨어지는 꼴도 하나씩.
- V3 **변조본** — P1 의 자리마다 하나(이름 검사를 걷는다 · `CLAUDE.local.md` 를 읽지 않는다 · 백틱 토막을 빼지 않는다 · 앞뒤 경계를
  보지 않는다)가 자체 시험에서 떨어진다 — 이 저장소 모드는 `bite-gates.sh`, 다른 레포 모드는 `bite-verify-docs.py`. `KINDS` 의 여섯째를
  지운 사본도 하나.
- V4 **세 트리에 댄다** — B 머리의 검사를 ERP `main` · 강호쟁패 기본 가지 · ERP#125 의 머리에 `--repo` 로 대어 exit 0 인 것을 B 의 PR
  본문에 싣는다(요구사항 성공 기준 3). 고친 검사를 걷어 낸 `7bd2aa1` 의 검사에 V1 의 꼴을 대어 지나가는 것도 싣는다 — 검사가 없던
  자리임을 보인다.

**그 밖**
