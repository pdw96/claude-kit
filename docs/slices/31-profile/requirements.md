# 조각 31 — 프로필(`Profile.md`) (2026-10-20 착공)

요구사항이다 — **무엇을 · 왜.** 어떻게 · 경계는 같은 폴더의 `design.md`, 대안이 있던 결정은 ADR 0042.

이 조각을 「다음 조각」으로 적은 닫힌 조각은 없다. 조각 30 의 `## 닫으며 (2026-10-20)` 가 다음 조각을 `없음` 으로 적고, 근거가
생기면 그때 순서를 매겨 꺼낸다고 했다(ADR 0012). 근거는 저자의 물음과 방향(2026-10-20 대화), 그리고 아래 「문제」의 ERP 인터뷰
한 판이다. 이 착공 PR 이 조각 나눔에 줄을 더하며 순서 31 로 매긴다. 이 착공 세션의 클론은 얕지 않았다
(`git rev-parse --is-shallow-repository` → `false`).

## 문제

**절차가 저자 · 소유자에게 묻는 자리는 여럿인데, 그 사람에게 어떻게 묻고 설명하는지는 어디에도 없다.**

- **묻는 자리.** 스킬 `slice-review` 의 멈춤(쏠림 신호 · 리뷰 한도)은 「소유자에게 묻는다」고, ADR 마다 「저자가 정했다」가 있다.
  절차는 그 사람이 물음을 알아듣는다고 전제한다.
- **알아듣지 못한 물음은 위임이 된다.** 이 저장소와 ERP 의 저자는 제조 ERP Setup TF 에 참여해 업무 흐름을 알지만 코딩은
  모른다. 그래서 코딩 쪽 결정은 「무슨 말인지 모르니」 추천안대로 받아 왔다(저자, 2026-10-20). 그 가운데 업무 결정이기도 한 것 —
  잘못 넣은 입고를 지우나 취소 전표로 남기나, 출고 도중 오류가 나면 재고만 빠져도 되나 — 은 업무 말로 물으면 저자가 판단할 수
  있다. 코드 말로 물으면 세션이 정하게 된다.
- **한 레포에서 손으로 했다.** 세션이 인터뷰 두 묶음(여덟 물음)으로 저자의 분야별 수준 · 결정을 가르는 법 · 설명하는 법을
  받아 ERP 에 `Profile.md` 를 쓰고 `CLAUDE.md` 가 `@Profile.md` 로 가져오게 했다 — pdw96/ERP#125(`fb160d9`, 초안). 절 셋, 수준 표
  네 줄. 틀이 없어 물음을 그 자리에서 지었고, 다른 레포는 같은 일을 다시 지어야 한다.
- **만들어도 읽히지 않을 수 있다.** Claude Code 가 세션마다 저절로 읽는 것은 `CLAUDE.md` 와 `CLAUDE.local.md` 이고, 다른 파일은
  `@<경로>` 로 가져와야 읽힌다(ADR 0042 「맥락」). 가져오는 줄이 빠져도 아무것도 떨어지지 않는다 — `INTENT.md` 가 자동으로
  읽히지 않아 ADR 0009 · 0041 이 막은 것과 같은 꼴이다.
- **원본의 일이다.** 조각으로 나눠 진행하는 레포라면 어디서나 「사람에게 묻는 자리」가 있다(`INTENT.md` Why). 다만 다른 레포에서
  같은 말인지 가른 실물은 ERP 하나다(ADR 0042 의 대가).

## 핵심 사용자와 시나리오

- 사용자: 레포를 조각으로 여는 저자, 그리고 그 레포에서 매 세션 그 저자에게 설명하고 묻는 Claude Code 세션.
- 시나리오: 저자가 스킬 `slice-docs` 를 부른다 → 의도 · 마스터플랜 · `CLAUDE.md` 다음에 스킬이 프로필을 세울지 묻는다 → 저자가
  받으면 틀의 물음으로 인터뷰한다 — 분야별 수준(그 레포의 업무 분야 · 코딩 · 협업 도구), 업무에 영향이 없는 결정을 알리는 법,
  있는 결정을 묻는 법, 용어, 동작을 보이는 법, 레포를 혼자 쓰나 → 혼자 쓰면 저장소 맨 위에 `Profile.md` 를 쓰고 `CLAUDE.md` 에
  `@Profile.md` 를 넣는다. 여럿이 쓰면 `Profile.md` 와 `CLAUDE.local.md` 를 `.gitignore` 에 더하고 `CLAUDE.local.md` 가 가져온다 →
  PR 을 내기 전 `verify-docs.py --repo .` 가 0 이다 → 다음 세션은 시작할 때 프로필을 읽고, 업무에 영향이 있는 결정을 업무 말로
  묻는다. 이미 `Profile.md` 가 있으면 스킬은 덮지 않고, 빠진 절과 가져오는 줄만 보여 준 뒤 저자가 받으면 더한다.

2. `verify-docs.py` 가 두 모드(이 저장소 · `--repo`)에서 P1(설계 ②)을 문다 — 자체 시험(`test-verify-docs.py`)의 거절 꼴마다 exit 1 과
   P1 이 나오고, P1 의 자리를 망가뜨린 변조본과 `KINDS` 의 여섯째를 지운 변조본이 자체 시험에서 다 떨어진다(`gates.sh`).
3. 지금의 세 트리가 새 검사를 지난다 — claude-kit(프로필 없음)은 `gates.sh`, ERP `main`(프로필 없음) · 강호쟁패 기본 가지와
   ERP#125 의 머리(프로필 있음)는 B 머리의 검사를 `--repo` 로 대어 exit 0(B 의 PR 본문).
4. 스킬 `slice-docs` 가 프로필을 「틀」 표 · 「어디서 시작하나」(세울지 묻기 · 혼자와 여럿의 두 자리 · 이미 있을 때)로 든다.
   호출 시 4,500 자 안이다(`verify-budget.py`).
5. pdw96/ERP#125 가 B 의 머지 커밋에서 다시 심은 스킬 사본과 틀 모양의 `Profile.md` 를 싣고 머지되며, ERP 에서
   `verify-docs.py --repo .` 가 0 이다(그 PR 본문).
6. `./scripts/gates.sh` 가 B 의 로컬과 CI gate 잡에서 다 통과한다.

## 하지 않을 일

1. **`Profile.md` 의 절 제목과 내용을 검사하지 않는다** — 사람마다 다르고 대화로 고친다(ADR 0042 의 6).
2. **수준을 시험으로 재지 않는다** — 자기 신고를 인터뷰로 받는다(ADR 0042 의 2).
3. **기록 문서와 감사자 출력을 수준에 따라 바꾸지 않는다** — 프로필이 바꾸는 것은 대화의 설명과 묻는 법뿐이다. 요구사항 · 설계 ·
   ADR 의 모양은 문서 대조 검사가, 감사자 출력의 모양은 eval 그레이더가 문다.
4. **스킬 `slice-review` 의 본문을 고치지 않는다** — 프로필은 입구가 매 세션 가져오므로 따로 부르지 않는다. 지도 링크의 판만
   다시 박는다.
5. **강호쟁패에 프로필을 만들지 않고 PR 도 내지 않는다** — 플러그인 갱신으로 새 틀과 검사를 받는다(ADR 0042 의 9).
6. **이 저장소에 `Profile.md` 를 만들지 않는다** — 이 조각은 틀과 검사를 세운다. 이 저장소에 쓸지는 그 인터뷰를 할 때 정한다.
7. **홈 폴더(`~/.claude/`)의 프로필을 받지 않는다** — 저장소 밖이라 검사가 못 본다(ADR 0042 의 3).

### 배포

설계 ⑤ 「단계 5」 그대로 — #114 의 머지가 `vibe-slice` 0.6.0 의 배포이고, ERP#125 의 머지가 ERP 사본과 ERP 프로필의 배포다. 보이는 것은 `main` 의
`plugin.json` 판 `0.6.0` 과 ERP `main` 의 두 `SKILL.md` 머리줄 `pdw96/claude-kit@ee9f58f` · 맨 위 `Profile.md` 다. 강호쟁패와 플러그인으로 받은 대화형
세션은 `claude plugin marketplace update pdw96-kit` 뒤 `claude plugin update vibe-slice@pdw96-kit` 을 돌리고 리로드해야 새 틀과 검사를 읽는다(ADR 0013 ·
ADR 0042 의 9). 되돌리는 길은 이 닫는 기록을 먼저 되돌린 뒤 C → B 순으로 되돌리고 판을 0.6.1 로 올리는 것이다(`CHECKLIST.md` 「플러그인의 파일을
고쳤다면」) — 이 기록이 마스터플랜의 31 줄(`닫힘`)을 고치므로, 그것을 두고 구현만 되돌리면 살아 있는 문서가 되돌린 상태와 갈린다. ERP 의
`Profile.md` 는 C 를 되돌려도 ERP 저자가 다시 쓸 수 있다 — 검사는 프로필이 없으면 묻지 않는다.

### 지켜본 것 — 줄을 더하지 않는다

첫 실물이 아직 없거나 겪지 않은 꼴이라 조각 나눔에 줄을 더하지 않는다.

- **스킬로 처음 세우는 프로필** — ERP 의 프로필은 스킬이 서기 전에 세션이 손으로 인터뷰해 썼고, C 는 그것을 틀에 맞췄을 뿐이다. 틀의 물음
  여섯으로 처음부터 인터뷰하는 길은 아직 돌지 않았다. 다음에 프로필이 없는 레포에서 `slice-docs` 를 부를 때가 첫 실물이다.
- **여럿이 쓰는 레포** — `.gitignore` · `CLAUDE.local.md` · `git rm --cached` · 혼자와 여럿을 바꾸는 길은 겪지 않았다. 세 레포가 다 혼자 쓴다.
- **세션이 프로필대로 설명하는가** — 검사가 보는 것은 가져오는 줄뿐이다(설계 ② 의 보장하지 않는 것). ERP 의 다음 조각에서 업무 결정을 업무
  장면으로 묻는지, 동작을 전표 · 장부 모양의 표로 보이는지가 첫 실물이다. 어긋나면 그 레포의 `Profile.md` 를 고친다 — 원본의 일이 되는 것은
  다른 레포에서도 같은 말일 때다.
- **강호쟁패** — 플러그인 갱신으로 받는다(하지 않을 일 5). 그 레포에 `Profile.md` 가 없어 P1 은 묻지 않는다.
- **`slice-review` 의 예산 여유 6** — 조각 28 · 29 · 30 「지켜본 것」 그대로다. 이 조각은 `slice-review` 의 지도 링크만 다시 박아 길이가 그대로다.
- **클론** — 이 닫는 세션의 claude-kit 클론은 얕지 않았다(`git rev-parse --is-shallow-repository` → `false`).
