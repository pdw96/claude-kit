설계다 — **어떻게 · 경계.** 무엇을 · 왜는 같은 폴더의 `requirements.md`.

| 파일 | PR | 무엇 |
|---|---|---|

| `README.md` | A | `:110` 「바뀐 것에 맞는 감사자는 … 「대략의 주기」」를 두 표를 가리키게 고친다. `README.en.md` 에는 같은 자리가 없다 — 절차를 영어로 설명하지 않는다(`README.en.md:31`). 영어 쪽의 「When \| Run」 표는 「대략의 주기」의 옮김이고 그대로다 |
| `docs/audit/` | 닫기 | 닫기 전 감사 회차의 기록 · 브리핑 · 대장 등록 |

앵커볼트는 건드리지 않는다 — `docs/procedure.md` 의 절 제목과 「…의 칸」 여섯 절의 표, `CLAUDE.md` 의 절 제목 다섯이 그대로다. 「가변」의 「검사가 읽는 글」은 둘이 닿는다 —
`scripts/verify-counts.py` 가 원천 「감사자 고르는 원천」으로 「어느 감사자」 아래 굵은 항목을 세고 닻 「원천 {N}에서 고르고」로 견준다. A 는 첫째 항목의 글만 바꾸고 항목 수(셋) ·
굵은 머리 · 닻 글을 그대로 둔다. `README.md` · `CLAUDE.md` 의 닻(「감사자 {N}」 따위 · 「읽기 전용 {N}.」 · 「「…의 칸」 {N} 절」)도 고치지 않는다 — 새 글에 수를 적지 않는다. 스크립트 ·
플러그인 · CI 는 그대로다. 시스템 구조(`docs/architecture.md`)는 그대로다 — 부품 · 경계 · 흐름이 같다.

## ② 보장하는 것 / 보장하지 않는 것

**보장하는 것**

- **A 정의가 고르는 법과 맞는다** — 「바뀌는 것」은 설계 ① 을 두 표에 대어 감사자 후보를 낸다. 담당 표는 검사 장치 → `audit-quality`, 문서에 적은 규칙 → `audit-internal` 처럼 바뀐 것의
  종류로 고르고, 시점 표는 앵커볼트 층 · 공개 API · 첫 배포 · 조각 서너 개 · 장애처럼 일의 때로 고른다. 문제의 열여섯 줄이 든 변경(③ A)은 다 담당 표의 한 행에 닿는다.
- **B 한 자리** — 감사자의 담당은 `vibe-audit` README 「감사자 6종」 표 한 자리가 들고, 지도는 그 표를 가리킬 뿐 담당을 옮겨 적지 않는다(ADR 0073 의 5 · ADR 0045 의 2). 상시 회차는
  `CLAUDE.md` 「새 장치는 새어 나간 결함에만」 줄이 들고, 꼴의 목록은 같은 줄의 첫 「—」 뒤를 가리킨다 — 둘째 목록을 두지 않는다.
- **C 상시 회차의 문턱이 diff 로 보인다** — 문턱은 「새 장치를 세웠다」는 가름이 아니라 그 줄이 든 꼴(검사 · 시험 · 게이트 줄 · CI · 변조본 · 대조군 · eval 케이스)을 **더하거나 고친다**는
  사실이다. 가름이 틀린 조각(새 장치를 고침으로 읽은 조각)도 회차를 받는다(ADR 0077 의 3).
- **D 세 주장이 원천에 닿는다** — ③ B 의 셋마다 회차를 세우는 원천이 하나 이상 있다.
- **E 장치와 `vibe-audit` 가 그대로다** — 요구사항 성공 기준 5.

**보장하지 않는 것(알려진 한계)**

- **담당에 대는 일은 판단이다** — 두 표에 대어 후보를 내는 일을 무는 검사는 없다. 담당 표의 「무엇만 보는가」는 한 줄이라, 경계의 변경(예: README 의 주장 한 문장)은 세션이 가르고 「왜」에 적는다.
  사람(`CHECKLIST.md` 「요구사항 「제약」에 감사 회차가 있다」)과 리뷰가 본다.
- **원천이 낸 후보를 다 돌리지 않는다** — 지도의 「줄이 고른다」 그대로다. 넓어진 정의가 후보를 늘려도 회차 수를 정하지 않는다.
- **다른 레포는 다음 링크 재고정 때까지 옛 정의를 읽는다** — `vibe-slice` 의 두 스킬은 지도를 커밋으로 박았고, 지도만 고친 커밋은 링크를 건드리지 않는다(ADR 0019 의 2 · ADR 0077 의 5).
- **`vibe-audit` README 의 「아래 표는 그 원천 가운데 하나(바뀐 것 → 감사자)입니다」(`vibe-audit/README.md:79`)는 그대로다** — 시점 표가 원천의 몫인 것은 참이고, 담당 표를 함께 든다는
  말이 없을 뿐이다. 고치면 `vibe-audit` 판이 오르고 route 수트가 돈다(ADR 0057 의 2 · 3) — 하지 않을 일 1.
- **상시 회차를 건너뛴 조각을 키 없이 막지 않는다** — 감사 회차 줄과 같다(ADR 0045 의 3).
- **설계 ② 가 「다음 감사 회차가 본다」로 넘긴 일 일반** — 조각 나눔 「같은 목록의 경계」가 든다(하지 않을 일 7). 이 조각은 ③ B 의 셋만 원천에 닿게 한다.
- **리뷰가 이 밖을 짚으면 범위 밖이다** — 요구사항 하지 않을 일.

## ④ 결정

**정한 것**

- 「바뀌는 것」의 정의를 넓힌다 — 두 표(담당 · 시점) — ADR 0077 의 1(저자)
- 상시 회차를 `CLAUDE.md` 「새 장치는 새어 나간 결함에만」 줄에 두고 감사자는 `audit-internal` — ADR 0077 의 2(저자)
- 상시 회차의 문턱은 꼴을 더하거나 고치는 조각 — ADR 0077 의 3
- `vibe-audit` 는 그대로 — ADR 0077 의 4
- 지도만 고치고 `vibe-slice` 링크를 다시 박지 않는다 — ADR 0077 의 5
- 세 결정 · 지난 줄을 고치지 않는다 — ADR 0077 의 6
- 감사 회차 `audit-internal` 하나 — ADR 0077 의 7

**열어 둔 것**

없음 — 세 자리의 글은 PR A 가 쓰고 리뷰가 본다. 글이 들 것은 ① · ② A ~ C 가 닫는다.
