# 조각 58 — 감사 회차의 바뀌는 것 (2026-11-08 착공)

요구사항이다 — **무엇을 · 왜.** 어떻게 · 경계는 같은 폴더의 `design.md`, 대안이 있던 결정은 ADR 0077.

이 조각을 「다음 조각」으로 적은 닫힌 조각은 조각 57(새 장치는 새어 나간 결함에만)이다 — 그 `## 닫으며 (2026-11-06)` 를 읽었다. 넘겨받은 것은 이 줄에 더한 사례(회차 37 OB-1 ·
38 「문서에 없어서」 B — 「닫기 전 감사 회차가 본다」를 받칠 원천이 없다)와 NC-41(고침 — 다음 `audit-internal` 회차의 재감사를 기다린다)이다. 의존은 `—` 다. 저자가 이 착공 세션에서
갈래 둘을 정했다 — 둘 다 세션이 추천한 쪽이다(ADR 0077 의 1 · 2). 착공은 `main`(`2d48d97`) 위에서 연다. 이 착공 세션의 클론은 얕지 않았다
(`git rev-parse --is-shallow-repository` → `false`).

## 문제

**감사자를 고르는 원천 「바뀌는 것」의 정의가 실제로 고르는 법보다 좁다.** 절차 지도 「감사 회차」(`docs/procedure.md:62`)는 「바뀌는 것」을 「설계 ① 을 `vibe-audit` 의 README
「대략의 주기」 표에 댄 것」으로 정한다. 그 표의 행은 다섯 — 앵커볼트 층 · 공개 API · 첫 배포 직전 · 조각 서너 개 머지한 뒤 · 장애 후 — 이고(`vibe-audit/README.md:83-89`), 검사 ·
시험 · 평가셋 · 스킬 · 틀 · 절차 지도 · 작업 규칙의 글이 바뀌는 행이 없다.

- **줄이 정의 밖으로 고른다** — 조각 39 ~ 56 의 감사 회차 줄 열여덟 가운데 열여섯(39 ~ 43 · 46 ~ 56)이 표에 없는 변경(검사 · 변조본 · 평가셋 · 러너 → `audit-quality`, 지도 · 스킬 · 틀 ·
  `CLAUDE.md` · 살아 있는 문서 → `audit-internal`)을 「바뀌는 것」으로 들었다(2026-11-08 각 `requirements.md` 「제약」에서 셌다). 나머지 둘(44 · 45)과 그 앞의 넷(35 ~ 38)은 같은
  꼴의 변경을 「표의 어느 행에도 닿지 않는다」고 적고 다른 원천이나 저자 결정으로 골랐다. 지난 회차들은 열여섯 줄을 받아들였다.
- **감사가 두 번 짚었다** — 감사 회차 36 「문서에 없어서 판정할 수 없었던 것」 B(`docs/audit/records/audit-internal-2026-11-05-140016.md`)가 「관행이 정의보다 넓은 것은 규칙이 비어 있다는
  신호」라 했다. 회차 38 「문서에 없어서」 B(`…/audit-internal-2026-11-06-074921.md`)가 같은 뿌리로 2 회째를 셌다.
- **세 결정이 원천 없는 회차에 기댄다** — ADR 0076 의 3(`docs/adr/0076-leaked-defects-only.md:39`) · ADR 0073 의 7(`docs/adr/0073-repeated-asks.md:59`) · 조각 56 설계 ②
  (`docs/slices/56-review-follows-map/design.md:37`)가 키 없이 지키는 규칙을 「사람과 닫기 전 감사 회차가 본다」고 했다. 새 장치를 세운 조각에 `audit-internal` 회차를 세우는 원천이
  셋 가운데 없다 — 표에 그 행이 없고, 대장의 기한은 따로 걸릴 때만 돕고, `CLAUDE.md` 에 상시 회차가 없다. 조각 57 에서는 NC-40 이 대장 원천으로 `audit-internal` 을 불렀다 — 우연이다
  (감사 회차 37 OB-1 · `docs/audit/records/audit-quality-2026-11-06-073737.md`).

## 핵심 사용자와 시나리오

- 사용자: 이 저장소에서 조각을 착공하며 요구사항 「제약」의 감사 회차 줄을 쓰는 세션.
- 시나리오: 세션이 설계 ① 에 검사 스크립트의 새 규칙과 `CLAUDE.md` 의 한 줄을 적는다 → 절차 지도 「감사 회차」를 읽는다 → 「바뀌는 것」을 `vibe-audit` README 의 「감사자 6종」(담당)에
  대어 검사 → `audit-quality`, 문서에 적은 규칙 → `audit-internal` 을 후보로 얻는다 → `CLAUDE.md` 「새 장치는 새어 나간 결함에만」 줄을 읽고, 검사를 고치는 조각이라 닫기 전
  `audit-internal` 이 상시 회차로 든다는 것을 안다 → 줄에 셋 가운데 고른 원천을 「왜」로 적는다. 닫기 전 `audit-internal` 회차가 그 규칙 줄을 읽고 새 규칙의 ADR 이 새어 나간 결함을
  가리키는지 본다.

## 성공 기준

1. **결정이 기록된다** — 착공 PR 이 ADR 0077 을 더하고, 그 ADR 이 1 · 2 를 이 착공 세션의 저자가 정한 것으로 든다.
2. **정의가 고르는 법과 맞는다** — PR A 뒤 `docs/procedure.md` 「감사 회차」의 「바뀌는 것」이 `vibe-audit` README 의 「감사자 6종」과 「대략의 주기」 두 표를 원천으로 든다. 원천의 수는
   셋 그대로다(`python3 scripts/verify-counts.py` PASS — 닻 「원천 {N}에서 고르고」).
3. **상시 회차가 선다** — PR A 뒤 `CLAUDE.md` 「작업 방식」의 「새 장치는 새어 나간 결함에만」 줄이 새 장치의 꼴을 더하거나 고치는 조각은 감사 회차 줄에 닫기 전 `audit-internal` 을
   든다고 말하고 ADR 0077 을 가리킨다. 꼴의 목록은 옮겨 적지 않는다. `CLAUDE.md` 의 절 제목 다섯은 그대로다.
4. **세 주장이 원천에 닿는다** — 닫는 PR 의 `## 닫으며` 가 ADR 0076 의 3 · ADR 0073 의 7 · 조각 56 설계 ② 의 「닫기 전 감사 회차」마다 새 정의나 상시 회차 가운데 어느 원천이
   그 회차를 세우는지 든다.
5. **장치와 `vibe-audit` 가 그대로다** — `git diff --stat 2d48d97 <각 머지> -- scripts .github vibe-audit vibe-slice compare` 가 빈 출력이다. 수트 지문(`scripts/eval-key.py route` ·
   `full`)이 `2d48d97` 과 같다.
6. **게이트** — `./scripts/gates.sh` 가 이 조각의 PR 마다 작업트리와 CI gate 잡에서 통과한다.
7. **감사 회차** — 닫기 전 감사 회차를 돌려 `docs/audit/` 의 대장에 등록했다.

## 하지 않을 일

1. **`vibe-audit` 를 고치지 않는다** — README 의 두 표(「감사자 6종」 · 「대략의 주기」)에 행을 더하거나 글을 바꾸지 않고, 판 · 수트 지문 · 사본이 그대로다(ADR 0077 의 1 · 4).
2. **`vibe-slice` 를 고치지 않는다** — 두 스킬의 지도 링크를 다시 박지 않고 판을 올리지 않는다. 요구사항 틀의 감사 회차 자리표시도 그대로다(ADR 0077 의 5).
3. **감사 회차 줄을 무는 검사를 세우지 않는다** — 사람이 본다(ADR 0045 의 3 · `CHECKLIST.md`). 새 실패 조건이 없다(`CLAUDE.md` 「새 장치는 새어 나간 결함에만」).
4. **원천을 넷으로 늘리지 않는다** — 셋의 첫째의 정의를 넓히고, 상시 회차는 셋째(그 레포의 상시 회차)로 둔다.
5. **지난 감사 회차 줄과 세 결정을 고치지 않는다** — 조각 39 ~ 57 의 요구사항 · ADR 0073 · 0076 · 조각 56 설계는 기록이다. 규칙은 소급하지 않는다.
6. **다른 레포에 상시 회차를 보내지 않는다** — `CLAUDE.md` 의 그 줄은 이 저장소의 작업 규칙이다(ADR 0076 의 6 · ADR 0077 의 2).
7. **조각 나눔의 다른 줄을 다루지 않는다** — 「같은 목록의 경계」(설계 ② 가 「다음 감사 회차가 본다」로 넘긴 일을 무엇이 잡는가 포함) · 「리뷰 기준의 원천 경계」 · 「`audit-quality` 가 넘긴
   두 자리」 등.

## 제약

- 스택: 마크다운. 스크립트를 고치지 않는다.
- 원본: `main` `2d48d97`.
- 비용: **$0** — 측정이 없다. 수트 지문은 `vibe-audit/` 만 읽는다(`scripts/eval-key.py` 머리) — 이 조각은 그 밖이다.
- 기간: 닫기까지 **사흘**(2026-11-11 까지).
- 리뷰: 착공 PR 도 구현 PR 도 스킬 `slice-review` 로 가른다. PR 마다 **3라운드**를 넘기면 소유자가 판정한다.
- 감사 회차: 닫기 전 — `audit-internal`(대장이 이 조각에 기대는 것 — NC-41 이 고침으로 다음 `audit-internal` 회차를 기다린다. 바뀌는 것 — 절차 지도 · `CLAUDE.md` 의 규칙 글이 ADR 0077 ·
  `vibe-audit` README 의 두 표와 같은 말을 하는가). `audit-quality` 는 고르지 않는다 — 검사 · 변조본 · 평가셋이 바뀌지 않는다.
