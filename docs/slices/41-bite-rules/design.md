## ② 보장하는 것 / 보장하지 않는 것

**보장하는 것**

- **C (가) 센 수** — ③ A 의 절마다 기대한 수를 상수로 두고, 끝에서 돈 변조본 · 대조군의 수를 그와 견준다. 다르면 `::error::` 와 종료 1. 루프 · glob 으로 도는
  묶음도 한 회마다 센다. 끝 줄은 견준 수를 찍는다 — 글자로 박은 수가 남지 않는다. 지문 절(B21 · B22 · B23)도 바뀌어야 하는 쪽 · 그대로여야 하는 쪽의 수를
  견준다.
- **N (나) 좁힌 「물었다」**
  - **N1 규칙 ID 를 찍는 검사** — `verify-eval-gate.py`(`FAIL [코드]`) · `verify-docs.py`(`[번호]`) · `verify-slice-gate.py`(`[번호]`) · `verify-map-pin.py`
    (`[M번호]`) · `test-gates.py`(`FAIL <태그>`) · `sync-agents.sh --merge`(`merge:` 이유 코드). 변조본은 그 검사의 실패 종료이고 기대한 ID 가 실패 줄에 있을
    때만 물었다로 센다. 변조본마다 기대한 ID 를 적는다.
  - **N2 자유 글 검사** — 그 꼴에 그 검사가 내는 종료 코드와 정확히 같고, 그 검사의 실패 머리 줄이 있을 때만 센다. 0 이 아닌 아무 종료 · 트레이스백
    (`Traceback` 줄) · 사용법 거절(종료 2, 그 꼴이 거절을 재는 것이 아니면)은 세지 않는다. 출력을 버리던 절(`>/dev/null`)은 출력을 받는다.
- **K (다) 대조군** — 대조군은 종료 0 과 그 검사의 PASS 줄(`^PASS <검사>` 꼴 — 검사마다의 꼴은 ③ C)을 함께 본다. `bite-slice-gate.py` · `bite-map-pin.py` ·
  `bite-eval-merged-pass.py` 는 고치지 않은 검사 사본에 자체 시험을 대 PASS 를 보는 대조군을 하나씩 세운다 — 변조본을 대기 전에 그 판이 지나가야 한다.
- **R 규칙마다 변조본** — N1 의 여섯에서, 검사가 낼 수 있는 ID 의 목록과 변조본이 기대하는 ID 의 집합을 견준다. 변조본이 없는 ID 가 있으면 떨어진다.
  `sync-agents.sh --merge` 는 이미 이 대조(B3 의 V5, `bite-gates.sh:466-475`)가 있어 그대로 센다. 이 대조에도 떨어지는 변조본을 둔다 — 한 ID 의 변조본을 다
  지운 목록을 대조에 댄다(`CLAUDE.md` 「새 검사를 세우면 …」).
- **W 규칙의 글** — `CLAUDE.md` 「작업 방식」의 「새 검사를 세우면 …」 줄에 「변조본을 도는 절은 (가) 돈 수를 기대한 수와 견주고 (나) 그 규칙의 실패(종료와
  ID · 실패 머리 줄)로만 물었다고 세고 (다) 대조군은 종료 0 과 PASS 줄을 함께 본다」가 붙는다. `CHECKLIST.md` 의 변조본 줄이 셋을 확인 항목으로 든다.
- **G 판정은 그대로** — 구현 PR 의 diff 는 ① 의 파일 안이다. 고치지 않은 원본 트리에서 모든 절이 지나간다(요구사항 성공 기준 7).
- **T 시간** — CI gate 잡의 「키 없이 도는 게이트」 스텝이 9 분 안이다. 대조군을 더하는 절은 이미 돈 실행의 출력을 다시 쓰고, 새 실행은 `bite-*.py` 셋의 대조군
  셋이다.

**보장하지 않는 것**

- **자유 글 검사의 규칙 하나** — N2 는 「그 검사가 실패로 끝났다」까지다. 규칙 하나를 지운 자유 글 검사가 다른 규칙의 실패로 같은 변조본을 떨어뜨리면 지나간다.
  ID 를 들이지 않기로 했다(ADR 0054 의 2 · 요구사항 하지 않을 일 1).
- **목록과 기대 수를 함께 고친 PR** — 변조본 한 줄과 기대 수 하나를 함께 지우면 지나간다. 두 벌은 갈리면 떨어질 뿐이다(ADR 0049 와 같은 꼴). 그 PR 의 리뷰가 본다.
- **절을 통째로 지운 PR** — `test-gates.py` 는 파일 단위로 부르는 것을 고정한다. 한 파일 안의 절 하나를 지우는 것은 리뷰가 본다.
- **ID 목록의 원천이 놓친 ID** — R 은 검사 코드에서 읽은 ID 만 본다. 문자열을 조립해 찍는 ID 는 읽는 법(④ 열어 둔 것)이 놓칠 수 있다.
- **두 ID 를 함께 무는 변조본** — N1 은 기대한 ID 가 있는지를 본다. 다른 ID 가 함께 찍히는 것을 막지는 않는다 — 이미 그렇게 보는 절(`test-verify-docs.py` 의
  QUIET · PROFILE)은 그대로 둔다.

**센 수의 모양.** 파일마다 `WANT = (<변조본>, <대조군>)` 를 두고 돈 수와 견준다 — 종료가 0 이 아닌 꼴이 변조본, 0 인 꼴이 대조군이다.
`test-verify-docs.py` 는 모드마다 둘(`WANT_BOTH` · `WANT_REPO`)이다. `PASS` 줄의 수는 목록의 길이가 아니라 돈 수를 찍는다. 예외 하나 —
`test-gates.py` 의 S 는 기대 수를 `2 × 고정 목록 + CHECKS` 로 셈한다. 목록 자체는 L2 가 `gates.sh` 와 견주므로, 셋째 벌을 두면 검사를 더하는 PR 이
세 군데를 고친다(ADR 0049). 셈한 수는 고리가 일찍 끝나거나 꼴을 거르는 것을 문다.

**대조군을 새로 세운 것** — `bite-slice-gate.py` · `bite-map-pin.py` · `bite-eval-merged-pass.py` 의 대조군 셋(성공 기준 3). 변조본보다 먼저 돌고,
어긋나면 아무 변조본도 돌리지 않고 멈춘다. 종료만 보던 대조군과, 종료조차 보지 않던 둘 — `test-verify-docs.py` 의 「원천 표에 제목을 더하면」 · `test-sync-slice.py`
의 L3 앞의 심기 — 도 이제 그 길의 줄을 본다.

**이름이 틀린 변조본 — 없었다.** 좁혀도 떨어진 변조본이 없다. `bite-*.py` 의 이름은 검사의 보장을 들고 넷째 칸이 자체 시험의 꼴을 들어, 이름이
꼴과 다른 것(예: 「A1 — 틀의 원천을 빈 목록으로 읽는다」가 `--first` 에서 F3 꼴로 처음 떨어진다)은 틀린 것이 아니다.
