설계다 — **어떻게 · 경계.** 무엇을 · 왜는 같은 폴더의 `requirements.md`, 갈림길은 ADR 0039.

**앵커볼트.** 「…의 칸」 — 네 절의 제목과 표 서식(머리 · 가름줄 · 제목 칸)은 바이트가 그대로다. 바뀌는 것은 「설계 문서의 칸」 표 ⑤ 행의 「담는 것」
칸 하나다. 이름(`vibe-slice` · `slice-docs` · `slice-review`) · 감사자 · 대장 · `AGENTS.md` 는 건드리지 않는다.

**고정 영역 · 수트.** 위 파일은 다 수트 지문(`eval-key.py route --list` · `full --list`) 밖이다 — 두 PR 의 CI 는 eval 잡을 건너뛴다. 스크립트 ·
`gates.sh` · `eval.yml` 은 그대로다.

**사실.**
- 지금 ⑤ 행의 「담는 것」 — 「무엇으로 맞음을 보일지. 검사를 세우면 **어긋내 봐서 떨어지는 것**까지」(`docs/procedure.md` 164 줄). 틀 ⑤ 의 안내 —
  「무엇으로 맞음을 보일지. 검사를 세우면 어긋내 봐서 떨어지는 것까지. 검사마다 ⑥ 의 어느 PR 에서 돌리나 — 여러 PR 을 걸치면 마지막 PR」(틀 44 줄).
- `slice-review` 「1. 기준」의 구현 PR 줄은 ② 의 보장하지 않는 것 · 날짜 항목의 보장하지 않음(조각 전체)과 「② 의 보장하는 것 · ③ 의 받는 입력 · 날짜
  항목의 보장 가운데 그 줄이 닫는 몫」을 기준으로 든다 — ⑤ 가 없다. 착공 PR 줄은 「…의 칸」(틀의 제목과 칸마다의 안내)과, 설계를 짚은 지적에 같은 PR
  요구사항의 성공 기준 · 제약을 든다 — 틀 ⑤ 의 안내가 착공의 기준에 이미 든다.
- `slice-review` 「2. 가르기」의 밖 — 「보장하지 않는 것을 보장하라, 받지 않는 입력을 받으라, 하지 않을 일을 하라는 요구. 구현 PR 에 ⑥ 의 다른 줄이 닫는
  몫을 하라는 요구도 밖이다」(29 줄). 사실의 틀림은 경계가 아니다 — 이 PR 이 들이거나 건드린 자리면 안.
- 예산 — `slice-review` 호출 시 4,443 / 천장 4,500(`verify-budget.py` 의 `SKILL_ON_INVOKE_MAX`), `slice-docs` 1,903. 지도 링크를 다시 박는 것은 길이가
  같다(전체 sha 40 자).
- 지도 판 — 두 스킬의 링크가 `fe31909` 를 박았고 `verify-map-pin.py` 는 「링크 2 · 박은 커밋 fe31909 · 기준 d561c67」로 지나간다. 지도와 플러그인을 한
  PR 에서 고치면 지도를 고친 커밋을 박는 커밋이 하나 더 든다(ADR 0019 결과 2 · 7 — 검사의 메시지가 박을 커밋을 찍는다).

**시스템 구조.** 부품 · 경계 · 흐름은 그대로다 — `docs/architecture.md` 를 고치지 않는다. 바뀌는 것은 절차의 칸과 그것을 읽는 스킬의 문구다.

## ② 보장하는 것 / 보장하지 않는 것

**보장하는 것** — 번호는 ⑤ 와 PR 본문이 같이 쓴다. 문구는 B 의 일이고, 아래 뜻을 다 든다.

- **D1 절차의 ⑤** (B) — 「설계 문서의 칸」 ⑤ 행의 「담는 것」이 지금 문장 둘을 그대로 두고 덧붙인다.
  - 시험을 세우는 조각의 착공 ⑤ 는 **보장의 조건마다 무엇으로 보일지와 시험 규칙까지** 든다.
  - **규칙**은 한 갈래의 시험이 다 지는 것이다 — 예: 거절 시험이 보는 것 · 성공 시험이 보는 것 · 조건마다 꼴 하나 이상 · 시험마다 변조본. 무슨 규칙을
    둘지는 그 조각이 정한다.
  - ③ 이 닫힌 목록이면 규칙이 그 목록을 가리킨다(예: 「③ 의 꼴마다 하나」) — 꼴은 ③ 이 이미 닫는다.
  - **꼴 하나하나는 구현 PR 이 시험 코드로 든다.** 보장의 조건 → 꼴 → 변조본의 대응은 그 PR 본문이 든다 — 설계 끝 날짜 항목에 쌓지 않는다(ADR 0039 의 4).
- **D2 틀의 ⑤** (B) — 틀 `design.md` ⑤ 의 안내가 D1 과 같은 말이다(지금 문장 셋을 두고 덧붙인다). 다른 레포의 착공은 틀을 읽는다(`slice-review` 「1.
  기준」 착공 PR · `verify-docs.py --repo` 의 원천).
- **D3 구현 PR 의 기준** (B) — `slice-review` 「1. 기준」 구현 PR 줄의 「그 줄이 닫는 몫」에 ⑤ 의 규칙이 든다 — 「② 의 보장하는 것 · ③ 의 받는 입력 ·
  ⑤ 의 규칙 · 날짜 항목의 보장 가운데 그 줄이 닫는 몫」. 그래서 구현 PR 에서 「이 조건에 꼴이 없다」는 ⑤ 의 규칙(조건마다 꼴 하나 이상)에 비춰
  안이다(ADR 0039 의 3).
- **D4 착공 PR 의 밖** (B) — `slice-review` 「2. 가르기」 밖 갈래에 「착공 PR 에 ⑤ 가 구현 PR 에 맡긴 꼴을 채우라는 요구」가 든다. 규칙의 빈칸(한 갈래의
  시험이 다 같이 놓치는 것)은 지금처럼 기준(틀 ⑤ 의 안내 · 요구사항의 성공 기준)에 비춰 가른다 — 밖이 아니다(ADR 0039 의 2). 착공이 꼴을 실었는데 그
  꼴이 틀렸으면(사실의 틀림) 지금 규칙대로 그 PR 이 들인 자리라 안이다.
- **D5 판과 지도** (B) — `vibe-slice` 판 0.4.3. 두 스킬의 지도 링크가 B 에서 `docs/procedure.md` 를 고친 커밋을 박는다 — `verify-map-pin.py` 가 지나간다.
  두 `SKILL.md` 에서 링크 말고 바뀐 바이트는 D3 · D4 뿐이다.
- **D6 사례** (B) — `docs/procedure.md` 「사례」 끝에 claude-kit #101 절 — 단계마다 무엇을 건너뛰었나 · 무엇이 났나(그 절의 꼴), 회차마다 규칙 · 꼴 ·
  그 밖의 수(요구사항 「문제」의 표), 구현 #102 의 회차, 반대 사례 #52(③ 의 꼴), 이유 코드는 그 조각의 장치이고 절차의 규칙이 아니라는 것(ADR 0039 의 5).
- **D7 예산** (B) — `slice-review` 호출 시 문자가 4,500 이하다. `budget.txt` 는 `slice-review` 줄과 `vibe-slice` 의 합계 줄만 바뀐다.
- **게이트** (A · B)
  - G1 `./scripts/gates.sh` 스물넷 그대로 통과 — `verify-docs.py`(제목 · 경로 · 조각 나눔) · `verify-manifest.py`(판) · `verify-budget.py` ·
    `verify-map-pin.py` 가 그 안이다.
  - G2 A 는 결정 문서뿐이다 — `verify-slice-gate.py` 가 본다. B 는 A 가 머지된 뒤에 선다.
  - G3 A · B 의 `git diff --name-only main...HEAD` 와 수트 지문 목록의 교집합 0.

**보장하지 않는 것(알려진 한계)**

- **⑤ 의 뜻을 기계로 묻지 않는다** — 착공 ⑤ 에 규칙이 있는지, 규칙이 망가진 구현을 막는지, 구현 PR 이 조건마다 꼴을 들었는지는 리뷰가 본다.
  `verify-docs.py` 는 제목만 본다(ADR 0010 · 하지 않을 일 3).
- **규칙과 꼴의 경계가 흐린 지적** — D1 의 가르는 말(한 갈래의 시험이 다 지는가 / 한 조건의 시험인가)로 가른다. 그래도 갈리지 않으면 `slice-review`
  의 말하지 않음(3)이다 — 착공 PR 은 그 PR 의 ⑤ 에 정한다.
- **회차가 줄어드는지** — 이 조각은 #101 에 대어 갈래가 갈리는 것(요구사항 성공 기준 3)까지 본다. 다음 검사 · 스크립트 조각의 착공 · 구현 회차는 그
  조각이 보인다.
- **이미 설치된 판과 사본** — `vibe-slice` 0.4.2 이하를 깐 세션은 갱신해야 새 문구를 읽는다. ERP 의 스킬 사본은 그 레포의 다음 `sync-slice.sh` 에서
  바뀐다(하지 않을 일 5).
- **지난 조각의 기록** — 지난 착공 설계의 ⑤ 가 꼴을 들었어도 그대로다. 그 조각들의 리뷰를 다시 가르지 않는다(하지 않을 일 1).
- **시험을 세우지 않는 조각** — 수트 · 감사자 문구 조각의 ⑤(측정 · 전수)는 D1 이 바꾸지 않는다. 「시험을 세우는 조각」은 키 없이 도는 시험(자체 시험 ·
  `bite-*` · `bite-gates.sh` 의 절)을 더하거나 고치는 조각이다.
- **아직 겪지 않은 가설적 경계 사례** — 예: 착공 PR 에 구현을 함께 실은 PR(그것은 `slice-review` 「1. 기준」 대로 착공 PR 이고 구현은 2 의 안이다), 꼴을
  착공에서 일부러 닫기로 한 조각. 리뷰가 그 밖을 짚으면 범위 밖이다(조각 6 「닫으며」).

## ④ 결정

**정한 것** — ADR 0039. 일곱 다 저자가 정했다(2026-10-19) — 1 은 조각 나눔의 목표 줄로, 2 ~ 7 은 착공 대화에서. 일곱 다 세션이 추천한 쪽이다.

- 1 착공 ⑤ 의 범위 — 보장의 조건 · 시험 규칙까지, 꼴 하나하나는 구현 PR(조각 나눔의 목표 줄 그대로)
- 2 착공 PR 의 꼴 지적 — 밖(구현 PR 이 받는다), 규칙의 빈칸은 안(② D4)
- 3 구현 PR 의 기준 — ⑤ 의 규칙을 넣는다(② D3)
- 4 꼴의 자리 — 시험 코드와 그 PR 본문, 설계에 쌓지 않음(② D1)
- 5 이유 코드 — 절차에 넣지 않고 사례로만(② D6)
- 6 사례 — #101 을 더한다(② D6)
- 7 PR 나눔 — 착공 A 뒤 구현 B 하나

**열어 둔 것**

없음 — 일곱 다 정했다. ⑤ 칸 · 틀 · 스킬의 글자 그대로의 문구는 결정이 아니라 B 의 일이다 — ② 의 뜻을 다 들고 D7 의 예산 안에서 무엇을 썼는지를 PR
