# 조각 44 — 감사자 README 의 모호한 수 (2026-10-29 착공)

요구사항이다 — **무엇을 · 왜.** 어떻게 · 경계는 같은 폴더의 `design.md`, 대안이 있던 결정은 ADR 0057.

이 조각을 「다음 조각」으로 적은 닫힌 조각은 조각 43 「부적합 대장 검사」다 — 그 `## 닫으며 (2026-10-29)` 끝 줄이 이 줄을 다음 조각으로 적었다(닫는 세션이 남은
순서 없는 줄을 대 보이고 꺼내는 조건이 없고 모델 비용이 거의 없는 이 줄을 추천해 저자가 골랐다). 고치면 `vibe-audit` 판을 올린다고 적었고, 착공은 그 닫는 PR 이
머지된 `main`(`e37e7a4`) 위에서 연다. 의존한 조각은 없다(조각 나눔의 의존 칸 `—`). 착공 세션이 갈래 넷(지운다 · 「둘」로 고치고 닻을 단다 · 표에 줄을 더해
셋으로 · 「셋」이 무엇인지 밝힌다)을 보이고 물어, 저자가 세션이 추천한 「지운다」를 골랐다(ADR 0057 의 1). 이 착공 세션의 claude-kit 클론은 얕지 않았다
(`git rev-parse --is-shallow-repository` → `false`).

## 문제

**`vibe-audit/README.md` 의 한 문장이 무엇을 센 수인지 읽히지 않는다.** 「이 감사자들은 감사받는가」 절의 「케이스 스물여섯이 셋을 잽니다.」 바로 아래 표는 두 줄
(판정 · 트리거)이다. 읽는 사람은 셋째 줄을 찾거나, 표가 낡았다고 읽는다.

- **처음부터 두 줄 표 위에 있었다.** 표를 세운 `75d17c5`(2026-09-24)부터 「셋」이었고 그때도 표는 판정 · 트리거 두 줄이었다. 그 뒤 케이스 수만 세 번 바뀌었다
  (열여덟 → 스물넷 → 스물다섯 → 스물여섯 — `844318e` · `2177869` · `e185a4a`). 「재는 것」 칸의 「오검율과 판정의 근거」 · 트리거를 셋으로 센 것으로 읽을 수 있지만
  그렇게 적힌 곳은 없다.
- **감사가 두 번 짚었고, 닻이 「셋」을 글자로 고정해 두었다.** 조각 42 「적힌 수 검사」의 PR C 가 찾았고(그 설계 끝 「PR C 에서 정한 것」의 「찾은 것 — 고치지
  않았다」), 닫기 전 `audit-internal` 회차 13 이 OB-12 로 냈다(`docs/audit/records/audit-internal-2026-10-28-112733.md`). 「스물여섯」은 `verify-counts.py` 의 닻
  `케이스 {N}이 셋을` 이 문다 — 그 꼴에 「셋을」이 글자로 들어 있어, 문장을 고치는 PR 은 닻을 함께 고쳐야 한다.
- **고치면 플러그인 판을 올린다.** 플러그인의 파일이라 판이 그대로면 이미 설치한 레포가 `claude plugin update` 로 받지 않는다(`CHECKLIST.md`, ADR 0013). 판을 그대로
  둔 조각 42 가 고치지 않고 조각 나눔의 줄로 넘겼다.

## 핵심 사용자와 시나리오

- 사용자: `vibe-audit` 를 설치하고 README 로 「이 감사자들이 무엇으로 감사받나」를 읽는 사람, 그리고 그 문장을 지난 기록으로 읽는 감사자(`audit-internal`).
- 시나리오: README 의 「이 감사자들은 감사받는가」를 읽는다 → 케이스 수와 「아래 표」를 읽고 표의 두 줄로 바로 간다 — 셋째를 찾지 않는다 → 케이스 폴더가 늘면
  `verify-counts.py` 가 「스물여섯」을 계속 문다 → 표에 줄이 늘거나 줄어도 그 문장은 낡지 않는다.

## 성공 기준

1. **모호한 수가 없다** — `vibe-audit/README.md` 「이 감사자들은 감사받는가」의 그 문장에 「셋」이 없고, 수 없이 아래 표를 가리킨다. 케이스 수(「스물여섯」)는 남고
   닻을 그대로 가진다 — `verify-counts.py` 의 닻 수는 늘지도 줄지도 않는다.
2. **닻이 새 문장을 문다** — `verify-counts.py` 가 `main` 트리에서 PASS 이고, 그 문장을 옛 꼴(「…이 셋을 잽니다」)로 되돌린 사본은 `FAIL [D2]` 로, 케이스 수만 틀리게
   고친 사본은 `FAIL [D1]` 로 떨어진다(구현 PR 본문의 손 재현). `bite-gates.sh` 의 대조군(케이스 다섯을 더하고 문장을 합성 낱말로 고친 사본)이 고치지 않은 채 지나간다.
3. **판** — `vibe-audit` 판이 0.4.6 이고 `claude plugin validate` 가 두 플러그인을 통과한다.
4. **게이트** — 구현 PR 의 CI gate 잡이 변조 시험까지 통과하고, 작업트리의 인자 없는 `./scripts/gates.sh` 가 끝 줄 「스물여덟 다 통과」로 끝난다. 수트 지문이 바뀌는
   그 PR 의 route 수트가 통과한다.
5. **감사 회차** — 닫기 전에 `audit-internal` 을 돌려 `docs/audit/` 의 부적합 대장에 등록하고(그 등록이 `verify-ledger.py` 를 지난다), `## 닫으며` 가 회차를 든다.

## 하지 않을 일

1. **README 의 다른 수를 다루지 않는다** — 「셋은 요청하지 않아도 뜹니다」 · 「부르지 않은 셋」 · 「감사자 6종」 따위는 뜻이 읽히거나 이미 닻을 가졌다(조각 42 설계 끝
   「닻 없이 둔 것」). 이 조각은 OB-12 가 짚은 한 문장만 고친다.
2. **표에 줄을 더하지 않는다** — 회수율(`vibe-audit/recall/`)을 README 에 들이지 않는다. 회수율 케이스는 「스물여섯」 밖이고 재기만 한다(`vibe-audit/evals/README.md`
   「회수율」). README 의 범위를 넓히는 일은 이 줄의 목표가 아니다(ADR 0057 의 1).
3. **감사자 · 커맨드 · 검사기 · 케이스를 고치지 않는다** — 감사자 문구와 공통 절은 그대로다. 사본(`copies.json`)도 다시 심지 않는다 — README 는 사본에 가지 않는다.
4. **`verify-counts.py` 의 규칙을 바꾸지 않는다** — 닻 하나의 꼴만 새 문장에 맞춘다. 닻을 더하거나 원천을 더하지 않고, 규칙 ID · 무는 범위는 그대로다.
5. **조각 나눔의 다른 줄을 다루지 않는다** — 「가르지 못한 결함 다섯」 · 「항목 10 과 머리의 어긋남」 · 「가르지 못한 빈 갈래 둘」 · 「모델이 모르는 판」.

## 제약

- 스택: 마크다운 한 문장 · python3 표준 라이브러리의 닻 한 줄 · 매니페스트 하나(`vibe-audit/.claude-plugin/plugin.json`).
- 원본: `main` `e37e7a4`.
- 비용: route 수트 한 번 — `vibe-audit/.claude-plugin/plugin.json` 이 수트 지문(`eval-key.py`)에 든다. README 는 지문 밖이다(`bite-gates.sh` 의 `keyed same`). `route-*`
  10 × 3 회다. 전수는 돌지 않는다 — 판정 케이스에 닿는 감사자 문구를 고치지 않는다. 구현 PR 은 `verify-counts.py` · `plugin.json` 이 변조 시험 지문(`gate-key.py`)에 들어
  CI 가 변조 시험까지 돈다(약 7 분).
- 기간: 닫기까지 **2026-11-05**.
- 리뷰: PR 본문에 설계 ② 를 적고, 착공 PR 도 구현 PR 도 스킬 `slice-review` 로 가른다. PR 마다 **3라운드**를 넘기면 소유자가 판정한다.
- 감사 회차: 닫기 전 — `audit-internal`(대장의 NC-15 가 고침으로 재감사를 기다리고, 저자가 「다음 `audit-internal` 회차」가 닫는다고 정했다 — `docs/audit/nc-ledger.md`.
  이 조각이 고치는 것도 회차 13 의 OB-12 다). 바뀌는 것(README 한 문장 · 닻 · 판)은 `vibe-audit` README 「대략의 주기」 표의 어느 줄에도 닿지 않는다.
