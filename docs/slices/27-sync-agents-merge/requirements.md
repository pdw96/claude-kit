# 조각 27 — `sync-agents.sh --merge` (2026-10-18 착공)

요구사항이다 — **무엇을 · 왜.** 어떻게 · 경계는 같은 폴더의 `design.md`, 대안이 있던 결정은 ADR 0038 — 충돌을 푸는 규칙은 ADR 0027 의 2 를 그대로
따른다.

이 조각을 「다음 조각」으로 적은 것은 조각 26 의 `## 닫으며 (2026-10-18)` 이다 — 그 기록의 「넘긴 것」(없음) · 「지켜본 것」 넷을 읽고 착공한다
(ADR 0012). 「다음 조각」 문단이 이 줄을 순서 27 로 매기며 목표 · 의존 · README 를 어떻게 옮길지를 이 조각에 넘겼다 — README 는 ADR 0038 의 1 이
정한다. 「다음 전수의 `brief-absent`」 · 「줄기 밖의 근거 한정 a3 · e1」 · 「줄기가 다른 질문의 줄에 걸리는 몫」은 수트의 일이라 이 조각이 다루지
않는다(하지 않을 일 6). 「얕은 클론」은 이 착공 세션의 클론이 얕지 않았다(`git rev-parse --is-shallow-repository` → `false`) — `--merge` 가 원본의
역사를 읽으므로 이 조각에서는 그 줄이 스크립트의 멈춤이 된다(설계 ② P1).

## 문제

**특화가 있는 사본을 다시 심는 일이 스크립트 밖에 있다.** `sync-agents.sh` 의 길은 둘뿐이다 — `--force` 없이는 사본이 있는 파일을 건너뛰고 대장을
옮기지 않으며, `--force` 는 감사자 · 커맨드 · 검사기 · README 를 다 덮는다. ERP 사본은 `feedback.json` 이 특화로 판정한 덩어리를 들어(조각
「사본을 0.4.1 로 다시 심기」 성공 기준 3 — 판정된 해시 스물일곱 가운데 특화 스물둘), 덮으면 그것이 사라진다. 그래서 두 번 다 손으로 세 쪽 병합을
했다(ADR 0027 의 1).

- **손 병합 두 번** — 조각 「사본 다시 심기」 C(pdw96/ERP#111, 2026-10-14)는 충돌 여덟을 저자가 풀었다. 조각 「사본을 0.4.1 로 다시 심기」
  C(pdw96/ERP#113, 2026-10-16)는 같은 명령을 되풀이해 여덟 파일 충돌 0 이었다 — 바뀐 줄 `audit-contract` · `audit-data` · `audit-internal` ·
  `audit-ops` · `audit-quality` 1 · `audit-secrets` 2 · `audit-brief` 1 · `verify-brief.py` 0. 두 번 다 명령은 PR 본문의 스크립트였고, 저장소에는 없다.
- **README 는 두 번 다 병합 밖이었다** — ERP 의 `.claude/agents/README.md` 는 ERP 가 다시 쓴 것(44 줄)이고, 3 줄의 출처 SHA 를 손으로 바꿨다. 대장은
  `verify-copy.py` PASS 뒤 손으로 옮겼다 — `CHECKLIST.md` 「대장을 건드렸다면」 첫 줄(「`copies.json` 은 `sync-agents.sh` 를 거쳤다」)의 예외다.
- **재현하면 같은 결과가 나온다** — 2026-10-18 에 스크래치에서 두 번을 다시 돌렸다(ERP 익명 클론 `6dda439`, claude-kit 역사 전체). 밑은
  `synced_commit` 의 작업트리에서 그 커밋의 `sync-agents.sh` 를 빈 자리에 돌린 모양, 새 원본은 같은 식으로 새 커밋을 심은 모양, 사본은 그 PR 의
  가지가 선 ERP 커밋이다.

  | 재현 | 밑 → 새 원본 | 사본 | 감사자 · 커맨드 · 검사기 여덟 | README |
  |---|---|---|---|---|
  | #111 | `3d6964a` → `018842c` | `edab087^` | 충돌 여덟(`audit-data` 1 · `audit-internal` 4 · `audit-quality` 2 · `audit-secrets` 1). 깨끗한 넷은 `edab087` 과 바이트로 같다 | 세 쪽 병합 충돌 1 · SHA 치환 = `edab087` |
  | #113 | `018842c` → `ddcd21f` | `c75c215` | 충돌 0 · 여덟 다 `c9331a3` 과 바이트로 같다 | 세 쪽 병합 충돌 1 · SHA 치환 = `c9331a3` |

  밑을 지금 스크립트의 awk · `HDR` 에 옛 SHA 만 넣어 세우면 #111 이 충돌 열넷이다 — `3d6964a` 의 머리줄 꼴이 지금과 달랐다(ADR 0038 「맥락」).
- **다음 심기도 같은 손을 부른다** — 원본 감사자 · 커맨드 · 검사기가 움직이면 두 레포를 다시 심는다(ADR 0022 의 1 — 두 레포는 사본만 쓴다).
  손 병합의 명령 · README · 대장 셋을 사람이 매번 맞춘다.

## 핵심 사용자와 시나리오

- 사용자: claude-kit 의 저자(ERP · 강호쟁패의 소유자이기도 하다), 그리고 원본이 움직인 뒤 사본을 다시 심는 세션.
- 시나리오: 원본 `vibe-audit` 의 감사자 한 줄이 바뀌어 머지된다 → 세션이 claude-kit `main` 에서 `./scripts/sync-agents.sh <ERP> --merge` 를 돌린다 →
  스크립트가 파일마다 밑 · 사본 · 새 원본으로 `git merge-file` 을 돌리고, 충돌 0 · README 의 출처 자리 하나 · `verify-copy.py` PASS 를 본 뒤 감사자 ·
  커맨드 · 검사기 · README 를 쓰고 대장의 그 줄을 옮긴다 → 파일마다 충돌 수 · 바뀐 줄 수 표를 찍는다 → 세션이 그 표를 ERP PR 본문에 싣는다. 충돌이
  하나라도 나면 스크립트는 ERP 에 아무것도 쓰지 않고 세 재료와 충돌 표시 병합본이 든 임시 폴더를 찍는다 → 그 레포의 PR 에서 저자가 ADR 0027 의 2 로
  푼다.

## 성공 기준

1. **충돌 없는 병합을 쓴다** — 대장에 있는 사본에 `--merge` 를 돌리면 감사자 · 커맨드 · 검사기가 파일마다 「밑 · 사본 · 새 원본의 `git merge-file`」
   결과와 바이트로 같고, README 는 출처 SHA 한 자리만 바뀌며, 대장의 그 줄은 `synced_commit` 이 HEAD 의 전체 SHA · `synced_at` 이 그날이고 `repo` ·
   `agents_path` 는 그대로다. 파일마다 충돌 수 · 바뀐 줄 수를 찍는다.
2. **걸리면 아무것도 쓰지 않는다** — 충돌 하나 · README 의 출처 자리가 하나가 아님 · 원본의 파일 집합이 `synced_commit` 과 다름 · 병합본의
   `verify-copy.py` FAIL · 대장에 그 사본의 줄이 없음 · 얕은 복제 · `--force` 와 함께 줌 · 사본 레포가 원격 기본 가지보다 뒤 · 사본 자리에 커밋 안 된
   것 · 사본 레포의 원격을 못 받음, 그 어느 것이든 종료 코드가 0 이 아니고 사본 레포와 대장의
   바이트가 그대로다. 충돌이면 세 재료와 충돌 표시 병합본이 든 사본 밖 임시 폴더를 찍는다.
3. **물린다** — `./scripts/bite-gates.sh` 의 `sync-agents.sh` 절이 1 · 2 를 임시 원본 · 사본으로 본다. 그 절의 새 시험마다, 그 시험이 막는 자리를
   망가뜨린 `sync-agents.sh` 사본에서 떨어지는 것을 PR 본문에 보인다. `--merge` 의 멈춤마다 이유 코드가 있고, 코드마다 그것을 기대하는 시험이 있는지를
   그 절이 문다 — 시험이 없는 코드가 생기면 떨어진다(ADR 0038 의 13).
4. **손 병합 두 번이 다시 나온다** — ERP 익명 클론에서 #113 을 재현하면(사본 `c75c215`, 대장 줄 `018842c`, 원본 `ddcd21f` 의 `vibe-audit/`) 감사자 ·
   커맨드 · 검사기 · README 아홉이 출처 SHA 자리 말고 ERP `c9331a3` 과 바이트로 같다 — 재현의 원본 커밋은 `ddcd21f` 에 B 의 스크립트를 얹은 스크래치
   커밋이라 그 SHA 가 박힌다(설계 ② R1). #111 을 재현하면(사본 `edab087^`, 대장 줄 `3d6964a`, 원본 `018842c` 의 `vibe-audit/`) 충돌 여덟 — 파일마다
   1 · 4 · 2 · 1 — 을 찍고 클론과 스크래치 대장이 그대로다. ERP 에는 쓰지 않는다.
5. **지금 길은 그대로다** — `--merge` 없이 · `--force` 의 동작은 바이트 하나 바뀌지 않는다 — 지금 `bite-gates.sh` 의 `sync-agents.sh` 시험이 다 지나가고,
   빈 자리에 심은 결과와 `--force` 로 덮은 결과가 `main` 의 스크립트로 심은 것과 `diff -r` 같다.
6. **살아 있는 문서가 지금과 맞다** — `docs/architecture.md` 「심기」 · `README.md` 의 사본 레인 · `CHECKLIST.md` 「대장을 건드렸다면」 첫 줄 · 스크립트
   머리의 쓰는 법이 `--merge` 를 든다 — 다시 심기는 늘 `--merge`, `--force` 는 사본을 일부러 원본으로 되돌릴 때다. 손 병합이 남는 자리는 ADR 0038 의
   3 과 `--merge` 가 멈춘 경우뿐이라고 적는다.
7. `./scripts/gates.sh` 가 이 조각의 PR 마다 로컬과 CI gate 잡에서 통과하고, 검사 수는 스물넷 그대로다. 이 조각의 PR 은 수트 지문(`eval-key.py
   route --list` · `full --list`) 밖이다 — eval 잡이 건너뛴다.

## 하지 않을 일

1. **사본 레포를 다시 심지 않는다** — `ddcd21f` 뒤 원본 감사자 · 커맨드 · 검사기는 움직이지 않았다(`git diff --stat ddcd21f 30bc0e2 -- vibe-audit/agents
   vibe-audit/commands vibe-audit/scripts` 가 비었다). 두 레포 · 대장 `copies.json` · `feedback.json` 은 그대로다. `--merge` 의 첫 실물은 다음 심기다.
2. **충돌을 스크립트가 풀지 않는다** — 푸는 규칙은 ADR 0027 의 2 이고 그 레포의 PR 에서 저자가 정한다. 충돌 표시를 사본에 쓰지 않는다.
3. **새 파일 · 물러난 파일을 다루지 않는다** — 원본의 파일 집합이 `synced_commit` 과 다르면 멈춘다(ADR 0038 의 3).
4. **원본 · 수트를 고치지 않는다** — 감사자 · 커맨드 · 검사기 · 판 · `run-evals.sh` · `eval.yml` · `eval-key.py` · `verify-copy.py` · `verify-copies.py` ·
   `compare-copies.py` 는 그대로다. 앵커볼트(이름 · `tools` · 공통 절 · 대장의 모양 · 「…의 칸」 · `AGENTS.md`)를 건드리지 않는다.
5. **`sync-slice.sh` 에 같은 길을 두지 않는다** — 스킬 사본은 대장에 적지 않고 `--force` 로만 폴더째 덮는다(ADR 0013). 특화가 있는 스킬 사본의 증거가
   없다.
6. **조각 나눔의 다른 줄을 다루지 않는다** — 「회수율 측정」 · 「가르지 못한 결함 다섯」 · 「항목 10 과 머리의 어긋남」 · 「가르지 못한 빈 갈래 둘」.
   조각 26 「지켜본 것」의 수트 셋도.
7. **`--merge` 를 기본으로 하지 않는다** — 인자 없는 길(사본이 있으면 건너뛰고 대장을 옮기지 않음)은 그대로다.

## 제약

- 스택: bash · python3 표준 라이브러리 · git(`git merge-file` · `git worktree`). `sync-agents.sh` 는 bash 이고 대장은 그 안의 python3 이 쓴다 — 같은 틀을
  따른다.
- 원본: `main` `30bc0e2`. `scripts/sync-agents.sh` 는 `c56e571`(조각 8 B)에서 마지막으로 바뀌었다.
- 재현: ERP 는 공개 저장소라 익명 클론(`GIT_LFS_SKIP_SMUDGE=1`)으로 읽는다 — 쓰지 않으므로 `add_repo` 를 붙이지 않는다. 스크래치 · 클론 · 재현
  스크립트는 저장소에 싣지 않는다.
- 클론: claude-kit 은 역사 전체 — 밑이 `synced_commit` 의 작업트리다.
- CI: `scripts/sync-agents.sh` · `scripts/bite-gates.sh` · `docs/` · `README.md` · `CHECKLIST.md` 는 두 수트 지문 밖이다 — eval 잡이 건너뛴다.
- 네트워크: `--merge` 는 사본 레포의 원격 기본 가지를 받는다(ADR 0038 의 8) — 오프라인이면 멈춘다.
- 비용: 모델 호출이 없다.
- 기간: 구현 PR 하나까지 **사흘**(2026-10-20 까지).
- 리뷰: PR 본문에 설계 ② 를 적고, 착공 PR 도 구현 PR 도 스킬 `slice-review` 로 가른다. PR 마다 **3라운드**를 넘기면 소유자가 판정한다.

### 배포

#102 의 머지가 배포다(설계 ⑤ 「단계 5」) — `sync-agents.sh` 는 claude-kit 안의 스크립트라 플러그인 판이 오르지 않고, 사본 레포가 받을 것이 없다.
첫 실물은 다음 심기의 사본 레포 PR 이다(하지 않을 일 1). 되돌리는 길은 이 닫는 기록을 먼저 되돌린 뒤 #102 를 되돌리는 것이다 — 이 기록이
마스터플랜의 27 줄(`닫힘`)과 「착공 시험 계획의 경계」 줄(순서 28)을 고치므로, 그것을 두고 구현만 되돌리면 살아 있는 문서가 되돌린 상태와 갈린다.

### 지켜본 것 — 줄을 더하지 않는다

증거가 해를 보이지 않거나 첫 실물이 아직 없어 조각 나눔에 줄을 더하지 않는다.

- **`--merge` 의 첫 실물** — 다음 심기의 사본 레포 PR 이다. 그 PR 본문에 M7 표를 싣고, 멈추면 이유 코드와 남긴 폴더로 ADR 0027 의 2 를 따른다.
  설계 ② 「보장하지 않는 것」의 「특화 없는 사본(강호쟁패)」 — `--merge` 결과가 `--force` 와 같은지 — 도 그때 처음 보인다.
- **대장에 적히는 `agents_path` 의 꼴** — 조각 「사본을 0.4.1 로 다시 심기」 「지켜본 것」의 갈림(`--force` 는 `$HOME` 으로 `~/…` 를 다시 만든다)은
  `--merge` 길에서는 나지 않는다 — M6 은 그 줄의 바이트를 그대로 둔다(T14). 인자 없는 길 · `--force` 는 그대로라(성공 기준 5) 그 갈림도 그대로다.
- **`bite-gates.sh` 의 시간** — `--merge` 절로 로컬 5 분 → 7 분 남짓이 됐다(#102 본문). CI gate 잡의 「키 없이 도는 게이트」 단계는 `c76ce04` 에서 4 분 19 초였다.
- **조각 「`brief-absent` 정규식의 머리 근거 한정」의 「지켜본 것」 셋** — 다음 전수의 `brief-absent` · 줄기 밖의 근거 한정 a3 · e1 · 줄기가 다른
  질문의 줄에 걸리는 몫. 이 조각은 수트를 돌리지 않아(하지 않을 일 6) 그대로 지켜본다. 원문의 아티팩트는 그 기록에 적힌 날짜(가장 이른 것
  2027-01-05)까지 남는다.
- **얕은 클론** — 이 닫는 세션의 클론은 얕지 않았다(`git rev-parse --is-shallow-repository` → `false`).
