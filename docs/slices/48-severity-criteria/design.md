## ② 보장하는 것 / 보장하지 않는 것

**보장하는 것**

- **S 기준** — 공통 절 「판정은 넷이다」가 세 등급을 **놔두면 무엇을 잃나**로 정의한다(ADR 0061 의 2).
  - **높음** — 되돌릴 수 없는 손실이다. 지워진 데이터 · 새어 나간 자격증명 · 조용히 틀린 값이 이미 밖에 나간 것.
  - **보통** — 되돌릴 수는 있지만 틀린 결과가 사람이나 다른 시스템에 닿거나, 막는다고 믿는 회귀를 검사 · 게이트가 막지 않는다.
  - **낮음** — 결과는 같고 문서 · 주석 · 표기만 어긋난다.
  - 기존 규칙은 그대로이고 이 기준과 부딪히지 않는다 — 모를 때 「틀렸을 때 잃는 것이 큰 쪽」(공통 절), `audit-data` 의 「사람이 입력한 데이터가 있으면 한 단계 올린다」,
    `audit-contract` 의 「조용히 깨지는 변경을 가장 높은 심각도로」(높음의 「조용히 틀린 값」과 같은 말이다).
- **R 까닭** — 여섯의 출력 형식에서 심각도 칸이 등급과 그 까닭 한 줄(무엇을 잃나)을 받는다. 까닭이 없으면 다음 회차와 저자가 등급을 견줄 수 없다.
- **P 공통 절이 같다** — 원본 여섯의 공통 절이 글자 단위로 같다 — `verify-copy.py` PASS. 「판정은 넷이다」 밖의 공통 절 셋은 글자 그대로다.
- **B 예산** — `verify-budget.py` PASS, 호출 시 천장 11,000 · 상시 천장 그대로. 넣은 글자만큼 줄인다 — 공통 절 안에서 줄이면 여섯이 함께 준다. 출력 형식 칸 · 체크 항목 표 ·
  판정 표는 줄이지 않는다.
- **M 측정** — 새 판정 케이스가 5/6 이상(요구사항 성공 기준 4), 대조 케이스가 기준선과 같고(성공 기준 5), 전수 verdict 가 통과다. 측정은 `docs/eval-log/2026-11.md` 에 남는다.
- **L 할 일** — 대장 틀이 등급마다 **기본 할 일**을 든다(ADR 0061 의 3).
  - **높음** — 머지 전에 고친다. 등록하려면 저자가 까닭을 판정 칸에 적는다.
  - **보통** — 이번 조각에서 고치거나, 사건을 기한으로 등록한다.
  - **낮음** — 등록해 모아 고친다. 기한은 그 레포가 정한 사건(예: 다음 닫는 PR)이다.
  - 레포가 기본값을 바꾸면 대장에 적는다. 기본값은 판정을 대신하지 않는다 — 판정은 저자의 것이고, 기본값과 다르면 까닭을 적는다. 규칙은 소급하지 않는다.

**보장하지 않는 것**

- **모델이 기준을 늘 같게 쓰는가** — 새 케이스는 한 픽스처의 두 꼴(높음 하나 · 낮음 하나)만 잰다. 보통의 경계나 다른 감사자의 같은 꼴은 재지 않는다.
- **경계에 걸린 결함** — 되돌릴 수 있는지 저장소만으로 알 수 없는 결함은 기존 「잃는 것이 큰 쪽」 기본값과 확인불가에 맡긴다. 새 규칙을 더하지 않는다.
- **지난 줄** — 대장의 지난 등급은 다시 매기지 않는다(요구사항 하지 않을 일 3).
- **사본 레포** — 다시 심을 때까지 옛 공통 절이다. 사본 레포의 대장은 틀을 베낀 뒤 그 레포의 문서라 기본 할 일을 저절로 받지 않는다(대장 틀의 머리).
- **기본 할 일이 지켜지는가** — 판정과 기본값의 어긋남을 무는 검사는 없다(요구사항 하지 않을 일 6). 사람이 본다.

## ⑤ 검증 계획

시험을 세우는 조각이 아니다 — 키 없이 도는 검사와 그 변조본은 그대로다. 맞음은 기존 검사와 측정으로 보인다.

- V1 **성공 기준 1 · ② S · P** — B 의 diff 가 공통 절에서는 「판정은 넷이다」 안에만 있다. `gates.sh` 의 `verify-copy.py`(원본 여섯의 공통 절) PASS.
- V2 **성공 기준 2 · ② R** — B 의 diff 에서 여섯의 출력 형식 심각도 칸이 같은 글로 바뀐다. B 본문이 그 줄을 든다.
- V3 **성공 기준 3 · ② B** — `python3 scripts/verify-budget.py` PASS 와 `budget.txt` 의 여섯 줄. 줄인 자리와 그 말을 이미 드는 곳의 표는 B 의 PR 본문.
- V4 **성공 기준 4 · ② M** — B 의 머리에서 `./scripts/run-evals.sh --case <새 케이스> --ablation none --runs 6`. 끝 줄의 점수 · 모델 · 비용을 `docs/eval-log/2026-11.md` 에. 새
  케이스에 정규식 그레이더가 있으면 그 샘플(`pass.md` 는 통과, `fail*.md` 는 첫 줄의 그레이더가 문다)을 `verify-graders.py` 가 키 없이 본다. 등급을 읽는 심판 그레이더는
  측정만 본다.
- V5 **성공 기준 5** — 같은 머리에서 ③ C 의 둘을 `--ablation none --runs 3` 으로. 그 뒤 `workflow_dispatch` 전수 한 번 — verdict 와 run 링크를 B 본문과
  `docs/eval-log/2026-11.md` 에.
- V6 **성공 기준 6 · ② L** — C 의 작업트리에서 `python3 scripts/verify-ledger.py` PASS. C 본문이 틀과 이 저장소 대장에 더한 글을 든다.
- V7 **성공 기준 7** — 각 PR 의 CI gate 잡. 구현 PR 작업트리에서 인자 없는 `./scripts/gates.sh` 를 끝까지 돌려 끝 줄을 PR 본문에.
- V8 **성공 기준 8** — B · C 가 머지된 뒤 `main` 에서 기준 `061df14` 로 `audit-quality` · `audit-internal` 을 돌리고 닫는 PR 의 대장에 등록한다.
