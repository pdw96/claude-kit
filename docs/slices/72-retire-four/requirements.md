# 조각 72 — 감사자 넷 은퇴 (2026-11-16 착공)

요구사항이다 — **무엇을 · 왜.** 어떻게 · 경계는 같은 폴더의 `design.md`, 대안이 있던 결정은 ADR 0091.

의존은 `—` 다. 이 조각이 기대는 것은 조각 「덜어내기」(71)의 닫기가 아니라 그 설계 끝 2026-11-16 항목에 적힌 저자의 답(은퇴 대상)이다 — 그 조각은 `진행` 이고 PR #257 이 드래프트로 열려 있다.
저자가 이 착공 세션에서 「#257 위에 쌓아 연다」와 「의존을 `—` 로」를 골랐다(ADR 0091 의 7). 이 조각을 「다음 조각」으로 적은 닫힌 조각은 없다(`없음`). 착공은
`claude/trim-measure`(`f167a93`) 위에서 연다. 그 아래 `main` 은 `8b6c81e` 이고, 같은 커밋에 되돌릴 자리 태그 `v-archive-2026-11` 가 있다.

## 문제

- **앞섬이 없는 감사자를 들고 있다** — 조각 71 의 측정에서 맥락 한 줄을 레포에 둔 일반 도구가 결함 찾기 여섯을 18/18 로 맞혔다(`vibe-audit` 17/18). 미리 박은 기준(ADR 0090 의 3 (나))이 `audit-quality` ·
  `audit-contract` · `audit-secrets` 의 은퇴를 권했고, 저자가 그 셋과 `audit-ops` 를 은퇴로 정했다(2026-11-16).
- **감사자 하나가 지키는 장치보다 장치가 크다** — 이 넷을 태우는 eval · 회수율 케이스가 열넷이고, 넷을 이름으로 든 자리가 스크립트 · 그레이더 · 문서에 퍼져 있다(설계 ① · ③).
- **이름은 앵커볼트다** — 감사자 이름 · 플러그인 구성(`CLAUDE.md` 「앵커볼트」)과 공통 절 문구(사본이 글자 단위로 견준다)를 건드리고, 의도 What 의 「감사자 여섯」이 바뀐다. 결정 기록 없이 지우면 되돌릴
  근거가 남지 않는다.

## 핵심 사용자와 시나리오

- 사용자: 이 저장소의 저자, 그리고 `vibe-audit` 를 마켓플레이스로 받는 사람.
- 시나리오: 착공이 머지된다 → PR A 가 감사자 넷과 그 케이스를 빼고, 남는 둘의 공통 절과 「여섯」을 박은 자리를 맞추고, 의도를 고친다 → 게이트와 CI 수트가 초록이다 → PR B 가 README · 절차 지도에 넘길 곳과
  배포 전 체크리스트를 적는다 → 받는 사람이 `vibe-audit` 에서 `audit-internal` · `audit-data` 둘을 받고, 보안 · 계약 · 품질 · 운영을 어디로 넘기는지 README 에서 읽는다.

## 성공 기준

1. **결정이 기록된다** — 착공 PR 이 ADR 0091 을 더하고, 그 ADR 이 은퇴 대상 넷 · 파일을 지움 · 케이스를 가르는 법 · 공통 절을 고침 · 쌓아 연 순서를 저자가 정한 것으로 든다. 마스터플랜 「범위 변경」에
   의도 What 이 바뀌는 줄이 있다.
2. **감사자가 둘이다** — PR A 뒤 `ls vibe-audit/agents/` 가 `audit-data.md` · `audit-internal.md` 둘이고, 두 파일의 `tools` 가 `["Read", "Grep", "Glob"]` 그대로다.
3. **은퇴 이름이 살아 있는 자리에 없다** — PR B 뒤 `git grep -nE 'audit-(secrets|quality|contract|ops)' -- . ':!docs/audit' ':!docs/eval-log' ':!docs/slices' ':!docs/adr' ':!feedback.json'` 의 줄이 다
   은퇴를 적는 줄(README 의 넘길 곳 · 의도의 범위 변경 기록)이다. PR 본문이 그 출력을 싣는다.
4. **케이스가 ③ 대로다** — PR A 뒤 수트 · 회수율의 케이스가 설계 ③ 의 「지움」을 빼고 「옮김」 · 「좁힘」 · 「그대로」로 남고, 케이스마다 PR A 본문이 한 줄씩 든다.
5. **게이트 · 수트** — `./scripts/gates.sh` 가 PR A · B 마다 작업트리와 CI gate 잡에서 통과한다. PR A 의 CI 수트(route · full)가 통과한다.
6. **맞대기가 돈다** — PR A 뒤 `./scripts/run-compare.sh none --case 'trap-*'` 가 재료 없음(종료 2)으로 멈추지 않는다 — 지운 케이스의 픽스처가 `compare/` 로 옮겨졌다.
7. **감사 회차** — 닫기 전 감사 회차를 돌려 `docs/audit/` 의 대장에 등록했다.

## 하지 않을 일

1. **사본 레포(ERP · 강호쟁패)를 고치지 않는다**(`INTENT.md` Not 4) — 사본의 감사자 여섯은 그 레포가 다시 심을 때 따라온다. `copies.json` 도 그대로다.
2. **글자 예산 천장을 바꾸지 않는다**(ADR 0004) — 스냅숏(`vibe-audit/evals/budget.txt`)만 지금 값으로 맞춘다.
3. **남는 감사자의 체크 항목을 넓히지 않는다** — 은퇴한 담당을 `audit-internal` · `audit-data` 에 옮겨 담지 않는다. 공통 절은 은퇴 이름을 빼고 넘길 곳을 드는 만큼만 고친다.
4. **새 케이스 · 새 검사를 세우지 않는다** — 「옮김」은 태우는 감사자를 바꿀 뿐 그레이더의 뜻을 바꾸지 않는다. 새 실패 조건이 없다.
5. **기록을 고치지 않는다** — `docs/audit/` · `docs/eval-log/` · 조각 문서 · ADR · `feedback.json` 의 은퇴 이름은 그대로다.
6. **`vibe-slice` 를 고치지 않는다** — 스킬 · 틀 · 판이 그대로다.
7. **README 의 맞대기 측정을 다시 하지 않는다** — 「무엇이 다른가」는 조각 71 의 측정을 적고, 새로 재지 않는다.
