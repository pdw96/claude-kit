# 조각 4 — README · CLAUDE.md 를 제 역할로 줄이기 (2026-10-06 착공)

요구사항이다 — **무엇을 · 왜.** 어떻게 · 경계는 같은 폴더의 `design.md`, 대안이 있던 결정은 ADR 0011.

## 문제

세 문서가 제 역할 밖의 값을 들고 있고, 같은 값이 두 군데 있다. 「같은 목록을 두 군데 두면 갈린다」(`CLAUDE.md`)를
이 저장소의 입구와 규칙 문서가 어기고 있다.

- **README(152줄)가 입구가 아니다.** `##` 절 여섯 가운데 「사본은 갈려도 된다」가 되먹임 원칙(`INTENT.md` Why 와 같은
  말)과 1 ~ 3차 되먹임 이야기, 검사 넷의 설명과 「무는지 확인했다」를 든다 — 줄 수로 절반이 넘는다. 마스터플랜
  「가리키는 문서」는 시스템 구조로 README 를 가리키고 「구조를 맡은 문서가 따로 없다」고 적는다. 조각 2 성공 기준 4
  (「claude-kit 이 이 모양으로 선다」)는 이 때문에 **일부**로 닫혔다(조각 2 요구사항 「닫으며」).
- **CLAUDE.md 가 주인이 따로 있는 값을 든다** — CLI 버전 `2.1.28x`, 수트 모델 `claude-sonnet-5-5`(2026-10-05 부터),
  CI 잡 셋의 이름, 되먹임 원칙의 출처(「README」). 수트 모델은 `run-evals.sh` 의 `DEFAULT_MODEL`, 잡은 `eval.yml`,
  CLI 버전은 수트 지문(`eval-key.py`)이 든다. 모델을 `claude-sonnet-5-5` 로 바꿀 때 CLAUDE.md 를 손으로 따라 고쳤다.
- **`vibe-audit/evals/README.md` 가 2157줄 · `##` 절 예순다섯이다.** 지금 상태(케이스 표 · 재는 법 · 고정한 것)와 날짜를 박은
  작업 기록(Codex 1 ~ 35차 · 되먹임 회차 · 측정)이 한 파일에 섞였고, 기록은 순서도 뒤섞였다(26차 → 35차 → 34차 …).
  케이스 표는 다섯 줄인데 케이스는 스물넷이다. `AGENTS.md` 고정 영역이 가리키는 절 셋도 이 안에 묻혀 있다. 덧붙이기만
  하는 기록을 한 파일에 쌓은 결과다 — 조각 폴더가 `PRD.md` 를 대신한 것과 같은 원리(ADR 0008)가 여기엔 없었다.

## 핵심 사용자와 시나리오

- 사용자: 저자 한 명, 그리고 매 세션 `CLAUDE.md` 를 읽는 Claude Code 세션.
- 시나리오: 저자가 수트 모델을 바꾼다 → `run-evals.sh` 한 군데만 고친다 — CLAUDE.md 는 그 파일을 가리키기만 하므로
  따라 고칠 줄이 없다 → 새 세션은 CLAUDE.md 에서 규칙과 주인을 읽고 값은 주인에서 읽는다. 처음 온 사람은 README 에서
  무엇인지 · 어떻게 설치하는지만 읽고 링크로 의도 · 마스터플랜 · 구조 · 수트로 간다. 수트를 고친 날의 작업 기록은
  `docs/eval-log/<YYYY-MM>.md` 끝에 덧붙인다. 살아 있는 `vibe-audit/evals/README.md` 는 그 파일이 든 것 — 케이스 표 ·
  재는 법 · 고정한 것과 그 알려진 한계 — 이 바뀔 때 그 자리를 고치고, 날짜를 박은 작업 기록은 거기 쌓지 않는다.
  리뷰 봇은 `AGENTS.md` 를 따라 살아 있는 README 의 「고정한 것」에서 고정 범위를 읽는다.

## 성공 기준

- README 의 `##` 절이 넷 이하 — 들어 있는 것 · 설치(두 경로) · 새 프로젝트를 열 때 · 가리키는 곳. 되먹임 이야기와
  검사의 설명이 0 줄이고, 지운 문단마다 그 값의 주인이 저장소에 있다(구현 PR 본문의 대응표).
- CLAUDE.md 에 CLI 버전 숫자 · 모델 id · CI 잡 이름이 0 개이고, 그 줄은 주인 파일을 가리킨다.
- 마스터플랜 「가리키는 문서」의 시스템 구조 줄이 `docs/architecture.md` 를 가리키고, 목표 · 범위는 `INTENT.md` 한
  군데만 든다 — 조각 2 성공 기준 4 의 넘긴 것이 닫힌다.
- 옮기기 전의 `vibe-audit/evals/README.md` 와 `docs/eval-log/` 의 첫 기록 파일이 바이트로 같다.
- 살아 있는 `vibe-audit/evals/README.md` 의 케이스 표가 케이스 폴더마다 꼭 한 줄이고(지금 스물넷), 날짜를 박은 작업
  기록 절이 0 개이며, `AGENTS.md` 가 가리키는 절이 다 그 파일에 있다.
- 구현 PR 이 바꾼 파일 가운데 수트 지문(`eval-key.py route --list` · `full --list`)에 드는 것이 0 개 — route 수트가 이
  조각 때문에 다시 돌지 않는다.
- `./scripts/gates.sh` 열둘이 구현 PR 마다 통과한다.

## 하지 않을 일

1. **새 검사를 세우지 않는다** — README · CLAUDE.md 가 값을 다시 드는지는 사람이 본다(ADR 0011 의 6).
2. **수트 지문 안 파일의 옛 참조를 고치지 않는다** — `run-evals.sh` · `eval-key.py` · `sync-agents.sh` · `eval.yml` ·
   `verify-brief.py` · 그레이더의 `evals/README.md 「…」`. 살아 있는 README 의 한 줄이 잇는다(ADR 0011 의 5).
3. **지난 기록의 글자를 고치지 않는다** — 옮길 뿐이다. 뒤섞인 순서와 낡은 숫자도 그대로다. 조각 폴더 · ADR 의 옛
   참조도 고치지 않는다.
4. **플러그인 입구 `vibe-audit/README.md` 를 줄이지 않는다** — 수트를 가리키는 두 줄만 살아 있는 README 의 있는 절로
   고친다.
5. **앵커볼트를 바꾸지 않는다** — 이름 · 감사자의 `tools` · 공통 절 · 대장 · 문서의 모양. `AGENTS.md` 고정 영역은
   가리키는 자리만 바꾼다(ADR 0011 의 4, 저자 결정). 고정한 대상과 알려진 한계는 그대로다.
6. **`docs/architecture.md` 의 모양을 정하지 않는다** — 필수 절을 두지 않고 절차 지도의 칸도 늘리지 않는다.
7. **다른 레포의 README · CLAUDE.md 를 보지 않는다** — 조각 나눔 「틀 배포」.

## 제약

- 스택: 마크다운과 `git mv`. 스크립트를 고치지 않는다.
- 모델 비용 **$0** — 수트 지문에 드는 파일을 건드리지 않으므로 route 수트가 다시 돌지 않는다. 조각 3 은 `eval.yml` 을
  고칠 때마다 수트가 돌아 한 번이 네 번이 됐다(조각 3 요구사항 「닫으며」).
- 기간 **하루**.
- `./scripts/gates.sh` 는 지금 열둘이 그대로 통과해야 한다.
- 리뷰: PR 본문에 설계 ② 를 적고, 그 밖의 지적은 고치지 않고 답글로 넘긴다. **3라운드**를 넘기면 소유자가 판정한다.
