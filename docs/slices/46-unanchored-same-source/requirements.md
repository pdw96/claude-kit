# 조각 46 — 닻 없는 같은 원천 문장 (2026-10-29 착공)

요구사항이다 — **무엇을 · 왜.** 어떻게 · 경계는 같은 폴더의 `design.md`, 대안이 있던 결정은 ADR 0059.

이 조각을 「다음 조각」으로 적은 닫힌 조각은 조각 45 「모델이 모르는 판」이다 — 그 `## 닫으며 (2026-10-29)` 끝 줄이 이 줄을 다음 조각으로 적었다(닫는 세션이 남은
순서 없는 줄을 대 보이고, 근거가 세 회차이고 키 없이 도는 일이라 모델 비용이 거의 없는 이 줄을 추천해 저자가 골랐다). 착공은 그 닫는 PR 이 머지된 `main`(`3d2c0ba`)
위에서 연다. 조각 나눔의 이 줄은 의존이 `—` 다. 착공 세션이 `3d2c0ba` 를 시제품으로 훑은 수(설계 ③)를 보이고 갈래 넷과 무는 범위 셋을 물어, 저자가 세션이 추천한
「좁은 훑기 검사」와 「모든 원천」을 골랐다(ADR 0059 의 1 · 2). 이 착공 세션의 claude-kit 클론은 얕지 않았다(`git rev-parse --is-shallow-repository` → `false`).

## 문제

**원천을 바꾼 PR 이 같은 원천의 수를 적은 다른 문장을 닻 없이 두고, 아무것도 떨어지지 않는다.**

- **세 회차 연달아 같은 갈래다.** `audit-internal` 회차 15 NC-15(셋째 검사를 심은 뒤에도 주석 둘이 「심은 두 검사」) · 회차 16 NC-16(그 주석을 「세 검사」로 고쳤는데
  닻이 없다) · 회차 17 NC-17(`docs/procedure.md` 머리의 「세 검사는」에 닻이 없다). 셋 다 원천 「조각 문서 검사」(`scripts/verify-counts.py` 의 `SOURCES`)이고, 그때마다
  그 자리에 닻만 더했다(`docs/audit/nc-ledger.md` · `nc-ledger-history.md`). 셋째 회차의 감사자는 `CHECKLIST.md` 한 줄과 좁은 훑기 검사 가운데 하나를 정하자고 했다.
- **검사가 보지 않기로 한 자리다.** `verify-counts.py` 는 닫힌 닻 목록만 본다 — 「닻 없이 새로 적은 수는 지나간다 — 그 몫은 `CHECKLIST.md` 의 한 줄과 리뷰가 진다」(ADR 0055 의 5).
  `CHECKLIST.md` 「항상」에는 「수를 새로 적었다면 닻을 더했다」는 줄이 이미 있다. 그 줄이 있는 채로 NC-16 · NC-17 이 났다 — NC-16 은 수를 새로 적은 PR 이 닻을 빠뜨린
  꼴 그대로다.
- **지금도 남아 있다.** 착공 세션이 `3d2c0ba` 를 훑으니, 원천의 명사 옆에 그 원천의 지금 값과 같은 수가 닻 없이 적힌 자리가 52 곳이고, 그 가운데 약 11 곳은 같은 원천을
  든 문장이다 — `vibe-audit/README.md` 의 「감사자 6종」 둘(감사 회차 16 · 17 의 OB-16), 플러그인 설명 넷(`plugin.json` 둘 · `marketplace.json` 둘의 「감사자 6종」 ·
  「틀 여섯」), 시험 · 검사의 「틀 여섯」 · 「틀 둘」 · 「감사자 6개」 따위(설계 ③ A). 원천이 바뀌는 날 이 문장들은 지금처럼 아무것도 떨어뜨리지 않고 낡는다.

## 핵심 사용자와 시나리오

- 사용자: 원천(감사자 · 틀 · 케이스 · 검사 · 단계 …)을 더하거나 빼는 PR 을 내는 세션과 그 PR 을 머지하는 저자.
- 시나리오: 세션이 조각 문서 스킬에 넷째 검사를 더한다 → 닻을 가진 문장의 「셋」은 `verify-counts.py` 가 D1 로 찍어 고친다 → 닻이 없던 문장도 이 조각 뒤에는 남지 않는다 —
  이 조각이 「검사 셋」이 적힌 자리를 다 닻이나 예외로 세웠기 때문이다 → 세션이 새 문장 「네 검사」를 닻 없이 적으면, 「검사」 옆의 4 가 원천의 새 값과 같아 새 규칙이
  그 자리를 찍는다 → 세션이 닻을 더하고(또는 같은 원천이 아니면 예외 목록에 이유와 함께 더하고) 게이트가 초록이 된다.

## 성공 기준

1. **지금 빠진 자리가 섰다** — B 뒤 `main` 트리에서 설계 ③ A 의 「같은 원천」 자리마다 닻이 있고, 「같은 원천 아님」 자리마다 예외 목록의 줄이나 설계 ② U 의 구조로 빼는 것이
   있다. B 본문이 자리마다 어느 쪽인지 표로 든다.
2. **세 NC 의 꼴을 문다** — NC-15 · NC-16 · NC-17 이 짚은 자리 넷(`scripts/gates.sh` 의 「심은 세 검사가 대상에서」 · `scripts/test-sync-slice.py` 의 두 주석 ·
   `docs/procedure.md` 머리의 「세 검사는」)의 닻을 하나씩 지운 `verify-counts.py` 사본 넷이 다 새 규칙의 ID 로 떨어진다(종료 1). B 본문이 넷의 실패 줄을 든다.
3. **새 규칙마다 변조본** — 새 규칙의 ID 마다 `bite-gates.sh` 의 「verify-counts.py」 절에 그 ID 로만 셈하는 변조본이 있고, 고치지 않은 사본 · 원천과 문장을 함께 바꾼 사본이
   종료 0 과 PASS 줄로 지나간다. 절 끝의 기대 수가 돈 수와 맞고, 「ID 마다 변조본」 절이 새 ID 를 읽어 견준다(ADR 0054).
4. **게이트 목록이 그대로다** — `gates.sh` 의 `checks` · `bites` 와 `test-gates.py` 의 고정 목록이 바뀌지 않는다. 구현 PR 작업트리의 인자 없는 `./scripts/gates.sh` 가 끝 줄
   「스물여덟 다 통과」로 끝나고, 착공 PR 과 구현 PR 의 CI gate 잡 · verdict 가 초록이다. `python3 scripts/eval-key.py route` · `full` 의 끝 줄이 `main`(`3d2c0ba`)과 같다 —
   route 수트가 돌지 않는다.
5. **감사 회차** — 닫기 전에 `audit-quality` · `audit-internal` 을 돌려 `docs/audit/` 의 부적합 대장에 등록하고(그 등록이 `verify-ledger.py` 를 지난다), `## 닫으며` 가 회차를
   든다.

## 하지 않을 일

1. **새 검사 파일을 세우지 않는다** — 규칙은 `verify-counts.py` 안에 선다. `gates.sh` · `test-gates.py` 의 목록과 「스물여덟」은 그대로다(ADR 0059 의 4).
2. **`CHECKLIST.md` 에 새 줄을 더하지 않는다** — 저자는 훑기 검사만 골랐다(ADR 0059 의 1). 「항상」의 닻 줄 끝에 있는 「닻 없는 수는 검사가 보지 않는다(ADR 0055 의 5)」는 이 조각
   뒤에 틀린 말이 되므로 B 가 그 꼬리만 고친다.
3. **문장의 수를 고치지 않는다** — ③ A 의 자리는 지금 다 원천과 같다. 닻이나 예외를 더할 뿐 문장의 글은 그대로다. 그래서 플러그인 파일(`plugin.json` · `marketplace.json` ·
   `vibe-audit/README.md`)이 바뀌지 않고 판도 그대로다.
4. **명사 옆에 있지 않은 수는 보지 않는다** — 「셋이다 — 문서의 모양 · …」처럼 나열이 뒤따르는 수, 「한 번」 · 「둘 다」 같은 수, 원천의 지금 값과 다른 수는 이 규칙 밖이다
   (설계 ② 「보장하지 않는 것」).
5. **기록을 훑지 않는다** — 기록 넷(`docs/slices/` · `docs/adr/` · `docs/eval-log/` · `docs/audit/`)은 ADR 0055 의 범위 그대로 밖이다. 평가 픽스처(`vibe-audit/evals/<케이스>/` ·
   `vibe-audit/recall/`)도 밖이다.
6. **감사자 · 커맨드 · 스킬을 고치지 않는다** — 감사자 여섯의 공통 절은 앵커볼트다. 거기 걸리는 자리(「같은 자리에서 세 회차를」)는 명사 고르기와 예외로 다룬다.

## 제약

- 스택: python3 표준 라이브러리 — `scripts/verify-counts.py` 의 새 규칙 · 명사 목록 · 예외 목록 · 닻, `scripts/bite-gates.sh` 의 변조본, `CHECKLIST.md` 한 줄의 꼬리 ·
  `docs/architecture.md` 한 칸, ADR 하나.
- 원본: `main` `3d2c0ba`.
- 비용: 모델 비용 **0** — 고치는 파일은 다 수트 지문(`eval-key.py`) 밖이라 route 수트가 돌지 않는다. `verify-counts.py` · `bite-gates.sh` 는 변조 시험 지문(`gate-key.py`)에
  들어 구현 PR 의 CI 는 변조 시험까지 돈다.
- 기간: 닫기까지 **2026-11-05**.
- 리뷰: PR 본문에 설계 ② 를 적고, 착공 PR 도 구현 PR 도 스킬 `slice-review` 로 가른다. PR 마다 **3라운드**를 넘기면 소유자가 판정한다.
- 감사 회차: 닫기 전 — `audit-quality`(검사의 규칙과 그 변조본이 바뀌는 것이다 — 조각 42 · 43 이 검사에 둔 회차와 같은 자리) · `audit-internal`(대장의 NC-17 이 고침으로 「다음
  `audit-internal` 회차」의 재감사를 기다리고, 이 조각이 그 감사자의 세 회차 제안이다 — `docs/audit/nc-ledger.md`).
