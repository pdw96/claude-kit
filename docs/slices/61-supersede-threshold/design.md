설계다 — **어떻게 · 경계.** 무엇을 · 왜는 같은 폴더의 `requirements.md`.

시스템 구조(`docs/architecture.md`)는 그대로다.

## ② 보장하는 것 / 보장하지 않는 것

**보장하는 것**

- **A 문턱 한 자리** — 어디부터 대체인지는 지도 「살아 있는 문서와 기록」의 기록 행이 든다. ADR 0080 은 그날의 결정이고, `CHECKLIST.md` 는 그 절을 가리킨다.
- **B 문턱이 가른다** — ③ 의 사례마다 새 문장으로 「대체」 · 「대체 아님」 · 「밖」이 하나로 정해진다. 판단이 드는 자리(「틀리게 되는가」)는 ③ 의 「앞 글이 틀리게 되나」 칸이 근거를 든다.
- **C 판단이 남는다** — 앞 ADR 의 결정을 번호로 들고 범위를 메우거나 넓힌 새 ADR 은 대체 표기나 「대체가 아니다 — <까닭>」 가운데 하나를 든다. 근거로만 드는 인용은 이 규칙 밖이다.
- **D 지난 사례가 선다** — ③ 의 「남은 일」이 PR A 뒤 없다. 덧붙인 대체 절은 ADR 0073 의 4 의 꼴이고, 두 ADR 의 지난 줄은 고치지 않는다.
- **E 이 조각이 먼저 지킨다** — ADR 0080 은 ADR 0073 의 4 를 메우며 결정 아래 「대체가 아니다 — <까닭>」을 든다(③ 의 행).
- **F 장치가 늘지 않는다** — 요구사항 성공 기준 5.

**보장하지 않는 것(알려진 한계)**

- **문턱은 판단이다** — 「틀리게 되는가」 · 「메우거나 넓힌다」 · 「근거로만 드는 인용」을 무는 검사는 없다(ADR 0080 의 6). 애매한 꼴은 그것을 만나는 세션이 저자에게 묻는다.
- **③ 밖의 지난 ADR** — 새 문턱으로 대체인데 표기가 없는 사례가 더 있을 수 있다. 그 ADR 은 대체 절 없이 남는다(하지 않을 일 2). 찾는 일은 감사 회차가 만날 때 그 회차의 몫이다.
- **표기를 무는 검사는 없다** — 사람(`CHECKLIST.md` 의 대체 줄)과 닫기 전 `audit-internal` 회차가 본다. 이 넘김은 이 조각의 감사 회차 줄이 범위로 든다(요구사항 「제약」 — 지도 「감사 회차」의
  「넘긴 일」).
- **ADR 밖의 넓힘** — 살아 있는 문서가 ADR 보다 넓어지는 꼴과 구현 PR 의 ⑥ 넓힘은 이 문턱이 다루지 않는다(하지 않을 일 5).
- **다른 레포는 다음 링크 재고정 때까지 옛 지도를 읽는다** — 지도만 고친 커밋은 `vibe-slice` 의 링크를 건드리지 않는다(ADR 0019 의 2 · ADR 0080 의 5).
- **리뷰가 이 밖을 짚으면 범위 밖이다** — 요구사항 하지 않을 일.

## ④ 결정

**정한 것**

- 앞 ADR 의 결정 문장을 지금 결정으로 읽으면 틀리게 되면 대체 — 좁힘 · 닫힌 말의 넓힘이 들고, 메움과 앞 글이 참인 넓힘은 들지 않는다 — ADR 0080 의 1(저자)
- 대체가 아니면 새 ADR 의 그 결정 줄에 「대체가 아니다 — <까닭>」, 근거로만 드는 인용은 밖 — ADR 0080 의 2(저자)
- 지난 사례는 감사 기록이 든 것만(③) — ADR 0080 의 3(저자)
- 자리는 지도 「살아 있는 문서와 기록」, `CHECKLIST.md` 는 한 구절로 가리킨다 — ADR 0080 의 4
- `vibe-audit` · `vibe-slice` 그대로, 지도만 고치고 링크를 다시 박지 않는다 — ADR 0080 의 5
- 검사를 세우지 않는다 — ADR 0080 의 6
- 감사 회차 `audit-internal` 하나 — ADR 0080 의 7

**열어 둔 것**

없음 — 세 자리의 글과 대체 절 둘은 PR A 가 쓰고 리뷰가 본다. 글이 들 것은 ① · ② A ~ E · ③ 이 닫는다.

## ⑤ 검증 계획

시험을 세우지 않는다 — 규칙의 문구와 기록의 덧붙임이다. 있는 검사와 `git` · ③ 에 대어 본다.

| 보장 | 무엇으로 보이나 |
|---|---|
| A 문턱 한 자리 | PR A 본문에 지도 기록 행의 새 문장 둘과 `CHECKLIST.md` 줄의 글. `CHECKLIST.md` 줄이 문턱을 다시 적지 않고 절을 가리키는지 |
| B 문턱이 가른다 | ③ 의 여섯 행마다 새 문장으로 「가름」 칸이 하나로 나오는지 PR A 본문에 한 줄씩 |
| C 판단이 남는다 | 새 문장에 「대체가 아니다 — <까닭>」과 「번호로 들고 범위를 메우거나 넓히는」이 있다 |
| D 지난 사례 | `git diff --numstat 667ffcf <A 머리> -- docs/adr` — 바뀐 파일이 0045 · 0077 둘이고 지운 줄이 0. 덧붙인 두 절의 글이 ADR 0073 의 4 의 꼴(「- k 는 ADR MMMM 이 대체했다 — …」 · 「k 는 ADR NNNN 의 j 가운데 … 를 대체한다」)이다 |
| E 이 조각이 먼저 | ADR 0080 결정 끝의 「대체가 아니다」 문단 |
| F 늘지 않는다 | 요구사항 성공 기준 5 의 명령과 `eval-key.py route` · `full` 의 출력 |

- **게이트** — `./scripts/gates.sh` 를 PR 마다 돌리고 끝 줄을 PR 본문에 든다. `python3 scripts/verify-counts.py` · `python3 scripts/verify-docs.py` · `python3 scripts/verify-map-pin.py` 가
  PASS 다(「문서 종류」의 행 · 절 제목 · 지도만 고친 커밋).
