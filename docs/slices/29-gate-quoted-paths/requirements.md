# 조각 29 — 관문 검사의 한글 경로 (2026-10-19 착공)

요구사항이다 — **무엇을 · 왜.** 어떻게 · 경계는 같은 폴더의 `design.md`, 대안이 있던 결정은 ADR 0040.

이 조각을 「다음 조각」으로 적은 닫힌 조각은 없다 — 조각 28 의 `## 닫으며 (2026-10-19)` 가 다음 조각을 `없음` 으로 적고 「근거가 생기면 그때
순서를 매겨 꺼낸다」고 했다(ADR 0012). 근거는 pdw96/ERP#116 이고, 이 착공이 조각 나눔에 줄을 더하며 순서 29 로 꺼낸다. 이 착공 세션의 클론은
얕지 않았다(`git rev-parse --is-shallow-repository` → `false`).

## 문제

**`verify-slice-gate.py` 가 한글 경로를 결정 문서로 알아보지 못한다.** 바꾼 파일을 `git diff --name-only` · `git ls-files --others` 의 줄로 받는데,
git 은 기본 설정(`core.quotepath=true`)에서 ASCII 밖의 글자가 든 경로를 따옴표로 감싸 8진수로 이스케이프해 낸다 —
`docs/slices/3-이동/design.md` 는 `"docs/slices/3-\354\235\264\353\217\231/design.md"` 로 온다. 조각 7 설계 ② D1 의 정규식(조각 문서 · ADR)과
의도 · 마스터플랜 경로 비교가 그 글자에 맞지 않는다.

- **드러난 곳 — pdw96/ERP#116.** ERP 의 착공 PR 이다. 그 레포는 조각 폴더(`docs/slices/3-이동/`)와 ADR 파일 이름(`docs/adr/0025-재검사-….md`)이
  한글이다. 결정 문서 다섯만 담았는데 기본 설정에서 이렇게 떨어졌다 — 그 PR 은 `core.quotepath=false` 를 환경으로 주고 돌려 0 을 봤다(PR 본문 「검사」).

  ```
  [G2] 기준에 설계가 머지된 `진행` 조각이 없다 — 기준의 `진행` 조각: 없다. 결정 문서 밖: "docs/adr/0025-\354\236\254…", "docs/slices/3-\354\235\264\353\217\231/design.md", "docs/slices/3-\354\235\264\353\217\231/requirements.md"
  FAIL 설계 → 구현 관문 — 바꾼 파일 5
  ```

- **두 방향으로 틀린다.**
  1. 결정 문서만 담은 착공 PR 이 G2 로 떨어진다 — 거짓 빨강.
  2. 착공 PR 에 구현 파일이 섞여도 G1 이 서지 않는다 — 조용한 통과. 새 조각 문서를 조각 문서로 알아보지 못해 G1 의 「기준에 없던 조각 문서」가
     비기 때문이다. 기준에 설계가 머지된 다른 `진행` 조각이 있으면 G2 도 서지 않아 PASS 다.
- **재현 — 이 착공 세션(2026-10-19).** ERP 의 `main`(`d3ca1d7`, #116 의 기준)과 #116 머리(`9c85054`)를 인자로 ERP 의 사본(claude-kit `987df53`)에
  댔다 — 위의 G2 로 exit 1. #116 머리에 `backend/zz_probe.txt` 하나를 더한 커밋이면 G2 만 서고 G1 은 서지 않는다(저자가 #116 에서 본 것과 같다).
  claude-kit 자체 시험의 꼴에 한글 조각 폴더 · ADR 을 넣어 `987df53` 의 검사에 대 보았다 — 결정 문서만 담은 착공은 G2, 구현이 섞인 착공은 기준에
  다른 `진행` 조각이 있을 때 exit 0, 작업트리의 새 한글 ADR 도 G2. 실패 줄의 경로도 이스케이프된 채 찍힌다.
- **원본의 결함이다.** 사본은 원본의 바이트이고, 경로에 ASCII 밖의 글자를 쓰는 레포라면 어디서나 같은 말이다(`INTENT.md` Why). 절차 지도와 틀은
  조각 폴더 이름을 `<순서>-<이름>` 으로만 정하고 글자를 묶지 않는다. 스킬 `slice-docs`(PR 을 내기 전에)와 `slice-review`(구현 PR 을 가르기 전에)가
  둘 다 이 검사를 부른다.
- 이 저장소에서는 드러나지 않았다 — 조각 폴더 · ADR 이름이 다 ASCII 이고, 자체 시험의 꼴도 다 ASCII 라 이 자리를 아무것도 물지 않았다.

## 핵심 사용자와 시나리오

- 사용자: 한글 이름의 조각 폴더와 ADR 을 쓰는 레포(ERP)에서 스킬 `slice-docs` 로 착공 PR 을 내는 세션과 그 레포의 저자.
- 시나리오: 세션이 `docs/slices/3-이동/` 의 요구사항 · 설계와 `docs/adr/0025-재검사-….md` 를 쓴다 → PR 을 내기 전에 git 설정 없이
  `python3 .claude/skills/slice-docs/scripts/verify-slice-gate.py` 를 부른다 → PASS 다 → 구현 파일 하나가 섞였으면 G1 이 그 파일을 글자 그대로 찍고
  떨어진다 → 착공이 머지된 뒤의 구현 PR 은 `slice-review` 가 `--base origin/main --head <PR 머리>` 로 불러 같은 판정을 본다.

## 성공 기준

1. **한글 경로를 결정 문서로 읽는다** — git 설정 없이(기본 `core.quotepath=true`), 한글 이름의 조각 폴더 · ADR 을 담은 착공 PR(결정 문서만)이
   PASS 이고, 구현 파일이 섞이면 G1 이, 기준에 `진행` 조각이 없는 구현이면 G2 가 선다. 바꾼 파일의 두 길 — 커밋된 머리 · 작업트리(무시되지 않은
   새 파일까지) — 다 같다. 실패 줄의 한글 경로는 글자 그대로이고, 제어 문자(줄바꿈 따위)는 이스케이프해 실패가 한 줄로 남는다.
2. **자체 시험이 문다** — `test-verify-slice-gate.py` 에 1 의 꼴이 있고, 고침을 걷어 낸 검사(`987df53` 의 것)에 대면 그 꼴이 떨어진다.
   `bite-slice-gate.py` 에 고침의 자리를 망가뜨리는 변조본이 있고 자체 시험에서 떨어진다.
3. **판** — `vibe-slice` 판이 0.4.4 이고 `verify-manifest.py` · `verify-map-pin.py` 가 지나간다.
4. **ERP 에서 맞게 돈다** — ERP 의 스킬 사본을 B 의 머지 커밋에서 `sync-slice.sh --force` 로 다시 심고(pdw96/ERP#114 와 같은 길), 두 사본 머리줄의
   출처 커밋이 그 커밋이다. 그 사본을 git 설정 없이 #116 의 기준 · 머리에 인자로 대면 PASS 이고, 그 머리에 결정 문서 밖의 파일 하나를 더한 커밋이면
   G1 이 선다.
5. `./scripts/gates.sh` 가 이 조각의 claude-kit PR 마다 로컬과 CI gate 잡에서 통과하고, 검사 수는 스물넷 그대로다. 이 조각의 PR 은 수트 지문
   (`eval-key.py route --list` · `full --list`) 밖이다 — eval 잡이 건너뛴다.

## 하지 않을 일

1. **판정 규칙과 받는 입력의 닫힌 목록을 바꾸지 않는다** — 결정 문서의 다섯 꼴(D1)과 관문(G1 · G2), 기준과 머리(B1 ~ B5)는 조각 7 설계 ② 그대로다.
   바뀌는 것은 바꾼 파일의 경로를 git 에서 받는 법뿐이다.
2. **`verify-docs.py` 를 고치지 않는다** — git 을 쓰지 않고 파일 시스템에서 읽어 이 결함이 없다(설계 ③).
3. **유니코드 정규화(NFC · NFD)를 맞추지 않는다** — 마스터플랜의 조각 폴더 글자와 커밋된 경로가 다른 정규형이면 맞지 않는다. 겪지 않은 꼴이다.
4. **UTF-8 이 아닌 POSIX 로케일에서 한글 경로를 git 인자로 넘기는 길을 고치지 않는다** — 설계 ② 「보장하지 않는 것」.
5. **이 저장소의 다른 스크립트를 고치지 않는다** — git 의 경로 출력을 줄로 받는 다른 자리는 이 저장소 · 사본 레포의 ASCII 이름만 읽는다(설계 ③).
6. **ERP 의 스킬 사본 밖을 고치지 않는다** — C 는 `.claude/skills/slice-docs` · `slice-review` 를 폴더째 덮는 것뿐이다. #116 을 고치지 않는다.
   다른 사본 레포는 그 레포의 다음 `sync-slice.sh` 에서 바뀐다.
7. **스킬 문구 · 절차 지도 · 틀을 바꾸지 않는다** — 고침이 스크립트 안이라 스킬이 부르는 명령은 그대로다. 예산 · 지도 링크도 그대로다.

## 제약

- 스택: 파이썬 표준 라이브러리 · git.
- 원본: `main` `987df53`. `verify-slice-gate.py` 는 `824cbf2`(조각 9 PR D)에서 마지막으로 바뀌었다. `vibe-slice` 판 0.4.3, 두 스킬의 지도 링크는
  `6a9f582` 를 박았다 — 지도를 고치지 않으므로 그대로 지나간다(이 세션의 로컬 확인).
- CI: `vibe-slice/` · `scripts/test-verify-slice-gate.py` · `scripts/bite-slice-gate.py` 는 두 수트 지문 밖이다(이 세션의 `eval-key.py --list`).
- 비용: 모델 호출이 없다.
- 사본 레포: C 는 pdw96/ERP 의 PR 이고 그 레포의 저자가 머지한다. B 가 claude-kit `main` 에 머지된 뒤에 심는다 — 원격에 없는 원본은 심지 않는다
  (`sync-slice.sh` P1).
- 기간: 닫기까지 **이틀**(2026-10-21 까지).
- 리뷰: PR 본문에 설계 ② 를 적고, 착공 PR 도 구현 PR 도 스킬 `slice-review` 로 가른다. PR 마다 **3라운드**를 넘기면 소유자가 판정한다.
