## PR B 에서 정한 것 (2026-11-03)

④ 의 열어 둔 것 하나(머리 주석의 종료 문장)를 정했고, ② 를 러너에 옮기며 넷을 정했다.

- **머리 주석의 종료 문장 — 주석을 사실에 맞춘다.** 하네스 길도 점수로 종료가 바뀐다 — 하네스는 `--threshold` 를 받지 않으면 1.0 을 써서 한 회차라도 못 맞히면 1 이다
  (`scripts/run-evals.sh` 의 회수율 주석이 같은 사실을 든다). 하네스 밖 길도 같은 규칙이다. 종료를 점수와 떼려면 하네스 호출에 `--threshold 0` 을 더해야 하는데, 그러면 다른 세 팔의
  하네스 호출이 바뀌어 ② F 를 깬다. 주석은 「종료는 판정이 아니다 — 하네스의 종료를 그대로 돌려줄 뿐이고, 판정은 끝 표로 사람이 낸다」로 고쳤다(회차 26 「안 본 것」의 `audit-internal` 몫).
- **「정답지 낱말」은 끝 표의 칸이 아니라 그 아래 따로 된 표다.** ② B 는 「끝 표의 `claude-security` 줄이 칸에 찍는다」고 적었지만, 끝 표에 칸을 더하면 네 팔의 끝 표가 바뀌어 ② F 를
  깬다. 그래서 `claude-security` 팔만 끝 표 아래에 표 하나를 더 찍는다 — 케이스마다 정답지 낱말이 나온 회차 · 세션 기록 수 · 하위 호출이 있던 회차와 그 가운데 하위 기록이 남은 회차.
  뒤의 둘이 ⑤ 「측정」이 견줄 자리다. 낱말이 나온 자리는 그 표 아래에 「파일: 낱말」로 한 줄씩 찍는다.
- **하위 기록** — 세션 기록 가운데 프로젝트 폴더 바로 아래가 아닌 `*.jsonl`(하위 에이전트가 쓰는 자리). 주 기록과 가른다.
- **기록은 심판보다 먼저 옮긴다** — 심판도 같은 임시 HOME 에서 돌아 기록을 쓴다. 심판의 요청에는 그레이더 글이 들어 있어, 뒤에 옮기면 낱말이 잡히지 않아도 기록이 섞인다.
- **재료 폴더는 플러그인과 다른 임시 폴더다** — 같은 부모에 두면 그 팔이 플러그인 폴더의 부모를 훑을 때 바로 보인다.
- **② F 의 「재료 엮기는 글자 그대로」** — 엮는 줄은 `$plug/compare` 가 `$mat/compare` 로 바뀌었다. 하네스 팔에서 `$mat` 는 `$plug` 라 엮이는 파일은 같다 — 가짜 `claude` 로 `vibe-audit` ·
  `none` 팔을 돌려 하네스가 받은 플러그인 안 `compare/` 의 재료 파일이 열 케이스 × 넷 = 40 인 것을 PR B 본문에 보였다. 하네스 호출 줄은 글자 그대로다.
- **끝 줄(② E)은 네 팔 다 찍는다** — NC-28 은 팔을 가리지 않는다. 끝 표 아래 `하네스 종료` 줄 뒤에 붙어 끝 표는 그대로다.

## PR C 에서 정한 것 (2026-11-03)
