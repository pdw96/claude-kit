# 조각 64 설계 — 넘긴 일이 받지 않는 꼴

설계다 — **어떻게 · 경계.** 무엇을 · 왜는 같은 폴더의 `requirements.md`.

## ① 바뀌는 것

| 파일 | PR | 무엇 |
|---|---|---|
| `docs/master-plan.md` | 착공 · 닫기 | 조각 나눔 — 「넘긴 일이 받지 않는 꼴」을 순서 64 · `진행` 으로 · 조각 폴더. 닫기에서 `닫힘` · 다음 조각. 목표 칸은 고치지 않는다 |
| `docs/slices/64-handoff-forms/` · `docs/adr/0083-handoff-forms.md` | 착공 | 이 요구사항 · 설계 · ADR |
| `docs/procedure.md` | A | 「일곱 단계」 아래 「감사 회차」의 굵은 항목 「넘긴 일」 하나. 지금의 두 꼴(닫기 전 → 감사 회차 줄 「왜」, 다음 조각 → 조각 나눔의 줄)은 그대로 두고 셋을 더한다 — (가) 「그 조각의 닫기 전 회차면」을 「그 조각 안의 회차(닫기 전 · 어느 PR 의 머지 전)면」으로, (나) ADR 의 결정 · 대가가 감사 회차로 넘기면 같은 조각의 설계 ② 가 그 넘김을 다시 들고(착공 뒤에 쓴 ADR 이면 설계 끝의 날짜를 박은 항목이) 이 항목을 따른다, (다) 조각을 들지 않은 넘김은 그 넘김을 쓴 조각의 회차다 — 뒤 조각의 회차는 넘김이 아니라 감사자를 고르는 원천이 세운다. 끝의 근거에 ADR 0083 을 더한다 |
| `docs/audit/` | 닫기 | 닫기 전 감사 회차의 기록 · 브리핑 · 대장 등록 |

항목의 글은 PR A 가 쓰고 리뷰가 본다. 원천의 수를 글자로 다시 적지 않는다 — 「위 원천 셋」처럼 적으면 `scripts/verify-counts.py` 가 읽는 수가 하나 는다. 「언제」 · 「어느 감사자」 · 「돌리는
법」 · 「결과」와 단계 표 · 「이 줄을 무는 검사는 없다」 문장은 그대로다.

앵커볼트는 건드리지 않는다 — 지도의 절 제목(「…의 칸」 여섯 절의 제목 · 표 서식)이 그대로이고, 「감사 회차」는 「일곱 단계」 절 안의 굵은 항목이다. 「가변」의 「검사가 읽는 글」은 셋이 닿는다 —
`scripts/verify-docs.py` 는 지도의 절 제목 · 표를 원천으로 읽고, `scripts/verify-counts.py` 는 살아 있는 문서에 적힌 수를 보고, `scripts/verify-map-pin.py` 는 두 스킬의 지도 링크가
`vibe-slice/` 를 마지막으로 고친 커밋의 지도인지 본다. 항목은 절 제목 · 표를 건드리지 않고 수를 적지 않으며, `vibe-slice/` 를 고치지 않는다(ADR 0083 의 4). 스크립트 · 플러그인 · CI ·
시스템 구조(`docs/architecture.md`)는 그대로다.

## ② 보장하는 것 / 보장하지 않는 것

**보장하는 것**

- **A 조각 안의 회차** — 설계 ② 가 그 조각 안의 회차(닫기 전 · 어느 PR 의 머지 전)로 넘긴 일은 그 조각의 감사 회차 줄 「왜」에 범위가 남는다. PR 의 머지 전 회차는 그 PR 이 ⑥ 의 줄이고
  결과는 그 PR 의 단계 4 가 든다(「언제」 그대로).
- **B ADR 의 넘김** — ADR 의 결정 · 대가가 감사 회차로 넘긴 일은 같은 조각의 설계 ② 가 다시 든다 — 착공 뒤의 ADR 이면 설계 끝의 날짜를 박은 항목이. 남는 자리는 A 와 지금의 두 꼴을 따른다.
- **C 조각을 들지 않은 넘김** — 「닫기 전 회차가 본다」처럼 조각을 들지 않은 넘김은 그 넘김을 쓴 조각의 회차다. 뒤 조각의 회차는 「어느 감사자」의 원천이 세운다.
- **D 지금의 두 꼴은 그대로** — 닫기 전 → 감사 회차 줄 「왜」, 다음 조각 → 조각 나눔의 줄(ADR 0078 의 3). 「넘긴 일」은 굵은 항목 하나로 남는다(요구사항 성공 기준 3).
- **E 지난 넘김이 선다** — ③ 의 행마다 항목이 남는 자리를 하나로 낸다.
- **F 장치가 늘지 않는다** — 요구사항 성공 기준 5.

**보장하지 않는 것(알려진 한계)**

- **넘김을 쓰지 않은 세션** — 넘긴 일을 설계 ② · ADR 어디에도 적지 않으면 항목이 받을 것이 없다. 무는 검사는 없다 — 사람(`CHECKLIST.md` 의 감사 회차 줄)과 닫기 전 `audit-internal`
  회차가 본다(ADR 0083 의 6). 이 넘김은 이 조각의 감사 회차 줄이 범위로 든다(요구사항 「제약」 — 이 항목의 A · C).
- **ADR 과 설계 ② 의 두 번 적기** — ADR 의 넘김을 설계 ② 가 다시 들면 같은 넘김이 두 자리에 적힌다. 남는 자리는 설계 ② 를 따라 하나지만, 두 글이 갈리면 무엇을 볼지 갈린다 — 그 조각의
  닫기 전 회차가 본다(ADR 0083 의 2 의 대가).
- **뒤 조각에서 어긴 규칙** — 조각을 들지 않은 넘김을 그 넘김을 쓴 조각의 회차로 읽으면, 뒤 조각이 그 규칙을 어겨도 그 조각의 바뀐 것이 담당 표에 닿지 않으면 회차가 서지 않는다(ADR 0083 의
  3 의 대가).
- **지난 넘김은 그대로** — 조각 54 설계 ② 의 「다음 `audit-internal` 회차가 본다」는 기록 그대로 남는다(하지 않을 일 2).
- **다른 레포는 링크가 박힐 때까지 옛 항목을 읽는다** — 두 스킬의 지도 링크를 다시 박지 않는다(ADR 0083 의 4).
- **리뷰가 이 밖을 짚으면 범위 밖이다** — 요구사항 하지 않을 일.

## ③ 받는 입력

검사 장치가 아니다 — 항목을 대어 볼 대상을 착공 `41caaf4` 의 ADR 과 조각 설계에서 뽑은 닫힌 목록으로 든다. 뽑은 법 — `grep -n '회차가 본다' docs/adr/*.md` 의 줄 가운데 결정 · 결과가 감사
회차로 넘기는 것(맥락 · 대안의 줄과 넘김을 다루는 ADR 0077 · 0078 자신은 뺀다), 그리고 `grep -n '머지 전' docs/slices/*/design.md docs/adr/*.md` 가운데 회차로 넘기는 것. 뒤의 것은 이
저장소에 없다(조각 34 설계 ③ E3 은 다른 레포의 지난 회차를 지도에 대 본 사례라 넘김이 아니다). 이 밖의 꼴이 나오면 그것을 만나는 조각이 항목에 비춰 가르고, 항목에 없으면 저자에게 묻는다.

## ④ 결정

**정한 것**

- 어느 PR 의 머지 전 회차로 넘긴 일은 그 조각의 감사 회차 줄 「왜」 — ADR 0083 의 1(저자)
- ADR 의 넘김은 같은 조각의 설계 ② 가 다시 든다 — 착공 뒤의 ADR 이면 설계 끝 날짜 항목 — ADR 0083 의 2(저자)
- 조각을 들지 않은 넘김은 그 넘김을 쓴 조각의 회차 — ADR 0083 의 3(저자)
- 지도의 「넘긴 일」 항목 하나만, `vibe-audit` · `vibe-slice` 그대로 — ADR 0083 의 4
- 소급하지 않는다 — ADR 0083 의 5
- 검사를 세우지 않는다 — ADR 0083 의 6
- 감사 회차 `audit-internal` 하나 — ADR 0083 의 7

**열어 둔 것**

없음 — 항목의 글은 PR A 가 쓰고 리뷰가 본다. 글이 들 것은 ① · ② A ~ D · ③ 이 닫는다.

## ⑤ 검증 계획

시험을 세우지 않는다 — 규칙의 문구다. 있는 검사와 `git` · `grep` · ③ 에 대어 본다.

| 보장 | 무엇으로 보이나 |
|---|---|
| A 조각 안의 회차 | PR A 본문에 고친 항목의 글. 「그 조각 안의 회차(닫기 전 · 어느 PR 의 머지 전)」가 감사 회차 줄 「왜」로 가고, 「언제」의 글이 그대로인지(`git diff` 의 덩이가 「넘긴 일」 항목 하나) |
| B ADR 의 넘김 | 항목에 「같은 조각의 설계 ②」 · 「설계 끝의 날짜를 박은 항목」이 있다 |
| C 조각을 들지 않은 넘김 | 항목에 「그 넘김을 쓴 조각의 회차」와 「원천이 세운다」가 있고 ADR 0083 을 든다 |
| D 두 꼴은 그대로 | `grep -c '\*\*넘긴 일\*\*' docs/procedure.md` → 1. 「다음 조각의 회차면 조각 나눔에 줄을」 · ADR 0078 의 3 이 남았다 |
| E 지난 넘김 | ③ 의 열 행마다 항목의 어느 구절이 자리를 내는지 PR A 본문에 한 줄씩 — 「항목이 내는 자리」와 같다 |
| F 늘지 않는다 | 요구사항 성공 기준 5 의 명령과 `eval-key.py route` · `full` 의 출력 |

- **게이트** — `./scripts/gates.sh` 를 PR 마다 돌리고 끝 줄을 PR 본문에 든다. `python3 scripts/verify-docs.py` · `python3 scripts/verify-counts.py` · `python3 scripts/verify-map-pin.py` 가
  PASS 다(절 제목 · 새 수 없음 · 링크 그대로).
