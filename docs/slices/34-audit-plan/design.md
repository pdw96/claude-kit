앵커볼트를 건드리지 않는다 — 이름 · 감사자의 `tools` · 공통 절 · 대장 둘(`copies.json` · `feedback.json`)의 모양 · 고정 영역이 그대로다.
앵커볼트 「요구사항 · 설계 문서의 모양」은 절 제목이고, 「…의 칸」 여섯 절의 제목과 표 서식은 문서 대조 검사가 원천으로 읽는다. 이 조각은
「요구사항 문서의 칸」 표의 「제약」 줄의 「담는 것」 칸 글만 넓힌다 — 제목 열 · 표의 열 수 · 다섯 절의 제목은 그대로이고, 검사는 「담는 것」 칸을 읽지
않는다. 저자가 착공 세션에서 이 자리를 골랐다(ADR 0045 의 1). 요구사항 틀은 절 제목이 그대로이고 「제약」 아래 자리표시 줄만 는다.
`docs/architecture.md` 는 고치지 않는다 — 부품 · 경계 · 흐름이 그대로다(요구사항 틀은 이미 「조각 문서 스킬」 부품의 틀 여섯에 있다). `INTENT.md` 도
그대로다 — 감사 계획은 What 의 「절차 지도」 안이고 Not 에 걸리지 않는다.

## ② 보장하는 것 / 보장하지 않는 것

**보장하는 것** — 다 B 가 싣는다.

- T1 **「일곱 단계」의 칸.**
  - 1 의 나가는 조건 — 「… 제약에 리뷰 한도와 감사 회차가 있다(돌릴 것이 없으면 `없음 — <이유>`)」.
  - 4 의 산출물 · 나가는 조건의 「감사 계획이 이 PR 을 들 때」를 「요구사항 「제약」의 감사 회차가 이 PR 을 들 때」로, 결과의 자리를 대장으로. 맡는
    도구 칸의 「감사 계획은 빈자리」를 지우고 「감사 회차는 요구사항 「제약」이 든다 — 고르는 법은 아래 「감사 회차」」로.
  - 6 의 들어가는 조건 — 지금 조건에 「그리고 요구사항 「제약」의 닫기 전 감사 회차를 돌려 대장에 등록했다(감사 회차가 `없음` 이면 이 조건이 없다)」.
    산출물의 `## 닫으며` 가 드는 것에 「돌린 감사 회차」를 더한다.
- T2 **「감사 회차」 단락** — 「일곱 단계」 표 아래, 「4 에서 지적은 기준에 비춰 가른다」 단락 다음에 한 자리. 고르는 법은 지도의 이 단락 한 곳만 든다.
  - **모양** — 요구사항 「제약」의 한 줄, 「감사 회차: <언제> — `<감사자>`(<왜>) · …」. 돌릴 것이 없으면 「감사 회차: 없음 — <이유>」.
  - **언제** — 기본은 **닫기 전**이다 — ⑥ 의 마지막 PR 이 머지된 뒤, 6 에 들기 전. 어느 PR 의 머지 전에 돌릴 것이 있으면 그 PR 을 ⑥ 의 줄로
    적는다 — 그 PR 의 4 가 결과를 든다.
  - **어느 감사자** — 원천 셋에서 고르고, 고른 원천을 「왜」에 적는다. 원천이 낸 후보를 다 돌리지 않아도 된다 — 줄이 고른다.
    - (가) **바뀌는 것** — 설계 ① 을 `vibe-audit` 의 README 「대략의 주기」 표에 댄 것. 그 표가 「바뀐 것 → 감사자」의 주인이고 지도는 옮겨 적지 않는다.
    - (나) **대장이 이 조각에 기대는 것** — 기한이 이 조각인 줄, 재감사를 기다리는 줄(고침 · 부분 닫힘)의 담당, 지난 회차가 이 조각의 다른 담당에게
      넘긴 자리. 착공할 때 대장을 읽는다.
    - (다) **그 레포의 상시 회차** — 그 레포의 작업 규칙(`CLAUDE.md`)이 바뀌는 것과 상관없이 정한 회차(예: 「조각을 끝낼 때마다 `audit-internal`」).
  - **돌리는 법** — 한 작업트리에서 하나씩(`vibe-audit` 의 README). 기준이 있으면 `/audit-brief` 로.
  - **결과** — 대장에 등록한다. 레포에 대장이 없으면 `vibe-slice` 스킬 `slice-docs` 의 `templates/nc-ledger.md` · `nc-ledger-history.md` 를 베껴 먼저
    세운다 — 베끼는 법은 그 틀의 머리가 든다.
  - 이 줄을 무는 검사는 없다 — `CHECKLIST.md` 가 사람이 보는 줄로 든다.
- T3 **「빈자리」 표에서 「감사 계획」 줄을 지운다** — 지도의 규칙대로 그 조각 나눔 줄이 닫히면 빈자리가 아니다. 줄을 지우는 B 가 닫기보다 앞서지만
  자리가 그 PR 로 생기므로 B 의 머지가 그 자리를 채운다(조각 33 ② T5 와 같다). 「빈자리」 머리의 설명과 다른 줄은 그대로다.
- T4 **「요구사항 문서의 칸」의 「제약」 줄** — 「담는 것」이 「스택 · 비용 · 기간 · 쿼터 · 리뷰 한도(몇 회차를 넘기면 소유자가 판정하나) · 감사
  회차(언제 · 어느 감사자 · 왜 — 「일곱 단계」의 「감사 회차」. 없으면 `없음 — <이유>`)」다. 제목 열은 `## 제약` 그대로다.
- T5 **요구사항 틀** — 「제약」 아래 자리표시가 두 줄이다 — 지금 줄과 「감사 회차: <언제 — `<감사자>`(왜) · …. 돌릴 것이 없으면 「없음 — <이유>」>」.
  머리 주석에 한 줄 — 「감사 회차를 적었는데 레포에 부적합 대장이 없으면 같은 폴더의 `nc-ledger.md` · `nc-ledger-history.md` 를 베껴 세운다 —
  고르는 법은 claude-kit `docs/procedure.md` 「감사 회차」」. 틀에는 claude-kit 을 가리키는 링크를 더하지 않는다 — 박을 링크가 늘지 않게
  (`verify-map-pin.py`). 머리 주석은 베낄 때 지우는 자리라 베낀 요구사항에 남지 않는다.
- T6 **입구와 사람이 보는 줄.**
  - `README.md` 「새 프로젝트를 열 때」 — 3 의 「첫 조각이 끝나면 `@audit-data` 부터」를 「조각마다 요구사항 「제약」에 감사 회차를 적고 닫기 전에
    돌린다」로. 끝 문단의 「무엇을 언제 감사할지는 절차 지도 「빈자리」에 있다」를 「무엇을 언제 감사할지는 조각 요구사항의 감사 회차가 든다 —
    고르는 법은 절차 지도, 바뀐 것에 맞는 감사자는 `vibe-audit/README.md` 「대략의 주기」」로.
  - `vibe-audit/README.md` 「감사 계획과 부적합 대장」 — 「무엇을 언제 돌릴지는 맡지 않습니다 — … 「빈자리」입니다」를 「언제 돌릴지는 조각
    요구사항 「제약」의 감사 회차가 정합니다 — 고르는 법은 claude-kit 절차 지도. 아래 표는 그 원천 가운데 하나(바뀐 것 → 감사자)입니다」로. 지도는
    GitHub 링크 그대로(플러그인 폴더라 상대 경로가 저장소 밖에서 깨진다 — 조각 32 설계 ② D4). 표의 행은 그대로다(하지 않을 일 3).
  - `CHECKLIST.md` 「조각을 시작했다면」에 두 줄 — 「요구사항 「제약」에 감사 회차가 있다(없으면 `없음 — <이유>`)」 · 「조각을 닫았다면 닫기 전
    감사 회차를 돌려 대장에 등록했고 `## 닫으며` 가 그것을 든다」.
  - 다 살아 있는 문서라 「아직」 · 「다음 조각에서」를 쓰지 않는다.
- T7 **감사자 · 커맨드 · 검사기와 두 스킬의 본문은 그대로다.** B 의 diff 에 `vibe-audit/agents/` · `vibe-audit/commands/` · `vibe-audit/scripts/` 가
  없고, 두 스킬의 `SKILL.md` 는 지도 링크의 커밋 40 자만 바뀐다. 주의 예산(`budget.txt`)이 그대로다 — 요구사항 틀은 스킬이 쓸 때 읽는 파일이지만
  예산이 재는 것은 `SKILL.md` 와 감사자 · 커맨드다.
- T8 **`vibe-slice` 판이 0.8.0 이다.** 이미 설치한 세션은 판을 받아야 고친 틀이 생긴다. 장터 · `plugin.json` 의 설명은 그대로다 — 틀의 수와
  종류가 그대로다(`verify-manifest.py` 가 두 자리를 견준다).

**보장하지 않는 것(알려진 한계)**

- **감사 회차 줄이 있는지 · 적은 대로 돌렸는지** — 무는 검사가 없다(하지 않을 일 1). 줄이 빠지거나 닫기 전 회차를 건너뛰어도 아무것도 떨어지지
  않는다. `CHECKLIST.md` 를 사람이 본다.
- **고른 감사자가 맞는지** — 원천 셋은 후보를 내고 줄이 고른다. 후보를 빠뜨려도, 원천 밖의 감사자를 골라도 아무것도 막지 않는다 — 「왜」가 적혀 저자가
  착공 PR 에서 본다.
- **「대략의 주기」 표의 행이 맞는지** — 이 조각은 행을 고치지 않는다(하지 않을 일 3). 그 표가 지도의 원천 (가) 로 읽힐 뿐이다.
- **조각 밖의 시점** — 「첫 배포 직전」 · 「장애 후」처럼 조각과 상관없이 오는 회차는 「대략의 주기」 표에 남고 지도가 들지 않는다. 그 레포가 상시로
  두려면 원천 (다) 로 작업 규칙에 적는다.
- **머지된 요구사항** — 이 저장소의 조각 1 ~ 33 과 다른 레포의 머지된 요구사항에는 감사 회차 줄이 없다(하지 않을 일 5). 규칙은 소급하지 않는다.
- **이미 설치한 `vibe-slice` 0.7.0 의 틀** — 판을 받기 전에는 옛 자리표시다. 이미 설치한 `vibe-audit` 의 README 에는 옛 문단이 남는다(ADR 0043 의 3 과
  같은 까닭으로 그 판을 올리지 않는다).
- **다른 레포에서도 같은 말인지** — 갈라 본 실물이 둘(ERP · 강호쟁패)이고, 돌린 회차가 넷 · 계획된 줄이 하나다(③ E1 ~ E5 · E10). 원천 하나가 다음 레포에서 특화로
  드러나면 그때 원본에서 뺀다 — 되먹임과 같은 한 방향이다.

## ④ 결정

**정한 것**

- 감사 계획의 자리는 조각 요구사항 「제약」의 한 줄(감사 회차)이다 — 설계 ⑤ 도, 프로젝트 층 한 곳도 아니다. ADR 0045 의 1.
- 기본 시점은 닫기 전이고 PR 머지 전은 고른다. 감사자는 원천 셋(바뀌는 것 · 대장 · 상시 회차)에서 고르고, 「바뀐 것 → 감사자」 표는
  `vibe-audit/README.md` 「대략의 주기」 한 곳에 둔다. ADR 0045 의 2.
- 감사 회차 줄을 무는 검사를 세우지 않는다 — 사람이 본다. ADR 0045 의 3.
- 대장이 없을 때 틀을 부르는 자리는 요구사항 틀과 지도의 글이다 — 스킬 · 감사자 · 커맨드를 고치지 않는다. ADR 0045 의 4.
- `vibe-slice` 판을 0.8.0 으로 올리고 `vibe-audit` 판은 그대로 둔다. ADR 0045 의 5.

**열어 둔 것**

없음 — 저자가 이 착공 세션에서 1 ~ 4 를 정했고 5 는 앞선 예(ADR 0044 의 5)와 같은 갈래다.

- V5 **성공 기준 5** — B 의 diff 를 ② T6 과 줄마다 대어 PR 본문에 싣는다.

  `verify-map-pin.py` · `verify-manifest.py` · `verify-budget.py`)을 PR 마다 돌린다 — 변조 시험이 약 20분이라 세션의 백그라운드 한도 안에 끝나지 않을 수
  있다(조각 33 「닫으며」). A 는 결정 문서만이라 설계 → 구현 관문을 지난다. B 는 `진행` 조각 34 의 설계가 머지된 위라 관문을 지난다. 셋 다 두 수트
  지문 밖이다 — 머리마다 `eval-key.py route --list` · `full --list` 가 `main` 과 같고 eval 잡이 건너뛴다.

- 단계 5 — 배포는 B 의 머지와 `vibe-slice` 판 0.8.0 이다. 장터로 받은 세션은 플러그인을 갱신하면, 클라우드 레인은 `sync-slice.sh` 로 다시 심으면 고친
  틀이 생긴다. 보이는 것은 `main` 의 지도 · 틀과 판이다. 되돌리는 길은 B 를 되돌리는 것이다(판이 0.7.0 으로, 「빈자리」에 「감사 계획」 줄이 돌아온다) —
  닫는 기록이 머지된 뒤라면 그것을 먼저 되돌린다. 이미 고친 틀로 쓴 다른 레포의 요구사항은 그 레포의 기록이라 되돌림이 닿지 않는다.
