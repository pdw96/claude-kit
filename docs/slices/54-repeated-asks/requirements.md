# 조각 54 — 감사자가 거듭 청한 절차 물음 (2026-11-05 착공)

요구사항이다 — **무엇을 · 왜.** 어떻게 · 경계는 같은 폴더의 `design.md`, 대안이 있던 결정은 ADR.

이 조각을 「다음 조각」으로 적은 닫힌 조각은 조각 50(프로필의 언어 칸)이다 — 그 `## 닫으며 (2026-11-02)` 를 읽었다. 넘겨받은 것은 회차 25 가 3 회째 청한 물음 둘(대체 ADR · 같은 목록)을
그 줄에 더했다는 것이다. 그 뒤 조각 51 ~ 53 이 먼저 갔고, 조각 52 의 닫는 세션이 회차 29 의 새 사례를 같은 줄에 더했다. 조각 53 의 `## 닫으며 (2026-11-04)` 는 다음 조각을 `없음` 으로
적었다 — 저자가 이 착공 세션에서 이 줄을 골랐다(2026-11-05). 의존은 `—` 이다. 저자가 이 착공 세션에서 물음 다섯의 답을 정했다 — 다섯 다 세션이 추천한 쪽이다(ADR 0073 의 1 ~ 5).
착공은 `main`(`2884f09`) 위에서 연다. 이 착공 세션의 클론은 얕지 않았다(`git rev-parse --is-shallow-repository` → `false`).

## 문제

**감사자가 같은 물음에서 회차마다 멈춘다.** `audit-internal` 은 저장소의 규칙에 대어 판정하는데, 규칙이 없는 자리는 「문서에 없어서 판정할 수 없었던 것」에 올리고 저자 결정을 청한다.
다섯 물음이 회차를 넘어 되풀이됐다 — 횟수는 가장 늦게 센 감사 기록의 것이다.

| 물음 | 횟수 | 가장 늦게 센 기록 |
|---|---|---|
| 1. 검사가 읽는 제목 · 글(원천의 머리 줄 · 닻의 꼴 · 변조본이 바꿀 글)이 앵커볼트인가 | 7 회째 | `docs/audit/records/audit-internal-2026-11-01-070820.md` |
| 2. 닫는 PR 이 대장 판정의 고침으로 코드를 실어도 되는가 · 그것이 그 조각의 하지 않을 일 · 성공 기준에 묶이는가. 구현 PR 이 새 ADR 로 설계 ⑥ 과 하지 않을 일을 넓혀도 되는가 | 4 회째 · 새 사례(ADR 0070) | `audit-internal-2026-11-01-070820.md` · `audit-internal-2026-11-03-081932.md` |
| 3. 설계 ④ 의 대응표 · 성공 기준의 확인 출력을 PR 본문에만 둬도 되는가 | 5 회째 | `audit-internal-2026-11-01-070820.md` |
| 4. 대체 ADR 이 바꾼 결정을 적어야 하는가 | 4 회째 | `audit-internal-2026-11-03-081932.md` |
| 5. 「같은 목록을 두 군데 두면 갈린다」(`CLAUDE.md`)가 그 파일 밖의 목록에도 걸리는가 | 4 회째 | `audit-internal-2026-11-03-081932.md` |

- **판정이 회차마다 빈다** — 물음 3 의 자리는 체크 항목이 확인불가로 남는다(NC-19 · NC-22 가 같은 뿌리 — 약속한 기록이 저장소 안에 없다). 감사자는 저장소만 읽어 PR 본문을 못 본다.
- **앞 ADR 이 지금 결정처럼 읽힌다** — ADR 0060 의 1 이 0013 의 1 을, 0061 이 0044 결과 7 을, 0065 의 2 가 0042 결과 3 을, 0070 이 0069 의 3 과 2 의 근거를 바꿨는데 바꾼 쪽이 앞 ADR 을 들지
  않고, 앞 ADR 에는 바뀌었다는 줄이 없다. 머리에 적은 대체(0052 · 0059 · 0071 따위)도 앞 ADR 쪽에는 줄이 없다.
- **같은 원칙이 자리마다 다르게 읽힌다** — 회차 21 은 코드 상수 두 벌, 회차 25 는 틀 주석과 스킬의 두 목록, 회차 29 는 설계 · 러너 · `compare/README.md` 의 세 목록을 들고 원칙의 범위가 문서에
  없어 부적합으로 세지 않았다.
- **잃는 것** — 감사 회차가 같은 물음을 다시 쓰는 데 자리를 쓰고, 그 자리에서 판정이 멈춘다. 마스터플랜의 그 줄은 2026-10-30 에 섰고 2026-11-02 · 11-03 에 물음이 더해졌다.

## 핵심 사용자와 시나리오

- 사용자: 이 저장소에서 조각을 닫기 전에 `audit-internal` 을 부르는 세션 — 저자가 그 기록을 읽고 판정한다.
- 시나리오: 조각의 닫는 PR 이 대장 판정의 고침으로 스크립트 한 줄을 싣고, 구현 PR 하나가 새 ADR 로 하지 않을 일 하나를 넓혔고, 한 ADR 이 앞 ADR 의 한 항목을 대체했고, `README.md` 의
  절 제목 하나가 바뀌어 `verify-counts.py` 의 원천 머리 줄을 같은 PR 이 고쳤다 → 세션이 닫기 전 `audit-internal` 을 부른다 → 감사자가 `CLAUDE.md` · `docs/procedure.md` 에서 다섯 자리의
  규칙을 찾아 적합 · 부적합으로 판정하고, 성공 기준의 확인 출력은 `## 닫으며` 에서 읽는다 → 「문서에 없어서」에 다섯 물음이 다시 오르지 않는다.

## 성공 기준

1. **답이 기록된다** — 착공 PR 이 ADR 0073 을 더하고, 그 ADR 이 물음 다섯의 답을 저자가 정한 것으로 든다.
2. **이 저장소의 규칙이 선다** — PR A 뒤 `CLAUDE.md` 「가변」이 검사가 읽는 글(원천의 머리 줄 · 닻의 꼴 · 변조본이 바꿀 글)을 들고, 「작업 방식」이 같은 목록의 원칙을 저장소 전체(문서 ·
   코드 · 틀 · 스킬)로 든다. 「앵커볼트」 절의 항목은 그대로다.
3. **절차가 선다** — PR A 뒤 `docs/procedure.md` 가 셋을 든다: 단계 3 의 나가는 조건에 ⑥ · 하지 않을 일을 넓히는 길(새 ADR 이 넓히는 ⑥ 줄과 하지 않을 일의 번호를 적고 저자가 정한다),
   단계 6 에 닫는 PR 의 고침(대장에 저자 판정이 있는 고침 · 하지 않을 일 · 성공 기준에 묶이지 않는다 · `## 닫으며` 가 판정을 가리킨다)과 `## 닫으며` 의 근거(성공 기준마다 대어 본 명령과
   결과의 핵심 줄), 「살아 있는 문서와 기록」에 대체 ADR 을 양쪽에 적는 법.
4. **사람이 볼 줄이 있다** — PR A 뒤 `CHECKLIST.md` 가 셋의 줄을 든다 — 닫는 PR · `## 닫으며` 의 근거 · 대체 ADR. 줄마다 규칙의 주인(`docs/procedure.md` 의 절)을 가리키고 규칙을 옮겨 적지
   않는다.
5. **지난 대체가 양쪽에 선다** — PR B 뒤 설계 ③ B 의 쌍마다 앞 ADR 끝에 날짜를 박은 대체 줄이 있고, ③ B 의 「적지 않은 넷」은 새 ADR 끝에도 있다. `git diff --numstat <PR A 머지> <PR B 머지>
   -- docs/adr` 의 지운 줄 칸이 다 0 이다.
6. **두 벌 셋이 넘어간다** — 착공 PR 뒤 조각 나눔에 「같은 목록의 두 벌 셋」 줄이 있다.
7. **감사자가 다시 묻지 않는다** — 닫기 전 `audit-internal` 회차의 기록에서 「문서에 없어서 판정할 수 없었던 것」이 다섯 물음을 다시 올리지 않는다. 올리면 그 회차의 근거를 대장에 등록하고
   `## 닫으며` 에 미달로 적는다.
8. **도구 · 수트는 그대로다** — `git diff --stat 2884f09 <각 머지> -- vibe-audit vibe-slice .claude-plugin scripts` 가 비고, 이 조각의 PR 마다 `eval-key.py route` · `full` 이 `main` 과 같다.
9. **게이트** — `./scripts/gates.sh` 가 이 조각의 PR 마다 작업트리와 CI gate 잡에서 통과한다.
10. **감사 회차** — 닫기 전 감사 회차를 돌려 `docs/audit/` 의 대장에 등록했다.

## 하지 않을 일

1. **새 검사 · 변조본 · 게이트를 세우지 않는다** — 다섯 규칙은 사람이 본다(`CHECKLIST.md`). 같은 목록 두 벌을 견주는 검사, 대체 줄을 무는 검사, `## 닫으며` 의 근거를 무는 검사를 두지
   않는다(ADR 0073 의 7 · 마스터플랜 「새 장치는 새어 나간 결함에만」).
2. **플러그인을 고치지 않는다** — `vibe-slice` 의 스킬 · 틀 · 검사 · 지도 링크 · 판, `vibe-audit` 의 감사자 · 커맨드 · 판이 그대로다. 다른 레포는 지도 링크가 다음에 박힐 때 새 절차를 받는다
   (ADR 0073 의 8).
3. **알려진 두 벌 셋을 고치지 않는다** — `SCAN_SKIP_LOCAL` ↔ `DEFAULT_EXCLUDE`, 프로필 틀 머리 주석 ↔ `slice-docs` 스킬, 조각 52 설계 ③ B ↔ `run-compare.sh` ↔ `compare/README.md` 는 조각 나눔
   「같은 목록의 두 벌 셋」이 맡는다.
4. **감사 기록의 다른 「문서에 없어서」를 다루지 않는다** — 넘길 일이 없는 미달 · 손 판정으로 대는 성공 기준, 머지된 ADR 「맥락」의 사실이 틀렸을 때, 조각 비용 천장의 범위, 부정 진술의 근거,
   영어 명사 → 원천, 옮김의 원천, 감사 기록이 살아 있는 문서의 원문이 되는가, 사본이 아닌 레포에서 온 틀의 고침, 이 저장소 문서의 말, 브리핑의 둘째 기준(OB-26).
5. **지난 조각의 기록을 고쳐 맞추지 않는다** — 지난 `## 닫으며` · 설계 · PR 본문은 그대로다. 새 규칙은 이 조각의 PR 부터 걸린다. 지난 ADR 에는 대체 줄을 **덧붙일** 뿐이다.
6. **대체 쌍을 더 찾지 않는다** — PR B 는 설계 ③ B 의 닫힌 목록만 다룬다. ADR 전체를 읽어 머리 · 결과에 적지 않은 대체를 더 찾는 일은 하지 않는다.
7. **조각 나눔의 다른 줄을 다루지 않는다** — 「항목 10 과 머리의 어긋남」 · 「새 장치는 새어 나간 결함에만」 · 「걷은 사본의 대장 줄」 등.

## 제약

- 스택: 마크다운. 스크립트를 고치지 않는다.
- 원본: `main` `2884f09`.
- 비용: **$0** — 측정이 없다. 수트 지문을 바꾸지 않아 route 수트가 돌지 않는다.
- 기간: 닫기까지 **사흘**(2026-11-08 까지).
- 리뷰: 착공 PR 도 구현 PR 도 스킬 `slice-review` 로 가른다. PR 마다 **3라운드**를 넘기면 소유자가 판정한다.
- 감사 회차: 닫기 전 — `audit-internal`(바뀌는 것 — `CLAUDE.md` · 절차 지도 · `CHECKLIST.md` · ADR. 다섯 물음이 이 감사자의 「문서에 없어서」에서 왔고, 성공 기준 7 이 그 회차의 기록에
  선다. 대장이 이 조각에 기대는 것 — NC-36 이 고침으로 다음 `audit-internal` 회차를 기다린다). `audit-quality` 는 고르지 않는다 — 검사 · 변조본 · 게이트가 바뀌지 않는다.
