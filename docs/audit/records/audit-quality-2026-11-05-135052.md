  - 설계 ⑤(「시험을 세우지 않는다」)
  - `scripts/eval-key.py:53`(`vibe-audit` 만), `scripts/run-evals.sh`(`vibe-slice` 0 건), `vibe-slice/` 아래 eval 0 건
- 증상:
  - 0.9.4 는 리뷰 지적을 가르는 기준을 넓혔습니다. 넓힘 ADR 의 넓힌 몫과 대장 판정의 고침은 「안」에서 뺍니다.
  - 그 지시를 따른 세션이 실제로 그렇게 가르는지 보는 것이 없습니다. 반대쪽도 보지 않습니다 — ADR 없이 ⑥ 밖을 한 PR 을 여전히 「안」으로 가르는지.
  - 성공 기준 2 ~ 6 의 검사는 다 글의 모양입니다: 자리 · 예산 · 링크 · 판.
- 근거:
  - 이 상태에서는 넓힌 규칙이 과하게 읽혀도(ADR 없는 ⑥ 밖 작업이 「넓힌 몫」으로 지나감) 초록입니다. 덜 읽혀도(넓힘 ADR 을 여전히 「안」으로 가름) 초록입니다.
  - 조각의 성공 여부를 가를 근거가 없습니다. 다음 문구 손질이 개선인지 회귀인지도 견줄 기준선이 없습니다.
  - 지난 회차의 판단을 뒤집는 근거: 회차 14(2026-10-29) OB-2 는 같은 모양(`vibe-slice` 스킬 행동을 재는 케이스가 없음)을 관찰로 두었습니다. 그때 지시는 스크립트를 부르라는 것이었고, 그 효과는 스크립트가 봤습니다. 이번 지시는 판정 그 자체라 그 효과를 보는 것이 따로 없습니다. 체크 항목 3 · 9 를 정면으로 어깁니다.
- 심각도: 보통 — 되돌릴 수 있으나 틀린 결과가 누군가에게 닿습니다.
  - 전제: 0.9.4 는 마켓플레이스 · `sync-slice.sh` 로 다른 레포에 갑니다. 거기서 틀린 가르기가 PR 머지 판단에 닿습니다. 다음 판으로 되돌릴 수 있습니다.
  - 높음으로 두지 않은 까닭: 스킬 글의 옛 판(0.9.3)은 git 에 있습니다. 나중에 평가를 세워도 같은 모델에서 옛 글과 새 글을 견줄 수 있습니다.
  - 다른 레포에서 이미 틀리게 가른 PR 이 있는지는 이 저장소 밖입니다. 저자 · 사본 레포가 줄 수 있습니다.
- 제안(세우지는 않음):
  - `slice-review` 를 재는 케이스를 자동 게이트로 세웁니다. 최소 셋입니다.
    - (가) 같은 PR 의 새 ADR 이 ⑥ 줄과 하지 않을 일 번호를 들고 소유자가 정한 넓힘 → 「안」이 아님
    - (나) 대장 「고침」 판정 줄의 고침을 실은 닫는 PR → 「안」이 아님
    - (다) 대조군: ADR 없이 ⑥ 밖을 한 구현 PR → 「안」
  - (다)가 없으면 「뭐든 안이 아니다」로 무너진 스킬도 지나갑니다.

  - `vibe-slice` 의 행동을 재지 않기로 정한다면, 그 결정을 ADR 로 남기고 반박으로 닫는 길도 있습니다. 그때는 이 행이 다음 회차부터 관찰로 내려갑니다.
