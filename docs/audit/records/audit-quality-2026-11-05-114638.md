### NC-38 · 변조본 (나)가 「검사 파일 옆에서 읽는다」 회귀에서 떨어지지 않는다 — 설계 ② C 의 절반에 무는 것이 없다
- 위치:
  - `scripts/bite-gates.sh:1723-1724`(`vbite` 는 사본의 검사 `$VC/scripts/verify-counts.py` 를 `$VC` 에 댑니다) · `:1812-1816`
  - `scripts/verify-counts.py:43`(`ROOT = pathlib.Path(__file__).resolve().parent.parent`) · `:497`
  - `docs/slices/55-duplicate-lists/design.md` ② C(「그 검사 파일 옆이 아니다」)와 ⑤ 의 C 줄(「변조본 (나)가 … 떨어진다」)
- 증상:
  - (가) · (나)는 사본에 든 검사를 사본에 댑니다. 그래서 「검사 파일 옆」(`ROOT / BRIEF`)과 「훑는 트리」(`root / BRIEF`)가 같은 파일, 곧 고친 사본입니다.
  - `local_skip` 이 `ROOT / BRIEF` 를 읽도록 바뀌어도 (나)는 여전히 `FAIL [U1] .claude/audit-brief.md:…` 로 떨어지고, 절은 지나갑니다.
  - 저장소의 검사를 사본에 대는 대조군 둘(`:1829` · `:1837`)은 `verify-brief.py` 를 고치지 않아서, 그 회귀를 보지 못합니다.
  - (나)가 실제로 가르는 것은 cwd(`$R`)나 박은 경로에서 읽는 회귀뿐입니다.
- 근거: 이 상태에서는 「검사 파일 옆에서 읽기」가 변조본 29 · 대조군 3 을 다 지납니다. 설계 ⑤ 는 C 가 (나)로 보인다고 적었습니다.
- 심각도: 보통 — 막는다고 믿는 회귀를 막지 않습니다.
  - 전제: 지금은 검사의 트리와 훑는 트리가 다르면서 `verify-brief.py` 까지 다른 호출이 없습니다(`verify-counts.py` 를 부르는 곳은 `gates.sh:93` · `bite-gates.sh` 뿐 — grep). 그래서 지금 틀린 결과가 닿는 사람은 없습니다.
  - 그래도 낮음으로 두지 않은 까닭: 설계가 이 회귀를 막는다고 적었고, 앞으로 저장소의 검사로 사본을 보는 변조본이 서면 그 사본의 목록을 보지 못합니다.
- 제안(세우지는 않음):
  - (나) 한 줄을 저장소의 검사로 사본을 보게 바꿉니다: `bit 1 '^FAIL \[U1\] \.claude/audit-brief\.md:[0-9]+ ' "첫 자리에서 브리핑 작업본을 뺌" python3 scripts/verify-counts.py "$VC"`.
    - 그러면 `ROOT=$R` · `root=$VC` 가 갈라집니다. 검사 옆 읽기(바꾸지 않은 `$R` 의 목록)도, cwd 읽기도 지나가 버려 떨어집니다.
  - 고치는 것은 `verify-brief.py` 뿐이라 저장소 검사로 대도 됩니다. 변조본 수는 29 그대로입니다.
  - `vbite U5` 는 `rgap` 이 읽으니 그대로 둡니다.

### OB-1 · 손으로 둔 보장 가운데 D 는 대조군 하나로 자동화되고, ADR 0074 의 4 의 경계는 아무것도 물지 않는다
- 위치: 설계 ⑤ 의 D · B 줄 · `scripts/verify-counts.py:526` · ADR 0074 「결정」 4
- 무엇:
  - D(실행하지 않는다): 설계는 「떨어질 ID 가 없다」를 까닭으로 변조본을 두지 않았습니다. 그러나 대조군(`keep`)은 ID 가 필요 없습니다. 사본 `verify-brief.py` 맨 위에 `raise SystemExit(9)` 를 심고 종료 0 과 `$VPASS` 를 보면, `importlib` 로 바꾸는 회귀가 떨어집니다. 지금은 PR #207 에서 한 번 손으로 댔을 뿐입니다.
  - 경계: `keep` 의 `rel == e or rel.startswith(e + "/")` 를 옛 앞부분 견주기(`rel.startswith(e)`)로 되돌려도, 지금 트리에는 `.claude/audits-…` 꼴 파일이 없어 PASS 줄의 「훑은 파일 N」이 같습니다. 무는 것이 없습니다.
- 왜 부적합이 아닌가:
  - 설계 ⑤ 가 D · E 를 손 확인으로 두기로 정했고, B 는 「같은 집합」만 약속합니다.
  - 새 ID 마다 변조본을 두라는 규칙(조각 42 ② R)은 지켰습니다.
- 알아 둘 값: `local_skip` · `keep` 을 다시 고치는 PR 은 D 와 경계를 손으로 다시 대야 합니다. 대지 않으면 아무도 모릅니다. 대조군 하나와 `.claude/audits-x/` 를 심은 변조본 하나가 싼 길입니다.

  - 그러나 `found.md` 본문의 다른 줄만 맞히는 읽기는 여전히 0 입니다. 예: 「세지 않는 것」 줄만 맞히는 grep, `--include=*.md` 로 좁힌 grep.
- 왜 부적합이 아닌가: NC-30 의 제안(낱말 셋 · 절 머리와 첫 줄 · 돌리기 전 충돌 확인)이 그대로 섰고, 그 팔은 잠겨 돌지 않습니다(ADR 0071).
- 알아 둘 값: 「맞대기 다시 재기」가 그 팔을 풀 때, 본문의 비지 않은 줄을 다 목록에 넣을지 볼 자리입니다. 넣어도 오탐은 충돌 확인(`:205-210`)이 막습니다.
