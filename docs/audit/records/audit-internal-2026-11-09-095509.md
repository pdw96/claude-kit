## 부적합 목록

### NC-46 · ADR 0079 맥락과 요구사항 「문제」는 커맨드가 「세 자리」를 `.gitignore` 에 두라고 알린다고 했지만, 커맨드는 두 자리(브리핑 · `.claude/briefs/`)만 든다
- 규칙
  - 「커맨드는 세 자리를 `.gitignore` 에 두라고 알린다(「남기는 것」 끝). 그렇게 두면 갈린 경로의 작업본은 추적 안 된 파일 목록에도 나오지 않아 갈려도 말이 없다」(`docs/adr/0079-brief-exclude-list.md:13`)
  - 「커맨드는 세 자리를 `.gitignore` 에 두라고 알리고」(`60/requirements.md:15-16`)
  - 두 문장이 ADR 0079 의 1 에서 「약한 두 벌」로 가른 근거입니다.
- 실제
  - 「**브리핑과 `.claude/briefs/` 가 `.gitignore` 에 없으면 알리세요**」(`vibe-audit/commands/audit-brief.md:126-127`). 이 줄은 착공 `7a15be0` 에서도 같습니다.
  - `.claude/audits/` 는 알림에 없습니다. 같은 줄 앞은 「`.claude/audits/` 에 두면 감사자가 지난 기록으로 집습니다」입니다.
  - 그래서 `.claude/audits` 경로에서는 커맨드를 따른 레포에서도 작업본이 git 에 보입니다. 갈림은 `verify-brief.py` 대조가 잡습니다. 「갈려도 말이 없다」는 세 자리 가운데 둘에만 섭니다.
- 어느 쪽을 고칠 문제인가: 사람이 결정
  - ADR 0079 와 요구사항은 기록이라 고치지 않습니다. 닫는 기록에 바로잡음을 남기는 길이 있습니다.
  - 커맨드 알림에 `.claude/audits/` 를 더하는 길도 있습니다. 다만 「남기는 것」을 고치는 일이라 하지 않을 일 5 에 걸립니다.
- 심각도: 낮음 — 결정(커맨드가 상수를 가리킨다)과 결과는 같습니다. 잃는 것은 ADR 0079 를 연 사람이 세 자리 다 말없이 갈린다고 읽는 것입니다.
- 제안(고치지는 않음): 닫는 PR 의 `## 닫으며` 에 「`.gitignore` 알림은 두 자리(`audit-brief.md:126-127`)」라고 한 줄 남깁니다.

### NC-47 · 살아 있는 문서 `vibe-audit/evals/README.md` 가 사라진 길 「검사기를 못 찾으면 「못 돌림」」을 아직 말한다
- 규칙
  - ADR 0079 의 3(저자): 「검사기를 못 찾을 때: **멈추고 알린다** … 대가 — 「검사기를 못 찾으면 `검사:` 에 적고 감사자에게 알린다」는 지금의 길이 사라진다. 검사기를 찾았는데 돌리지 못한 경우 … 의 「못 돌림」은 남는다」
  - 살아 있는 문서는 「늘 지금과 맞아야 한다」(`docs/procedure.md:128`). `vibe-audit/evals/README.md` 는 그 표에 듭니다.
- 실제
  - 「플러그인 폴더의 `scripts/verify-brief.py` 로 찾게 하고, 못 찾으면 머리의 `검사:` 에 「못 돌림」과 까닭을 적는다 — 말없이 건너뛰지 않는다」(`vibe-audit/evals/README.md:249-250`)
  - 커맨드: 「**못 찾으면 모으지 말고 멈추고 알리세요**」(`audit-brief.md:36`), 「못 돌리면 `검사:` 에 까닭을 적고」(`:102`)

- 어느 쪽을 고칠 문제인가: 사람이 결정

  - 닫는 PR 이 「고침」 판정으로 싣는 길이 있습니다(`procedure.md:47` — 성공 기준에 묶이지 않습니다).
- 심각도: 낮음 — 커맨드의 행동은 커맨드 글이 정해 결과는 같습니다. 잃는 것은 이 README 를 읽은 유지자가 설치가 깨진 레포에서도 브리핑이 나온다고 믿는 것입니다.
- 제안(고치지는 않음): 「못 찾으면 멈춘다 · 찾았는데 못 돌리면 「못 돌림」」으로 두 갈래를 가르고 ADR 0079 의 3 을 가리킵니다.

### NC-48 · 요구사항 「제약」이 커맨드의 호출 시 천장을 11100 으로 적었는데, 실제 천장은 4500 이다
- 규칙: 「글자 예산: 커맨드 본문은 호출 시 예산에 든다(`vibe-audit/evals/budget.txt` 의 `audit-brief` 4491, 천장 11100)」(`60/requirements.md:56`)

- 어느 쪽을 고칠 문제인가: 문서
  - 요구사항은 기록이라 고치지 않고 닫는 기록에 바로잡습니다. 호출자가 PR A 본문에 적었고 `## 닫으며` 에 적을 예정이라고 알렸습니다.

## 문서에 없어서 판정할 수 없었던 것

**A. 조각 나눔 「목표 한 줄」의 사실 서술은 살아 있는 문서인가**
- 마스터플랜은 살아 있는 문서입니다(`procedure.md:128`). 그런데 60 줄(`master-plan.md:91`)은 「커맨드 본문(`audit-brief.md:36-37`)이 … 세 경로를 pathspec 으로 적고」를 지금 사실처럼 적었고, PR A 뒤 이 문장은 거짓입니다.
- 닫힌 55 · 56 줄도 같은 꼴로 남아 있어, 목표 칸은 착수 때의 사실로 두는 관행으로 보입니다. 다만 그 관행을 적은 곳이 없습니다. 「목표 칸은 꺼낼 때의 사실이고, 상태가 `닫힘` 이면 그때의 것으로 읽는다」 같은 한 줄이 지도 「마스터플랜의 칸」에 있으면 판정됩니다.

**B. 「제 일의 대상 이름」과 「무엇을 볼지 정하는 열거」의 경계 — 규칙 5 의 경계 판단 4 회째**
- `audit-brief.md:126-127` 의 `.gitignore` 알림은 세션이 무엇을 `git check-ignore` 로 볼지 정하는 두 자리의 열거입니다. `CLAUDE.md` 정의(「무엇이 드는지 정하는 열거」)에도 걸리고, ADR 0079 의 6 · 하지 않을 일 4(「제 일의 대상」 — 밖)에도 걸립니다.
- 이번에는 `DEFAULT_EXCLUDE` 와 같은 목록이 아니라(둘 대 셋) 판정할 필요가 없었습니다. 그러나 「밖」 근거는 기록(ADR 0079 의 6)에만 있습니다. 회차 40 NC-43 과 같은 꼴입니다.
- 회차 38 NC-41 · 39 C · 40 NC-43 · 44 · C 에 이어 같은 규칙의 경계가 판단으로 남은 4 회째입니다. ADR 0078 「대가 — 경계는 판단으로 가른다」가 받아들인 것이라 자동 게이트로 세울 꼴은 아닙니다. 회차 40 C 의 제안(경계 자리를 닫힌 표로 살아 있는 자리에 둔다)을 저자가 정할지 다시 올립니다.
