+5. 끄는 법을 잴 자리: **claude-kit 의 버리는 가지 — 머지하지 않고 지운다 — 를 저자가 앱에서 연 세션** / 사본 레포(ERP)의 가지 / 재지 않고 후보만 적는다.
+6. 끄는 법이 없을 때 README 가 적는 것: **두 벌이 뜬다는 것과 부르는 이름(스코프 없는 이름은 사본, `vibe-audit:` · `vibe-slice:` 를 붙인 이름은 동기화본)** / 계정
+   설정에서 동기화를 끄라고 적는다 / 조각을 닫지 않고 기다린다.
+
+## 결정
+
+1. **세 경로로 적는다 — 로컬 대화형 세션은 마켓플레이스, 앱에서 연 클라우드 세션은 계정 동기화, 레포 사본은 특화가 있는 레포와 동기화가 닿지 않는 세션의 몫.**
+   특화가 없는 레포는 사본을 심지 않아도 원본을 받는다. `INTENT.md` What 의 배포 줄이 바뀐다 — 마스터플랜 「범위 변경」에 적는다.
+2. **겹침은 끄는 법부터 잰다.** 사본 레포의 세션에 원본과 특화 사본이 같은 설명으로 함께 뜨면, 이름을 부르지 않고 설명으로 고를 때 원본이 잡힐 수 있다 — 그러면 특화가
+   빠진다. 레포 쪽 설정으로 동기화본을 끌 수 있으면 그 법을 적어 사본 레포가 고른다.
+3. **근거는 착공 세션에서 앱으로 연 ERP 세션이다.** 도구로 연 세션은 동기화를 받지 않아 저자가 앱에서 쟀다(「맥락」의 표).
+4. **기준은 후보 대장의 `specific` 판정이다.** 저자가 한 판정이라 레포의 말과 원본의 말을 이미 갈랐다. 사본이 원본과 다르다는 것은 심은 뒤 원본이 나아가도 참이라 특화의
+   증거가 아니다. 판정이 없는 레포가 특화를 세우려면 사본을 심고 고친 뒤 비교기가 낸 후보를 저자가 `specific` 으로 가른다 — 지금의 흐름 그대로다.
+5. **끄는 법은 claude-kit 의 버리는 가지에서 잰다.** 사본 레포를 고치지 않는다(`INTENT.md` Not 4). 끄는 것이 되는지는 사본의 유무와 상관없이 동기화본이 사라지는지로
+   보인다. 도구로 연 세션은 동기화를 받지 않으므로 그 가지의 세션은 저자가 앱에서 연다.
+6. **끄는 법이 없으면 두 벌과 부르는 이름을 적는다.** 2026-10-30 ERP 실측이 이름의 갈림을 보였다. 계정 설정으로 끄면 모든 레포에서 꺼져 1 이 무너진다.

+요구사항이다 — **무엇을 · 왜.** 어떻게 · 경계는 같은 폴더의 `design.md`, 대안이 있던 결정은 ADR 0060.
+
+이 조각을 「다음 조각」으로 적은 닫힌 조각은 없다 — 조각 46 의 `## 닫으며 (2026-10-30)` 가 다음 조각을 `없음` 으로 적었다(ADR 0012). 이 줄은 같은 날 저자가 「플러그인이
+로컬과 클라우드에서 다르게 도는 버그가 해결됐는지」를 물은 세션이 조각 나눔에 더했고(#174, 머지 `20dc828`), 저자가 그 세션에서 착공하라고 했다. 의존은 `—` 다. 착공
+세션이 갈래 셋을 물어 저자가 「특화 레포에만 사본」 · 「끄는 법부터 잰다」 · 「지금 ERP 세션으로 확인」을 골랐다(ADR 0060 의 1 ~ 3). 이 착공 세션의 claude-kit 클론은
+얕지 않았다(`git rev-parse --is-shallow-repository` → `false`).
+
+## 문제
+
+**살아 있는 문서가 「클라우드 레인은 마켓플레이스 경로를 받지 못하니 레포 사본으로만 받는다」고 적는데, 앱에서 연 클라우드 세션은 계정 동기화로 원본을 받는다. 사본
+레포에서는 원본과 사본이 같은 설명으로 두 벌 뜬다.**
+
+- **세 세션이 갈렸다(2026-10-30, CLI 2.1.314, 같은 계정 · 같은 환경).** 앱에서 연 claude-kit 세션은 `CLAUDE_CODE_SYNC_PLUGINS=1` 이고 `~/.claude/plugins/synced/` 에
+  `vibe-slice` 0.9.0 · `vibe-audit` 0.4.6 이 계정 마켓플레이스(`marketplaceName: claude-kit`)로 받아져 있었다. 도구로 연 ERP 세션은 그 변수가 없고 폴더가 비어 사본만
+  떴다. 저자가 앱에서 연 ERP 세션은 감사자 여섯 · `audit-brief` · `slice-docs` · `slice-review` 가 다 두 벌이었다(ADR 0060 「맥락」의 표).
+- **저장소 선언 길은 여전히 막혀 있다.** 세 세션 다 `SKIP_PLUGIN_MARKETPLACE=true` 다. README 가 든 버그 셋 가운데 anthropics/claude-code#78119 는 열려 있고 #32606 ·
+  #13097 은 수정 없이 봇이 닫았다. 그러니 README 의 버그 표는 맞고, 「클라우드 레인은 받지 못한다」는 틀렸다.
+- **옛 문장이 살아 있는 파일 일곱 자리에 있다.** `README.md` 셋(22 · 41 ~ 43 · 58행) · `vibe-audit/README.md` 「설치」 · `docs/architecture.md` 「사본」 줄 ·
+  `scripts/sync-agents.sh` · `scripts/sync-slice.sh` 머리의 까닭 줄(`main` `20dc828`). `INTENT.md` What 의 「배포 두 경로」는 이 착공이 고친다.
+- **겹침은 특화를 빼먹을 자리다.** 이름을 부르면 갈린다 — 스코프 없는 `slice-docs` 는 사본(`/home/user/ERP/.claude/skills/slice-docs`)으로, `vibe-slice:slice-docs` 는
+  동기화본으로 갔다. 그러나 감사자는 설명으로도 불린다(감사자 설명의 「요청이 없어도 먼저 띄우세요」 따위). 설명이 같은 두 벌 가운데 원본이 잡히면 ERP 의 특화(후보 대장의
+  `specific` 24 건)가 그 감사에서 빠진다. 레포 쪽에서 동기화본을 끌 수 있는지는 아무도 재지 않았다.
+- **사본이 모든 레포에 필요하지 않다.** 강호쟁패는 후보 대장에 후보가 없다 — 특화가 없다. 앱에서 연 세션이라면 그 레포는 사본 없이도 원본을 받는다.
+
+## 핵심 사용자와 시나리오
+
+- 사용자: 새 프로젝트 레포에 감사자와 조각 문서 스킬을 들이려는 저자, 그리고 사본 레포에서 감사자를 부르는 세션.
+- 시나리오: 저자가 새 레포를 연다 → README 「설치」를 읽고, 앱에서 여는 클라우드 세션이면 계정에 붙인 마켓플레이스로 원본이 뜬다는 것과 특화할 일이 생기기 전에는 사본을
+  심지 않아도 된다는 것을 안다 → 그 레포에 특화가 생겨 사본을 심는다(`sync-agents.sh`) → README 의 겹침 글을 따라 동기화본을 끄거나(끄는 법이 있으면), 감사자를 스코프
+  없는 이름으로 부른다(없으면) → 그 레포의 세션이 특화 사본으로 감사한다.
+
+## 성공 기준
+
+1. **끄는 법을 쟀다** — 구현 PR A 를 열기 전에 설계 ③ 의 꼴마다 저자가 앱에서 연 세션의 결과(연 곳 · `CLAUDE_CODE_SYNC_PLUGINS` · `~/.claude/plugins/synced/` · 뜬
+   `vibe-audit:*` · `vibe-slice:*` 의 유무 · CLI 판)가 설계 끝 날짜 항목에 있고, 그 결과로 README 의 겹침 글을 정했다(설계 ④ 의 열어 둔 것).
+2. **옛 문장이 없다** — A 뒤 `main` 에서 `git grep -n -E "받지 못한다|받지 못하므로"` 가 기록 넷(`docs/slices/` · `docs/adr/` · `docs/eval-log/` · `docs/audit/`) 밖에서
+   0 줄이다(`20dc828` 에서 넷).
+3. **세 경로가 같은 말로 적혀 있다** — `README.md` 「설치」에 경로마다 닿는 세션 · 받는 법 · 부르는 이름이, 사본을 심는 레포의 기준(ADR 0060 의 4)이, 사본 레포의 겹침(두
+   벌 · 부르는 이름 · 끄는 법이나 없다는 것)이, 잰 세션과 재지 않은 세션이 있다. `vibe-audit/README.md` 「설치」 · `docs/architecture.md` 「사본」 줄 · 두 심기
+   스크립트의 머리가 그것과 어긋나지 않고, `INTENT.md` What 의 배포 줄(이 착공)과 같은 셋이다.
+4. **판과 게이트** — `vibe-audit` 판이 0.4.7 이고 `claude plugin validate` 가 두 플러그인을 통과한다. A 작업트리의 인자 없는 `./scripts/gates.sh` 가 끝 줄 「스물여덟 다
+   통과」로 끝나고, 착공 PR 과 A 의 CI gate · verdict 가 초록이며 A 의 route 수트가 통과한다. `gates.sh` · `test-gates.py` 의 목록은 그대로다.
+5. **감사 회차** — 닫기 전에 `audit-internal` · `audit-quality` 를 돌려 `docs/audit/` 의 부적합 대장에 등록하고(그 등록이 `verify-ledger.py` 를 지난다), `## 닫으며` 가
+   회차를 든다.
+
+## 하지 않을 일
+
+1. **사본 레포를 고치지 않는다** — 강호쟁패의 사본을 걷거나 ERP 에 끄는 설정을 넣는 일은 그 레포가 한다(`INTENT.md` Not 4). 이 조각은 원본의 문서만 고친다.
+2. **대장의 모양과 줄을 바꾸지 않는다** — `copies.json` · `feedback.json` 은 앵커볼트다(`CLAUDE.md`). 사본 레포가 사본을 걷으면 그때 대장의 줄을 다룰 조각을 조각 나눔에
+   더한다.
+3. **감사자 · 커맨드 · 스킬의 글을 고치지 않는다** — 설명에 「사본이 있으면 그쪽을」 같은 줄을 넣으면 원본에 레포별 분기가 생긴다(`CLAUDE.md` 「금지」). `audit-brief.md`
+   의 「사람이 없는 자리(클라우드 레인 · CI)」는 설치가 아니라 사람 없는 세션을 말하므로 그대로 둔다.
+4. **저장소 선언을 넣지 않는다** — 이 저장소에도 사본 레포에도 `extraKnownMarketplaces` · `enabledPlugins` 로 마켓플레이스를 선언하지 않는다. 클라우드 세션은 그 길을
+   건너뛴다(`SKIP_PLUGIN_MARKETPLACE=true`). 끄는 법을 재는 버리는 가지는 머지하지 않는다.
+5. **재지 않은 세션을 넘겨짚지 않는다** — 웹에서 연 세션 · 예약 작업 · Slack · CI 에 동기화가 닿는지는 재지 않았다고 적고, 닿는다고도 닿지 않는다고도 쓰지 않는다.
+6. **업스트림 이슈에 댓글을 달지 않는다** — README 의 버그 표는 이슈를 가리키기만 한다.
+
