# claude-kit 기준 문서

프로젝트 전체의 기준이고 **살아 있는 문서**다. 다른 문서가 이미 든 값은 옮겨 적지 않고 가리킨다. 목표 · 범위는
맡은 문서가 따로 없어 여기가 직접 든다 — README 는 입구다(ADR 0007). 모양은 `docs/schema.md` 「기준 문서의 칸」.

## 목표와 범위

**목표.** 목적별로 좁힌 읽기 전용 감사자를 **일반형 원본**으로 두고 여러 레포에 사본으로 부은 뒤, 사본에서
드러난 **결함만** 원본으로 되먹인다. 고친 것이 도로 풀리지 않게 되먹임마다 회귀 케이스로 잰다. 원본은 아무
레포에도 안 들어가 본 일반형으로 남아야 다음 프로젝트에 부을 수 있다.

**문제.** 감사자는 써 봐야 결함이 드러나는데, 그 발견이 사본 레포에 흩어지고 고친 뒤 좋아졌는지 잰 적이 없었다.
그리고 리뷰 회차가 끝나지 않는 일이 레포마다 되풀이된다 — 조각 2.

**범위.**

- `vibe-audit` 플러그인 — 감사자 여섯 · `audit-brief` 커맨드 · `verify-brief.py`
- 배포 두 경로 — 마켓플레이스(대화형 세션)와 레포 사본(클라우드 레인)
- 사본 대장 · 비교기 · 되먹임 대장
- eval 수트와 키 없이 도는 게이트
- 절차 지도와 기준 · 기획 · 설계 틀

**하지 않을 일.**

1. **감사자는 고치지 않는다** — 읽기 전용 도구만(`CLAUDE.md` 「앵커볼트」).
2. **원본에 특화 · 레포별 분기를 두지 않는다**(`CLAUDE.md` 「금지」).
3. **계정 스킬은 여기서 배포하지 않는다** — `project-kickoff` · `build-gate` · `separate-audit` · `ai-native-build` 은
   계정 경유로 클라우드 레인까지 닿는다. 고칠 자리가 나오면 「계정 스킬의 일」로 적는다.
4. **사본 레포를 고치지 않는다** — 원본 → 사본은 `sync-agents.sh` 가, 사본 안의 특화는 그 레포가 맡는다.
