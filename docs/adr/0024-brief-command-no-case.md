# 0024 — 브리핑 커맨드의 빈 인자는 케이스 없이 단계 5 에서 본다

2026-10-13 · 결정함 · ADR 0023 의 2 · 3 을 대체한다 · 저자가 조각 14 PR B 의 첫 측정 뒤 정했다 — 세션이 추천한 쪽이다

## 맥락

ADR 0023 은 기준만 준 부름을 커맨드 케이스 `command-base-only` 로 재고(2), `verify-evals.py` 가 셋째 모양 「커맨드
케이스」를 알게 하기로(3) 했다. 대조군은 커맨드가 `.claude/audit-brief.md` 를 쓴 것(`file_exists`)이다. 설계 ④ 는 eval 이
플러그인 커맨드를 펴는지를 열어 두었다.

PR B 의 첫 커밋(79346c9 — 케이스 · `verify-evals.py` · `bite-gates.sh`)에서 옛 커맨드로 잰 것(2026-10-13, CLI 2.1.296):

- **eval 은 커맨드를 편다.** 세션이 커맨드대로 기준을 SHA 로 굳히고 diff 를 모았다. 열어 둔 것은 펴는 쪽으로 닫혔다.
- **`Bash` · `Write` 는 운영자 허가가 있어야 열린다.** `case.yaml` 의 `allowed_tools` 만으로는 막히고, 하네스가
  `--allow-tools` 를 요구한다. `Bash` 허가는 셸 격리 도구(bubblewrap · socat)가 없는 기계에서 회차를 거절한다.
- **허가해도 `.claude/` 에는 못 쓴다.** eval 세션은 don't-ask 모드다. `.claude/` 아래 쓰기는 `Write` 를 줘도 거부되고,
  `Edit(.claude/**)` · 절대경로 규칙 · 프로젝트 `settings.json` 의 허용 규칙도 열지 못했다. 같은 모드에서 보통 경로는
  써진다. `Write` 를 빼고 `Bash` 만 주면 세션은 리다이렉션으로 쓰는 것을 「거부의 우회」라며 하지 않았다.
- 그래서 세 회차 다 「셋」에서 멈췄다 — 0.71 · 0.71 · 0.43, `command-ran` 세 번 다 떨어짐. 결함이 있는 「넷」(감사자)에
  닿지 못하므로 옛 커맨드와 새 커맨드를 가를 수 없다.

## 대안

1. **케이스를 세우지 않는다 — 첫 커밋을 되돌리고, 기준만 준 부름도 단계 5 에서 저자가 대화형 세션으로 본다**
2. 대조군을 「쓰려 했다」(`tool_used` — `Write` 가 `.claude/audit-brief.md` 를 겨눔)로 바꿔 케이스를 둔다
3. 브리핑 자리를 `.claude/` 밖으로 옮긴다

## 결정

1. 저자가 정했다(2026-10-13).

- 2 는 「셋」에서 멈추는 것이 바뀌지 않아 덫과 목적이 결함 자리에 닿지 못한다 — 옛 커맨드도 같은 점수를 받는 회귀
  검사이고, 대조군이 거부된 호출에 기댄다. 하네스가 `.claude/` 를 열면 바로 무너지는 모양이다.
- 3 은 커맨드의 일을 바꾼다 — 감사자 여섯 · 검사기 · 사본 둘이 `.claude/audit-brief.md` 를 읽는다(조각 14 하지 않을 일 4).
- 1 은 「되먹임 한 건에 eval 케이스 하나」(`CLAUDE.md` 「작업 방식」)의 예외다. 까닭이 커맨드가 아니라 eval 하네스의
  권한 모델이라, 케이스를 세워도 재는 것이 없다.
- 커맨드의 고침(ADR 0023 의 1)과 사본(4)은 그대로다.

## 결과

- 수트는 두 모양 그대로다. `verify-evals.py` · `bite-gates.sh` 는 `main` 과 같다. 커맨드 케이스의 모양을 아는 검사는
  케이스가 생길 때 함께 세운다.
- 조각 14 의 성공 기준 2 · 3 은 이 ADR 이 대체한다 — 기준만 준 부름(감사자를 묻는다)과 인자 없는 부름(git 전에 기준을
  묻는다)을 둘 다 단계 5 에서 저자가 본다.
- 하네스가 don't-ask 모드에서 `.claude/` 쓰기를 열게 되면 대안 1 을 다시 본다. 측정의 트레이스는 남기지 않았다 —
  결과 폴더는 git 밖이다. 숫자와 마지막 답은 `docs/eval-log/2026-10.md` 2026-10-13 항목에 있다.
