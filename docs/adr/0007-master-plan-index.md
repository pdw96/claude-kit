# 0007 — 프로젝트의 마스터플랜은 색인 + 조각 나눔이고, 저장소 안에 산다

2026-10-06 · 결정함

## 맥락

절차 지도(ADR 0005)의 일곱 단계는 조각 하나 안의 일이다. 조각이 매달릴 프로젝트 전체의 기준이 지도에 없었다.
저자가 「프로젝트 전체를 아우르는 문서를 두고, 그것을 기반으로 조각을 나눠 진행한다」고 정했다. 두 레포에 이미
있는 모양이 다르다 — ERP 는 저장소 밖 아티팩트 「설계도」(여덟 단계)에서 단계와 조각을 꺼내고, 강호쟁패는
`PRD.md`(범위) · `docs/architecture.md`(구조)는 있는데 조각 나눔이 없다.

## 대안

- 모양: **색인 + 조각 나눔** — 목표 · 범위 · 구조 · 데이터는 각자의 문서가 들고 마스터플랜는 가리킨다. 직접 드는
  것은 조각 나눔과 범위 변경뿐 / **한 파일 마스터플랜** — ERP 설계도처럼 다 담는다.
- 자리: **저장소 안 파일** / **저장소 밖**(아티팩트 등).

## 결정

**색인 + 조각 나눔, 저장소 안 파일**(`docs/master-plan.md` — 이름은 ADR 0008). 다른 문서가 이미 든 값은 가리키고, **주인 없는 값**
(프로젝트의 목표 · 전체 범위 · 하지 않을 일을 맡은 문서가 없을 때)은 마스터플랜가 든다 — README 는 입구라 그 주인이
아니다. claude-kit 은 그 값을 README 가 대신 들어 왔고, 마스터플랜가 README 를 가리키면 README 가 계속 커진다.

## 결과

- 같은 값이 두 군데 생기지 않는다. 강호쟁패 ADR-0005 의 교훈(복제된 값은 한 곳만 고쳐진다)과 이 저장소의 「같은
  목록을 두 군데 두면 갈린다」를 따른다. 대가: 마스터플랜 하나만 읽어서는 전체가 안 보인다 — 가리키는 문서를 따라가야 한다.
- git 으로 판이 남고 세션 · 검사가 읽는다. 세션은 지난 대화를 모르므로 기준은 파일에 있어야 한다. 보기 좋은 화면이
  필요하면 파일에서 만든 아티팩트를 둘 수 있지만 원천은 파일이다.
- ERP 의 설계도는 특화 사본으로 두고 옮기지 않는다(조각 2 기획 하지 않을 일 4).
