# 0059 — 닻 없는 같은 원천 문장은 원천의 명사 옆에서 지금 값과 같은 수를 훑어 찍는다

2026-10-29 · 결정함 · 1 · 2 는 저자가 조각 46 의 착공 세션에서 정했다(세션이 `main` `3d2c0ba` 를 시제품으로 훑은 첫 어림 — 명사 아홉으로 닻이 빠진 같은 원천 자리 약 8,
오검 약 24 — 를 보이고 갈래 넷과 무는 범위 셋을 물어, 저자가 세션이 추천한 쪽을 골랐다. 아래 「맥락」의 수는 그 뒤 명사를 원천 전부로 넓혀 다시 센 것이다). 3 ~ 7 은 세션이
제안했고 착공 PR 에서 저자가 본다. 1 이 ADR 0055 의 5 가운데 「닻 없이 새로 적은 수는
지나간다 — 그 몫은 `CHECKLIST.md` 의 한 줄과 리뷰가 진다」를 대체한다 — 닻 목록이 판단을 고정한다는 나머지는 그대로다

## 맥락

`verify-counts.py` 는 닫힌 닻 목록만 본다(ADR 0055 의 5). 닻 없는 문장의 몫은 `CHECKLIST.md` 「항상」의 「수를 새로 적었다면 닻을 더했다」와 리뷰였다. `audit-internal` 이 같은
갈래를 세 회차 연달아 냈다 — 회차 15 NC-15(셋째 검사를 심은 뒤에도 주석 둘이 「심은 두 검사」) · 회차 16 NC-16(그 주석을 「세 검사」로 고쳤는데 닻이 없다) · 회차 17
NC-17(`docs/procedure.md` 머리의 「세 검사는」에 닻이 없다). 셋 다 원천 「조각 문서 검사」이고 그때마다 그 자리에 닻만 더했다. NC-16 은 `CHECKLIST.md` 의 그 줄이 있는 채로 났다.
셋째 회차의 감사자는 `CHECKLIST.md` 한 줄과 좁은 훑기 검사(ADR 0055 의 5 를 대체하는 새 ADR) 가운데 하나를 정하자고 했다.

착공 세션이 `3d2c0ba` 에서 원천마다 명사를 한둘 골라 살아 있는 파일을 훑었다(조각 46 설계 ③ A, 어림). 명사 옆에 닻 없는 수가 선 자리는 215 곳(「회차」 · 「회」를 빼면 113)이고,
그 가운데 수가 그 원천의 지금 값과 같은 자리는 52 곳(38)이다. 52 곳 가운데 같은 원천을 든 문장은 약 11 곳이다 — `vibe-audit/README.md` 의 「감사자 6종」 둘(회차 16 · 17 의
OB-16) · 플러그인 설명 넷 · 시험과 검사의 「틀 여섯」 · 「틀 둘」 · 「감사자 6개」 따위. 나머지는 원천 자신의 줄 둘, 변조본의 바꿀 글 약 15, 다른 것을 센 같은 값 약 24 다.

## 대안

1. 갈래: **좁은 훑기 검사** / `CHECKLIST.md` 한 줄(「원천을 바꿨다면 그 원천의 명사와 수를 Grep 으로 찾아 닻을 더했다」) / 둘 다 / 두지 않는다는 결정을 이 ADR 로 남긴다.
2. 무는 범위: **`SOURCES` 의 원천 전부** / 닻을 하나라도 가진 원천만 / 감사가 짚은 원천(「조각 문서 검사」)만.
3. 찍는 꼴: **명사 옆의 수가 그 원천의 지금 값과 같을 때만** / 명사 옆의 수 전부 / 기본 가지와 견주어 원천이 바뀐 PR 에서만 옛 값을 찾는다.
4. 자리: **`verify-counts.py` 안의 새 규칙** / `scripts/` 의 새 검사를 `gates.sh` 의 `checks` 에 / `bite-gates.sh` 의 절로.
5. 오검: **구조로 빼는 것(원천을 읽는 자리 · 검사 자신)과 닫힌 예외 목록(파일 · 꼴 · 횟수 · 까닭)** / 문서 안의 표지(주석 · 꼬리표) / 명사를 좁혀 예외를 두지 않는다.
6. 지금 빠진 자리: **이 조각에서 닻 · 예외를 다 세운다 — 문장은 고치지 않는다** / 규칙만 세우고 빠진 자리는 예외로 묶어 두고 다음 조각에서.
7. PR 나눔: **구현은 B 하나** / 닻을 먼저(B) · 규칙을 뒤에(C).

## 결정

굵은 쪽 일곱.

1. **훑기 검사** — `CHECKLIST.md` 의 닻 줄이 있는 채로 NC-16 · NC-17 이 났다. 사람이 보는 줄을 하나 더해도 같은 자리를 같은 사람이 본다. 키 없이 돌아 모델 비용이 없다. 저자가
   골랐다.
2. **원천 전부** — 감사가 짚은 원천만 물면 다른 원천의 같은 꼴은 다시 감사가 회차마다 줍는다. 원천 목록과 명사 목록의 이름을 함께 견주면, 원천을 더하는 PR 이 그 원천의 명사를
   함께 정해야 초록이다. 저자가 골랐다.
3. **지금 값과 같을 때만** — 같은 원천을 든 문장이면 그 수는 원천의 지금 값과 같아야 한다. 값을 가리지 않으면 「케이스 하나」 · 「회차 17」 같은 자리까지 다 찍어 오검이 네 배를
   넘는다(215 와 52). 이 규칙이 `main` 에서 늘 돌면, 원천이 바뀌기 전의 같은 원천 문장은 이미 닻을 가져 원천이 바뀌는 PR 에서 D1 이 찍는다 — NC-15 의 꼴(옛 값으로 남은 문장)을
   이 길로 문다. 기본 가지와 견주는 꼴은 사본 트리(`bite-gates.sh` 의 변조본 — `.git` 이 없다)에서 돌지 못한다.
4. **있는 검사 안** — 원천 셈 · 닻의 자리 · 수 낱말 읽기를 `verify-counts.py` 가 이미 든다. 새 검사 파일이면 그 셋을 다시 짓거나 가져와야 하고, `gates.sh` 와 `test-gates.py`
   의 목록(ADR 0049)과 「스물여덟」 · `eval.yml` 주석의 수를 고쳐 route 수트가 한 번 돈다.
5. **구조 둘과 예외 목록** — 원천을 읽는 줄은 늘 그 값과 같으니 구조로 뺀다. 그 밖의 오검은 닻과 같은 꼴(파일 · 꼴 · 횟수)의 예외로 두고 까닭을 적는다 — 횟수가 맞지 않으면
   「예외가 낡았다」로 떨어져, 문장을 지우거나 고친 PR 이 예외를 함께 고친다. 문서 안의 표지는 살아 있는 문서 · 플러그인 파일 · 감사자 공통 절(앵커볼트)에 검사의 흔적을 남긴다.
   명사만 좁히면 「검사」 · 「감사자」처럼 꼭 필요한 명사에서 나는 오검을 지울 수 없다.
6. **이 조각에서 다 세운다** — 규칙이 처음부터 초록으로 서야 하고(ADR 0055 의 3 과 같은 까닭), 같은 원천 자리를 예외로 묶으면 예외 목록이 「같은 원천 아님」이라는 판단과
   갈린다. 지금 자리는 다 원천과 같은 값이라 닻을 더할 뿐 문장을 고칠 일이 없다 — 플러그인 파일과 판이 그대로다.
7. **B 하나** — 규칙만 먼저 실으면 지금 자리가 그 PR 을 빨강으로 만든다. 닻만 먼저 실으면 두 PR 이 다 `verify-counts.py` 를 고쳐 변조 시험이 두 번 돈다.

## 결과

- 1 · 3: 원천의 명사 옆에 지금 값과 같은 수를 닻 없이 적은 PR 은 빨강이다. 다른 값의 수 · 명사 옆이 아닌 수는 여전히 사람이 본다 — 남는 한계다. `CHECKLIST.md` 「항상」의 닻 줄
  꼬리 「닻 없는 수는 검사가 보지 않는다(ADR 0055 의 5)」는 이 ADR 에 맞게 고친다.
- 2: 원천을 더하는 PR 은 그 원천의 명사(또는 둘 수 없는 까닭)를 함께 적는다.
- 4: `gates.sh` 의 검사는 스물여덟 그대로다. 구현 PR 은 수트 지문 밖이라 route 수트가 돌지 않고, 변조 시험 지문은 바뀌어 CI 가 변조 시험까지 돈다.
- 5: 예외 목록은 닻 목록처럼 사람이 판단을 적는 닫힌 목록이다. 새 규칙의 ID 마다 변조본이 있어야 한다(ADR 0054).
- 6: 조각 46 의 B 가 지금 트리의 같은 원천 자리(설계 ③ A, 어림 약 11)에 닻을 더한다.
- 7: 조각 46 의 구현 PR 은 B 하나다.
