# 0068 — `claude-security` 팔은 하네스 밖에서 `claude -p` 로 돌고, 같은 그레이더 글을 같은 심판 모델에 세 번 물어 가르며, 여섯 회차를 사람이 다시 읽는다

2026-11-02 · 결정함 · 길은 저자가 정했다(조각 51 PR B 세션에서 세션이 셋을 대 보이고 「하네스 안에서 고쳐 보고, 안 되면 밖에서」를 추천했고 저자가 그쪽을 골랐다). 밖에서 돌리는
꼴(격리 · 심판)은 세션이 정했고 PR B 에서 저자가 본다

## 맥락

조각 51 설계는 하네스에서 돌지 않는 경쟁 팔을 「돌지 않음」으로 두고 그 축을 두 팔로 가르며, 「하네스 밖(사람이 연 세션)에서 견주는 일은 이 조각 밖」이라 적었다(설계 끝
「PR B 에서 정한 것」). 저자가 보안 축의 가장 가까운 상대를 빼지 말자고 했다.

- **하네스 안은 고칠 수 없었다** — 못 맞힌 회차의 트레이스(2026-11-02)에서 `claude-security` 스킬을 부르자 그 스킬의 셸 전처리(`` !`date -u …` ``)가 `/tmp/claude-eval-…/tmp/claude-0/cwd-…:
  Read-only file system` 으로 떨어져 스킬이 서지 않았다. 명령 자체는 날짜를 찍었다 — 하네스의 격리가 셸의 작업 위치 파일을 쓸 자리를 막는다. 같은 회차의 `Bash` 도구 호출은
  돌았다. 그 경로는 하네스 안쪽이라 이 저장소의 깃발로 바꿀 수 없다.
- **하네스 밖은 돌았다** — 같은 픽스처(`trap-local-dev-password`)를 빈 HOME 과 필요한 변수만 넘긴 `claude -p --plugin-dir <claude-security>` 로 돌리자(같은 수트 모델 ·
  같은 요청 · 같은 도구), 스캔 파이프라인이 끝까지 돌았다 — 연구원 넷 · 검증 셋, `verified`. 비용 $0.61, 2.8 분. 실린 플러그인은 `claude-security` 와 CLI 의 내장뿐이었다.

## 대안

1. 측정: **하네스 밖에서 `claude -p` — 재료 · 요청 · 모델 · 도구는 다른 팔과 같게** / 빼고 「돌지 않음」.
2. 격리: **빈 HOME 과 고른 변수만(`env` 를 비우고 경로 · 프록시 · 인증서 · 자격만)** / 이 세션의 환경 그대로 / `--bare`.
3. 채점: **같은 그레이더 글을 같은 심판 모델(`sonnet`)에 도구 없이 세 번 묻고 다수로 — 여섯 회차를 다 사람이 다시 읽는다** / 사람만 / 하네스의 심판 결과만 믿는다(쓸 수 없다).

## 결정

굵은 쪽 셋.

- 1 — 저자가 정했다. 빼면 보안 축은 감사자와 맨 Claude 의 비교만 남는다.
- 2 — 이 세션의 환경은 원격 세션의 변수(세션 주소 · 동기화 플러그인 · 자격 파일)를 들고 있어, 그대로 넘기면 이 세션의 `vibe-audit` 동기화본까지 실릴 수 있다. `--bare` 는
  구독 자격을 읽지 않아 측정 자격(`EVAL_OAUTH_TOKEN`)으로 돌 수 없다.
- 3 — 하네스의 심판은 하네스 밖 회차를 채점하지 못한다. 같은 글 · 같은 모델 · 같은 표수로 묻는 것이 가장 가깝지만, 하네스가 그레이더를 감싸는 글은 보이지 않아 같다고 말할 수
  없다. 여섯 회차라 사람이 다 읽을 수 있다 — 심판과 사람이 갈린 회차는 표에 적는다(설계 ⑤ 「심판」과 같은 규칙).

대가 — 이 팔은 측정 조건이 다른 팔과 다 같지 않다. 판정 표는 이 팔의 칸에 「하네스 밖」을 적고, 보안 축의 판정은 이 차이를 함께 든다. 밖 실행은 하네스의 비용 천장 ·
회차 수 확인 · 모델 확인을 쓰지 못해 러너가 같은 것을 스스로 센다(비용 누계로 천장 · 회차 수 · 트레이스의 모델).
