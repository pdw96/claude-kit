# 0019 — 원본 스킬의 절차 지도 링크를 커밋으로 박고, 박은 지도가 플러그인을 마지막으로 고친 커밋의 지도인지 검사가 문다

2026-10-10 · 결정함(1 ~ 4) · 제안함(5 · 6 — 세션 제안, 저자 승인 대기) · 1 ~ 4 는 저자가 착공 전 인터뷰에서 정했다

## 맥락

두 스킬은 절차 지도를 `https://github.com/pdw96/claude-kit/blob/main/docs/procedure.md` 로 가리킨다. 사본은 `sync-slice.sh` 가 출처
커밋으로 박지만(ADR 0017 의 1), 플러그인은 심는 단계가 없어 원본 그대로 `blob/main/` 이다 — 대화형 세션은 설치한 판이 아니라 `main` 의
지도를 읽는다(ADR 0017 결과 1 · 7). `vibe-slice` 0.1.0(980eff6) 뒤로 `docs/procedure.md` 를 고친 커밋이 아홉이고, 그 가운데 다섯(조각 6 · 7 ·
9 를 닫는 PR 의 커밋 넷과 조각 7 PR B)은 플러그인을 고치지 않아 판이 오르지 않았다(2026-10-10 에 셌다). 강호쟁패가 플러그인 길로 조각 1 을 착공부터
닫기까지 돌았다(조각 9 「닫으며」).

## 대안

1. 판의 지도를 읽게 하는 길: **원본 스킬의 링크를 `blob/<전체 sha>/` 로 박고 키 없는 검사가 문다** / 판마다 git 태그
   `vibe-slice-v<판>` 를 링크에 박고, 검사는 태그 이름과 `plugin.json` 판만 견주며 태그는 머지 뒤 워크플로가 만든다 / 지도의 실물을
   `vibe-slice/skills/slice-docs/` 로 옮기고 `docs/procedure.md` 를 링크로(ADR 0018 의 3 꼴) — ADR 0013 의 2 를 대체.
2. 박은 커밋의 지도를 무엇에 견주나: **`vibe-slice/` 를 마지막으로 고친 커밋의 지도 — 지도만 고친 PR 은 링크를 건드리지 않고, 플러그인을
   고칠 때 지도가 바뀌었으면 다시 박는다** / 지금 작업트리의 지도 — 지도를 고치는 PR 마다 링크를 다시 박고 판을 올린다.
3. 사본의 링크: **원본이 박은 `blob/<sha>/` 도 출처 커밋(전체 sha)으로 다시 박는다 — 조각 8 의 L1 그대로** / 원본이 박은 커밋을
   바이트 그대로 둔다.
4. 단계 5 의 실물: **강호쟁패에서 저자가 새 판으로 갱신하고, 세션이 읽는 링크와 그 커밋의 지도를 본다 — 닫는 조건** / 임시 레포의
   시험만으로 닫고 실물은 조각 나눔의 줄로 넘긴다.
5. 검사의 자리: **새 검사 `verify-map-pin.py` · 자체 시험 `test-verify-map-pin.py` · 변조본 `bite-map-pin.py` 를 `gates.sh` 가
   부른다** / `verify-manifest.py` 에 더한다 / `verify-docs.py` 의 원본 모드에 더한다.
6. 박는 꼴: **전체 sha 하나 — 짧은 sha · 가지 · 태그는 받지 않는다** / 7 자 이상의 sha.

## 결정

굵은 쪽 여섯. 1 ~ 4 는 저자가 착공 전 인터뷰에서 정했다(2026-10-10) — 넷 다 세션이 추천한 쪽이다. 5 · 6 은 세션이 저장소 규칙에서
끌어내 제안했고 착공 PR 에서 저자의 승인을 기다린다.

- 1 의 태그는 머지와 태그 만들기 사이에, 그리고 태그 워크플로가 실패하면 그 판의 링크가 열리지 않는다. 태그는 옮길 수 있어 박은 것이
  판의 지도라는 보장이 사람의 약속이고, 검사는 태그가 없는 PR 시점에 지도를 견줄 수 없다. 지도를 싣는 안은 네트워크가 필요 없지만
  지도 안의 claude-kit 경로(`gates.sh` · `docs/slices/…` · 「사례」)를 다른 레포 세션이 제 레포의 것으로 읽을 수 있고, 지도를 고치는
  PR 마다 — 닫는 PR 까지 — 플러그인 파일을 고쳐 `verify-slice-gate.py` 의 결정 문서 목록과 판 올리기가 함께 바뀐다. 커밋 박기는
  ADR 0017 의 6 과 같은 글자(전체 sha)라 사본과 플러그인이 같은 꼴을 읽는다.
- 2 의 작업트리 안은 지도를 고치는 PR 마다 링크와 판을 바꿔, 조각을 닫는 PR 도 플러그인 PR 이 된다. 마지막으로 고친 커밋에 견주면
  「설치한 판 = 그 판을 만든 커밋의 플러그인」이고 그 커밋의 지도가 바로 판의 지도다 — `CHECKLIST.md` 대로 플러그인을 고칠 때마다 판이
  오르면 판과 지도가 하나로 맞는다.
- 3 은 조각 8 의 보장(사본의 머리줄과 링크가 같은 출처)을 그대로 둔다. 원본이 박은 커밋을 두면 사본 한 파일에 커밋이 셋(머리줄 ·
  링크 · 출처)이 되고, 출처 HEAD 가 검사를 지나지 않은 가지면 박은 지도와 출처의 지도가 다를 수 있다.
- 4 는 ADR 0018 의 4 와 같은 까닭이다 — 임시 레포는 플러그인 캐시와 `claude plugin update` 를 지나지 않는다. 강호쟁패는 이 길을 지금 쓴다.
- 5 는 조각 7 · 9 의 길이다(ADR 0016 의 6 · ADR 0018 의 6) — `eval.yml` 을 고치지 않고 수트 지문 밖에서 문다. 자체 시험만 두면 시험을
  비워도 `gates.sh` 가 0 으로 끝난다. `verify-manifest.py` 는 장터와 플러그인 폴더를 맞대는 검사이고, `verify-docs.py` 는 다른 레포에
  가는 파일이라 claude-kit 의 git 역사를 읽는 판정을 싣지 않는다.
- 6 은 ADR 0017 의 6 의 까닭 그대로다 — 짧은 sha 는 저장소가 커지면 GitHub 이 열지 못한다. `sync-slice.sh` 의 L2 도 이 꼴만 더 받는다.

## 결과

- 1: 대화형 세션이 읽는 지도가 판을 따른다. 이미 설치한 0.4.1 이하는 `blob/main/` 그대로라 갱신해야 바뀐다. 대가 — 원본 스킬 두 줄이
  36 자씩 늘어 `slice-review` 호출 시 예산 여유가 93 에서 57 로 준다. 링크는 여전히 네트워크로 읽는다.
- 2: 지도만 고친 PR 은 그대로 지나간다. 지도와 플러그인을 한 PR 에서 함께 고치면 커밋이 둘 든다 — 지도를 고친 커밋, 그 커밋을 박은 커밋.
  링크를 고친 뒤 가지를 다시 쓰면(rebase · amend) 박은 커밋이 조상이 아니게 되어 떨어진다. 대가 — 판이 오르지 않은 채 플러그인을 고치면
  검사는 지나가도 설치한 판과 지도가 갈린다 — 판 올리기는 `CHECKLIST.md` 가 사람에게 든다.
- 3: `sync-slice.sh` 의 L2 가 `blob/<전체 sha>/` 를 받고 L1 이 그것도 출처로 바꾼다. ERP 의 사본은 다시 심어도 diff 가 조각 8 과 같다.
- 4: 저자가 단계 5 에서 강호쟁패의 `vibe-slice` 를 갱신한다. 그 레포에 커밋은 없다.
- 5: `gates.sh` 의 끝 개수가 열여덟에서 스물하나가 된다. 대가 — 변조본이 `eval.yml` 과 `gates.sh` 로 더 갈린다(조각 나눔 「게이트 변조본을
  수트 지문 밖으로」).
- 6: 짧은 sha 를 박은 원본은 `sync-slice.sh` 가 멈추고 검사가 떨어진다.
