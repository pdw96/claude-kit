# 0067 — 맞대기의 플러그인 팔은 요청 머리에 그 도구를 부르는 한 줄을 붙이고, 「플러그인 없음」은 중립 요청 그대로 따로 돈다 — ADR 0066 의 2 를 대체한다

2026-11-02 · 결정함 · 세션이 조각 51 PR B 의 시험 회차를 보고 정했다. 저자는 PR B 에서 본다

## 맥락

ADR 0066 의 2 는 세 팔에 같은 중립 요청을 주고(도구 이름을 부르지 않는다) 떴는지를 점수 밖에서 세기로 했다. 「플러그인 없음」 팔은 하네스의
`--ablation with-without` 이 `vibe-audit` 팔과 같은 요청으로 함께 돌렸다(ADR 0066 의 1).

PR B 의 시험 회차(2026-11-02, `claude-sonnet-5-5`, 회차마다 `--runs 1` · `2`)에서 경쟁 플러그인이 한 번도 뜨지 않았다.

| 팔 | 케이스 | 맞힘 | 떴는가 | 비용($) |
|---|---|---|---|---|
| `vibe-audit` | `trap-local-dev-password` | 1/1 | 1/1 | 0.1443 |
| (기준 팔) 플러그인 없음 | `trap-local-dev-password` | 0/1 | — | 0.0632 |
| `claude-security` | `trap-local-dev-password` | 0/1 | 0/1 | 0.0659 |
| `pr-review-toolkit` | `recall-commit-after-response` | 1/1 | 0/1 | 0.1151 |
| `pr-review-toolkit` | `trap-slice-scope` | 0/2 | 0/2 | 0.2729 |

뜨지 않은 회차의 최종 응답은 「설치된 리뷰 도구는 쓰지 않았다 — 저장소가 작아 직접 읽는 편이 빨랐다」고 적었다. 그 팔은 플러그인이 아니라 맨 Claude 를 쟀다 —
비용도 「플러그인 없음」과 같은 크기다. 경쟁 쪽의 설명은 리뷰를 청할 때가 아니라 코드를 쓴 뒤 · PR 앞(`pr-review-toolkit`)이나 「Claude Security 로」라고 부를
때(`claude-security`)를 든다. `vibe-audit` 의 감사자 설명은 이런 요청을 먼저 받게 썼다. 중립 요청은 그 차이를 잴 뿐 탐지를 견주지 못한다.

## 대안

1. **플러그인 팔은 요청 머리에 그 도구를 부르는 한 줄을 붙인다(`compare/arms.tsv`) — 본문은 세 팔에 같다. 「플러그인 없음」은 빈 플러그인을 대상으로 중립 요청
   그대로 따로 돈다(러너의 `none` 팔)** / 중립 요청 그대로 두고 「뜬 회차만」 표에 기댄다 / 중립 요청에 「설치된 도구를 먼저 써라」를 더 세게 적는다.

## 결정

굵은 쪽.

- 「뜬 회차만」 표는 경쟁 팔이 뜨지 않으면 비어 판정이 서지 않는다 — 시험에서 넷 가운데 영이었다. 더 세게 적는 문장은 어느 도구를 고를지 여전히 세션에 맡겨, 같은 중립성을
  잃으면서 뜨는 것을 보장하지 않는다. 이름을 부르면 「그 도구를 썼을 때 무엇을 잡나」를 같은 본문 위에서 잰다.
- 「플러그인 없음」을 하네스의 기준 팔로 돌리면 플러그인 팔과 같은 요청 — 이제 없는 도구를 부르는 줄 — 을 받는다. 그래서 빈 플러그인을 대상으로 따로 돌려 중립 요청을 준다.
  하네스는 대상이 있어야 돌므로 에이전트 · 스킬 · 훅이 없는 `plugin.json` 하나를 러너가 임시 폴더에 만든다.

대가 — 맞대기는 트리거를 재지 않는다. 「알아서 뜨는가」는 route 수트가 `vibe-audit` 만 잰다. 위의 시험 표는 경쟁 쪽이 중립 요청에서 뜨지 않았다는 관찰로만 남는다 —
회차가 다섯이라 판정이 아니다.

## 결과

- ADR 0066 의 2 를 대체한다. 0066 의 1 의 「플러그인 없음은 `with-without` 이 함께 돌린다」도 이 결정으로 바뀐다 — 팔은 넷(`vibe-audit` · `none` · 경쟁 둘)이고 다 `--ablation none` 이다.
- 조각 51 설계 끝 「PR B 에서 정한 것」이 러너의 팔 · 비용 천장 · 부르는 줄을 든다.
