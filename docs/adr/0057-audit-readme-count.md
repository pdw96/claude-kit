# 0057 — 감사자 README 의 모호한 「셋」은 지우고 표를 가리킨다

2026-10-29 · 결정함 · 1 은 저자가 조각 44 의 착공 세션에서 정했다(세션이 갈래 넷을 보이고 물어, 저자가 세션이 추천한 쪽을 골랐다). 2 는 저자가 조각 43 의 닫는
세션에서 정했다. 3 은 세션이 제안했고 착공 PR 에서 저자가 본다

## 맥락

`vibe-audit/README.md` 「이 감사자들은 감사받는가」의 「케이스 스물여섯이 셋을 잽니다.」 바로 아래 표는 두 줄(판정 · 트리거)이다. 표를 세운 `75d17c5`(2026-09-24)부터
「셋」이었고 그때도 표는 두 줄이었다. 「재는 것」 칸의 「오검율과 판정의 근거」 · 트리거를 셋으로 센 것으로 읽을 수 있지만 그렇게 적힌 곳은 없다. 조각 42 의 PR C 가
찾고 `audit-internal` 회차 13 이 OB-12 로 냈다. 「스물여섯」은 `verify-counts.py` 의 닻 `케이스 {N}이 셋을` 이 문다 — 닻의 꼴이 「셋을」을 글자로 든다. 플러그인의
파일이라 고치면 `vibe-audit` 판을 올린다(ADR 0013). 조각 나눔의 줄은 「문장을 고칠지 · 표에 줄을 더할지 · 「셋」을 지울지」를 꺼내는 조각에 맡겼다.

## 대안

1. 「셋」을: **지운다 — 수 없이 아래 표를 가리킨다** / 「둘」로 고치고 README 표의 줄 수를 세는 새 원천(`rows`)에 닻을 단다 / 표에 회수율 줄을 더해 셋으로 맞춘다 /
   「오검율 · 판정의 근거 · 트리거 반응 셋」으로 무엇인지 밝힌다.
2. 언제: **이 조각으로 따로 낸다** / 다음에 `vibe-audit` 판을 올리는 조각에 함께 싣는다.
3. 판: **끝자리 — 0.4.6** / 가운데 자리 — 0.5.0.

## 결정

굵은 쪽 셋.

1. **지운다** — 표의 줄은 표가 보인다. 수를 남기면 닻 하나와 원천 하나가 늘고, 줄이 하나 늘 때마다 문장을 함께 고쳐야 한다. 회수율 줄을 더하면 회수율 케이스가
   「스물여섯」 밖이라 문장을 다시 써야 하고 README 의 범위가 넓어진다 — 회수율은 `vibe-audit/evals/README.md` 「회수율」이 든다. 무엇인지 밝히면 뜻으로만 가리는 수가
   되어 닻을 못 대고, 처음 쓴 뜻이 그것이었다는 근거도 없다. `CHECKLIST.md` 는 새로 적는 수에 닻을 더하거나 수를 적지 않고 원천을 가리키라고 한다(ADR 0055 의 5) — 이
   결정은 원천(표)을 가리키는 쪽이다. 저자가 골랐다.
2. **따로 낸다** — 다음에 판을 올릴 조각이 정해지지 않았고, 모호한 문장은 감사가 두 번 짚었다. 판을 올려 route 수트가 한 번 도는 것 말고 드는 것이 없다. 저자가
   조각 43 의 닫는 세션에서 이 줄을 다음 조각으로 골랐다.
3. **끝자리** — 고친 것이 문서 한 문장이고 감사자 · 커맨드 · 검사기의 동작은 그대로다. 조각 40 의 닫는 PR 이 README 고침으로 0.4.4 → 0.4.5 를 올린 것과 같다.

## 결과

- 1: README 의 그 문장은 케이스 수만 들고, `verify-counts.py` 의 닻은 꼴 글자만 바뀐다(닻 · 원천의 수는 그대로). 표에 줄이 늘거나 줄어도 그 문장은 낡지 않는다.
  회차 13 의 OB-12 가 짚은 자리가 닫힌다.
- 2: 조각 44 의 구현 PR 하나에서 route 수트가 한 번 돈다(`route-*` 10 × 3 회) — `vibe-audit/.claude-plugin/plugin.json` 이 수트 지문에 든다.
- 3: 이미 설치한 레포는 `claude plugin update` 로 새 README 를 받는다. 클라우드 레인의 사본에는 README 가 가지 않는다.
