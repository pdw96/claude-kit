# 0079 — `/audit-brief` 커맨드는 제외 경로를 적지 않고 `verify-brief.py` 의 `DEFAULT_EXCLUDE` 를 읽어 쓰며, 검사기를 못 찾으면 멈춘다

2026-11-09 · 결정함 · 1 ~ 3 은 저자가 조각 60 의 착공 세션에서 정했다(세션이 갈래마다 추천을 앞에 두고 물어, 저자가 셋 다 추천한 쪽을 골랐다). 4 ~ 7 은 세션이 정했고 착공 PR 에서
저자가 본다

## 맥락

- **두 벌** — `/audit-brief` 커맨드 본문(`vibe-audit/commands/audit-brief.md:36-37`)이 브리핑 · 기록 작업본의 세 경로를 pathspec 으로 적는다 — `':(top,exclude).claude/audits'` ·
  `':(top,exclude).claude/briefs'` · `':(top,exclude).claude/audit-brief.md'`. 검사기 `vibe-audit/scripts/verify-brief.py:44` 의 `DEFAULT_EXCLUDE` 가 같은 세 경로를 든다. 조각 55 가
  `DEFAULT_EXCLUDE` 를 첫 자리로 두고 `scripts/verify-counts.py` 가 읽게 했고(ADR 0074 의 2), 커맨드 쪽은 조각 나눔의 줄로 넘겼다(ADR 0074 의 6). 조각 59 설계 ③ A 가 이 쌍을 「안」 —
  무엇을 diff 에서 빼는지 정하는 설정 — 으로 갈랐다(ADR 0078 의 1).
- **갈리면** — 커맨드가 덜 빼면 브리핑에 작업본이 담기고, 더 빼면 변경이 빠진다. `verify-brief.py` 는 그것을 git 과 견줄 때 불일치로 잡지만, 갈린 경로에 git 이 보는 파일이 있을 때만이다.
  커맨드는 세 자리를 `.gitignore` 에 두라고 알린다(「남기는 것」 끝). 그렇게 두면 갈린 경로의 작업본은 추적 안 된 파일 목록에도 나오지 않아 갈려도 말이 없다. 그래서 ADR 0049 의
  「갈리면 떨어지는 두 벌」로 보기에 약하다(ADR 0074 의 6).
- **커맨드와 검사기는 늘 함께 간다** — 플러그인은 `vibe-audit/` 를 통째로 싣고, 사본 심기(`scripts/sync-agents.sh`)는 `agents/*.md` · `commands/*.md` · `scripts/*.py` 를 한 묶음으로
  심는다. 커맨드는 이미 검사기의 두 자리(사본 `.claude/scripts/verify-brief.py` · 플러그인 폴더의 `scripts/verify-brief.py`)를 적고, 검사 PASS 전에는 감사자를 부르지 말라고 한다.
- **pathspec 의 꼴** — 검사기는 기본 경로와 `--exclude` 를 다 `:(top,literal,exclude)` 로 뺀다(`verify-brief.py` 의 `pathspec`). 커맨드는 기본 셋을 `:(top,exclude)`, 따로 둔 대장을
  `:(top,literal,exclude)` 로 뺀다. 세 경로에 와일드카드 글자가 없어 지금은 같은 집합이다.
- **알려진 셋째 자리** — `scripts/test-verify-brief.py:34` 의 `SPEC` 은 시험이 커맨드를 흉내 내는 기대값이다. ADR 0074 의 맥락이 ADR 0049 의 예외로 적었다.

## 대안

1. 두 벌: **커맨드가 상수를 가리킨다 — 커맨드는 경로를 적지 않고 `DEFAULT_EXCLUDE` 를 첫 자리로 쓴다** / 고치지 않고 `CLAUDE.md` 의 예외(갈리면 떨어지는 두 벌)에 넣는다 / 둘을 견주는
   시험을 더해 갈리면 늘 떨어지는 두 벌로 만든다.
2. 가리키는 법: **커맨드 글이 검사기 파일의 `DEFAULT_EXCLUDE` 한 줄을 읽어 pathspec 을 만들게 한다** / 검사기에 pathspec 을 찍는 옵션을 더하고 커맨드가 그 출력을 쓴다.
3. 검사기를 못 찾을 때: **멈추고 알린다** / 빼지 않고 모으고 머리에 「제외 목록을 못 읽음」을 적는다.
4. pathspec 의 꼴: **기본 셋도 검사기처럼 `:(top,literal,exclude)`** / 지금처럼 기본 셋은 `:(top,exclude)`.
5. 자리 · 판: **커맨드 본문과 `vibe-audit` 판(0.4.8 → 0.4.9)만 고친다 — 검사기 · 시험 · 사본은 그대로** / 시험의 `SPEC` 도 `DEFAULT_EXCLUDE` 에서 만들게 고친다 / 사본을 다시 심는다.
6. 커맨드가 만드는 자리의 이름: **그대로 둔다 — 브리핑 · 기록 · 옮긴 브리핑의 자리는 커맨드가 제 일의 대상으로 적는 이름이다** / 그 이름도 상수를 가리키게 고친다.
7. 감사 회차: **닫기 전 `audit-internal` 하나** / `audit-internal` · `audit-quality` 둘 / `audit-contract` 를 더한다.

## 결정

굵은 쪽 일곱.

- 1 — 저자가 정했다. 첫 자리는 ADR 0074 의 2 가 이미 `DEFAULT_EXCLUDE` 로 정했고 `verify-counts.py` 가 읽는다. 커맨드가 그것을 가리키면 갈릴 둘째 자리가 없어 시험도 예외도 들지 않는다.
  예외로 넣으면 「갈리면 떨어진다」는 예외의 조건을 이 쌍에 맞춰 넓혀야 한다. 견주는 시험은 새 실패 조건이고, 이 쌍은 갈린 적이 없어 들 새어 나간 결함이 없다(`CLAUDE.md` 「새 장치는 새어
  나간 결함에만」). 대가 — `vibe-audit` 판이 오르고, 수트 지문 · 변조 시험 지문이 움직여 구현 PR 의 CI 가 route 수트와 변조 시험을 한 번 돈다.
- 2 — 저자가 정했다. 커맨드는 모델이 읽고 따르는 글이고, 검사기의 자리는 이미 그 글에 있다. 상수 한 줄을 읽는 것은 검사기 · 시험 · 변조 시험을 건드리지 않는다. 옵션을 더하면 기계가 만들어
  옮겨 적기 틀림이 없지만, 스크립트 · 시험을 고치고 셸마다 다른 받는 법(NUL · 줄)을 커맨드에 적어야 한다. 대가 — 모델이 상수를 잘못 읽으면 브리핑이 갈린다. 그것을 잡는 것은 지금과 같은
  `verify-brief.py` 대조뿐이다(맥락 「갈리면」).
- 3 — 저자가 정했다. 제외 목록이 검사기에 있으므로 검사기를 못 찾으면 무엇을 뺄지 모른다. 빼지 않고 모은 브리핑은 지난 기록 · 브리핑을 담을 수 있고 대조도 못 한다 — 근거로 쓸 수 없는
  브리핑이다. 플러그인과 사본 심기는 둘을 함께 싣기 때문에, 못 찾는 것은 설치가 깨진 꼴이다. 대가 — 「검사기를 못 찾으면 `검사:` 에 적고 감사자에게 알린다」는 지금의 길이 사라진다. 검사기를
  찾았는데 돌리지 못한 경우(파이썬이 없는 따위)의 「못 돌림」은 남는다. 이 멈춤은 커맨드의 행동이고 게이트가 아니다 — 새 실패 조건이 아니다.
- 4 — 커맨드가 검사기와 같은 꼴로 빼야 상수 하나가 두 쪽에서 같은 집합을 뜻한다. 앞으로 상수에 와일드카드 글자가 든 경로가 와도 두 쪽이 같게 읽는다. 지금의 세 경로에서는 집합이 같다.
- 5 — 시험의 `SPEC` 은 ADR 0049 의 예외로 이미 적힌 자리이고, 고치면 키 없이 도는 시험이 바뀌어 이 조각의 일이 넓어진다. 사본은 다시 심기에서 따라온다 — 사본 레포는 그때까지 옛 커맨드를
  읽는다. 판은 `CHECKLIST.md` 「플러그인의 파일을 고쳤다면」이 요구한다.
- 6 — 커맨드는 브리핑을 `.claude/audit-brief.md` 에 쓰고, 기록을 `.claude/audits/` 에 남기고, 브리핑을 `.claude/briefs/` 로 옮긴다. 이것은 제 일의 대상이고 「무엇을 뺄지」의 열거가 아니다 —
  `DEFAULT_EXCLUDE` 는 그 자리들을 뺀다(ADR 0074 의 2 「그 경로를 만드는 쪽은 커맨드이고 그 짝인 `verify-brief.py`」). 그 이름까지 상수로 돌리면 커맨드가 제 일을 읽기 어려워진다. 대가 —
  커맨드가 자리를 옮기면 같은 PR 이 `DEFAULT_EXCLUDE` 를 고쳐야 하고, 그것을 무는 검사는 없다.
- 7 — 대장의 NC-43 · NC-44 · NC-45 가 고침으로 다음 `audit-internal` 회차를 기다린다. 바뀌는 것은 커맨드가 규칙 5(ADR 0073 의 5 · ADR 0078)를 지키는가 — 담당 표의 「문서에 적은 규칙 대비
  실제 코드」다. 검사 · 변조본 · 평가셋이 바뀌지 않아 `audit-quality` 는 고르지 않는다. 커맨드의 인자 · 브리핑 모양이 그대로이고, 검사기 없는 설치는 플러그인 · 사본 심기가 만들지 않는 꼴이라
  `audit-contract` 도 고르지 않는다. 새 장치의 꼴을 더하거나 고치지 않아 상시 회차도 걸리지 않는다.

대가 — 커맨드를 따르는 모델이 상수를 읽는 한 걸음이 는다. 그 걸음이 틀린 것은 평가가 재지 않는다 — 커맨드 본문을 쓰는 평가 케이스가 없다.

  두고 못 찾으면 멈춘다. 셋째 단계의 「검사기를 못 찾으면」 줄을 고친다.
