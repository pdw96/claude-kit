# 0091 — 감사자 넷을 은퇴시킨다 — 파일을 지우고, 케이스를 넷으로 가르고, 공통 절을 고치며, #257 위에 쌓아 연다

2026-11-16 · 결정함 · 1 은 저자가 조각 71 의 판정표를 보고 정했다(2026-11-16 인터뷰). 2 · 3 · 4 · 7 은 저자가 조각 72 의 착공 세션에서 정했다(세션이 추천을 앞에 두고 물어, 저자가 넷 다 추천한 쪽을
골랐다). 5 · 6 · 8 · 9 는 세션이 정했고 착공 PR 에서 저자가 본다

## 맥락

- 조각 71 의 측정 — 맥락 한 줄을 레포에 둔 일반 도구가 결함 찾기 18/18(`vibe-audit` 17/18), 함정 5/6(`vibe-audit` 6/6). 미리 박은 기준(ADR 0090 의 3)이 `audit-quality` · `audit-contract` ·
  `audit-secrets` 의 은퇴를 권했다. `audit-ops` 는 기준이 가르지 않았다.
- 감사자 이름 · 플러그인 구성 · 공통 절 문구는 앵커볼트다(`CLAUDE.md`). 공통 절은 사본이 글자 단위로 견준다(`verify-copy.py`).
- 은퇴 감사자를 태우는 케이스가 서른셋 가운데 열넷이고, 공통 절을 재는 일곱이 `audit-secrets` 를 태운다(조각 72 설계 ③).
- `INTENT.md` What 이 「감사자 여섯」을 든다. `scripts/verify-counts.py` 가 그 수를 `vibe-audit/agents/audit-*.md` 의 파일 수에 묶는다.
- 의존 조각 「덜어내기」는 `진행` 이다(PR #257 드래프트).

## 대안

1. 은퇴 대상: **`audit-secrets` · `audit-quality` · `audit-contract` · `audit-ops`** / 기준이 권한 셋만 / 더 잰 뒤.
2. 파일: **지운다 — 되돌릴 자리는 태그 `v-archive-2026-11`** / `vibe-audit` 밖으로 옮겨 글을 남긴다.
3. 케이스: **지움 · 옮김 · 좁힘 · 그대로로 가른다 — 은퇴 감사자만 재는 것은 지우고, 공통 절을 재는 것은 태우는 감사자를 옮기고, 그레이더의 은퇴 이름은 뺀다** / 은퇴 이름이 든 케이스를 다 지운다 /
   수트에서 빼고 다 맞대기 재료로.
4. 공통 절: **은퇴 이름을 빼도록 고친다 — 사본은 다시 심을 때 맞춘다** / 이름을 두고 한계로 적는다.
5. 넘길 곳: **README 의 안내 — 보안 → `/security-review`, 계약 · 품질 → `pr-review-toolkit` · `code-review`, 운영 → `vibe-audit` README 의 배포 전 체크리스트. 지도 단계 5 는 그 체크리스트를 든다** /
   지도가 밖 도구를 맡는 도구로 든다 / 넘길 곳을 적지 않는다.
6. 맞대기: **지운 케이스 넷의 픽스처를 `compare/` 로 옮기고, `vibe-audit` 팔은 남는 축(internal · data)만 돈다** / 그 케이스를 맞대기에서도 뺀다.
7. 순서: **착공을 #257 위에 쌓아 연다(base `claude/trim-measure`) · 의존 칸은 `—`, 구현은 착공 머지 뒤** / 의존을 「덜어내기」로 두고 문서 대조 검사(S6)의 실패를 받는다 / 「덜어내기」를 닫은 뒤 착공.
8. 의도 고침: **PR A 와 함께** / 착공 PR 에서.
9. 감사 회차: **닫기 전 `audit-internal`** / `audit-internal` · `audit-data`.

## 결정

굵은 쪽 아홉.

- 1 — 저자가 정했다(조각 71 설계 끝 2026-11-16 항목). 셋은 ADR 0090 의 3 (나)를 따르고, `audit-ops` 는 저자 판단이다. 남는 것은 `audit-internal` · `audit-data` 다. 의도 What 이 바뀌므로 마스터플랜
  「범위 변경」에 적는다. 대가 — 보안 · 계약 · 품질 · 운영을 이 저장소가 더는 재지 않고, 보안 · 품질 축은 측정 없이 은퇴한다(조각 71 eval-log 「한계」).
- 2 — 저자가 정했다. 플러그인이 읽지 않는 글을 남기면 고칠지 말지가 다시 묻는 자리가 된다. git 역사와 태그가 되돌릴 자리다. 대가 — 은퇴한 글을 보려면 태그를 연다.
- 3 — 저자가 정했다. 은퇴 감사자만 재는 케이스는 잴 대상이 없다. 공통 절은 남는 감사자도 들므로 그것을 재는 케이스는 태우는 감사자만 바꾸면 같은 것을 계속 문다 — 「있는 규칙이 같은 것을 계속 물게 하는
  고침」이다(`CLAUDE.md` 「새 장치는 새어 나간 결함에만」). 지움은 장치를 걷는 일이다. 대체가 아니다 — ADR 0076 의 7 은 새 규칙을 이미 선 장치에 소급해 증거를 다시 가르는 일을 막는다. 여기서는 증거를
  다시 가르지 않는다. 앵커볼트 결정(1)으로 잴 대상이 사라져 케이스가 따라 나간다. 대가 — `CLAUDE.md` 의 「이미 선 장치는 걷지 않는다」를 글대로 읽는 세션에게 이 조각은 예외로 보인다. 그 줄을 고칠지는
  닫기 전 `audit-internal` 회차와 저자가 본다.
- 4 — 저자가 정했다. 없는 감사자를 가리키는 공통 절은 받는 사람에게 틀린 넘김을 준다. 사본(ERP · 강호쟁패)은 심은 커밋(`ddcd21f`) 기준으로 견주므로 이 고침으로 떨어지지 않는다. 사본 레포는 고치지
  않는다(`INTENT.md` Not 4). 대가 — 다시 심는 날 사본의 공통 절이 한꺼번에 바뀐다.
- 5 — 절차는 밖 도구에 기대지 않는다(`INTENT.md` Not 3). 그래서 지도는 이 저장소의 README 체크리스트를 들고, 밖 도구는 README 의 안내로만 둔다. 대가 — 체크리스트는 사람이 본다. 감사자처럼 근거를
  모아 주지 않는다.
- 6 — 조각 71 의 맞대기 재료를 버리지 않는다. 러너는 픽스처를 출처 칸에서 읽으므로 출처를 `compare/` 로 바꾸면 그대로 돈다. `vibe-audit` 팔에 은퇴한 축의 줄이 없으면 그 케이스를 건너뛴다.
  대가 — `vibe-audit` 팔과 다른 팔의 케이스 수가 갈린다.
- 7 — 저자가 정했다. 은퇴 결정이 #257 에만 있어 착공을 `main` 위에 열면 그 근거를 가리킬 수 없다. 이 조각이 기대는 것은 「덜어내기」의 닫기(감사 회차 · `## 닫으며`)가 아니라 그 설계 끝에 적힌
  저자의 답이므로 조각 나눔의 의존 칸은 `—` 로 두고 근거는 목표 칸과 요구사항에 적는다 — 그래서 문서 대조 검사의 S6(진행 조각의 의존은 `닫힘`)이 이 줄을 묻지 않는다. 착공 PR 은 #257 이 머지되면
  base 를 `main` 으로 바꾸고, 구현 PR 은 착공 PR 이 머지된 뒤에 연다. 대가 — 「덜어내기」가 닫히기 전에 이 조각이 서고, 그 닫기가 이 조각을 기다리지 않는다.
- 8 — `verify-counts.py` 는 의도의 감사자 수를 파일 수에 묶는다. 착공 PR 에서 의도를 고치면 파일은 여섯인데 의도는 둘이라 게이트가 떨어진다. 범위 변경의 줄은 착공 PR 이 먼저 적고, 의도의 글은 파일과
  함께 PR A 가 고친다. 대가 — 착공 머지와 PR A 사이에 의도와 범위 변경 기록이 갈린다.
- 9 — 이 조각은 케이스 · 그레이더를 빼고 검사가 맞출 값을 바꿔 실패 조건을 고친다 — 상시 회차다(`CLAUDE.md` · ADR 0084). `audit-data` 는 바뀌는 것(감사자 · 수트 · 문서)이 담당과 닿지 않는다.

대가 — 은퇴는 되돌리기 비용이 크다. 다시 들이려면 태그에서 글을 꺼내고 케이스를 다시 세워야 한다.
