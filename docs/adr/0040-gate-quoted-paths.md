# 0040 — 관문 검사는 바꾼 파일의 경로를 `-z` 로 받고, ERP 사본을 이 조각에서 다시 심는다

2026-10-19 · 결정함 · 넷 다 저자가 착공 인터뷰에서 정했다(#107 이 열린 뒤) — 다 세션이 추천한 쪽이다. 1 은 저자의 요청 글이 「사용자 git 설정에
기대지 않는 쪽」을 조건으로 두 길을 제안했고 세션이 재현으로 `-z` 를 추천했다. 2 는 요청 글(「끝난 뒤 pdw96/ERP 에 다시 심는다」)이 든 쪽이다

## 맥락

`verify-slice-gate.py` 는 바꾼 파일을 `git diff --name-only` · `git ls-files --others` 의 줄로 받는다. git 은 기본 설정(`core.quotepath=true`)에서
ASCII 밖의 글자가 든 경로를 따옴표로 감싸 8진수로 이스케이프해 내고, `core.quotepath=false` 여도 따옴표 · 역슬래시 · 제어 문자(줄바꿈)가 든 경로는
여전히 감싼다. pdw96/ERP#116 의 한글 조각 폴더 · ADR 이 그래서 결정 문서로 읽히지 않았다 — 결정 문서만인 착공이 G2 로 떨어지고, 구현이 섞인 착공은
G1 을 지나간다(조각 29 요구사항 「문제」).

ERP 는 스킬 사본(`.claude/skills/`)을 쓰므로 원본을 고쳐도 다시 심기 전에는 그 레포의 검사가 그대로다. 조각 28 은 ERP 다시 심기를 그 레포의 다음
`sync-slice.sh` 에 맡겼고(그 요구사항 하지 않을 일 5), ERP 가 #114 로 직접 심었다.

## 대안

1. 경로를 받는 법: **`diff` · `ls-files` 를 `-z` 로 불러 NUL 로 가른다** / `git()` 도우미가 부르는 git 마다 `-c core.quotepath=false` 를 붙인다 /
   줄로 받고 따옴표 · 8진수 이스케이프를 풀어 읽는다.
2. ERP 사본: **이 조각의 C 로 다시 심는다** / 그 레포의 다음 `sync-slice.sh` 에 맡긴다.
3. UTF-8 모드와 로케일 강제를 다 끈 POSIX 로케일에서 한글 경로를 git 인자로 넘기기: **범위 밖 — 알려진 한계** / 이 조각에서 인자를 UTF-8 바이트로 넘겨 막는다.
4. 마스터플랜의 조각 폴더와 커밋된 경로의 유니코드 정규형(NFC · NFD)이 다를 때: **범위 밖 — 알려진 한계** / 이 조각에서 견주기 전에 NFC 로 맞춘다.

## 결정

굵은 쪽 넷.

- 1 은 `-z` 가 git 의 따옴표 처리를 통째로 비켜 가기 때문이다. `core.quotepath=false` 는 ASCII 밖의 글자만 풀고 줄바꿈 · 따옴표가 든 경로는 여전히
  감싼다 — 이 세션이 그 대안을 붙인 검사에 이름에 줄바꿈이 든 ADR 을 대어 G2 로 떨어지는 것을 봤다. 이스케이프를 풀어 읽는 것은 git 의 따옴표 규칙을
  검사가 다시 짓는 일이다. `-z` 는 바꾸는 자리가 `changed()` 하나라 변조본 하나로 물 수 있다. 기준 쪽(`git show` · `cat-file -e`)은 경로를 인자로
  받으므로 바꾸지 않는다.
- 2 는 결함이 드러난 레포가 ERP 이고, 그 레포의 착공(#116)이 설정을 바꿔 돌린 채로 머지를 기다리기 때문이다. 다시 심는 길은 #114 가 이미 밟았다 —
  사본에 특화가 없어 `--force` 로 폴더째 덮는다(ADR 0013 의 5 · 7). `INTENT.md` Not 4(사본 레포를 고치지 않는다)는 사본 안의 특화를 손으로 고치는
  것을 막는다 — 원본 → 사본 심기는 스크립트의 일이다.
- 3 은 고치기 전에도 같은 꼴이고(기준 마스터플랜의 한글 `진행` 조각 폴더를 `cat-file -e` 에 넘기는 자리) 겪지 않았기 때문이다. 한국어 Windows 는 인자를
  유니코드로 넘기고, 파이썬 3.7 뒤로 C 로케일은 UTF-8 모드 · 로케일 강제가 저절로 켜진다. 막으려면 인자를 바이트로 넘기는 길과 그 꼴을 흉내 내는
  시험 · 변조본이 더 든다.
- 4 는 겪지 않은 꼴이고, macOS 의 git 이 `core.precomposeunicode`(기본 켜짐)로 경로를 NFC 로 맞추기 때문이다. 맞추려면 기준 쪽(`cat-file -e` 는 바이트로 찾는다)까지 손봐야 해
  범위가 커진다.

## 결과

- 1: B 가 `verify-slice-gate.py` 의 `changed()` 와 그 도우미 하나만 바꾼다. 판정 · 인자 · 출력 모양은 그대로다. 자체 시험은 `core.quotepath=true` 를
  환경으로 박고 한글 · 줄바꿈 경로의 꼴을 갖는다. 변조본은 그 자리를 줄로 받기로 되돌린다(조각 29 설계 ⑤ V5).
- 2: C 는 pdw96/ERP 의 PR 이고 그 레포의 저자가 머지한다. B 가 claude-kit `main` 에 머지된 뒤 그 머지 커밋에서 심는다 — 원격에 없는 원본은 심지
  않는다(`sync-slice.sh` P1). 조각은 C 의 머지 뒤 닫는다.
- 3 · 4: 조각 29 설계 ② 「보장하지 않는 것」 첫째 · 둘째 줄이다. 리뷰가 이것을 짚으면 범위 밖이다. 겪으면 조각 나눔에 줄을 더한다.
