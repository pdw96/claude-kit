# 0055 — 살아 있는 파일에 적힌 수는 닻 목록으로 원천과 견준다

2026-10-28 · 결정함 · 1 ~ 3 은 저자가 조각 42 의 착공 세션에서 정했다(세션이 살아 있는 파일의 적힌 수 약 170 문장과 지금 틀린 6 · 모호한 4 를 보이고 무는
범위 · 끝 줄의 갈래 수 · 틀린 자리를 고칠 때를 물어, 저자가 세션이 추천한 쪽을 골랐다). 4 ~ 7 은 세션이 제안했고 착공 PR 에서 저자가 본다

## 맥락

`audit-internal` 이 「적힌 것과 있는 것이 같다」를 세 회차 연달아 깨진 것으로 냈다 — 회차 8 NC-6 ~ NC-9 · 회차 9 NC-10 · 회차 11 NC-12 · NC-13. 그때마다 그
자리만 고쳤다. 회차 8 은 그 가운데 둘(`vibe-audit/README.md` 의 케이스 수 · `verify-budget.py` 주석의 값)을 키 없이 물 수 있다고 적었고, 회차 9 · 11 은 검사를
조각 나눔에 세울지 정하자고 했다. 회차 11 은 끝 줄에서 묶음 안 갈래의 수 낱말(「감사가 든 둘」 · 「삼키기 넷」)이 조각 41 의 「글자로 박은 수가 남지 않는다」에
드는지 판정할 수 없었다.

`main` `97a2fb6` 에서 살아 있는 파일(기록 넷을 뺀 문서 · 스크립트 주석 · 끝 줄)에 적힌 수는 약 170 문장이다(조각 42 설계 ③ A, 어림). 원천은 대부분 파일 수 ·
코드의 목록 길이와 상수 · 표의 줄 수이고, 약 10 문장은 측정 · 지난 일이다. 6 문장이 지금 틀렸고 4 문장은 무엇을 센 수인지 모호하다. 틀린 6 가운데 5 는 수트
지문에 드는 파일(`eval.yml` · `run-evals.sh` · `verify-evals.py`)에 있다. 문서의 글에 적힌 수를 읽는 검사는 없다.

## 대안

1. 무는 범위: **원천을 기계로 셀 수 있는 것 전부 — 측정 · 지난 일의 수는 날짜를 박거나 지운다** / 감사가 짚은 꼴만(케이스 수 · 검사 수 · 끝 줄, 약 20) / 원천이
   있는 수를 문서에서 지우고 원천을 가리키게 한다(검사는 끝 줄만) / 두지 않는다는 결정을 이 ADR 로 남긴다.
2. 끝 줄의 갈래 수: **수 낱말을 뺀다 — 수는 견준 합 하나만** / 갈래마다 그 꼴의 수와 견준다 / 그대로 두고 한계로 적는다.
3. 지금 틀린 자리: **이 조각에서 다 고친다 — 수트 지문 안의 것은 새 검사와 같은 PR** / 지문 밖만 고치고 지문 안의 것은 검사에서 뺀다.
4. 검사의 자리: **`scripts/` 의 새 검사를 `gates.sh` 의 `checks` 에** / `bite-gates.sh` 의 절로 / `verify-docs.py` 를 넓힌다.
5. 무는 법: **닫힌 닻 목록(파일 · 꼴 · 횟수 · 원천 셈)** / 자유 글을 훑어 「수 낱말 + 명사」를 찾는다.
6. 실패 줄: **규칙 ID 를 찍고 ID 마다 변조본을 정적으로 대조한다(ADR 0054 의 N1 · R)** / 자유 글로 찍는다.
7. PR 나눔: **B(수트 지문 밖의 고침 · 끝 줄) · C(새 검사 · 목록 · 지문 안의 고침)** / 하나로 / 고침을 다 먼저 한 PR 로.

## 결정

굵은 쪽 일곱.

1. **셀 수 있는 것은 다 문다** — 감사가 짚은 자리만 물면 나머지 약 150 문장은 감사가 회차마다 손으로 줍는다. 지우기는 「감사자 여섯」 · 「틀 여섯」처럼 읽는
   사람에게 뜻이 있는 수까지 문서에서 뺀다. 원천이 측정 · 지난 일인 수는 기계로 견줄 원천이 없어 날짜 · 커밋을 박아 지난 일로 읽히게 하거나 지운다. 저자가 골랐다.
2. **갈래 수는 낱말을 뺀다** — 갈래마다 원천(고리의 길이 · 주석 아래의 줄 수)을 세우면 자리마다 닻이 따로 들고, 한 곳은 갈래가 겹쳐 따로 세면 13 이고 견준 합은
   11 이다. 갈래의 이름은 남겨 무엇이 돌았는지는 읽힌다. 조각 41 의 「끝 줄에 글자로 박은 수가 남지 않는다」가 갈래까지 닿는다. 저자가 골랐다.
3. **새 검사가 처음부터 초록으로 선다** — `gates.sh` 의 `checks` 에 한 줄을 더하면 `eval.yml` 주석의 「스물하나」를 고쳐야 해서 route 수트가 어차피 한 번 돈다. 틀린
   다섯을 같은 PR 에 실으면 더 드는 돈이 없고, 검사에 예외를 두지 않는다. 저자가 골랐다.
4. **문서만 고친 PR 에서도 돈다** — 변조 시험 묶음(`bites`)은 변조 시험 지문이 같으면 건너뛰는데, 이 검사가 대조하는 문서는 그 지문 밖이라 문서만 고친 PR 에서 검사가
   건너뛰어진다. `verify-docs.py` 는 플러그인에 실려 다른 레포에 가고 이 저장소의 원천(케이스 폴더 · `gates.sh`)을 모른다. 그래서 `scripts/` 에 따로 두고 `checks` 에서
   부른다. 검사를 더하므로 `gates.sh` 와 `test-gates.py` 의 고정 목록을 함께 고친다(ADR 0049).
5. **닻이 판단을 고정한다** — 자유 글을 훑으면 차례 · 단계 · 이름의 수 낱말에서 오검이 나고, 어느 원천과 견줄지를 글에서 짐작해야 한다. 닻은 「이 문장의 이 수는 이
   원천」이라는 판단을 한 번 사람이 내려 적고, 닻이 꼴의 횟수를 들어 문장을 지우거나 고치면 「닻이 낡았다」로 떨어진다. 닻 없이 새로 적은 수는 지나간다 — 그 몫은
   `CHECKLIST.md` 의 한 줄과 리뷰가 진다. 끝 줄의 갈래 수 낱말(2)만은 닫힌 파일 목록 안에서 훑는다 — 거기는 견준 변수 말고 수 낱말이 없어야 하는 자리다.
6. **조각 41 의 규칙 그대로** — 새 검사는 처음 서는 검사라 출력을 정할 수 있다. 규칙 ID 를 찍으면 ADR 0054 의 「규칙마다 변조본」을 기계로 문다. ID 는 실패의 갈래마다
   하나이고 닻마다가 아니다 — 닻이 약 150 이라 닻마다 변조본을 두지 않는다.
7. **지문 밖을 먼저** — B 는 수트 지문 밖이라 route 수트가 돌지 않는다. C 의 검사는 지문 밖의 틀린 자리가 고쳐진 트리 위에서 초록으로 선다. 수트 지문 안의 파일을 C
   에만 모아 route 수트가 한 번만 돈다.

## 결과

- 1: 살아 있는 파일의 「기계로」 문장이 다 닻을 가진다. 원천을 바꾸는 PR(케이스 · 검사 · 틀을 더하거나 빼는 PR)은 그 수를 적은 문장을 함께 고쳐야 초록이다.
- 2: 끝 줄에 남는 수는 견준 값과 닻을 가진 낱말뿐이다. 회차 11 의 「문서에 없어서 판정할 수 없었던 것」 첫째가 이 결정으로 닫힌다.
- 3: 조각 42 의 C 에서 route 수트가 한 번 돈다(`route-*` 10 × 3 회).
- 4: `gates.sh` 의 검사가 스물일곱(늘 도는 것 스물둘 · 변조 시험 다섯)이 된다. 변조 시험 지문의 빼는 목록(ADR 0046)은 그대로다.
- 5: 닻 없는 새 문장은 사람이 본다 — 남는 한계다.
- 6: 새 검사의 ID 를 더하면 그 ID 의 변조본이 없을 때 빨강이다.
- 7: B 와 C 의 구현 PR 마다 변조 시험 지문이 바뀌어 CI 가 변조 시험까지 돈다(약 7 분).
