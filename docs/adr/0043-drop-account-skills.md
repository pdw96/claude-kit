# 0043 — 지운 계정 스킬의 자리를 이 저장소의 도구와 「빈자리」로 옮기고, 절차를 계정 스킬과 다른 플러그인에 기대지 않는다

2026-10-21 · 결정함 · 1 · 2 · 4 는 저자가 이 착공 세션에서 정했다(세션이 추천한 쪽이다 — 2 의 막는 범위는 착공 PR #116 이 열린 뒤 저자가 물어
세 범위 가운데 골랐다). 3 은 세션이 정했다

## 맥락

저자가 계정 스킬 넷(`project-kickoff` · `build-gate` · `separate-audit` · `ai-native-build`)을 지웠다. 절차 지도 · README · `vibe-audit/README.md` 가
그 넷을 단계의 도구로 가리키고, `INTENT.md` Not 3 은 넷을 「계정 경유로 클라우드 레인까지 닿는」 이 저장소 밖의 것으로 든다(조각 32 요구사항
「문제」).

넷이 맡던 일은 갈 곳이 갈린다. 프로젝트 층을 세우는 일은 스킬 `slice-docs` 가 이미 하고, 넘어갈 준비는 단계마다의 나가는 조건과 키 없이 무는 두
검사가, 배포 직전은 `audit-ops` 가 든다. 감사 계획 · 부적합 대장은 맡을 도구가 없다 — ERP 가 대장을 `docs/audit/` 에 손으로 세워 감사 ㊸ 까지
따라왔다. `ai-native-build` 은 본문이 없어 맡던 일을 가르지 못한다.

## 대안

1. 지운 넷의 자리: **이 저장소의 도구와 「빈자리」로 옮긴다 — 문서만 고친다** / 계정 스킬을 다시 만든다 / 그 넷을 이 저장소의 플러그인으로 들인다.
2. `INTENT.md` Not 3: **바꾼다** / 지우고 뒤의 번호를 당긴다 / 그대로 두고 이름만 뺀다. 바꾸면 막는 범위는 — 계정 스킬만 / **계정 스킬과 다른
   플러그인, Claude Code 에 딸려 오는 명령은 둔다** / 이 저장소 밖의 것은 다(Claude Code 의 명령까지).
3. 고치는 플러그인 파일(`vibe-audit/README.md`)의 판: **올리지 않는다** / `vibe-audit` 판을 0.4.2 로 올린다.
4. 남는 둘: **조각 둘로 나눠 「부적합 대장」 → 「감사 계획」 순서로, 대장은 `vibe-audit` 에** / 한 조각으로 / 대장을 `vibe-slice` 에.

## 결정

굵은 쪽 넷.

- 1 은 저자가 골랐다. 넷 가운데 둘은 같은 일을 하는 도구가 이 저장소에 이미 있고, 다시 만들 본문이 이 저장소에 없다 — 넷은 여기서 배포하지 않았다.
  들이는 것은 의도를 가장 크게 바꾸는 길이다.
- 2 는 같은 일이 되풀이되지 않게다. 지운 것은 저자의 손이지만, 어긋난 까닭은 지도가 이 저장소가 고칠 수 없는 도구에 단계를 맡긴 것이다. 지우기만
  하면 다음에 다른 바깥 도구를 같은 자리에 앉혀도 막을 말이 없다. 번호를 당기면 기록들이 인용한 「Not 4」(ADR 0040 등)가 다른 줄을 가리킨다. 이름만
  빼면 「배포하지 않는다」가 가리킬 것이 없는 말이 된다. 막는 범위는 저자가 골랐다 — 막을 것은 이 저장소가 모르게 꺼지고 지워지는 도구다.
  다른 플러그인(예: `engineering`)도 계정 · 레포에서 끄면 사라지니 계정 스킬과 같다. Claude Code 에 딸려 오는 명령(`/init` ·
  `/code-review` 따위)은 지울 수 없고, 지도가 이미 `/init` 에 기댄다(ADR 0041 의 4) — 다 막으면 그 자리를 지도에서 빼야 한다.
  판이 바뀌면 동작은 달라질 수 있다 — 그것은 이 결정이 막지 않는다.
- 3 은 그 파일을 세션이 읽어 들이지 않기 때문이다 — 플러그인이 싣는 것은 감사자 · 커맨드 · 검사기이고 README 는 사람이 GitHub 에서 읽는다. 판을
  올리지 않고 그 파일만 고친 앞선 예가 있다(`844318e` · `5cefd85`). `vibe-audit` 의 `plugin.json` 은 두 수트 지문 안이라 판을 올리면 수트가 다시
  돈다 — 감사자는 한 글자도 바뀌지 않는다.
- 4 는 저자가 골랐다. 대장이 있어야 계획이 낸 감사 결과가 쌓일 자리가 생긴다. 대장은 감사 기록(`.claude/audits/`)을 남기는 `audit-brief` 와 지난
  기록을 읽는 감사자 옆이다.

## 결과

- 1: 조각 32 의 B 가 절차 지도 0 · 4 · 5 단계의 「맡는 도구」를 고치고 「계정 스킬의 일」을 지우며, 「빈자리」에 「감사 계획」 · 「부적합 대장」을 더한다.
  README · `vibe-audit/README.md` 가 같은 말을 한다(조각 32 설계 ② D1 ~ D4). `ai-native-build` 은 이름만 빠진다.
- 2: 조각 32 의 A 가 Not 3 을 바꾸고 마스터플랜 「범위 변경」에 적는다. 지도가 맡기는 도구는 이 저장소의 플러그인 · Claude Code 에 딸려 오는 명령 · 그 레포의 CI · 리뷰다 — 이
  계정에 켜진 다른 플러그인의 스킬도 앉히지 않는다(조각 32 하지 않을 일 6).
- 3: 이미 설치한 `vibe-audit` 의 README 는 옛 문단으로 남는다(조각 32 설계 ② 「보장하지 않는 것」). 다음에 `vibe-audit` 판을 올리는 조각에서 함께 간다.
- 4: 조각 나눔에 순서 없는 두 줄 — 「부적합 대장」(의존 「계정 스킬 걷어내기」) · 「감사 계획」(의존 「부적합 대장」). 대장을 `vibe-audit` 에 두는 것은
  `INTENT.md` What 을 넓히는 일이라 「부적합 대장」의 착공이 범위 변경으로 적는다.
