# 0073 — 감사자가 거듭 청한 절차 물음 다섯에 답한다 — 검사가 읽는 글은 앵커볼트가 아니고, 닫는 PR 은 판정된 고침을 싣고, 성공 기준의 근거는 저장소에, 대체는 양쪽에, 같은 목록은 저장소 전체에

2026-11-05 · 결정함 · 1 ~ 5 는 저자가 조각 54 의 착공 세션에서 정했다(세션이 물음마다 추천을 앞에 두고 물어, 저자가 다섯 다 추천한 쪽을 골랐다). 6 ~ 9 는 세션이 정했고 착공 PR 에서
저자가 본다

## 맥락

`audit-internal` 은 저장소가 스스로 정한 규칙에 대어 판정하고, 규칙이 없는 자리는 「문서에 없어서 판정할 수 없었던 것」에 올려 저자 결정을 청한다. 다섯 물음이 회차를 넘어 되풀이됐다 —
원문과 횟수는 조각 54 요구사항 「문제」 · 설계 ③ A.

- **1 검사가 읽는 글** — `verify-counts.py` 는 README 의 절 제목을 원천의 머리 줄로 읽고 문장의 꼴을 닻으로 잡는다. `bite-gates.sh` · `bite-*.py` 의 변조본은 검사 파일의 줄을 글자 그대로 찾아
  바꾼다. 그 글을 옮기면 검사가 떨어진다(D2 · S1 따위) — 같은 PR 이 검사를 함께 고쳐 왔다. `CLAUDE.md` 「앵커볼트」는 `docs/procedure.md` 「…의 칸」의 제목과 표 서식만 든다.
- **2 닫는 PR · 구현 PR** — #167 · #170 · #173 이 닫는 PR 에 코드를 실었고 그 조각 요구사항의 「제약에서 어긋난 것」 따위에 적었다. ADR 0070 은 조각 52 의 PR C 에서 ⑥ C 밖의 것을 들이고
  하지 않을 일 2 · 3 을 넓혔다. `docs/procedure.md` 단계 3 의 나가는 조건은 「⑥ 밖의 것을 싣지 않았고」, 단계 6 은 닫는 PR 이 무엇을 실어도 되는지 말하지 않는다.
- **3 PR 본문** — 성공 기준이 「PR 본문이 출력을 든다」로 근거를 저장소 밖에 둔 조각이 여럿이다. 감사자는 읽기 전용 도구로 저장소만 읽어(`INTENT.md` Not 1) 그 줄이 회차마다 확인불가로
  남는다 — NC-19 · NC-22 가 같은 뿌리다. `docs/procedure.md` 「설계 문서의 칸」 ⑤ 는 보장의 조건 → 꼴 → 변조본의 대응을 구현 PR 본문에 두게 정했다(ADR 0039).
- **4 대체 ADR** — 0052 · 0059 · 0071 따위는 머리나 제목에 「ADR NNNN 의 k 를 대체한다」를 적었다. 0060 · 0061 · 0065 · 0070 은 앞 ADR 의 결정을 바꾸고도 그 번호를 적지 않았다. 앞 ADR
  쪽에는 어느 경우에도 줄이 없다 — 앞 ADR 을 연 사람은 바뀐 결정을 지금 결정으로 읽는다. `docs/procedure.md` 「살아 있는 문서와 기록」은 기록에 「날짜를 박은 새 항목을 덧붙인다」를 허락하고
  「ADR 은 대체 ADR」이라고만 한다.
- **5 같은 목록** — `CLAUDE.md` 머리의 「같은 목록을 두 군데 두면 갈린다」는 `AGENTS.md` 와의 사이를 말한다. 감사 회차는 그 밖의 두 벌 셋을 들었다 — `verify-counts.py` 의 `SCAN_SKIP_LOCAL` ↔
  `verify-brief.py` 의 `DEFAULT_EXCLUDE`, 프로필 틀 머리 주석 ↔ `slice-docs` 스킬의 「이미 있는 프로필에서 고치는 것」, 조각 52 설계 ③ B ↔ `run-compare.sh` ↔ `compare/README.md` 의 정답지
  낱말. 원칙의 범위가 문서에 없어 부적합으로 세지 않았다.

## 대안

1. 검사가 읽는 글: **앵커볼트가 아니다 — 바꾸면 같은 PR 이 그 검사를 고친다. `CLAUDE.md` 「가변」에 든다** / 앵커볼트다 — 「앵커볼트」에 더하고 바꾸기 전에 저자에게 묻는다.
2. 닫는 PR · 구현 PR: **둘 다 된다 — 닫는 PR 은 대장에 저자 판정이 있는 고침을 싣고 그 조각의 하지 않을 일 · 성공 기준에 묶이지 않으며 `## 닫으며` 가 그 판정을 가리킨다. 구현 PR 은 새
   ADR 이 넓히는 ⑥ 줄과 하지 않을 일의 번호를 적고 저자가 정하면 넓힌다** / 닫는 PR 만 된다 — 구현 PR 이 넘치면 조각 나눔의 새 줄 / 둘 다 안 된다 — 닫는 PR 은 문서만.
3. 성공 기준의 근거: **저장소 안 — `## 닫으며` 가 성공 기준마다 대어 본 명령과 결과의 핵심 줄을 든다. PR 몫의 대응표(꼴 → 변조본 따위)는 PR 본문 그대로** / 전부 저장소 안 — 대응표도 설계 끝
   날짜 항목에 / PR 본문이면 된다 — 확인불가를 받아들이고 호출자가 브리핑에 본문을 싣는다.
4. 대체 ADR: **양쪽에 적는다 — 새 ADR 머리에 「ADR NNNN 의 k 를 대체한다」, 앞 ADR 끝에 날짜를 박은 대체 절. 지난 사례에도 적용** / 새 ADR 머리에만 / 적지 않는다.
5. 같은 목록: **저장소 전체(문서 · 코드 · 틀 · 스킬)에 걸린다 — 새 두 벌을 만들지 않고 둘째 자리는 첫 자리를 가리킨다. 있는 셋은 조각 나눔 줄로 넘긴다** / 걸리고 이 조각에서 셋도 고친다 /
   `CLAUDE.md` ↔ `AGENTS.md` 에만.
6. 규칙의 자리: **이 저장소의 것(1 · 5)은 `CLAUDE.md`, 일반 절차의 것(2 · 3 · 4)은 `docs/procedure.md`, 사람이 볼 줄은 `CHECKLIST.md` 가 그 절을 가리킨다** / 다 `CLAUDE.md` / 다
   `docs/procedure.md`.
7. 무는 것: **새 검사를 세우지 않는다 — `CHECKLIST.md` 와 `audit-internal` 회차가 본다** / 대체 절 · 같은 목록 · `## 닫으며` 의 근거를 무는 검사.
8. 다른 레포: **`vibe-slice` 판과 지도 링크를 그대로 둔다 — 링크가 다음에 박힐 때 간다** / 이 조각이 `vibe-slice` 를 고쳐 판을 올리고 링크를 다시 박는다.
9. 지난 대체: **조각 54 설계 ③ B 의 닫힌 목록만 — 머리 · 결과에 적은 열한 쌍은 앞 ADR 쪽에, 적지 않은 넷은 양쪽에 덧붙인다** / 적지 않은 넷만 / ADR 전체를 읽어 쌍을 더 찾는다.

## 결정

굵은 쪽 아홉.

- 1 — 저자가 정했다. 앵커볼트는 되돌리기 비용이 큰 것 — 사본 레포에 퍼진 이름 · 글자 단위로 견주는 공통 절 · 다른 레포의 문서가 따르는 모양 — 이다. 검사가 읽는 글은 옮기면 그 PR 의
  게이트가 떨어져 같은 PR 이 검사를 고친다 — 비용이 그 PR 안에서 끝나고 말없이 갈리지 않는다. 「…의 칸」의 제목은 다른 레포의 틀과 문서가 따르므로 그대로 앵커볼트다.
- 2 — 저자가 정했다. 닫는 PR 의 고침은 감사가 낸 부적합을 저자가 판정한 결과다 — 판정의 주인이 저자이고 대장에 근거가 있다. 그 조각의 하지 않을 일은 조각의 범위를 정한 것이지 감사가 낸
  결함을 고치지 못하게 하는 것이 아니다. 구현 PR 의 넓힘은 ADR 0070 처럼 그 자리에서 드러난 것을 저자가 판정한 결과다 — 새 조각으로 떼면 그 PR 이 다음 조각을 기다린다. 대가 — 조각의
  경계가 저자 판정 하나로 넓어진다. 넓힌 몫은 새 ADR 이 번호로 들어 감사자가 판정할 수 있다.
- 3 — 저자가 정했다. 성공 기준은 조각을 닫는 판정의 근거라 감사자가 읽어야 한다. 대응표(꼴 → 변조본)는 시험 코드가 저장소에 있어 감사자가 코드에서 다시 볼 수 있고, 설계에 쌓으면
  ADR 0039 가 피한 일이 된다. `## 닫으며` 는 이미 성공 기준마다 「무엇에 대어 봤나」를 든다 — 그 자리에 명령과 결과의 핵심 줄을 둔다.
- 4 — 저자가 정했다. 앞 ADR 끝의 날짜 절은 「지난 항목은 고치지 않고 날짜를 박은 새 항목을 덧붙인다」 안이다 — 앞 ADR 의 결정 문장은 그대로다. 꼴은 이렇다.
  - 새 ADR — 머리(날짜 줄 아래)에 「ADR NNNN 의 k 를 대체한다」. 일부만 바꾸면 그 몫을 따옴표로 든다.
  - 앞 ADR — 끝에 `## 대체 (<YYYY-MM-DD>)` 절, 그 아래 줄마다 「- k 는 ADR MMMM 이 대체했다 — <바뀐 몫 한 구절>」. 같은 ADR 에 대체가 또 오면 새 날짜 절을 덧붙인다.
- 5 — 저자가 정했다. 갈림은 파일의 종류를 가리지 않는다 — 감사 회차가 든 셋 다 한쪽만 고쳐질 수 있는 자리다. 둘째 자리가 첫 자리를 가리키면 갈릴 것이 없다. 갈리면 떨어지는 검사가 있는
  두 벌(`test-gates.py` 의 고정 목록)은 그대로 예외다(ADR 0049). 있는 셋을 이 조각에서 고치면 코드 · 스킬 · 측정 문서를 건드려 조각이 커지고 하지 않을 일 2 를 깬다.
- 6 — 1 · 5 는 이 저장소의 스크립트 · 파일을 두고 하는 말이라 다른 레포에 가지 않는다. 2 · 3 · 4 는 조각을 나눠 진행하는 레포 어디서나 같은 말이라 절차 지도가 든다(`INTENT.md` What — 절차를
  일반형으로). `CHECKLIST.md` 는 사람이 머지 전에 보는 목록이라 줄을 두되, 규칙은 옮겨 적지 않고 절을 가리킨다 — 5 를 이 결정이 먼저 지킨다.
- 7 — 다섯 다 사람이 쓰는 글의 규칙이고, 어겨서 게이트를 지나 새어 나간 결함은 없다 — 감사자가 「문서에 없어서」로 멈춘 것이다(마스터플랜 「새 장치는 새어 나간 결함에만」). 대가 — 어겨도
  키 없이 떨어지지 않는다. `CHECKLIST.md` 와 닫기 전 `audit-internal` 회차가 본다.
- 8 — 판을 올리면 두 스킬의 링크를 다시 박고 `vibe-slice/` 를 고친다 — 고칠 스킬 문구가 없는데 판만 오른다. ADR 0019 의 2 대로 지도만 고친 커밋은 링크를 건드리지 않는다. 대가 — 다른 레포는
  링크가 다음에 박힐 때까지 옛 단계 3 · 6 과 옛 대체 규칙을 읽는다.
- 9 — 4 를 지난 사례에 걸 때 감사 기록이 든 넷만 하면 머리에 적은 열하나는 앞 ADR 쪽이 여전히 비어 4 의 「양쪽」이 서지 않는다. 열하나는 착공 세션이 「대체」로 훑어 뽑은 것이라 닫힌 목록이
  된다. ADR 전체를 읽어 적지 않은 대체를 더 찾는 일은 판단이 들어 그 자체로 감사 회차의 일이다.

대가 — 규칙은 서지만 무는 것은 사람이다. 알려진 두 벌 셋은 규칙을 어긴 채 조각 나눔의 줄로 남는다. 다른 레포는 다음 링크까지 옛 절차를 읽는다.

- 5: 조각 나눔에 「같은 목록의 두 벌 셋」 — 조각 54 착공 PR.
- 7 · 8: 조각 54 요구사항 하지 않을 일 1 · 2.
- 9: 조각 54 PR B 가 설계 ③ B 의 ADR 에 대체 절을 덧붙인다. 이 ADR 이 앞으로의 첫 사례다 — 이 ADR 은 앞 ADR 을 대체하지 않는다.
