# 0018 — 다른 레포의 문서 대조 검사는 스킬 폴더에 실은 검사를 스킬이 부르고, 원천은 틀이다

2026-10-08 · 결정함 · 여덟 다 저자가 정했다 — 1 ~ 4 는 착공 전 인터뷰, 5 ~ 8 은 착공 PR(#39)을 연 뒤의 인터뷰. 5 ~ 7 은 세션이 저장소 규칙에서 끌어내 제안했다

## 맥락

claude-kit 은 문서의 모양을 `verify-docs.py`, 착공 → 구현의 순서를 `verify-slice-gate.py` 로 `gates.sh` 에서 문다. 다른 레포에 닿는 것은
`vibe-slice` 의 스킬 둘뿐이다(ADR 0016 의 1). `verify-docs.py` 는 필수 제목을 루트의 `docs/procedure.md` 「…의 칸」 표에서 읽고 틀을
루트의 `vibe-slice/…/templates/` 에서 찾는데, 지도는 다른 레포에 가지 않는다(ADR 0013 의 2). 순서의 판정은 `slice-review` 의 문구가
들고, 그 문구를 들인 #34 의 지적 셋이 다 「검사의 보장을 문구로 옮기며 뜻이 빠졌다」였다.

틀대로 선 다른 레포는 아직 없다 — 강호쟁패(플러그인 · 대화형 · Windows · CI 없음)와 ERP(사본 · 클라우드 · 조각 문서를 쓰지 않음) 둘 다
마스터플랜이 없다(2026-10-08). `eval.yml` 「게이트가 무는가」는 `scripts/verify-docs.py` 를 경로로 읽어 스무 자리를 망가뜨리고, `eval.yml`
은 수트 지문에 든다.

## 대안

1. 다른 레포에서 검사가 도는 자리: **검사를 `vibe-slice` 의 스킬 폴더에 싣고 스킬이 부른다(`slice-docs` 는 착공 · 닫는 PR 전에,
   `slice-review` 는 가르기 전에)** / 그에 더해 그 레포의 CI 에 거는 법을 README 에 적는다 / 플러그인 훅이 push · PR 생성 전에 돈다.
2. 다른 레포 모드의 원천: **스킬 폴더의 틀 넷의 `##` 제목** / 지도 「…의 칸」 절을 스킬 폴더에 한 벌 더 싣는다 / 사본이 박은 출처 커밋의
   지도를 네트워크로 읽는다.
3. 검사의 자리와 비용: **실물을 `vibe-slice/skills/slice-docs/scripts/` 로 옮기고 `scripts/` 에 그것을 가리키는 심볼릭 링크를 둔다** /
   `eval.yml` 의 경로를 고치고 route 수트 한 번을 감수한다 / 이 조각을 미루고 「게이트 변조본을 수트 지문 밖으로」를 먼저 닫는다.
4. 단계 5 의 실물: **강호쟁패에 저자가 `slice-docs` 로 마스터플랜을 세우고 검사를 돌린다** / ERP 가 다음 단계를 착공할 때 /
   실물 없이 시험의 임시 레포로만 닫고 실물은 조각 나눔의 줄로 넘긴다.
5. 모드를 고르는 길: **인자 `--repo <루트>`** / 루트에 `docs/procedure.md` 가 있는지로 / 루트에 `vibe-slice/` 가 있는지로.
6. 다른 레포 모드의 변조본: **`gates.sh` 가 부르는 새 변조본 `bite-verify-docs.py`** / `eval.yml` 「게이트가 무는가」에 더한다 /
   자체 시험만.
7. 검사 둘을 싣는 폴더: **`slice-docs/scripts/` — `slice-review` 는 `${CLAUDE_SKILL_DIR}/../slice-docs/scripts/` 로 부른다** /
   스킬마다 제 폴더에 / 플러그인 맨 위 `vibe-slice/scripts/`.
8. `slice-review` 가 구현 PR 의 착공 머지를 볼 때: **스크립트(`verify-slice-gate.py`)의 판정에 더해, 그 조각이 기본 가지의
   마스터플랜에서 `진행` 이고 설계가 있는지를 문구로 본다** / 스크립트의 판정만 쓴다.

## 결정

굵은 쪽 여덟. 1 ~ 4 는 저자가 착공 전 인터뷰에서, 5 ~ 8 은 착공 PR(#39)을 연 뒤의 인터뷰에서 정했다(2026-10-08) — 여덟 다
세션이 추천한 쪽이다. 5 ~ 7 은 세션이 이 저장소의 규칙에서 끌어내 제안했고, 8 은 착공의 설계 ④ 가 열어 둔 것이었다.

- 1 의 CI 는 강호쟁패에 없고, 거는 일은 그 레포의 몫이라(`INTENT.md` Not 4) 적어도 무는 것이 늘지 않는다. 훅은 플러그인 길에만
  저절로 서고, 사본 길은 그 레포의 `settings.json` 을 고쳐야 한다. 스킬은 두 길에 다 닿는다 — 판정은 스크립트가 하고 문구는
  「언제 부르나」만 든다.
- 2 의 틀은 claude-kit 에서 T2 가 「…의 칸」 표와 글자 그대로 같게 문다 — 지도를 보내지 않고도 같은 원천이다. 한 벌 더 싣는 안은
  ADR 0013 의 2 를 대체하고 두 벌을 맞대는 게이트를 들인다. 네트워크 안은 `verify-docs.py` R2(네트워크를 쓰지 않는다)를 깨고,
  플러그인 길에는 박을 커밋이 없다(ADR 0017 의 7).
- 3 의 링크는 `eval.yml` 이 읽는 경로를 그대로 둔다 — 「게이트가 무는가」는 경로를 열어 읽고 사본을 쓰므로 링크를 따라간다.
  플러그인은 폴더 밖을 가리키는 링크를 거절하므로(ADR 0013 결과 6) 실물이 플러그인 안에, 링크가 바깥에 선다. 수트를 돌리는 안은
  조각 3 에서 검사를 고칠 때마다 수트가 다시 돈 그 비용이고, 미루는 안은 다른 레포의 첫 실물을 늦춘다.
- 4 의 강호쟁패는 증거(#1)가 난 레포이고 플러그인 길을 본다. ERP 는 조각 문서를 쓰지 않아 시점을 그 레포가 정한다. 임시 레포만으로는
  플러그인 캐시의 `${CLAUDE_SKILL_DIR}` 에서 검사가 도는지 못 본다. 저자가 그 PC 의 `python3` 가 3.14 임을 확인했다.
- 5 는 「모르면 지나가지 않는다」(조각 7 B2)와 같은 쪽이다. 파일 유무로 고르면 지도를 지운 claude-kit 이 O3 대신 다른 레포 모드로 넘어가
  틀을 원천으로 읽고 지나간다 — 원천이 사라진 것을 아무도 못 본다.
- 6 은 ADR 0016 의 6 과 같은 길이다 — `eval.yml` 을 고치지 않는다. 자체 시험만 두면 시험을 비워도 `gates.sh` 가 0 으로 끝나
  `CLAUDE.md` 「작업 방식」(새 검사에는 늘 떨어지는 변조본)과 어긋난다(#32 Codex 2 회차).
- 7 은 틀과 같은 길이다 — `slice-review` 가 이미 `../slice-docs/templates/` 로 틀을 읽는다. 스킬마다 두면 같은 파일이 두 벌이다.
  `vibe-slice/scripts/` 는 `sync-slice.sh` 가 `vibe-slice/skills/` 만 심어 사본 길에 닿지 않는다.
- 8 의 스크립트는 어느 조각의 구현인지 가리지 않는다(ADR 0016 의 3) — 다른 조각이 `진행` 이면 이 조각의 착공이 머지되지 않았어도
  G2 를 지나간다. 지금의 `slice-review` 는 「그 조각」을 본다. 판정만 쓰면 스킬이 지금보다 약해진다.

## 결과

- 1: 다른 레포에서 모양과 순서의 판정이 결정론이 된다. 대가 — 세션이 스킬을 부를 때만 돈다. 머지를 막는 것은 없고, 그 레포의 CI 에
  거는 일은 그 레포에 남는다. 스킬 둘을 고치므로 `vibe-slice` 의 판이 오른다.
- 2: 지도는 여전히 한 벌이다. 대가 — 원천이 그 레포에 깔린 판의 틀이라, 판이 오르며 「…의 칸」이 바뀌면 옛 판으로 쓴 `진행` 조각 문서가
  새 판에서 떨어질 수 있다.
- 3: route 수트가 이 조각의 파일로 돌지 않는다. 대가 — 저장소에 첫 심볼릭 링크가 선다. Windows 에서 `core.symlinks` 없이 클론하면
  `gates.sh` 가 떨어진다(시끄러운 실패). 다른 레포에는 링크가 가지 않는다. 「키 없는 게이트」의 두 검사는 「조각 문서 스킬」 부품의 파일이 되고,
  그것을 고치는 PR 은 `vibe-slice` 의 판을 올린다(`CHECKLIST.md`).
- 4: 단계 5 에서 저자가 강호쟁패에 마스터플랜을 세운다 — 그 레포의 커밋이다. ERP 의 사본은 다음에 심을 때 검사를 받는다.
- 5: 스킬은 어느 레포에서나 `--repo .` 를 부른다 — claude-kit 에서도 틀이 표와 같아 판정이 같고, 원본에 레포별 분기가 없다.
- 6: `gates.sh` 의 끝 개수가 열일곱에서 열여덟이 된다. 대가 — 변조본이 `eval.yml` 과 `gates.sh` 의 둘로 더 갈린다(조각 나눔 「게이트 변조본을
  수트 지문 밖으로」가 모은다).
- 7: 두 스킬이 한 플러그인 · 한 사본에 같이 가므로 `../slice-docs/` 가 늘 있다.
- 8: 순서는 스크립트가 결정론으로, 「그 조각」은 세션이 문구대로 본다. 대가 — `slice-review` 에 문구가 남아 호출 시 예산(여유 252 자)을
  두 가지가 나눠 쓴다. 넘으면 압축이 먼저다(ADR 0004).
