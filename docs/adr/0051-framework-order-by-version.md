# 0051 — `audit-data` 는 프레임워크가 정하는 실행 순서도 판으로 판정한다

2026-10-27 · 결정함 · 1 ~ 3 은 저자가 조각 40 의 착공 세션에서 정했다(세션이 앵커볼트 둘과 전수의 월 한도를 대 보이고 고칠 자리 · 예산 · 전수의 때를 물어,
저자가 세션이 추천한 쪽을 골랐다). 4 · 5 는 세션이 제안했고 착공 PR 에서 저자가 본다

## 맥락

조각 39 의 회수율 기준선은 16/18 이었고, 놓친 둘은 `recall-commit-after-response` 의 두 회차다. 둘 다 결함의 자리(`yield` 의존성 뒤의 커밋 — 응답이 나간 뒤에
돈다)를 보고 확인불가로 적었다. 근거는 「프레임워크가 언제 돌리는지는 저장소 파일로 보일 수 없다」였는데, 판은 `requirements.txt` 에 고정돼 있었다
(`docs/eval-log/2026-10.md` 「2026-10-27 · 회수율 기준선」).

`audit-data` 는 이미 체크 항목 3 에서 「먼저 엔진 · 판을 저장소에서 확인합니다 … 확인하지 못하면 확인불가」로, 판을 확인하면 그 판으로 판정하라고 적는다. 항목
4 · 5 에는 그 말이 없다. 확인불가의 규칙 자체는 공통 절 「판정은 넷이다」에 있고, 그 절은 여섯 감사자와 사본이 글자 단위로 같이 든다(`scripts/verify-copy.py`).

`audit-data` 의 호출 시 크기는 천장 11,000 에 여유 0 이다(`vibe-audit/evals/budget.txt`). 판정 케이스에 닿는 변경은 머지 전에 전수를 돌리고(`CHECKLIST.md`),
전수의 월 한도는 $20 이다(ADR 0033) — 2026-10 의 전수 합은 이미 $41.05 다.

## 대안

1. 고칠 자리: **`audit-data` 의 공통 절 밖** / 공통 절 「판정은 넷이다」(여섯 감사자 다) / 문구 대신 회수율 그레이더가 결함을 짚은 U 도 찾은 것으로 세게 /
   고치지 않고 이 ADR 로 「U 가 통과를 막으니 숨는 결함이 아니다」를 남긴다.
2. 예산: **천장 그대로, 같은 파일의 고유 절에서 줄인다** / 천장을 올린다(ADR 0004 를 새 ADR 로 대체).
3. 전수: **2026-11-01 이후 B 의 머리에서 한 번, 머지는 그 뒤** / 10 월 한도를 넘는 한 번을 허용 / 전수 없이 회수율과 관련 판정 케이스만 로컬로.
4. 재는 자: **회수율 케이스(놓친 케이스 6 회차 · 나머지 `audit-data` 셋 3 회차씩) + `audit-data` 를 지목하는 판정 케이스 둘 · 문턱 5/6** / 놓친 케이스만 /
   새 함정 케이스를 세운다.
5. PR 나눔: **B 하나(문구 · 줄임 · 측정 · 기록)** / 줄임과 문구를 두 PR 로 / 측정을 따로.

## 결정

1. **공통 절 밖, `audit-data` 만 고친다.** 놓친 증거가 `audit-data` 하나에만 있다. 공통 절을 고치면 여섯 다 예산을 다시 맞추고 사본 둘을 다시 심어야 하는데,
   다른 감사자가 같은 꼴로 미룬다는 근거가 없다. 그레이더를 바꾸면 「놓침」의 정의가 바뀌어 기준선과 견줄 수 없고, 고치지 않으면 대장에 사람에게 프레임워크
   동작을 묻는 U 가 남는다. 항목 3 이 이미 쓰는 순서(판을 먼저 확인한다)를 항목 4 · 5 에 넓히는 것이라 새 원칙이 아니다.
2. **천장은 그대로다.** 넣는 글자만큼 같은 파일의 고유 절에서 공통 절이나 다른 줄이 이미 든 말을 되풀이한 자리를 줄인다. 호출 시 크기는 감사 대상 코드와 같은
   창을 쓰고(`budget.txt` 머리), 천장은 압축이 먼저다(ADR 0004) — 한 감사자를 위해 올리지 않는다.
3. **전수는 11 월에 돈다.** 10 월은 이미 한도의 두 배를 썼다. B 의 구현 · 로컬 측정은 지금 하고, 전수와 머지만 2026-11-01 이후로 미룬다. 조각의 기간을 그에
   맞춘다(2026-11-05).
4. **재는 자는 조각 39 의 자와 대조 둘이다.** 놓친 케이스는 기준선의 두 배(6 회차)로 재 흔들림을 덜고, 문턱 5/6 은 「셋 중 하나」에서 「거의 늘」로 올랐는지를 본다.
   `gate-ddl-lock` 은 판을 모를 때 미루는 쪽이라, 새 규칙이 「판을 모를 때도 단정한다」로 새는지를 가장 가까이 본다. 새 함정 케이스는 이 측정이 오검을 보일 때
   세운다 — 지금 세우면 수트 지문이 바뀌어 route 가 한 번 더 돈다.
5. **B 하나다.** 문구만 넣으면 천장을 넘어 게이트가 떨어지고, 줄임만 하면 판정을 바꿀 까닭이 없는 PR 이 전수를 부른다. 측정은 그 문구 위에서만 뜻이 있다.

## 결과

- `audit-data` 의 고유 절이 바뀌고 판이 0.4.4 가 된다. 사본은 공통 절만 견주므로 갈리지 않는다 — 사본에 심을지는 그 레포의 다시 심기가 정한다.
- B 는 11 월까지 열려 있다. 그동안 다른 PR 이 `audit-data` 를 고치면 B 가 그것을 받아 예산을 다시 맞춘다.
- 측정이 5/6 에 못 미치면 B 의 세션이 저자에게 다시 잴지 넘길지를 묻는다(설계 ④ 의 열어 둔 것).
- 다른 감사자의 같은 꼴과 판이 고정되지 않은 함정은 재지 않는다 — 근거가 생기면 조각 나눔의 줄로 세운다.
