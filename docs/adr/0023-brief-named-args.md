# 0023 — 브리핑 커맨드는 기준 · 감사자를 이름 자리표시로 받고, 기준만 준 부름을 커맨드 케이스로 잰다

2026-10-13 · 결정함 · 넷 다 저자가 착공 PR(#59)을 연 뒤 정했다. 넷 다 세션이 Claude Code 문서와 수트 검사 · 글자 예산 · 대장의 규칙에서
끌어내 제안한 쪽이다

## 맥락

`vibe-audit/commands/audit-brief.md` 는 기준을 `$0`, 감사자를 `$1` 로 받고, 빈 인자를 「`$0` 가 비어 있으면」 · 「`$1` 가 주어졌으면 …
아니면」으로 다룬다. Claude Code 는 짝이 없는 번호 자리표시를 글자 그대로 두고, 프런트매터 `arguments` 의 이름 자리표시는 짝이 없으면 빈
문자열로 편다. 이름 자리표시가 있으면 인자가 남아도 `ARGUMENTS:` 를 덧붙이지 않는다(code.claude.com/docs/en/skills, 2026-10-13). 강호쟁패
#11 의 Codex 리뷰가 사본에서 짚었고, 조각 13 「닫으며」가 원본의 결함으로 넘겼다.

커맨드의 호출 시 글자는 4,458 / 천장 4,500 이다. 천장은 저자 승인 없이 올리지 않는다(ADR 0004).

수트(`vibe-audit/evals/`)의 케이스 스물다섯은 다 감사자를 잰다. `verify-evals.py` 는 앞머리 `route-` 가 아닌 케이스를 다 판정 케이스로 보고
`prompt.md` 의 감사자 지목 · `real-nc-found` · `auditor-fired` 를 요구한다. 되먹임 한 건에 케이스 하나다(`CLAUDE.md` 「작업 방식」).

사본(ERP 3d6964a · 강호쟁패 b8d9243)은 옛 커맨드를 바이트 그대로 든다. `verify-copies.py` 는 사본 커맨드의 있음과 머리말만 본다.

## 대안

1. 빈 인자를 받는 꼴: **프런트매터 `arguments: [base, auditor]` 와 이름 자리표시 `$base` · `$auditor` — 빈 인자는 빈 문자열** / 번호
   자리표시를 두고 「`$0` 이 글자 그대로 보이면 인자가 없다」를 적는다 / `$ARGUMENTS` 한 덩어리를 받아 세션이 나눈다 / 커맨드를 스킬
   (`skills/audit-brief/SKILL.md`)로 옮긴다.
2. 결함을 재는 케이스: **기준만 준 부름 하나(`command-base-only`) — 대조군은 브리핑을 쓴 것(`file_exists`), 덫은 감사자를 짐작해 부름,
   목적은 감사자를 물음** / 인자 없는 부름 하나 — 덫은 git 을 돌림 / 둘 다.
3. 수트 검사: **`verify-evals.py` 가 셋째 모양 「커맨드 케이스」(`command-*`)를 안다 — 실재하는 커맨드를 부르는 `prompt.md` · 대조군
   `command-ran` · 목적 그레이더를 요구하고, 감사자 지목 · `real-nc-found` · `auditor-fired` 는 요구하지 않는다. `bite-gates.sh` 에 변조
   둘** / 판정 케이스 모양에 맞춘다 — `prompt.md` 에 감사자를 적고 `real-nc-found` 를 둔다 / 검사가 이 케이스를 건너뛴다.
4. 사본: **이 조각에서 다시 심지 않는다 — 다음 심기에서 받는다** / 이 조각에서 ERP · 강호쟁패를 다시 심는다.

## 결정

굵은 쪽 넷. 저자가 착공 PR(#59)을 연 뒤 정했다(2026-10-13) — 넷 다 세션이 추천한 쪽이다.

- 1 은 문서가 약속한 동작에 기대고 글이 가장 짧기 때문이다. 둘째는 「글자 그대로 남은 `$0`」을 알아보라는 문장이 인자를 준 부름에서도
  펴져(「`origin/main` 이 글자 그대로 보이면」) 뜻이 깨진다 — `\$0` 으로 막으면 그 문장만 남아 읽는 쪽이 이중으로 헷갈린다. 셋째는
  셸식 따옴표 나누기를 세션의 짐작에 넘긴다. 넷째는 부르는 이름은 같지만 경로가 바뀌어 `sync-agents.sh` · `verify-copies.py` · 사본 둘 ·
  예산의 출처가 다 따라 바뀐다 — 빈 인자를 고치는 일보다 크다. 이름 둘이 늘리는 글자(약 +60)는 괄호 줄을 지우고 커맨드 안에서 압축해
  천장 안에 넣는다.
- 2 는 기준만 준 부름이 정상 사용(`argument-hint` 가 감사자를 선택으로 적는다)이고 막는 장치가 없는 쪽이기 때문이다. 인자 없는 부름은
  「하나」 단계의 글자 검사가 이미 멈추고, 옳은 동작이 「아무것도 안 함」이라 아무것도 안 하는 세션과 가를 대조군이 서지 않는다. 기준만
  준 부름은 브리핑을 써야 해 대조군이 선다. 둘 다는 되먹임 한 건에 케이스 하나를 넘긴다 — 인자 없는 쪽은 단계 5 에서 저자가 본다.
- 3 은 커맨드 케이스가 감사자를 부르지 않는 것이 정상이라, 판정 케이스의 요구를 그대로 대면 덫과 정반대를 요구하기 때문이다. 둘째는
  감사자를 `prompt.md` 에 적는 순간 덫이 사라진다. 셋째는 물지 않는 수트를 남긴다 — `claude plugin eval` 은 그레이더가 비어도 조용히 돈다.
  새 갈래는 무는 변조본과 함께 선다(`CLAUDE.md` 「작업 방식」).
- 4 는 다시 심기가 대장의 `synced_commit` 을 옮기고 두 레포에 PR 을 내는 일이라 이 결함의 크기보다 크기 때문이다. 커맨드는 내용을 견주지
  않아 대장은 갈리지 않는다. 두 레포에서는 다음 심기까지 결함이 남는다 — 그동안 기준만 주면 감사자를 직접 고르게 된다.

## 결과

- 커맨드의 프런트매터가 한 줄 늘어 상시 글자도 는다(상시 285 / 900 · 합계 5,223 / 5,600 안).
- 부르는 쪽의 인자가 셋 이상이면 셋째부터 말없이 버려진다 — 옛 커맨드에서도 쓰이지 않았다.
- 수트의 케이스가 세 모양이 된다. 커맨드 케이스는 `Bash` · `Write` 를 여는 첫 케이스라, 세션이 픽스처 밖을 건드리지 않는지는 하네스의
  작업공간 격리에 기댄다.
- eval 이 플러그인 커맨드를 펴는지는 공식 문서에서 확인하지 못했다. 첫 측정에서 펴지 않으면 2 · 3 을 다시 정한다(설계 ④ 의 열어 둔 것).
- 다른 커맨드 · 스킬을 원본에 더할 때는 번호 자리표시 대신 이름 자리표시를 쓴다. 지금은 `vibe-audit` 의 커맨드가 이것 하나이고, `vibe-slice`
  의 두 스킬은 자리표시를 쓰지 않는다.
