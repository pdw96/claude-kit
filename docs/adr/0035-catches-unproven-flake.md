# 0035 — `gate-catches-unproven` 의 흔들림은 재심으로 가르고, 심판이면 경계 예시를 박으며, 전수 없이 로컬로 확인한다

2026-10-16 · 결정함 · 셋 다 저자가 착공 대화에서 정했다 — 세션이 아티팩트 여섯 · README 「심판」 · 조각 20 · 22 에서 끌어내 추천한 쪽이다

## 맥락

`gate-catches-unproven` 이 여섯 전수의 열여덟 회차 가운데 셋에서 같은 이름의 심판 그레이더로 떨어졌다(2026-10-13 · 10-15 밤 · 10-16).
점수는 셋 다 0.875 로 문턱 위였다. 아티팩트 여섯을 받아 보니 열여덟 회차 다 pytest 행 「무엇을 잡는가」 칸이 「확인불가」와 「어긋낸 기록이
없다」를 들었고, 떨어진 셋 가운데 하나는 지나간 아홉과 글자까지 같았다 — 심판의 기준으로는 PASS 의 모양이다(조각 24 요구사항 「문제」).
하네스는 심판의 이유를 남기지 않는다. 그래서 원문만으로는 심판이 칸 밖의 무엇에 걸렸는지, 또는 같은 글에 다른 판정을 내는 흔들림인지
가르지 못한다.

고칠 자리의 사정도 다르다. 감사자 `audit-quality` 는 호출 시 예산이 10,998 / 11,000 이라 문구를 더할 여유가 없다. 심판 그레이더는
「고정한 것」 밖이고 full 지문에만 든다. README 「심판」은 심판이 틀리는 모양 하나로 「표면 토큰에 걸린다」를 들고 처방을 「경계 예시를 표로
박는 것」으로 적는다. 10월 전수 합은 이미 $41.05 로 월 한도 $20 을 넘었다(ADR 0033).

## 대안

1. 가르는 법: **재심 + 이유 묻기 — 떨어진 최종 응답을 그대로 다시 내는 재심 케이스(커밋하지 않음)로 같은 심판을 `run-evals.sh` 에서 다시 대어
   재현을 보고, 같은 기록을 심판 모델에 `claude -p` 로 넣어 이유를 받는다** / 재심만 — 이유는 심판 문구를 쪼갠 변형으로 짐작한다 / 로컬
   재측정만 — 조각 20 처럼 `--runs 6` 으로 다시 재 떨어진 회차를 원문으로 본다.
2. 고칠 쪽(심판 갈래일 때): **심판 문구에 경계 예시 표를 박는다 — 옛 · 새 심판을 같은 기록에 같은 시각에 대어 가른다** / 심판을 정규식으로
   바꾼다 — 마지막 칸의 확인불가 이유를 낱말로 본다 / 고치지 않고 기록만.
3. 확인: **로컬만 — 재심과 `run-evals.sh --case gate-catches-unproven --runs 6` 한 판, 전수는 다음에 돌 때 지켜본다** / 고친 머리에서 전수
   한 번(10월 한도를 더 넘김) / 11월 첫 전수에서 본다.

## 결정

굵은 쪽 셋. 저자가 착공 대화에서 정했다(2026-10-16). 셋 다 세션이 추천한 쪽이다.

- 1 은 떨어진 회차의 글이 이미 있고, 흔들린 것이 그 글에 대한 판정이기 때문이다. 재측정만 하면 감사자가 새 글을 써서 심판의 흔들림과 감사자의
  흔들림이 다시 섞이고, 떨어지는 빈도가 여섯에 하나꼴이라 여섯 회차 한 판에 하나도 안 나올 수 있다. 재심은 같은 글을 같은 심판에 대므로 재현이
  곧 갈래다. 다만 재심은 판정만 보이고 이유를 보이지 않아, 무엇을 고칠지는 이유 묻기가 받친다. 이유 묻기는 하네스 밖의 호출이라 갈래의 근거로
  쓰지 않는다.
- 2 는 이 심판이 보는 것이 「확인불가의 이유가 어긋낸 기록인가」라는 뜻이기 때문이다. 정규식으로 바꾸면 결정론이고 공짜지만, 「확인불가라고 적고
  잡는 것을 단정한 칸」은 낱말로 못 가르고, 고정한 정규식이 하나 는다. README 「심판」의 처방이 이 꼴을 이미 들고 있다. 기록만 하면 한 전수에서
  두 회차가 떨어질 때 verdict 가 빨개지는 일(전수마다 7% 안팎)이 남는다.
- 3 은 10월 전수 비용이 이미 한도의 두 배이고, 고치는 것이 그레이더 하나라 감사자 · 다른 케이스의 판정이 움직이지 않기 때문이다. 재심이 같은
  글에서 옛 · 새를 가르고, 로컬 한 판이 본 적 없는 기록에서 새 심판을 본다. 전수 한 번(세 회차)은 그 둘보다 이 케이스에 대해 더 말하지 않는다.

## 결과

- 1: 구현 PR 의 첫 커밋은 eval-log 의 원문 · 이유다. 재심 케이스 · 이유 묻기의 스크립트 · 트레이스는 저장소에 싣지 않는다. 재심의 옛 쪽이
  재현하지 못하면 「재현 못 함」으로 두고 심판을 고치지 않는다.
- 2: 심판으로 가르면 `graders/gate-catches-unproven.md` 의 본문만 바뀐다 — full 수트 지문이 바뀌고 route 지문은 그대로라 PR 의 CI 는 eval 잡을
  건너뛴다. 감사자 · 정규식 그레이더 · 케이스 입력은 그대로다. 감사자 갈래로 나면 고치지 않고 조각 나눔의 줄로 넘긴다.
- 3: 이 조각은 전수를 돌리지 않는다. 다음 전수에서 이 케이스가 다시 떨어지는지는 조각을 닫는 기록의 「지켜본 것」이 든다. 로컬 측정은 조각
  전체 $5 안이다.
