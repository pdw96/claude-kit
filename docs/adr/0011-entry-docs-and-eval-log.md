# 0011 — README 는 입구, 감사자 작업 기록은 `docs/eval-log/` 에 달마다, 구조는 `docs/architecture.md`

2026-10-06 · 결정함 · 1 ~ 4 는 저자가 인터뷰에서 정했다. 5 · 6 은 세션이 저장소 규칙에서 끌어내 제안했다 — 착공 PR 의 머지가 저자의 결정이다

## 맥락

조각 나눔 「README · CLAUDE.md 를 제 역할로 줄이기」는 세 문서를 제 역할로 돌린다(조각 4 요구사항 「문제」).
`vibe-audit/evals/README.md` 는 2157줄 · `##` 절 예순다섯이고, 그 가운데 날짜를 박은 작업 기록이 대부분이다. 나누려니
저장소의 장치 셋이 자리를 좁힌다.

- `scripts/verify-evals.py` 는 `vibe-audit/evals/` 아래 폴더를 `results` 말고 다 케이스로 읽는다 — 기록 폴더를 거기
  두면 게이트가 떨어진다.
- `scripts/eval-key.py` 는 `vibe-audit/` 아래에서 이름이 `README.md` 가 아닌 파일을 다 수트 지문에 넣는다 — 기록 파일을
  거기 두면 기록을 덧붙일 때마다 route 수트가 돈다. 조각 3 에서 `eval.yml` 을 고칠 때마다 수트가 네 번 돈 것과 같은 꼴이다.
- `AGENTS.md` 「Review guidelines」(고정 영역)가 그 파일의 절 셋을 이름으로 가리킨다.

README 를 입구로 줄이면 마스터플랜 「가리키는 문서」의 「시스템 구조」 줄이 가리킬 곳도 없어진다.

## 대안

1. 작업 기록의 자리: **`docs/eval-log/`** — 플러그인 밖이라 지문 · 배포에 들지 않는다 / `vibe-audit/evals/` 안 —
   `eval-key.py` · `verify-evals.py` 를 고치고 「게이트가 무는가」에 변조 줄을 더한다. 기록이 플러그인과 함께 배포된다.
2. 나누는 법: **지금 파일을 글자 그대로 첫 기록 파일로 옮기고, 그 뒤는 달마다 한 파일** / 옮기는 법은 같고 그 뒤는
   일 한 건마다 한 파일(ADR 처럼) / 날짜 박힌 절은 달별 파일로, 날짜 없는 절은 살아 있는 문서로 쪼갠다.
3. 시스템 구조: **`docs/architecture.md` 를 새로 둔다** / `없음 — 구조는 docs/adr/ 와 스크립트 머리말이 든다`.
4. `AGENTS.md` 가 가리키는 절: **살아 있는 README 에 「고정한 것」 절을 두고 그리로** / 경로만 첫 기록 파일로 바꾸고
   절 이름은 둔다.
5. 수트 지문 안 파일(스크립트 · 그레이더 · `eval.yml` · `verify-brief.py`)의 옛 참조 `evals/README.md 「…」`:
   **고치지 않는다 — 살아 있는 README 머리의 한 줄이 첫 기록 파일로 잇는다** / 다 고친다.
6. README · CLAUDE.md 가 값을 다시 들지 않는지: **검사를 세우지 않는다 — 사람이 본다** / `verify-docs.py` 에
   금지 낱말(모델 id · 버전 숫자)을 더한다.

## 결정

굵은 쪽 여섯.

## 결과

- 지난 기록의 글자가 하나도 바뀌지 않는다 — 옮긴 파일은 옮기기 전 파일과 바이트로 같다. 「지난 항목은 고치지 않는다」
  (`docs/procedure.md` 「살아 있는 문서와 기록」)를 나누는 일 자체가 어기지 않는다. 대가: 첫 기록 파일 안의 뒤섞인 순서
  (26차 → 35차 → 34차 …)와 지금은 낡은 숫자가 그대로 남는다.
- 기록을 덧붙여도, 나누어도 수트 지문이 그대로라 route 수트가 다시 돌지 않는다(5 와 함께). 대가: 감사자와 함께
  배포되는 것은 살아 있는 README 뿐이다 — 왜 지금 모양인가를 보려면 이 저장소를 본다.
- `docs/procedure.md` 「살아 있는 문서와 기록」에서 `vibe-audit/evals/README.md` 는 기록에서 살아 있는 문서로 옮기고,
  기록 자리는 `docs/eval-log/` 가 든다.
- 절차 3 단계의 나가는 조건(「부품 · 경계 · 흐름이 바뀌었으면 시스템 구조 문서도 고쳤다」)이 이 저장소에서 물 자리가
  생긴다. 그 모양(필수 절)은 정하지 않는다 — 절차 지도의 칸을 늘리지 않는다.
- 대가: 살아 있는 문서가 둘 는다 — 기록에서 옮겨 오는 수트 README 와 `docs/architecture.md`. `docs/procedure.md` 의
  「수를 늘리지 않는다」는 「늘리려면 ADR 로 정한다」로 고쳐, 이 ADR 이 그 자리가 된다.
- `AGENTS.md` 고정 영역의 문구가 바뀐다 — 가리키는 자리만 바뀌고, 고정한 대상과 알려진 한계는 그대로다.
- 수트 지문 안 파일과 기록(조각 폴더 · ADR)의 옛 참조는 살아 있는 README 의 한 줄을 거쳐야 찾는다. 다음에 그
  파일을 고치는 PR 이 참조도 따라 고친다.
- README · CLAUDE.md 가 값을 다시 드는 것은 `CHECKLIST.md` 에서 사람이 본다. 금지 낱말은 정상 문장(「수트 모델은
  `run-evals.sh` 가 든다」)과 뜻으로만 갈린다 — ADR 0010 의 2 와 같은 까닭이다.
