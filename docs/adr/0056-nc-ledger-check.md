# 0056 — 부적합 대장의 모양은 `slice-docs` 의 새 검사가 틀의 규칙 넷으로 문다

2026-10-28 · 결정함 · 1 ~ 3 은 저자가 조각 43 의 착공 세션에서 정했다(세션이 ERP 의 대장 시험 여덟을 틀에 있는 것과 없는 것으로 갈라 보이고 무는 범위 · 검사의
자리 · 다른 레포에서 대장을 찾는 법을 물어, 저자가 세션이 추천한 쪽을 골랐다). 3 의 「없을 때」 두 갈래 · 4 · 5 · 7 은 세션이 제안했고, 착공 PR #162 가
열린 뒤 세션이 넷을 대안과 함께 다시 물어 저자가 세션이 추천한 쪽을 골랐다(2026-10-29). 6 · 8 은 세션이 제안했고 착공 PR 에서 저자가 본다

## 맥락

조각 「부적합 대장」이 대장의 틀과 닫는 규칙을 `vibe-slice` 에 두고, 무는 검사를 순서 없는 줄 「부적합 대장 검사」로 넘겼다 — 틀을 베낀 레포가 없어 물 모양이
ERP 한 레포의 것이었다(ADR 0044 의 1). 이 저장소가 조각 35 의 닫기(2026-10-23)에 틀(`d022edd`)을 베껴 `docs/audit/` 에 대장을 세웠고 회차 13 을 따라왔다.

ERP 는 대장 규칙이 사람 손에서 거듭 깨져 `backend/tests/test_prose.py` 에 대장을 읽는 시험 여덟을 세웠다(`37c77b4`). 그 가운데 넷(상태 낱말 · 줄이 사는 표와 번호 ·
회차 절의 자리 · 회차 절의 첫 줄)은 틀이 든 규칙이고, 넷(낮음은 이슈로 · W 표 · 「아직 아무도 보지 않은 것」 표 둘)은 틀에 없다. 넷 가운데 하나는 ERP 게이트의
해석 한계에 맞춘 마크다운 제약을 함께 든다. 이 저장소에서도 회차 6 의 등록(`7a6f3e6`)이 상태 칸을 굵게 하지 않은 「열림 — 저자 판정 대기」로 적었다가 다음 커밋이
지웠고, 아무것도 떨어지지 않았다. 대장 등록은 변조 시험 지문 밖의 문서만 고치는 PR 이다.

`gates.sh` 의 `checks` 에 한 줄을 더하면 수트 지문에 드는 `eval.yml` 주석의 「스물둘」을 고쳐야 해 route 수트가 한 번 돈다(ADR 0055 의 결과 3 과 같은 꼴).

## 대안

1. 무는 범위: **틀이 든 규칙 넷 — 상태 낱말 · 줄이 사는 표 · 번호(NC · U) · 회차 절** / 조각 나눔 줄의 이름 그대로 셋(회차 절은 사람이) / 넷 + ERP 의 마크다운 제약.
2. 검사의 자리: **`slice-docs/scripts/` 의 새 검사 — 이 저장소는 `gates.sh` 의 `checks`, 다른 레포는 스킬이 PR 을 내기 전에** / `verify-docs.py` 를 넓힌다(게이트 목록이
   그대로라 모델 비용 0) / `scripts/` 에만 둔다(이 저장소만).
3. 대장을 찾는 법: **틀의 출처 줄로 살아 있는 쪽을, 그 머리의 경로로 지나간 쪽을 — 인자 없이** / 경로를 인자로 받는다.
4. 상태 낱말의 원천: **그 대장의 「닫는 규칙」 문장에서 읽는다** / 검사에 박는다(ERP 의 `_STATUS`) / 틀에서 읽는다.
5. 예외 목록: **두지 않는다** / ERP 처럼 옛 절 · 옮긴 번호의 예외 목록을 둔다.
6. 실패 줄: **규칙 ID 를 찍고 ID 마다 변조본을 정적으로 대조한다(ADR 0054 · 0055)** / 자유 글로 찍는다.
7. PR 나눔: **구현 B 하나** / 검사 · 이 저장소의 게이트(B)와 다른 레포 길 · 판(C)으로 둘.
8. 판: **`vibe-slice` 0.9.0, `vibe-audit` 그대로** / 판을 올리지 않는다.

## 결정

굵은 쪽 여덟.

1. **틀이 든 규칙만 문다** — 가르는 질문이 「다른 레포에서도 같은 말인가」이고(`INTENT.md` Why), 틀을 베낀 레포에서 같은 말인 것은 틀이 든 규칙이다. 셋만 물면 ERP 에서
   여섯 절이 지나간 「감사한 커밋」 줄이 사람 몫으로 남는다. 마크다운 제약은 ERP 게이트가 마크다운을 해석하다 리뷰마다 틈이 나 세운 표기 규칙이고(조각 33 ③ L22) 오검을
   늘린다. 저자가 골랐다.
2. **스킬 폴더의 새 검사** — 조각 나눔 줄이 검사를 `vibe-slice` 에 두라고 했고, 대장은 다른 레포에서도 같은 말이라 그 레포에도 가야 한다. `verify-docs.py` 를 넓히면
   모델 비용이 들지 않지만 문서의 모양과 대장의 모양이 한 파일에 붙고, 대장이 없는 레포에서의 동작을 문서 대조 검사가 함께 진다. route 수트 한 번은 `route-*` 10 × 3
   회다. 대장 등록은 변조 시험 지문 밖이라 검사는 `bites` 가 아니라 `checks` 에 둔다 — 회차만 등록한 PR 에서도 돈다(ADR 0055 의 4 와 같은 까닭). 저자가 골랐다.
3. **출처 줄로 찾는다** — 틀은 대장을 레포가 정한 자리에 베끼게 하고 출처 줄(베낀 커밋)을 남기게 한다. 그 줄은 베낀 대장에만 있고 틀 자신의 줄은 커밋 자리가 `<커밋>` 이라
   가려진다. 인자로 받으면 스킬이 `CLAUDE.md` 를 읽어 경로를 넘겨야 해 부르는 법이 레포마다 갈린다. 저자가 골랐다. **없을 때** — 틀은 고르는 것이라 대장이 없는 레포가
   많으므로 다른 레포 모드는 「대장 없음」 PASS 로 지나간다. 이 저장소는 대장이 있어야 하므로 인자 없이 부르면 떨어진다 — 출처 줄을 지운 PR 이 검사를 조용히 끄지 못하게. 저자가 골랐다(착공 PR 안에서).
4. **낱말은 대장 자신에서** — 틀 머리가 「낮음을 달리 다룰지(예: 대장 대신 이슈)는 그 레포가 정해 이 파일에 적는다」고 한다. 레포가 상태 말을 더하면(ERP 의 「이슈로
   옮김」 같은) 그 대장의 문장에 더하고 검사는 그 문장을 따른다. 검사에 박으면 그런 레포마다 검사를 고쳐야 하고, 틀에서 읽으면 베낀 뒤 갈라진 대장을 원본 틀로 잰다.
   다만 「닫힘」과 「열림 — 저자 판정 대기」는 줄이 사는 표와 판정 전 상태를 가르는 낱말이라 문장에 없으면 떨어진다. 저자가 골랐다(착공 PR 안에서).
5. **예외 목록이 없다** — ERP 의 예외는 규칙보다 먼저 선 옛 절 · W 로 옮긴 번호였다. 이 저장소의 대장은 지금 넷을 다 지키고(대장을 고친 커밋 14 에서 번호가 다 맞았다),
   새로 베낀 대장은 빈 표로 연다. 상태 칸은 살아 있는 칸이라 어긋나면 고친다. 저자가 골랐다(착공 PR 안에서).
6. **조각 41 · 42 의 꼴 그대로** — 새 검사는 처음 서는 검사라 출력을 정할 수 있다. 규칙 ID 를 찍으면 ADR 0054 의 「규칙마다 변조본」을 기계로 문다.
7. **한 PR** — 새 검사를 스킬 폴더에 두면 「조각 문서 검사」의 수(`verify-counts.py` 의 닻)와 게이트 수가 같은 PR 에서 바뀌어야 초록이고, 플러그인에 새 파일이 드는
   PR 에서 판을 올린다. 둘로 나누면 판을 올리지 않은 플러그인에 새 파일이 드는 PR 이 생긴다. 저자가 골랐다(착공 PR 안에서).
8. **`vibe-slice` 만 올린다** — 새 검사와 스킬의 한 줄 · 틀 머리 주석이 `vibe-slice` 에 든다. `vibe-audit` 는 고치는 파일이 없다.

## 결과

- 1: 틀을 베낀 대장에서 상태 칸 · 줄이 사는 표 · 번호 · 회차 절이 어긋나면 키 없이 떨어진다. 줄의 뜻(재감사 없는 닫힘 · 담당)과 마크다운 변형은 사람이 본다.
- 2: `gates.sh` 의 검사가 스물여덟(늘 도는 것 스물셋 · 변조 시험 다섯)이 되고, 스킬 `slice-docs` 의 검사가 셋이 된다. 조각 43 의 B 에서 route 수트가 한 번 돈다.
  다른 레포에서는 스킬이 부를 때만 문다 — 머지를 막지 않는다.
- 3: 틀의 출처 줄과 머리 문단의 지나간 쪽 경로가 검사의 입구가 된다. 그 줄을 지운 다른 레포의 대장은 검사 밖이다.
- 4: 틀의 절 제목 · 표 머리 · 다음 번호 줄이 검사의 원천이 된다 — 틀에서 바꾸면 옛 꼴로 베낀 레포의 검사가 「못 읽음」으로 떨어진다. 그 꼴을 앵커볼트 목록
  (`CLAUDE.md`)에 올릴지는 이 ADR 이 정하지 않는다. 상태 낱말은 대장 자신에서 읽어 이 결과 밖이다.
- 5: 이 저장소의 대장이 처음부터 초록으로 선다. 규칙 앞의 옛 꼴이 있는 레포는 상태 칸을 고쳐야 지나간다.
- 6: 새 검사의 ID 를 더하면 그 ID 의 변조본이 없을 때 빨강이다.
- 7: 조각 43 의 B 가 크다 — 리뷰 한도 3라운드는 그대로다.
- 8: 이미 설치한 세션은 판을 받아야 새 검사가 생긴다. 클라우드 레인은 `sync-slice.sh` 로 다시 심는다.
