# 0029 — 「피할 형태가 없다」는 적합으로, 빈 갈래는 FB 마다 오검 쪽으로 가르고 한 PR 에 싣는다

2026-10-14 · 결정함 · 셋 다 저자가 착공 대화에서 정했다(1 의 「영향은 저장소 밖」은 착공 PR #75 의 Codex 1회차 뒤) — 세션이 대장 · ERP#111 · ADR 0028 · 조각 18 의 측정에서 끌어내 추천한 쪽이다

## 맥락

`feedback.json` 의 FB-30 · 31 은 2026-10-14 에 `defect` · 혼합으로 갈렸다. 둘 다 원본 `audit-data` 항목 3 의 판정 표(엔진 · 판을 확인한
뒤의 표)에서 나온다 — 「쓰기를 멈추는데 피할 형태가 없다」 줄이 판정 넷 가운데 하나를 주지 않고(FB-30), 「네 눈 어느 것에도 해당하지
않는다」 갈래가 없다(FB-31). ERP 가 사본을 `018842c` 로 다시 심는 PR(pdw96/ERP#111)의 리뷰 2 · 3 라운드에서 찾았고, 그 PR 이 「원본으로
넘긴 것」으로 적었다.

ERP 사본은 두 자리를 이렇게 메웠다.

- 「쓰기를 멈추는데 피할 형태가 없고, 리비전 · PR 이 그 잠금을 맞게 적었다 → 적합 — 잠금 사실과 전제를 적고 심각도 확인불가」와
  「쓰기를 멈추는데 리비전 · PR 에 잠금 설명이 없다 → 부적합 — 고치는 것은 적는 것이다(W-1)」
- 「위 네 눈 어느 것에도 해당하지 않는다 → 적합」과 NC-21 의 예 한 문장

「적었으면 적합」 · 「설명이 없으면 부적합」은 FB-4 를 되먹일 때 「ERP 에 배포처가 없어서 나온 말」로 빼기로 한 것이고(대장 FB-4 `reason`),
NC-21 은 ERP 의 일이다. 원본에 남는 일반 몫은 「피할 형태가 없는 잠금의 판정」과 「해당 없음 갈래」다.

`audit-data` 는 호출 시 11,000 / 11,000 이라 여유가 없다(ADR 0004). 조각 18 은 수트 모델이 옛 문구로도 노골적인 자리를 대개 바르게
판정한다는 것을 다시 보였다 — 두 판 · $2.61 로 FB-34 · 8 을 가르지 못했다(`docs/eval-log/2026-10.md`).

## 대안

1. FB-30 의 판정: **적합 — 잠금 사실 · 전제와 「영향(행 수 · 트래픽 · 시간 창)은 저장소 밖」을 근거에 적는다** / 적합 — 잠금 사실과 전제만 근거에 /
   적합 + 심각도 확인불가를 따로(ERP 사본의 꼴에서 「적었으면」만 뺀다) / 확인불가 — 심각도(행 수 · 트래픽 · 시간 창)가 저장소 밖이라 행의 판정도
   확인불가 / 적합 — 잠금 사실은 관찰(OB)로 따로 적는다.
2. 두 판 안에 못 가르면: **ADR 0028 의 2 그대로 — 갈래를 넣지 않고 `defect` 그대로 · 조각 나눔의 순서 없는 후보로. 판은 FB 마다 둘** /
   표의 빈 갈래는 글자의 결함이라 갈래는 넣고, 케이스는 회귀 표본으로 들이고 `defect` 로 둔다.
3. PR 나눔: **착공 하나 · 구현 하나(FB-30 · 31 을 한 PR 에서 따로 재고, 가른 FB 의 갈래만 싣는다)** / FB 마다 구현 PR 하나.

## 결정

굵은 쪽 셋. 저자가 착공 대화에서 정했다(2026-10-14). 1 의 「영향은 저장소 밖」은 착공 PR #75 의 Codex 1회차(「피할 형태가 없는 잠금의
심각도 모름을 지우면 다 확인된 것처럼 지나간다」) 뒤에 저자가 더했다(같은 날). 셋 다 세션이 추천한 쪽이다.

- 1 은 항목 3 이 묻는 것이 「이 DDL 이 무엇을 하는가」이고(얼마나 오래인가가 아니라 — 행 수 · 트래픽은 저장소에 없다), 엔진 · 판과 구문으로
  그것을 확인했기 때문이다. 피할 형태가 없으면 고칠 것이 없다 — 「부적합과 관찰을 가릅니다」의 가르는 질문이 그것이다. 확인불가로 두면
  통과 여부에서 부적합처럼 묶여(「판정은 넷이다」), 더 할 수 없는 잠금이 근거를 기다리는 줄로 영영 남는다. 근거가 와도 고칠 자리가 없다.
  관찰로 따로 내리면 잠금 사실이 판정 행에서 떨어져, 배포하는 사람이 표를 읽을 때 그 잠금을 보지 못한다 — 근거 칸에 적으면 같은 행에
  남는다. 다만 근거가 잠금 사실만이면 표가 「다 확인했다」로 읽힌다 — 영향이 저장소 밖이라는 것을 같은 칸에 적어, 배포하는 사람이
  시간 창을 잡을 몫이 남았음을 보이게 한다. 심각도 확인불가를 따로 두면 U 항목이 되어 위와 같이 통과 여부에서 묶이고, 「적합인데
  확인불가」가 한 줄에 섞여 판정이 다시 갈린다. 잠금 설명이 어긋나는 자리는 원본의 셋째 줄(부적합)이 그대로 든다. ERP 의 「적었으면」 조건은 그 셋째 줄과 W-1 을 합친 것이라
  일반 몫이 아니다.
- 2 는 조각 18 의 규칙을 바꿀 근거가 없기 때문이다. `fed_back` 은 「지켜진다」를 뜻하고, 그 근거가 케이스다(ADR 0028 의 2). 빈 갈래가
  글자의 결함인 것은 맞지만, 수트 모델이 옛 표로 바르게 판정하면 갈래를 넣는 비용(같은 감사자의 다른 글자를 줄이는 것)을 치를 근거가 없다.
  못 가른 FB 는 조각 18 의 다섯과 같이 새 근거(다른 수트 모델 · 새 사본의 실패)를 기다린다.
- 3 은 두 갈래가 같은 파일 · 같은 표이고 예산을 줄이는 자리도 하나이기 때문이다. 감사자를 고치는 PR 이 하나라 전수도 한 번이다. FB 마다
  PR 을 두면 둘째 PR 이 첫째 PR 이 줄인 예산 위에서 다시 줄여야 하고 전수가 두 번이다. 케이스 · 판 · 가름은 FB 마다 따로다 — 한 PR 안에서
  FB-30 만 가르면 FB-30 의 갈래만 싣는다.

## 결과

- 1: FB-30 을 가르면 원본의 「피할 형태가 없다」 줄은 「적합 — 잠금 사실 · 전제와 「영향(행 수 · 트래픽 · 시간 창)은 저장소 밖」을 근거에 적는다」의 꼴이 된다. 심각도 확인불가는 없어진다 — U 항목을 만들지 않는다.
  케이스의 목적 그레이더는 그 자리의 판정이 적합이 아니면 떨어진다(오검 쪽).
- 2: 못 가른 FB 는 이 조각을 닫는 기록에서 조각 나눔의 순서 없는 줄로 넘어간다. 그 픽스처는 들이지 않고 모양 · 숫자는 eval-log 에 남는다.
- 3: 구현 PR 은 FB 마다 케이스 하나를 따로 재고, 가른 FB 의 갈래 · 케이스만 싣는다. 둘 다 못 가르면 eval-log 만 싣는다.
- 원본이 바뀌면 판이 0.4.1 이 되고, 사본 레포는 다음 심기에서 받는다.
