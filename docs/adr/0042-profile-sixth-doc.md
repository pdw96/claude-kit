# 0042 — `slice-docs` 는 프로필(`Profile.md`)을 여섯째 문서로 쓴다 — 인터뷰로, 읽히는지만 문다

2026-10-20 · 결정함 · 1 · 3 의 앞 · 9 는 저자가 대화에서, 3 의 뒤 · 4 · 5 · 6 은 착공 인터뷰에서 정했다(같은 날). 인터뷰의
넷은 다 세션이 추천한 쪽이다. 2 는 세션이 대화에서 제안했고 저자가 그 모양의 ERP 인터뷰에 답했다. 7 은 세션이 정했고, 8 은
절차 지도의 규칙을 따른 것이다

## 맥락

저자가 물었다(2026-10-20) — 「프로젝트를 진행할 때 그 사람의 수준을 파악하는 절차가 있으면 어떨까. 눈높이에 맞게 표현하고
설명해 주는 것」. 저자는 제조 ERP 의 Setup TF 에 참여해 회사 전반의 흐름을 알지만 코딩은 모른다. 그래서 코딩 쪽 결정은
「무슨 말인지 모르니」 추천안대로 받아 왔다.

추천안대로 받은 결정은 사실상 세션이 내린 것이다. 그 가운데 일부는 업무 결정이기도 하다 — 「잘못 넣은 입고를 지우나, 취소
전표로 남기나」는 코드로 물으면 「삭제를 실제 삭제로 할지」가 되고, 그렇게 물으면 업무를 아는 저자가 판단하지 못한다. 이
저장소의 절차는 저자 · 소유자에게 묻는 자리를 여럿 둔다 — 스킬 `slice-review` 의 멈춤과 리뷰 한도, ADR 의 「저자가 정했다」.
묻는 법은 어디에도 없다.

세션이 처음에 「클래스 하나보다 분야별로, 증거가 있으면 조각으로」를 제안했고, 저자는 증거(눈으로 확인한 사례)가 아직 없다고
했다. ERP 는 화면 없이 엔드포인트까지만 지어져 동작을 보기 전에는 판단하기 어렵다는 것이다. 그리고 원래 생각은
「`Profile.md` 같은 것」이었다고 했다.

세션은 그것을 ERP 에 손으로 만들었다 — 저자 인터뷰 두 묶음으로 분야별 수준 · 결정을 가르는 법 · 설명하는 법을 받아
`Profile.md` 를 쓰고, `CLAUDE.md` 「작업 방식」 한 줄이 `@Profile.md` 로 가져오게 했다(pdw96/ERP#125, `fb160d9`). 저자가
바로잡았다 — 「이 플러그인이 담당하는 걸 생각하고 있었다」.

Claude Code 는 `CLAUDE.md` 안의 `@<경로>` 를 세션이 시작할 때 가져온다(https://code.claude.com/docs/en/memory 「Import
additional files」). 줄 가운데에도 쓸 수 있고, 백틱 토막 · 코드 펜스 · 따옴표 안의 것은 가져오지 않는다. 상대 경로는 그 줄이 든
파일을 기준으로 읽는다. 작업 폴더 밖을 가리키면 처음 한 번 승인 창이 뜬다. 저장소에 올리지 않는 개인 지시는
`CLAUDE.local.md`(`.gitignore` 에 넣는다)가 받고, 지금도 지원한다. 가져올 파일이 없을 때 무슨 일이 나는지는 문서에 없다.

## 대안

1. 누가 맡나: **스킬 `slice-docs` 의 여섯째 문서** / 플러그인 `vibe-slice` 에 새 스킬 / 맡지 않고 레포마다 손으로.
2. 수준을 어떻게 받나: **분야를 나눈 자기 신고 — 인터뷰로 받고 대화 중에 고친다** / 등급(클래스) 하나 / 시험으로 잰다.
3. 어디에 두고 어떻게 읽히나: **인터뷰에서 묻는다 — 혼자 쓰는 레포면 저장소 맨 위 `Profile.md` 를 올리고 `CLAUDE.md` 가
   가져온다. 여럿이 쓰면 `Profile.md` 와 `CLAUDE.local.md` 를 올리지 않고 `CLAUDE.local.md` 가 가져온다** / 늘 올린다 / 홈
   폴더(`~/.claude/`)에 두고 가져온다.
4. 틀의 절: **`## 수준` · `## 결정을 가르는 법` · `## 설명하는 법` 셋** / 셋에 `## 고치는 때` 를 더한 넷.
5. 절차 지도: **「문서의 모양」에 「`Profile.md` 의 칸」 절을 더한다 — 「…의 칸」 절이 여섯이 된다** / 「대상과 관계」 표에
   한 줄만.
6. 문서 대조 검사(`verify-docs.py`): **`Profile.md` 가 있으면 `CLAUDE.md` 나 `CLAUDE.local.md` 가 가져오는지만 문다. 없으면
   묻지 않는다** / 절 제목까지 문다 / 묻지 않는다.
7. 가져오는 꼴: **`@Profile.md` 한 꼴 — 백틱 토막 밖에서 앞뒤가 공백이나 줄 끝** / Claude Code 가 받는 경로 변형
   (`@./Profile.md` 등)까지.
8. 범위: **착공 PR 에서 `INTENT.md` What 의 틀 목록에 프로필을 더하고 마스터플랜 「범위 변경」에 한 줄** / What 의 「틀」이 이미
   덮는다고 읽는다.
9. ERP: **pdw96/ERP#125 를 이 조각의 C 로 쓴다 — 닫지 않고, 스킬 사본을 다시 심고 `Profile.md` 를 틀 모양으로 고친다.
   강호쟁패는 플러그인 갱신으로 받는다** / #125 를 닫고 새 PR / 사본 레포에 손대지 않는다.

## 결정

굵은 쪽 아홉.

- 1 은 저자가 대화에서 골랐다. 앞선 길이 있다 — `CLAUDE.md` 를 다섯째 문서로 더한 ADR 0041 이다. 새 스킬은 새 이름이라
  앵커볼트에 닿는다(`CLAUDE.md` 「앵커볼트」 이름).
- 2 는 저자의 모양이 등급 하나로 맞지 않기 때문이다 — 업무는 익숙함, 코딩은 모름이다. 하나로 뭉치면 어느 쪽 설명이든
  어긋난다. 시험은 번거롭고 수준을 바로 고치는 길이 대화 안에 있다. 저자가 ERP 인터뷰를 그 모양으로 받았다.
- 3 의 앞(인터뷰에서 묻는다)은 저자가 대화에서 정했다. 프로필은 사람의 것이라 여럿이 쓰는 레포에 올리면 한 사람의 프로필이
  모두에게 걸린다. 뒤(여럿이면 `CLAUDE.local.md`)는 착공 인터뷰에서 정했다. 커밋된 `CLAUDE.md` 가 올리지 않은 파일을
  가져오는 길은 다른 사람의 체크아웃에서 그 파일이 없을 때의 동작이 문서에 없어 피한다. 홈 폴더는 저장소 밖이라 검사가 못
  보고 승인 창이 뜬다. 대가 — 여럿이 쓰는 레포의 프로필은 클라우드 세션의 새 클론에 없다.
- 4 는 ERP 인터뷰에서 나온 모양 그대로다(#125). 고치는 때는 설명하는 법의 한 줄로 든다 — 절로 박을 만큼 쌓인 것이 없다.
- 5 는 「…의 칸」 다섯 절의 제목과 표 서식이 앵커볼트이기 때문이다(`CLAUDE.md` 「앵커볼트」, ADR 0010 의 8 · ADR 0041 의 7).
  여섯째 절을 더하면 문서 대조 검사의 `KINDS` 가 늘어 틀의 제목이 지도와 어긋날 때 떨어진다. 저자가 착공 인터뷰에서
  승인했다.
- 6 은 만들어 놓고 읽히지 않는 것이 이 문서의 가장 큰 구멍이기 때문이다 — `INTENT.md` 가 자동으로 읽히지 않아 ADR 0009 ·
  0041 이 막은 것과 같은 꼴이다. 내용은 사람마다 다르고 대화로 고치므로 절 제목은 묻지 않는다. 프로필은 고르는 문서라
  없으면 묻지 않는다 — 여럿이 쓰는 레포의 CI 에는 늘 없다. 새 검사이므로 떨어지는 변조본을 `gates.sh` 가 부르는 자리에 함께
  넣는다(`CLAUDE.md` 「작업 방식」).
- 7 은 받는 꼴을 실제 파일에서 뽑은 닫힌 목록으로 두는 규칙 때문이다(절차 지도 「설계 문서의 칸」 ③). 실물은 #125 의 한
  줄뿐이다. 그 밖의 꼴은 Claude Code 가 가져오더라도 떨어지고, 실패 줄이 `@Profile.md` 로 쓰라고 말한다.
- 8 은 `INTENT.md` What 이 틀을 다섯으로 적기 때문이다(절차 지도 「두 층」 「벗어난다」 · ADR 0041 의 9).
- 9 는 저자가 대화에서 골랐다. 인터뷰 답은 그대로 쓴다. ERP 는 스킬 사본을 쓰므로 다시 심어야 새 틀과 검사가 닿는다
  (ADR 0041 의 11 과 같은 길).

대가 — 다른 레포에서도 같은 말인지 가른 실물은 ERP 하나뿐이다(`INTENT.md` Why). 강호쟁패에 프로필이 서면 둘째 실물이다.

## 결과

- 1 · 2 · 4: 틀 `vibe-slice/skills/slice-docs/templates/profile.md` 가 선다. 머리 주석이 인터뷰의 물음을 든다. 스킬의 「틀」
  표에 한 줄, 「어디서 시작하나」에 프로필 단계가 더해진다.
- 3: 스킬이 인터뷰에서 레포를 혼자 쓰는지 묻고, 그 답대로 가져오는 줄을 `CLAUDE.md` 나 `CLAUDE.local.md` 에 넣는다. 여럿이면
  두 파일을 `.gitignore` 에 더한다. 이미 있으면 덮지 않는다 — ADR 0041 의 3 과 같다.
- 5 · 6 · 7: `docs/procedure.md` 「문서의 모양」, `verify-docs.py` 와 그 시험 · 변조본, `CLAUDE.md` 「앵커볼트」의 문서 모양
  줄이 바뀐다. 새 보장의 번호와 받는 꼴은 조각 31 설계 ② · ③.
- 8: 착공 PR 이 `INTENT.md` What 과 마스터플랜 「범위 변경」을 고친다.
- 9: 판이 오른다 — `vibe-slice` 0.6.0. ERP 는 #125 로, 강호쟁패는 플러그인 갱신으로 받는다. 조각은 #125 의 머지 뒤 닫는다.
