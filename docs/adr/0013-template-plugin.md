# 0013 — 틀은 새 플러그인 `vibe-slice` 의 스킬로, 클라우드 레인은 사본으로 간다

2026-10-07 · 결정함 · 여덟 다 저자가 정했다 — 6 ~ 8 은 세션이 저장소 규칙에서 끌어내 제안했다

## 맥락

틀 넷은 claude-kit `docs/templates/` 에만 있다(조각 5 요구사항 「문제」). 받을 레포는 길이 둘이다 — 강호쟁패는 대화형
세션과 ① 마켓플레이스(전역 플러그인)로 섰고 저장소에 `.claude/` 가 없다. ERP 는 클라우드 세션으로 일해 레포 안의 사본만
뜬다. 저자는 강호쟁패가 플러그인 리로드만으로 새 틀을 받고, ERP 는 사본을 받기를 바란다. `audit-internal` 은 기준 문서로
`PRD.md` 를 찾는다(ADR 0008 의 대가).

## 대안

1. 틀이 가는 길: **두 경로 — 대화형은 플러그인, 클라우드 레인은 사본** / 새 스크립트 하나로 레포마다 베낀다 /
   `sync-agents.sh` 에 붙인다 / 심지 않고 README 에 베끼는 법만.
2. 절차 지도: **보내지 않고 가리킨다** / 지도 전문을 함께 보낸다 / 일반형과 claude-kit 몫으로 나눠 일반형만 보낸다.
3. 싣는 자리와 이름: **새 플러그인 `vibe-slice`, 스킬 `slice-docs`** / `vibe-audit` 안의 스킬 / 스킬 이름 `slice-start` ·
   `templates`.
4. `audit-internal`: **뼈대 1 · 6 · 7 의 문구와 판정 케이스 하나, 프론트매터 설명은 그대로** / 문구만 / 설명의 「PRD」도.
5. 대장: **적지 않는다 — 출처는 사본 `SKILL.md` 머리 한 줄** / `copies.json` 에 칸을 더한다 / 새 대장.
6. 틀의 원천: **스킬 폴더 하나 — `docs/templates/` 를 `vibe-slice/skills/slice-docs/templates/` 로 옮긴다** / 두 벌을 두고
   바이트 대조 게이트를 붙인다 / 스킬 폴더에서 `docs/templates/` 로 링크.
7. 사본 길: **새 스크립트 `scripts/sync-slice.sh`** / `sync-agents.sh` 가 스킬도 심는다.
8. 예산: **`verify-budget.py` 가 마켓플레이스의 플러그인마다 같은 천장으로 잰다 — 스킬(`skills/*/SKILL.md`)도** / 두
   플러그인의 상시를 합해 한 천장에 / `vibe-slice` 는 재지 않는다.

## 결정

굵은 쪽 여덟. 1 ~ 5 는 저자가 인터뷰에서 정했다(2026-10-07). 6 ~ 8 은 세션이 이 저장소의 규칙에서 끌어내 제안했고, 저자가
착공 PR(#24)에서 승인했다 — 6 은 「같은 목록을 두 군데 두면 갈린다」(`CLAUDE.md`), 7 은 `sync-agents.sh` 의 「사본이 일부만
있다」 멈춤과 대장 규칙, 8 은 ADR 0004 의 「천장은 올리지 않는다」.

3 의 근거는 인터뷰에서 저자에게 넷을 댔다.

- `eval-key.py` 는 `vibe-audit/` 아래 추적된 파일을 다 수트 지문에 넣는다 — 그 안의 틀을 고칠 때마다 route 수트(케이스
  열 × 세 회)가 돈다.
- `vibe-audit` 의 상시 합계는 5,223 자로 천장 5,600 까지 377 자다.
- ERP 는 감사자 사본이 있어 `sync-agents.sh` 가 「사본이 일부만 있다」로 멈추고, `--force` 는 특화 감사자를 덮는다.
- `vibe-audit` 의 설명은 「읽기전용 감사자 6종 … 발견과 수정이 구조적으로 분리」다 — 문서를 쓰게 하는 스킬이 맞지 않는다.

## 결과

- 1 · 3: 강호쟁패는 `vibe-slice` 를 한 번 install 한 뒤, 틀을 고친 PR 이 판을 올리면 갱신과 리로드로 새 틀을 받는다.
  리로드만으로는 받지 못한다 — 서드파티 마켓플레이스는 자동 갱신이 기본으로 꺼져 있어
  `claude plugin marketplace update pdw96-kit`(마켓플레이스 목록 — 이미 등록한 `pdw96-kit` 에는 이것 없이 `vibe-slice`
  줄이 없다)과 `claude plugin update vibe-slice@pdw96-kit` 을 부르거나 `pdw96-kit` 의 자동 갱신을 켜 둬야 하고,
  `plugin.json` 의 판이 그대로면 갱신도 새 틀을 받지 않는다(#24 Codex, Claude Code 문서 「plugins/install」 ·
  「manifest-reference」 · 「plugin-marketplaces」). 같은 까닭으로 `audit-internal` 을 고치는 PR 은 `vibe-audit` 의 판을 올린다.
  ERP 는 `sync-slice.sh` 로 받은 사본을 쓴다. 플러그인 커맨드 본문은 플러그인 폴더 경로를 풀지 못하므로(`sync-agents.sh` 의 브리핑 검사기 주석) 틀을 든 것은
  커맨드가 아니라 스킬이다 — 스킬은 `${CLAUDE_SKILL_DIR}` 로 자기 폴더의 파일을 읽고, 이 치환은 플러그인 스킬과
  `.claude/skills/` 사본에서 다 풀린다. 대가 — 앵커볼트 이름이 둘 늘고, 마켓플레이스 매니페스트 ·
  `gates.sh` 의 `validate` 가 플러그인 둘을 본다.
- 2: 지도는 한 벌이라 갈리지 않는다. 대가 — 다른 레포의 세션은 지도를 네트워크로 읽고, 다른 레포에서 문서 대조 검사가 돌지
  않는다(조각 나눔 「다른 레포의 문서 대조 검사」).
- 4: 틀대로 선 레포에서 `audit-internal` 이 조각 폴더의 범위를 기준으로 쓰는지 수트가 잰다. 설명은 라우팅에 닿아 그대로
  둔다. 대가 — route 수트 한 번과 전수 한 번. `audit-internal` 은 천장까지 38 자라 문구를 넓히려면 압축이 먼저다.
- 5: 대장의 모양(앵커볼트)이 그대로다. 틀은 베끼면 그 레포의 문서가 되는 씨앗이고, 스킬 사본은 감사자처럼 견줄 공통 절이
  없다. 대가 — ERP 사본이 원본보다 뒤인지 아무도 찍지 않는다.
- 6: claude-kit 도 틀을 스킬 폴더에서 베낀다. `docs/procedure.md` 의 틀 자리 세 군데와 문서 대조 검사의 틀 자리를 함께
  고친다. 「…의 칸」 네 절은 그대로라 ADR 0010 의 8 에 닿지 않는다. 링크는 플러그인 폴더 밖(`docs/templates/`)을
  가리켜 설치가 거절하고(Claude Code 문서 「plugins/loading」 — 「path escapes plugin directory」), 두 벌은 게이트
  하나를 더 들인다.
- 7: 감사자 사본의 규칙(대장 · 일부만 있음 · 물러난 것 지우기)과 스킬 사본의 규칙(대장 없음 · 폴더째 덮기)이 섞이지 않는다.
  대가 — 심는 스크립트가 둘이다.
- 8: 플러그인마다 잰다. 대가 — 두 플러그인을 다 깐 세션의 상시 합은 아무도 재지 않는다. 합해서 재면 `vibe-slice` 가
  감사자 되먹임의 여유를 먹는다.
