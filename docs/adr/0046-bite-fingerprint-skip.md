# 0046 — 변조 시험은 검사 코드와 규칙 원천의 지문이 이미 통과했으면 CI 에서 건너뛴다

2026-10-22 · 결정함 · 1 ~ 3 은 저자가 이 착공 세션에서 정했다(세션이 근거와 함께 셋을 묻고 저자가 셋 다 세션이 추천한 쪽을 골랐다). 4 ~ 7 은
세션이 제안했다 — 착공 PR(조각 35 A)에서 저자가 본다

## 맥락

`gates.sh` 는 키 없이 도는 검사 스물넷을 돌리는데, 그 가운데 변조 시험 다섯(`bite-verify-docs.py` · `bite-slice-gate.py` · `bite-map-pin.py` ·
`bite-eval-merged-pass.py` · `bite-gates.sh`)이 gate 잡의 거의 전부다 — `main` 푸시 `f2e458d` 의 스텝 17분 9초 가운데 16분 38초(run 39761325720).
그 시간의 대부분은 문서 대조 검사의 자체 시험(약 12초)을 변조본 일흔둘에 다시 돌리는 데서 온다. 변조 시험은 검사 코드가 무는지를 보는데, 최근
머지된 PR 60 가운데 41 은 검사 코드도 그것이 규칙으로 읽는 파일도 바꾸지 않았다(조각 35 요구사항 「문제」). 감사자 수트는 같은 입력이 이미
통과했으면 다시 돌지 않는다 — 통과한 지문을 Actions 캐시에 적고, `main` 푸시는 머지된 PR 의 merge ref 도 읽는다(ADR 0021). 조각 나눔의 줄이 「무엇을
지문에 넣을지 · 건너뛸 때 무엇을 남길지」를 이 조각에 넘겼다.

## 대안

1. 줄이는 길: **지문이 이미 통과했으면 건너뛴다** / 변조 시험을 빠르게(변조본을 함께 돌리고 첫 실패에서 멈춘다) — 늘 돈다 / 둘 다 이 조각에서.
2. 지문에 드는 것: **검사 코드와 규칙의 원천 — 빼는 쪽(검사가 대조하는 문서와 기록 열한 꼴)만 적는다** / 검사 코드만(`scripts/` · 스킬의 `scripts/` ·
   `.github/`) / 기록만 뺀다(조각 폴더 · ADR · 작업 기록 · 마스터플랜 · README · `CHECKLIST.md`).
3. 로컬: **늘 다 돈다 — 건너뛰기는 CI 캐시를 읽을 때만** / 사람이 고르는 깃발(`--no-bite`) / 로컬 기록 파일.
4. 건너뛰는 몫: **변조 시험 다섯 — 검사와 자체 시험(`test-*.py`)은 늘 돈다** / 자체 시험까지.
5. 지문을 내는 곳: **새 스크립트 `gate-key.py`** / `eval-key.py` 에 셋째 모드.
6. `main` 푸시: **`eval-merged-pass.py` 를 그대로 다시 써 머지된 PR 의 merge ref 를 읽는다** / 변조 시험 몫의 판정을 따로 / 읽지 않는다(`main` 범위만).
7. 건너뛸 때 남기는 것: **통과한 실행의 URL · 커밋과 지문을 `::notice::` 와 `gates.sh` 의 끝 줄에** / notice 만 / 아무것도.

## 결정

굵은 쪽 일곱.

- 1 은 지문이 같은 PR 의 gate 잡을 17분에서 1분 남짓으로 줄인다 — 조각마다 착공 · 닫기와 그 `main` 푸시가 다 그렇다. 빠르게 하는 길은 늘 물지만 모든
  PR 이 여전히 몇 분이고 얼마나 줄지는 재 봐야 안다. 지문이 바뀐 PR 과 로컬의 17 ~ 20분은 남으므로 조각 나눔 「변조 시험 빠르게」로 넘긴다.
- 2 는 60 PR 에 대면 19 가 돌고 41 이 건너뛴다(검사 코드만이면 5 · 55, 기록만 빼면 23 · 37). 절차 지도의 「…의 칸」 · 틀 · 수트 케이스 · 대장은 검사가
  규칙의 원천이나 변조의 재료로 읽어, 바뀌면 변조본이 여전히 떨어지는지 다시 본다. 빼는 것은 검사가 **대조하는** 문서와 기록뿐이다 — 그 문서가 바뀌면
  늘 도는 검사와 자체 시험이 다시 대조한다. 넣는 쪽을 적지 않고 빼는 쪽만 적어, 새 파일은 저절로 지문에 든다(`eval-key.py` 와 같은 까닭).
- 3 은 클라우드 세션이 매번 새 클론이라 로컬 기록이 있어도 거의 못 쓰기 때문이다. 깃발은 「물었는지 안 본」 초록을 사람이 고를 수 있게 한다. 세션은
  지금처럼 빠른 검사만 손으로 돌리고, 스물넷은 CI 가 본다. `--skip-bite` 는 CI(`GITHUB_ACTIONS=true`)에서만 받는다.
- 4 는 건너뛰는 이유가 「검사 코드가 그대로라 변조본이 떨어지는지는 같다」이기 때문이다. 검사와 자체 시험은 대조하는 문서가 바뀌면 결과가 달라질 수
  있고, 다 합쳐 31초다.
- 5 는 두 지문의 넣고 빼는 규칙이 다르기 때문이다 — 수트 지문은 `vibe-audit/` 과 러너만 넣고, 변조 시험의 지문은 거의 다 넣는다. 한 파일의 두 모드면
  한쪽 규칙을 고칠 때 다른 쪽 시험까지 다시 봐야 하고, `eval-key.py` 를 고치면 수트 지문 시험(`keyed`)의 기준도 흔들린다.
- 6 은 그 판정이 키를 가리지 않고(ADR 0021 의 1 ~ 3), 같은 믿음의 범위 — 그 푸시를 머지 커밋으로 가진 PR 하나 — 가 변조 시험에도 맞기 때문이다. 읽지
  않으면 검사를 고친 PR 마다 머지 뒤 `main` 에서 17분이 한 번 더 돈다. 출력의 「수트가 돈다」만 「돈다」로 바꾼다.
- 7 은 건너뛴 실행이 무엇을 근거로 초록인지 로그만으로 따라가게 한다 — 수트의 「건너뛰는 근거」(`eval.yml`)와 같은 모양이다. `gates.sh` 의 끝 줄이 「스물넷
  다 통과」로 남으면 물지 않은 실행이 문 실행처럼 읽힌다.

## 결과

- 1: 지문이 같은 PR 은 gate 잡이 1분 남짓이다. 대가 — 지문이 바뀐 PR 과 로컬은 그대로 17 ~ 20분이다. 조각 나눔에 「변조 시험 빠르게」 줄이 생긴다.
- 2: 대가 — 빼는 문서를 바탕으로 쓰는 변조 시험(`test-verify-docs.py` 는 작업트리를 베껴 쓴다)이 그 문서가 바뀐 뒤에도 무는지는 넣는 쪽이 바뀌거나
  `workflow_dispatch` 일 때 본다. 빼는 쪽에 새 꼴을 더하려면 이 ADR 을 대체한다.
- 3: 대가 — 로컬의 `gates.sh` 는 그대로 약 20분이다. `GITHUB_ACTIONS=true` 를 손으로 주면 로컬도 건너뛴다 — 실수만 막는다.
- 4: 건너뛴 실행에서도 열아홉과 `claude plugin validate` 둘이 돈다.
- 5: `gates.sh` 의 검사 수는 스물넷 그대로이고, `gate-key.py` 의 시험은 `bite-gates.sh` 의 수트 지문 시험 옆에 둔다. `gate-key.py` 는 수트 지문 밖이다.
- 6: 대가 — gate 잡이 `main` 푸시마다 API 를 두 번 더 부를 수 있다(수트 지문이 `main` 범위에 없을 때와 겹치면 네 번).
- 7: 다시 돌리려면 Actions → Caches 에서 `gate-bite-` 로 시작하는 항목을 지우거나 `workflow_dispatch` 를 부른다.
- `eval.yml` 을 고치므로 그 PR 의 첫 머리에서 route 수트가 한 번 돈다(30회).
