# 0038 — `sync-agents.sh --merge` 는 밑을 그 커밋의 스크립트로 세우고, README 는 출처 SHA 만 바꾸며, 하나라도 걸리면 아무것도 쓰지 않는다

2026-10-18 · 결정함 · 일곱 다 저자가 착공 대화에서 정했다 — 세션이 손 병합 두 번(pdw96/ERP#111 · #113)의 재현에서 끌어내 추천한 쪽이다

## 맥락

특화가 있는 사본 레포(ERP)는 두 번 다 손으로 세 쪽 병합해 다시 심었다(ADR 0027 의 1 · ADR 0034 의 1). 조각 「사본 다시 심기」 C(#111)는 충돌
여덟을 저자가 풀었고, 조각 「사본을 0.4.1 로 다시 심기」 C(#113)는 같은 명령을 되풀이해 여덟 파일 충돌 0 이었다. 두 번 다 `.claude/agents/README.md`
의 출처 SHA 는 병합 밖에서 손으로 바꿨다. ADR 0027 의 1 이 `--merge` 를 미룬 까닭(「손 병합을 겪어 본 적이 없다」)은 두 번으로 풀렸고, 조각
「`brief-absent` 정규식의 머리 근거 한정」의 닫는 기록이 이 줄을 다음 조각으로 정했다(저자, 2026-10-18).

2026-10-18 에 두 번을 스크래치에서 재현했다(조각 27 요구사항 「문제」). ERP 는 익명 클론, claude-kit 은 역사 전체.

- **밑을 그 커밋의 `sync-agents.sh` 로 세우면** — `git worktree` 로 `synced_commit` 을 열고 그 커밋의 스크립트를 빈 자리에 돌린 모양이 밑이다. #111 은
  충돌 여덟(`audit-data` 1 · `audit-internal` 4 · `audit-quality` 2 · `audit-secrets` 1)으로 역사와 같고, 깨끗한 넷은 ERP `edab087` 과 바이트로 같다.
  #113 은 여덟 파일 다 충돌 0 이고 ERP `c9331a3` 과 바이트로 같다.
- **지금 스크립트의 awk · `HDR` 에 옛 SHA 만 넣으면** — #111 이 충돌 열넷이다. `3d6964a` 의 머리줄은 「이 레포에 맞게 고쳐도 된다 — 원본으로 되먹이지
  않는다」였고(조각 8 이 바꿨다), 밑의 머리줄이 사본과 달라 깨끗하던 셋까지 머리줄에서 걸린다.
- **README 를 같은 세 쪽 병합에 넣으면** — 두 번 다 충돌 1 이다. ERP 가 README 를 다시 써서 3 줄의 줄바꿈부터 생성본과 다르다. 출처
  `pdw96/claude-kit@<밑 SHA>` 한 자리를 새 SHA 로 바꾼 것은 두 번 다 ERP 의 실제 README 와 바이트로 같다 — 그 자리는 README 에 하나다.
- 두 번 다 `synced_commit` 과 HEAD 사이에 감사자 · 커맨드 · 검사기의 파일 집합이 같았다(원본에 새로 생기거나 물러난 파일이 없었다).

## 대안

1. README: **출처 SHA 치환 — `pdw96/claude-kit@<밑의 짧은 SHA>` 가 README 에 정확히 하나면 새 짧은 SHA 로 바꾸고, 0 이거나 둘 이상이면 멈춘다** / 감사자와
   같은 세 쪽 병합 / 건드리지 않고, README 가 옮겨지기 전에는 대장을 옮기지 않는다.
2. 밑: **`synced_commit` 의 작업트리에서 그 커밋의 `sync-agents.sh` 를 빈 자리에 돌린 모양** / 지금 스크립트의 awk · `HDR` 에 옛 SHA 만 넣은 모양.
3. 파일 집합이 다르면(원본에 새 파일 · 물러난 파일): **아무것도 쓰지 않고 멈춘다** / 새 파일은 심고, 물러난 파일은 사본이 밑과 같을 때만 지운다.
4. 시험 · 변조본의 자리: **`bite-gates.sh` 의 `sync-agents.sh` 절에 덧붙인다 — `gates.sh` 의 검사 수는 스물넷 그대로** / 새 `test-sync-agents.py` 를
   세우고 `gates.sh` 에 한 줄(스물다섯).
5. 충돌로 멈출 때: **사본에는 아무것도 쓰지 않고, 세 재료와 충돌 표시가 든 병합본을 사본 밖 임시 폴더에 남겨 그 경로를 찍는다** / 파일마다 충돌 수만
   찍고 아무것도 남기지 않는다.
6. 맞음을 보이는 것: **`bite-gates.sh` 의 시험에 더해, 손 병합 두 번을 ERP 익명 클론에서 재현한다 — #113 은 ERP 머지와 바이트로 같게 쓰고, #111 은
   충돌 여덟로 멈춰 아무것도 쓰지 않는다. ERP 에는 쓰지 않는다** / 시험만 — 실물은 다음 심기가 보인다.
7. PR 나눔: **착공 A 뒤 구현 B 하나 — 스크립트 · 시험 · 살아 있는 문서(`docs/architecture.md` · `README.md` · `CHECKLIST.md`)** / 스크립트 B 와 문서 C 를
   나눈다.

## 결정

굵은 쪽 일곱. 저자가 착공 대화에서 정했다(2026-10-18). 일곱 다 세션이 추천한 쪽이다.

- 1 은 손 병합 두 번이 README 에 한 일이 바로 그것이고, 재현에서 바이트로 같았기 때문이다. README 를 병합에 넣으면 README 를 다시 쓴 사본(ERP)에서
  늘 멈춰 `--merge` 가 그 레포에 쓰이지 않는다. 손으로 두면 대장과 README 가 함께 옮겨지는지를 사람의 기억이 든다 — 이 줄이 「README 를 어떻게
  옮길지」를 물은 까닭이다. 그 자리가 하나가 아니면 어느 것이 출처인지 스크립트가 가를 수 없으므로 멈춘다.
- 2 는 밑이 「그 사본이 받은 모양」이어야 병합이 사본의 고침만 사본의 몫으로 읽기 때문이다. 머리줄 꼴이 바뀐 사이(#111)에 지금 스크립트로 세우면
  사본이 고치지 않은 머리줄이 사본의 고침으로 읽혀 거짓 충돌이 여섯 더 난다. 그 커밋의 스크립트를 돌리면 그때의 머리줄 · 심는 자리 · 파일 집합이
  그대로 나온다. 옛 스크립트를 돌리는 것은 이 저장소의 역사이고, 빈 임시 자리 · 임시 작업트리에서만 돈다.
- 3 은 두 번 다 겪지 않은 꼴이라 규칙을 지어내지 않기 때문이다(`docs/procedure.md` 「빈자리」의 같은 원리). 겪으면 그때 손으로 하고 이 결정을 대체한다.
- 4 는 `sync-agents.sh` 의 시험이 이미 그 절에 있고 `--merge` 는 새 검사가 아니라 그 스크립트의 길 하나이기 때문이다. 절이 그 스크립트를 커밋한
  모양으로 clone 해 돌리므로 같은 틀을 쓴다.
- 5 는 충돌을 푸는 것이 그 레포의 일이고(ADR 0027 의 2 · `INTENT.md` Not 4), 푸는 사람이 세 재료를 손으로 다시 만들지 않게 하기 때문이다. 남기는
  자리는 사본 밖이라 「아무것도 쓰지 않는다」가 사본에 대해 그대로 참이다.
- 6 은 스크립트가 대신하는 것이 손 병합 두 번이라, 그 두 번이 같은 결과로 다시 나와야 대신한다고 말할 수 있기 때문이다. `ddcd21f` 뒤 원본
  감사자 · 커맨드 · 검사기가 움직이지 않아 지금 다시 심을 것이 없다 — 재현이 실물에 가장 가깝다. ERP 에 쓰면 원본의 고침이 없는 PR 이 된다.
- 7 은 스크립트와 그 스크립트를 설명하는 살아 있는 문서가 같은 고침이기 때문이다. 나누면 문서가 스크립트와 갈린 머리가 `main` 에 선다.

## 결과

- 1: README 는 감사자 · 커맨드 · 검사기의 병합과 같은 「다 되거나 아무것도 안 되거나」 안에 든다 — README 에서 멈추면 감사자도 쓰지 않는다. 생성본
  README(강호쟁패)도 같은 치환으로 옮겨진다 — 생성본의 출처 자리도 하나다.
- 2: `--merge` 는 `--force` 처럼 원본의 역사 전체가 있어야 한다 — 얕은 복제에서는 멈춘다. 대장에 그 사본의 줄이 있어야 한다(`synced_commit` 이 밑).
  그 커밋의 스크립트가 빈 자리에 심지 못하면 멈춘다. 짧은 SHA 의 길이가 그 사이 바뀌면 밑의 머리줄이 사본과 달라 충돌로 멈춘다 — 안전한 쪽이다.
- 3: 원본에 감사자 · 커맨드 · 검사기가 새로 생기거나 물러난 뒤의 첫 심기는 `--merge` 가 멈추고, 그 심기는 ADR 0027 의 손 병합으로 한다.
- 4: `gates.sh` 는 고치지 않는다. 변조본은 `--merge` 가 충돌 · README · 파일 집합 · `verify-copy.py` FAIL 에서 아무것도 쓰지 않는지와, 충돌 없는 병합이
  사본의 특화를 지키고 대장을 옮기는지를 문다.
- 5: 멈출 때 찍는 임시 폴더는 스크립트가 지우지 않는다 — 다 쓰면 사람이 지운다.
- 6: 재현의 명령 · 파일별 표는 B 의 PR 본문에 싣고, 스크래치 · 클론은 저장소에 싣지 않는다.
- 7: ADR 0027 의 1(ERP 는 손으로 세 쪽 병합)과 CHECKLIST 「대장을 건드렸다면」 첫 줄의 예외는 이 조각 B 가 머지된 뒤의 심기부터 `--merge` 가 대신한다
  — 3 의 경우와 `--merge` 가 멈춘 경우만 손 병합이 남는다. ADR 0027 은 고치지 않는다.
