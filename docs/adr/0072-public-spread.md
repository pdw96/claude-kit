# 0072 — 밖 사용자는 받아 쓰게만 하고, 영어 입구는 `README.en.md` 하나로 `vibe-audit` 를 앞세우며, 감사자 · 스킬 · 매니페스트는 한국어 그대로 둔다

2026-11-03 · 결정함 · 1 ~ 4 는 저자가 조각 53 의 착공 세션에서 정했다(세션이 갈래마다 추천을 앞에 두고 물어, 저자가 넷 다 추천한 쪽을 골랐다). 5 ~ 8 은 세션이 정했고 착공 PR 에서
저자가 본다

## 맥락

조각 나눔 「공개 확산」은 다른 사람이 설치해 쓰게 하는 조각이다. 「차별점으로 좁히기」가 루트 `README.md` 에 「무엇이 다른가」 절을 세웠고, 이 조각이 그 주장을 영어로 옮긴다.

- **의도가 밖 사용자를 들지 않는다** — `INTENT.md` Why 는 저자 레포의 사본 → 원본 되먹임만 든다. 마스터플랜의 그 줄이 「착공에서 범위 변경이 먼저」라 적었다.
- **저장소는 이미 공개다** — `pdw96/claude-kit` 는 public · MIT 다(2026-11-03 확인). 빈 HOME 에서 `README.md` ① 의 명령 셋이 그대로 돌아 `vibe-audit` 0.4.8 · `vibe-slice` 0.9.3 이
  깔렸다(CLI 2.1.317, 모델 호출 없음). 밖 사람을 막는 것은 길이 아니라 입구다.
- **도구는 한국어로 말한다** — 감사자 여섯의 설명(세션이 감사자를 고르는 트리거 문장) · 본문 · 공통 절, `vibe-slice` 의 스킬 · 틀 · 절차 지도가 다 한국어다. route 수트의 요청과
  맞대기의 요청 본문(`compare/prompts/`)도 한국어다 — 영어 요청에서 감사자가 뜨는지는 잰 적이 없다.
- **README 를 무는 것** — `scripts/verify-counts.py` 가 `README.md` 의 한국어 문장 넷에 닻을 두고 「설치 — 경로가 셋인 이유」의 표 줄을 원천으로 센다. 다른 살아 있는 문서
  · 기록이 README 의 절을 이름으로 가리킨다. 살아 있는 문서의 목록은 `docs/procedure.md` 「살아 있는 문서와 기록」이 들고, 수를 늘리려면 ADR 로 정한다(ADR 0011).
- **감사 기록이 남긴 문구 둘** — 회차 29 OB-29 · 회차 27 OB-1: README 의 「로컬 개발에만 쓰는 값을 고칠 결함으로 올리지 않는다」는 `trap-local-dev-password` 에서 `vibe-audit` 가 그 값을
  **확인불가로 냈다**는 뜻이다 — 「로컬 전용이라 결함 아님」으로 닫은 회차는 없고, 감사자 공통 절은 확인불가를 통과 여부에서 부적합과 같이 다룬다. 회차 29 OB-28: README 의
  회차당 원값 「`pr-review-toolkit` $0.48」은 조각 51 의 값이고, 표의 `trap-local-dev-password` 칸 세 회차는 리뷰 에이전트를 띄우지 않은 회차당 $0.145 다. 두 기록 다 「공개 확산」이 옮길 때 볼
  자리라 적었다.

## 대안

1. 밖 사용자를 들이는 법: **받아 쓰게만 한다 — Why 에 밖 사용자를, Not 에 「밖 사용자의 보고를 되먹임으로 들이지 않는다」를 더한다** / 밖 이슈도 「다른 레포에서도 같은 말인가」로
   갈라 후보 대장에 들인다(이슈 틀 · 대장 줄의 출처 칸).
2. 영어로 옮길 범위: **README 만** / README 와 매니페스트 설명(`marketplace.json` · `plugin.json` 의 `description`) / 감사자 설명(트리거)까지 영어를 더하고 영어 요청에서 뜨는지 잰다.
3. 영어 README 의 자리: **`README.en.md` 를 새로 두고 `README.md` 맨 위에 그리로 가는 한 줄** / `README.md` 를 영어로 바꾸고 한국어를 `README.ko.md` 로 옮긴다 / `README.md` 한 파일
   위에 영어, 아래에 한국어.
4. 앞세울 것: **`vibe-audit` — 감사자 여섯 · 맞대기의 주장 · 마켓플레이스 설치. `vibe-slice` 는 한국어 절차에 묶인 문서 틀로 한 단락** / 두 플러그인을 같은 무게로.
5. 두 벌의 주인과 수: **`README.en.md` 는 `README.md` 의 옮김이다 — 주장 · 숫자 · 한계의 주인은 `README.md` 와 eval-log 다. 영어 README 에 적는 수는 아라비아 숫자로 쓰고
   `verify-counts.py` 의 닻에 더한다. `README.md` 를 고치는 PR 이 `README.en.md` 를 함께 고친다는 줄을 `CHECKLIST.md` 에 둔다** / 닻 없이 `CHECKLIST.md` 만 / 두 파일의 절 대응을 무는 새 검사.
6. 감사 기록이 남긴 문구 둘: **주장은 글자 그대로 두고, 두 README 의 「한계」에 사실 둘을 더한다 — `trap-local-dev-password` 에서 `vibe-audit` 는 그 값을 확인불가로 냈다, 그 케이스의
   `pr-review-toolkit` 세 회차는 리뷰 에이전트를 띄우지 않았고 회차당 원값이 따로다** / 지금 문장 그대로 옮긴다 / 주장을 고친다(ADR 0069 의 2 를 대체).
7. 설치가 서는지: **구현 PR 이 빈 HOME 에서 `README.en.md` 의 설치 명령을 글자 그대로 돌려 두 플러그인이 그때의 판으로 깔리는 것을 PR 본문에 보인다 — 모델 호출 없음** / 보이지
   않는다 / 게이트로 세운다.
8. 밖 사용자에게 보일 설치 경로: **① 마켓플레이스를 명령과 함께 앞세우고, ② 계정 동기화는 한 문장(앱에서 연 클라우드 세션에서 한 번 잰 것), ③ 레포 사본과 버그 표는 한국어
   README 로 가리킨다** / 셋 다 옮긴다 / ① 만.

## 결정

굵은 쪽 여덟.

- 1 — 저자가 정했다. 밖 이슈를 대장에 들이면 「다른 레포에서도 같은 말인가」를 가를 그 레포가 저자에게 없다 — 사본 레포의 되먹임은 저자가 그 레포의 맥락을 알아 가른다.
  이슈 틀 · 출처 칸은 대장의 모양(앵커볼트)을 건드린다. 밖 이슈는 읽을 수 있고, 저자가 자기 레포에서 같은 결함을 보면 그 길로 들어온다.
- 2 — 저자가 정했다. 매니페스트 설명을 바꾸면 `plugin.json` 이 수트 지문에 들어 route 수트가 돌고, 두 판을 올려 설치한 레포가 새 판을 받게 된다. 감사자 트리거를 영어로 넓히면 글자
  예산 · 수트 · 사본 · 공통 절이 다 갈리고 측정이 든다 — 이 조각이 커진다. 대가는 README 의 한계로 진다: 도구는 한국어로 말하고, 영어 요청에서 뜨는지는 재지 않았다.
- 3 — 저자가 정했다. `README.md` 를 옮기면 다른 문서가 이름으로 가리키는 절 · `verify-counts.py` 의 닻 넷과 원천 하나를 함께 옮겨야 한다. 한 파일에 두 말을 두면 한 쪽만 고쳐지는
  자리가 한 파일 안에 생긴다. 대가 — GitHub 첫 화면은 한국어이고 맨 위 한 줄이 영어 입구로 보낸다. 살아 있는 문서가 하나 는다(ADR 0011 의 규칙 — 이 ADR 이 그 결정이다).
- 4 — 저자가 정했다. 잰 차별점은 `vibe-audit` 에만 있다(ADR 0069 의 2). `vibe-slice` 의 틀 · 절차 지도 · 검사의 출력이 한국어라, 영어로 깊이 설명하면 README 가 약속하는 것과 받는 것이
  갈린다.
- 5 — 영어 수 낱말(「six」)은 `verify-counts.py` 가 읽지 못한다(그 검사의 L 은 고유어 수와 아라비아 수를 읽는다). 아라비아 숫자로 쓰면 있는 검사의 닻 목록에 줄을 더하는 것으로 물리고
  새 검사가 서지 않는다 — `CHECKLIST.md` 「항상」이 이미 「수를 새로 적었다면 닻」을 묻는다. 절 대응을 무는 검사는 새어 나간 결함 없이 세우는 장치다(마스터플랜 「새 장치는 새어 나간
  결함에만」). 문장의 번역이 맞는지는 무는 것이 없다 — 사람이 본다.
- 6 — 두 감사 기록이 적은 사실은 원문과 맞는다. 주장 문장은 저자 결정(ADR 0069 의 2)이라 이 조각이 바꾸지 않고, 영어로 옮기며 「로컬 전용이라 결함이 아니라고 판단한다」처럼 원문보다
  강하게 쓰지 않는다. 사실 둘을 한계에 두면 밖 사람이 표의 2/3 · 1/3 을 원문과 같은 뜻으로 읽는다. 영어에만 두면 두 벌이 갈리므로 한국어 README 도 같은 PR 에서 고친다.
- 7 — README 의 설치 명령은 밖 사람이 가장 먼저 그대로 붙여 넣는 글이다. 빈 HOME 에서 도는 데 키 · 모델 호출이 들지 않는다. 게이트로 세우면 네트워크가 드는 검사가 된다 — 키 없이 도는
  게이트의 목록(`gates.sh`)은 네트워크를 쓰지 않는다.
- 8 — 마스터플랜의 그 줄이 「밖 사용자의 설치 경로 하나(마켓플레이스)를 앞세우기」라 적었다. ② 는 claude.ai 계정이 있는 밖 사람에게도 열린 길이라 한 문장으로 두고, 2026-10-30 에 한 번
  잰 것이라고 적는다. ③ 은 특화가 있는 저자 레포의 길이고 버그 표는 그 길의 근거라 한국어 README 가 든다.

대가 — 밖 사람은 영어 입구를 읽고 한국어로 말하는 도구를 받는다. 영어 요청에서 감사자가 뜨는지 · 영어 저장소에서 같은 판정이 나오는지는 재지 않은 채로 둔다. 밖 사람의 보고는
대장에 들어오지 않는다.
