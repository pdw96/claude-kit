# 0054 — 변조본을 도는 절은 센 수 · 좁힌 「물었다」 · 대조군의 PASS 줄을 본다

2026-10-27 · 결정함 · 1 ~ 3 은 저자가 조각 41 의 착공 세션에서 정했다(세션이 지금 절 44 개를 세 규칙에 대 본 목록을 보이고 소급 범위 · 「규칙마다 변조본」 ·
규칙 글의 자리를 물어, 저자가 세션이 추천한 쪽을 골랐다). 4 · 5 는 세션이 제안했고 착공 PR 에서 저자가 본다

## 맥락

`audit-quality` 가 변조 시험 절의 같은 꼴을 네 회차에 걸쳐 관찰로 냈다 — 회차 4 OB-4 (나) · 5 OB-1 · 6 OB-1 · 7 OB-1. 꼴은 셋이다. (가) 돈 변조본의 수를
기대한 수와 견주지 않는다. (나) 0 이 아닌 아무 종료를 「물었다」로 센다. (다) 대조군이 종료 0 만 본다. 그때마다 짚은 절만 고쳤고, 회차 6 의 저자 판정이 규칙을
조각 나눔의 줄로 넘겼다. 회차 7 은 거기에 「검사의 규칙마다 그 규칙으로만 떨어지는 변조본」의 범위를 함께 정하자고 제안했다.

`main` `8d3e7d0` 에서 그런 절은 44 개다(`bite-gates.sh` 30 · `bite-*.py` 4 · `test-*.py` 10 — 조각 41 설계 ③ A). (가) 를 갖춘 절은 2 개, (나) 를 규칙의 글이나
ID 로 좁힌 절은 6 개, (다) 를 갖춘 절은 4 개다. 검사 가운데 실패 줄에 규칙 ID 를 찍는 것은 여섯이고, 나머지는 자유 글로 찍는다. `CLAUDE.md` 「작업 방식」과
`CHECKLIST.md` 는 「새 검사에 떨어지는 변조본을 함께 넣는다」까지만 적는다.

## 대안

1. 소급 범위: **(가) · (다) 는 44 절 전부, (나) 는 ID 가 있는 검사에서 ID 까지 · 자유 글 검사는 종료 코드와 실패 머리 줄까지** / 셋 다 전부(자유 글 검사도
   변조본마다 기대 글) / 규칙만 세우고 소급하지 않는다(앞으로 고치는 절만) / 두지 않는다는 결정을 이 ADR 로 남긴다.
2. 규칙마다 변조본: **ID 를 찍는 검사 여섯만 정적 대조** / 범위 밖으로 두고 ADR 에만 / 모든 검사에 규칙 ID 를 들여 다 대조.
3. 규칙 글의 자리: **`CLAUDE.md` 「작업 방식」과 `CHECKLIST.md` 둘 다** / `CHECKLIST.md` 만 / `bite-gates.sh` 머리 주석.
4. 고치는 것: **변조 시험 · 자체 시험만 — 검사 코드 · `--first` · `gates.sh` 의 목록은 그대로** / 좁히기 쉽게 검사의 출력도 고친다.
5. PR 나눔: **B(`bite-gates.sh` · 규칙 글) · C(`bite-*.py` · `test-*.py`)** / 하나로 / 규칙 글을 따로 먼저.

## 결정

굵은 쪽 다섯.

1. **센 수와 대조군은 값이 싸서 다 단다** — 절마다 상수 하나와 비교 한 줄, 대조군마다 PASS 줄 한 grep 이다. 좁히기는 검사가 ID 를 찍을 때만 ID 까지 간다.
   자유 글 검사에 변조본마다 기대 글을 달면 검사의 문장을 고칠 때마다 변조 시험이 함께 깨지고, 그 대가에 비해 막는 것(다른 규칙이 대신 무는 꼴)이 좁다. 자유 글
   검사도 「0 이 아닌 아무 종료」는 버린다 — 트레이스백 · 자원으로 죽은 실행이 「물었다」로 숨는 것이 회차 4 OB-4 의 다른 반이었다. 저자가 골랐다.
2. **규칙마다는 ID 가 있는 곳에서만 기계로 본다** — 여섯은 검사가 낼 수 있는 ID 를 코드에서 셀 수 있고, `sync-agents.sh --merge` 는 이미 같은 대조를 한다
   (`bite-gates.sh` 의 V5). 자유 글 검사에 ID 를 들이면 검사 출력이 바뀌고 수트 지문에 드는 `verify-evals.py` · `verify-graders.py` 까지 닿아 route 수트가 돈다.
   저자가 골랐다.
3. **세션이 매번 읽는 자리와 PR 마다 보는 자리에 다 둔다** — `CLAUDE.md` 의 그 줄은 이미 「새 검사를 세우면 변조본을 함께 넣는다」를 들고, 세 규칙은 그 변조본의
   모양이다. `CHECKLIST.md` 는 PR 을 낼 때 사람이 짚는다. 머리 주석은 그 파일을 고치는 세션만 본다. 저자가 골랐다.
4. **판정을 바꾸지 않는 조각이다** — 고치는 것이 검사가 아니라 검사를 재는 쪽이라, 검사 코드가 그대로면 「고치지 않은 원본 트리에서 모든 절이 지나간다」가 원본의
   동작이 그대로라는 근거가 된다. `--first` 는 문서 대조 절의 시간을 지키려 섰다(ADR 0047). 정적 대조는 이미 도는 절 안에 두어 `gates.sh` 와 `test-gates.py` 의
   고정 목록이 그대로다(ADR 0049).
5. **파일이 겹치지 않는 둘로 나눈다** — `bite-gates.sh` 만으로 30 절이고, 열네 파일을 더하면 리뷰가 길다. 규칙 글은 앞 PR 에 실어 뒤 PR 이 그 규칙을 따라 쓴다.
   어느 쪽도 수트를 돌리지 않아 나눠서 더 드는 돈이 없다.

## 결과

- 1: 끝 줄의 글자로 박은 수가 사라지고, 목록과 기대 수의 두 벌이 선다 — 갈리면 떨어진다. 함께 고친 PR 은 리뷰가 본다. 자유 글 검사에서 규칙 하나가 죽어도 다른
  규칙이 같은 변조본을 떨어뜨리면 지나간다 — 남는 한계다.
- 2: 여섯 검사에 새 ID 를 더하면 그 ID 의 변조본이 없을 때 빨강이다. 자유 글 검사는 사람이 본다.
- 3: `CLAUDE.md` 「작업 방식」의 한 줄이 길어진다. 절 제목은 그대로다.
- 4: 좁히다 검사의 결함이 드러나면 이 조각에서 고치지 않고 조각 나눔에 줄을 더한다.
- 5: 구현 PR 마다 변조 시험 지문이 바뀌어 CI 가 변조 시험까지 돈다(약 7 분). 수트 비용은 없다. 관찰을 닫는지는 닫기 전 `audit-quality` 회차가 본다.
