# 0020 — 「게이트가 무는가」를 `eval.yml` 에서 `gates.sh` 가 부르는 `bite-gates.sh` 로 옮긴다

2026-10-12 · 결정함 · 1 ~ 4 는 저자가 착공 전 인터뷰에서 정했다. 5 · 6 은 세션이 저장소 규칙에서 끌어내 제안했고, 착공 PR 에서 저자가 확인한다

## 맥락

키 없는 검사가 무는지는 CI 「게이트가 무는가」 스텝(`eval.yml` 70 ~ 778 줄, 멈춤 자리 63)이 변조본으로 본다. `eval.yml` 은 수트에 깃발을
넘겨 통째로 수트 지문(`eval-key.py`)에 들어, 변조본만 고쳐도 route 수트가 다시 돈다 — 조각 3 #18 은 네 번 돌았고, 그 스텝이 선 뒤
`eval.yml` 을 고친 커밋 59 가운데 40 이 그 스텝 안만 고쳤다(2026-10-12 에 셌다). 그래서 조각 7 · 9 · 10 은 제 변조본을 `gates.sh` 가 부르는
`bite-*.py` 셋에 두었고(ADR 0016 의 6 · ADR 0018 의 6 · ADR 0019 의 5), 변조본이 두 자리로 갈렸다. 스텝 안의 둘 —
`claude plugin validate` 변조본과 가짜 트레이스의 모델 id — 은 조각 4 #22 Codex 3회차가 짚어 이 조각으로 넘겨 왔다.

스텝은 CI 에서만 돌게 짜였다. `$GITHUB_WORKSPACE` 를 읽고, `copies.json` 과 지문 시험의 파일 열을 제자리에서 흔든 뒤 `git checkout --`
으로 되돌린다 — 로컬에서 돌리면 그 파일의 커밋 안 한 수정이 지워진다. 이 세션의 컨테이너에서 `gates.sh` 는 2분 31초, 스텝 본문은 3분
41초 걸렸다.

## 대안

1. 옮긴 파일을 부르는 자리: **`gates.sh` 가 부른다 — 키 없이 도는 것의 목록이 한 군데다** / `eval.yml` 의 스텝이 그 파일 하나만 부른다 —
   CI 에서만 돌고 로컬 `gates.sh` 는 지금 속도.
2. 꼴: **bash 한 파일 `scripts/bite-gates.sh` 로 글자 그대로 옮기고, CI 에 기댄 자리만 고친다** / 검사마다 `bite-<검사>.py` 로 다시 쓴다 —
   기존 셋과 같은 꼴 / 검사마다 bash 파일로 나눈다.
3. 제자리 변조의 되돌림: **흔들기 전에 임시 폴더로 베끼고 거기서 되돌린다 — trap 으로 끊겨도** / 그 파일에 커밋 안 한 수정이 있으면
   흔들기 전에 멈추고 `git checkout --` 은 그대로 / 저장소를 임시 폴더에 clone 해 거기서 흔든다.
4. 넘겨받은 둘: **모델 id 는 `run-evals.sh` 의 `DEFAULT_MODEL` 에서 읽고, `claude plugin validate` 변조본은 두지 않는다** / 둘 다 한다 /
   둘 다 하지 않고 조각 나눔에 줄로 넘긴다.
5. `eval.yml` 을 고치는 길: **스텝을 지우는 것과 `bite-gates.sh` 를 세우는 것을 한 PR 에, `eval.yml` 은 첫 머리의 지움으로만** / 먼저
   `bite-gates.sh` 를 세워 `gates.sh` 가 부르게 하고 스텝을 지우는 것은 다음 PR 로 — 그 사이 CI 에서 변조본이 두 번 돈다.
6. 변조본 파일이 지문 밖인지: **`bite-gates.sh` 가 `eval-key.py route --list` · `full --list` 를 읽어 `gates.sh` · `bite-*` 가 들면 멈춘다** /
   지문 시험(`keyed same`)에 `bite-gates.sh` 를 더한다 / 보지 않고 사람이 본다.

## 결정

굵은 쪽 여섯. 1 ~ 4 는 저자가 착공 전 인터뷰에서 정했다(2026-10-12) — 넷 다 세션이 추천한 쪽이다. 5 · 6 은 세션이 저장소 규칙에서 끌어내
제안했다.

- 1 은 `CLAUDE.md` 「작업 방식」(키 없이 도는 검사의 목록은 `gates.sh` 한 군데)을 따른다. CI 만 부르면 지문 밖으로는 나가지만 변조본이
  여전히 `gates.sh` 의 `bite-*.py` 셋과 CI 두 자리로 갈리고, 로컬에서 검사를 고친 세션은 변조본이 무는지 푸시해야 안다.
- 2 는 옮김을 읽을 수 있게 한다 — 기준 스텝과 새 파일의 diff 가 고친 자리뿐이다. 706 줄을 Python 으로 다시 쓰면 변조 한 자리가 무르게
  되어도 diff 로 보이지 않는다. 기존 `bite-*.py` 셋은 검사 하나의 자리를 하나씩 망가뜨리는 꼴이라 Python 이 맞았고, 이 스텝은 열세 검사를
  셸 · 임시 폴더 · 가짜 하네스로 흔드는 꼴이다.
- 3 은 1 의 값이다. `gates.sh` 는 커밋 전에 돌리는 것이라 작업트리가 더럽다. 멈추는 안은 조용히 지우지는 않지만 검사를 고치는 바로 그때
  `copies.json` · `run-evals.sh` 를 고친 세션의 `gates.sh` 를 막는다. clone 안은 커밋 안 한 검사를 보지 못한다 — `verify-copies.py` 를 고친
  수정이 변조본에 닿지 않는다.
- 4 의 모델 id 는 스텝이 지문 밖으로 나가면 `run-evals.sh` 를 읽어도 비용이 없다 — `CLAUDE.md` 「스택」의 「따라 고친다」가 지워진다.
  `claude plugin validate` 는 이 저장소의 검사가 아니라 CLI 의 것이고, CLI 판을 고정하지 않아(`CLAUDE.md` 「스택」) 변조본이 하네스를 따라
  깨질 수 있다.
- 5 는 지문이 내용이라 된다 — `eval.yml` 이 첫 머리 뒤로 같은 바이트면 다음 머리들은 같은 지문으로 건너뛴다. 두 PR 로 나눠도 `eval.yml` 을
  고치는 것은 한 번이라 수트 횟수는 같고, 그 사이 변조본이 CI 에서 두 번 돌며 문서가 두 자리를 말한다.
- 6 의 `keyed same` 은 돌고 있는 `bite-gates.sh` 자신을 고쳐 흔든다 — bash 는 스크립트를 읽어 가며 돌린다. 목록을 읽는 것은 아무것도
  흔들지 않는다.

## 결과

- 1: `gates.sh` 의 끝 개수가 스물하나에서 스물둘이 된다. 대가 — 로컬 `gates.sh` 가 6분 남짓이 된다. `CLAUDE.md` 「작업 방식」 ·
  `CHECKLIST.md` 의 「CI 「게이트가 무는가」나 `gates.sh`」가 `gates.sh` 하나가 된다.
- 2: `bite-gates.sh` 는 `::error::` 를 그대로 찍는다 — CI 에서는 주석이 되고 로컬에서는 글자다. 대가 — 변조본 파일이 bash 하나와 Python
  셋으로 꼴이 둘이다.
- 3: 로컬에서 돌려도 작업트리가 그대로다. 대가 — SIGKILL 에는 trap 이 돌지 않는다. 베낀 자리를 찍어 손으로 되돌릴 수 있게 한다.
  `sync-agents.sh` 블록은 여전히 커밋을 clone 한다 — 로컬의 커밋 안 한 `sync-agents.sh` 는 보지 않는다(옮기기 전과 같다).
- 4: 수트 모델을 바꾸는 PR 이 변조본을 고치지 않는다. `docs/architecture.md` 의 「`claude plugin validate` 를 떨어뜨리는 변조본은 없다」가
  그대로다 — 조각 4 가 넘긴 둘 가운데 하나는 이 ADR 로 닫고 줄을 더하지 않는다.
- 5: route 수트가 이 조각에서 한 번 돈다. 대가 — 스텝을 지우는 PR 이 리뷰 고침으로 `eval.yml` 을 다시 고치면 한 번 더 돈다.
- 6: 러너가 변조본의 이름을 적게 되는 고침이 `gates.sh` 에서 떨어진다.
