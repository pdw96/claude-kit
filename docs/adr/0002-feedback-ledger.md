# 0002 — 후보 대장은 JSON 이고, 후보는 내용 해시로 알아본다

2026-10-05 · 결정함

## 맥락

판정한 결과가 남는 자리가 없어서, 특화로 기각한 차이가 다음 비교에서 다시 올라온다(PRD 문제).
대장의 형식과, 같은 후보를 무엇으로 알아볼지를 정해야 했다.

## 대안

- 형식: **`feedback.json`** / 마크다운 표(`docs/feedback.md`) / 둘 다(JSON 원본 + 생성된 보기)
- 식별: **사본 문구의 내용 해시** / 파일 · 절 제목

## 결정

`copies.json` 옆에 `feedback.json` 을 둔다. 후보는 덩어리의 원본 쪽 · 사본 쪽 줄을 정규화해
만든 sha256 으로 알아본다. 모양은 `docs/schema.md`.

## 결과

- `verify-copies.py` 처럼 게이트가 대장이 성한지 물 수 있다. 마크다운 표는 파싱해야 물 수 있고,
  둘 다 두면 두 군데 적히는 것을 막을 게이트가 또 필요하다.
- 줄이 옮겨져도 같은 후보로 본다. 절 제목은 한 절에 변경 둘이 있으면 섞인다.
- 사본이 문구를 고치면 새 후보가 된다. 뜻이 바뀌었을 수 있으므로 다시 보는 쪽을 택했다.
- 판정 이유가 JSON 문자열 칸이라 긴 서술에는 불편하다. 길면 PR 본문에 쓰고 칸에는 요지를 적는다.
