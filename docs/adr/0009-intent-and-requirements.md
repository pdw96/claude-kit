# 0009 — 의도는 `INTENT.md` 로 떼고, 조각 문서는 `requirements.md` · `design.md`, 작업 목록은 빈자리

2026-10-06 · 결정함 · ADR 0007 의 「주인 없는 값」 자리와 ADR 0008 의 `plan.md` 이름을 대체한다

## 맥락

저자가 인터넷에서 `INTENT.md`(Why · What · Not)를 보고 물었다. 찾아보니 표준은 아니고(형식을 내는 곳이 여럿, 자동으로
읽는 도구 없음) 하는 일은 마스터플랜 「목표와 범위」와 같았다. 같은 흐름의 문서를 더 보니 GitHub Spec Kit
(`spec.md` · `plan.md` · `tasks.md`)과 Kiro(`requirements.md` · `design.md` · `tasks.md`)가 조각마다 세 문서를
둔다. Spec Kit 의 `plan.md` 는 기술 설계라 우리 `plan.md`(무엇을 · 왜)와 뜻이 정반대였다.

## 대안

1. 의도: **`INTENT.md` 로 뗀다** / 마스터플랜 안에 둔다.
2. 조각의 무엇을 · 왜: **`requirements.md`**(Kiro 와 같은 뜻) / `spec.md`(Spec Kit) / `plan.md` 유지.
3. 작업 목록(`tasks.md`): **빈자리로 둔다** / 조각 폴더에 틀까지 둔다.

## 결정

굵은 쪽 셋 — 저자가 인터뷰에서 하나씩 정했다.

## 결과

- 바뀌는 빈도가 다른 것이 갈린다 — 의도는 범위가 바뀔 때만, 조각 나눔은 조각을 닫을 때마다 고친다. 범위가 바뀌면
  `INTENT.md` 의 What · Not 을 고치고 마스터플랜 「범위 변경」에 한 줄을 남긴다.
- `INTENT.md` 는 자동으로 읽히지 않는다 — `CLAUDE.md` 가 가리킨다. 다른 문서(프로젝트 전체를 다루는 `PRD.md` 등)가
  이미 의도를 들면 새로 쓰지 않고 가리킨다.
- 조각 문서의 이름이 Kiro 와 같은 뜻이라, 그 도구를 아는 사람 · AI 가 이름만 보고 바르게 읽는다.
- 작업 목록은 설계 ⑥ 의 PR 나눔과 PR 의 상태가 맡는다. 두 도구가 `tasks.md` 를 둔다는 것은 지도의 빈자리
  「진척 관리」의 참고로만 적는다(조각 2 요구사항 하지 않을 일 6).
