# claude-kit

Claude Code 플러그인 마켓플레이스. **원본과 이력이 사는 곳**이고, 실제로 프로젝트에서 뜨는 것은 여기가 아니라 각 레포의 사본이다.

## 들어 있는 것

| 플러그인 | 무엇 |
|---|---|
| `vibe-audit` | 목적별로 범위를 좁힌 읽기전용 감사자 6종 — 시크릿 · 데이터 · 검사장치 · 운영 · 계약 · 내부규칙 |

## 배포 경로가 둘인 이유

**하나로 안 된다.** 프로젝트 레포가 `.claude/settings.json` 에 마켓플레이스를 선언해서 세션이 자동으로 받게 하는 길(`extraKnownMarketplaces` · `enabledPlugins`)이 열린 버그 셋을 달고 있다.

| 이슈 | 증상 |
|---|---|
| [#78119](https://github.com/anthropics/claude-code/issues/78119) | 클라우드 샌드박스 · CI 에서 통째로 무시된다 |
| [#32606](https://github.com/anthropics/claude-code/issues/32606) | 로컬에서도 자동 설치 안 됨. 오류도 안 뜬다 |
| [#13097](https://github.com/anthropics/claude-code/issues/13097) | 대화형 신뢰 승인을 요구 — 헤드리스 불가 |

그래서 **대화형 세션은 마켓플레이스로, 클라우드 레인은 레포 사본으로** 받는다. 위 버그가 닫히면 사본을 걷을 수 있다.

### ① 대화형 세션 — 마켓플레이스

계정에 한 번만 붙이면 로컬에서 여는 모든 레포에 뜬다.

```bash
claude plugin marketplace add pdw96/claude-kit
claude plugin install vibe-audit@pdw96-kit
```

호출 이름이 `@vibe-audit:audit-secrets` 로 **스코프가 붙는다.**

### ② 클라우드 레인 — 레포 사본

`claude/...` 가지에서 도는 세션은 위 경로를 받지 못한다. 그 레포의 `.claude/agents/` 에 파일이 있어야 뜬다.

```bash
./scripts/sync-agents.sh ~/src/ERP
```

호출 이름은 스코프 없이 `@audit-secrets`.

## 사본은 갈려도 된다 — 방향만 정해 둔다

> **특화는 되먹이지 않는다. 결함은 되먹인다.**

감사자는 레포를 읽을수록 좋아진다. 체크 항목이 「테스트가 있는가」에서 「골든케이스가 기준일을 고정하는가」로 내려가는 순간 값이 나온다 — 그런 항목은 그 레포에서만 참이므로 **사본에만 산다.**

그래서 사본을 고친 것을 여기로 올리지 않는다. 여기는 아무 레포에도 안 들어가 본 일반형으로 남아 있어야 다음 프로젝트에 부을 수 있다.

`sync-agents.sh` 가 각 파일 머리에 출처 커밋을 박아 두므로, 사본이 얼마나 멀어졌는지는 그 줄로 잰다.

**다만 사본에서 나온 것이 전부 특화는 아니다.** 감사자 자체가 잘못 설계됐거나 빠진 것이 있으면 그것은 어느 레포에서도 참이므로 **여기로 가져온다.** 가르는 질문 하나 — **다른 레포에서도 같은 말인가.** 그렇다면 결함이고, 이 레포에서만 참이면 특화다.

써 보기 전에는 알 수 없는 것들이 있어서 이 경로가 필요하다. 예를 들어 세 도구로는 diff 를 구할 수 없다는 것은 첫 감사를 돌리고 나서야 드러났다.

**첫 되먹임에서 일곱이 왔다** (ERP, 2026-09-16). 그중 셋은 감사자가 **거짓 판정**을 내게 하던 자리였다 — 로컬 전용 개발 비밀번호를 시크릿으로 거는 것, 저장소에 흔적이 없다고 롤백을 「안 해 봤다」로 단정하는 것, 라이브니스 프로브의 정상 설계를 부적합으로 보는 것. 거짓 지적을 두어 번 내면 아무도 감사자를 안 부르므로, 이 부류는 되먹임 중에서도 가장 급하다.

**둘째 되먹임은 한 건인데 가장 컸다** (ERP, 2026-09-20). 한 조각에 부적합 서른셋이 나왔는데 **담당별로 가르니 목적에 속하는 것은 열뿐이었다** — 열둘이 문서·말(`audit-internal`), 여섯이 검사 장치(`audit-quality`), 넷이 감사자 자신에 대한 것이었다. 「보지 않는 것」이 **시작할 때의 범위 선언**으로만 읽히고 **NC 를 적을 때의 관문**으로는 쓰이지 않았기 때문이다.

그래서 여섯 다에 관문을 넣었다. 증상은 회차가 안 끝나는 것으로 나타난다 — 담당 아닌 감사자가 같은 종류를 **회차마다 한 자리씩** 줍기 때문이다. 담당 감사자 한 회차면 전수로 끝난다.

**셋째는 관문이 한쪽으로만 서 있었다는 것이다** (ERP, 2026-09-21). 관문을 넣고 첫 회차에서 담당 밖 NC 가 **하나도 안 나왔고**(앞 여섯 회차는 서른셋 중 열여덟), 넘긴 아홉 줄에 담당이 적혀 있었다. 그런데 그 회차가 낸 **단 하나의 부적합을 담당이 다른 감사자라고 적어 넘겼다.** 고칠 자리는 마이그레이션 코드였고 다른 감사자가 줄 수 있는 것은 **심각도의 근거**뿐이었다.

관문이 「이것이 내 담당인가」만 묻고 **근거를 줄 사람과 고칠 담당이 다를 때**를 말하지 않아서 난 자리다. 담당을 근거 주는 쪽에 붙이면 그 줄은 아무도 집지 않는다 — 받은 회차는 고칠 자리를 모르고, 고칠 수 있는 감사자는 자기 목록에서 못 본다. 한 회차 앞에서 **기한**이 같은 모양으로 샜던 것의 담당 쪽 판이다. 그래서 반대쪽 절을 여섯 다에 나란히 세웠다.

### 되먹인 자리마다 회귀 검사를 세운다

되먹임 셋은 전부 **써 보다가 우연히** 나왔다. 가장 비싼 발견 경로이고, 더 나쁜
것은 **고친 것이 도로 풀려도 모른다**는 점이다. 감사자 문구를 다섯 번 고쳤는데
고친 뒤 좋아졌는지 잰 적이 한 번도 없었다.

그래서 `vibe-audit/evals/` 에 되먹임 한 건에 케이스 하나씩 붙였다.

```bash
./scripts/run-evals.sh
```

재는 것은 **오검율**이다. 회수율(심은 결함을 몇 개 잡는가)은 아직 안 잰다 —
지어낸 결함은 「재지 않고 단정한 것」의 픽스처 판이기 때문이다. 반면 함정
다섯은 ERP 에서 실제로 겪어 이 문서에 적힌 것이라 지어낸 것이 아니다.

각 픽스처에는 **진짜 부적합이 하나씩** 들어 있다. 이게 없으면 아무것도 안 내는
망가진 감사자가 함정을 안 걸었다는 이유로 만점을 받는다.

**이것도 무는지 확인해 두었다.** `audit-secrets` 체크 항목 1 을 1차 되먹임
이전 문구로 한 칸 되돌리자 점수가 1.0 → 0.5 로 떨어지고 함정 그레이더가 아홉
표 전부 실패했다. 대조군은 그대로 통과했으므로, 감사자가 망가진 것이 아니라
정확히 그 자리에서만 실패한 것이다.

**특화 항목은 첫 감사를 돌린 뒤에 얹는다.** 미리 지어낸 체크 항목은 재지 않고 단정한 것이다.

### 사본이 원본의 공통 절을 들고 있는지 견준다

```bash
python3 scripts/verify-copy.py <대상 레포>/.claude/agents
```

절이 있는지만 보는 검사는 소용없다 — 세션이 문구를 손으로 다시 쓰거나 한 줄
빠뜨려도 통과한다. 그래서 **문구를 글자 단위로** 견준다. 사본 고유의 특화는
보지 않는다. 물지 않는 검사는 게이트가 아니므로, 절 삭제 · 문구 한 글자 변경 ·
`tools` 변조 셋에서 실제로 실패하는 것을 확인해 두었다.

### 견줄 상대는 대장에서 온다

위 검사에는 오래 빈 자리가 있었다 — **사본이 어디에 있는지 적힌 데가 없었다.**
사본은 다른 레포에 살고, 심은 사람 말고는 아무도 경로를 모른다. 대장이 없으면
그 검사는 아무도 안 돌리는 검사이고, **안 도는 검사는 게이트가 아니다.**

`sync-agents.sh` 가 심을 때마다 `copies.json` 에 한 줄을 적는다 — 레포 · 경로 ·
심은 커밋 · 날짜.

```bash
python3 scripts/verify-copies.py
```

대장이 성한지 보고(빠진 자리 · 같은 레포 두 번 · **이 저장소에 없는 커밋**),
경로가 이 기계에 있으면 `verify-copy.py` 까지 **이어 돌린다.** 없으면 없어서
못 봤다고 찍는다 — 안 본 것을 본 것처럼 두지 않는다.

**갈린 것 자체는 실패가 아니다.** 사본은 갈리라고 둔 것이므로, 원본이 그 뒤
몇 커밋 움직였는지는 찍어 주되 판정하지 않는다.

이것도 무는지 확인해 두었다 — 사본 공통 절 한 글자 변경 · 이 저장소에 없는
커밋 · 자리 빠짐 · 같은 레포 두 번 · 대장이 JSON 이 아님, **다섯 전부**에서
실패한다.

## 감사 계획과 부적합 대장

무엇을 언제 돌릴지와 부적합 추적은 계정 스킬 `separate-audit` 이 맡는다. 스킬은 계정 경유로 클라우드 레인까지 도달하므로 여기서 배포하지 않는다.

## 새 프로젝트를 열 때

1. `scripts/sync-agents.sh <새 레포>` — 감사자 여섯을 심는다
2. 계정 스킬 `project-kickoff` 으로 착공
3. 첫 조각이 끝나면 `@audit-data` 부터

계정에 붙어 있는 스킬 넷(`project-kickoff` · `build-gate` · `separate-audit` · `ai-native-build`)은 설치가 필요 없다.
